SafeKitを使用した K3S 高可用性:フェイルオーバー用にk3s.safeモジュールをインストールします

Kubernetes の高可用性クイック インストール ガイド

このガイドでは、セットアップ方法について説明します。 ミラークラスタ のために Kubernetes を使用して SafeKit共有ストレージを必要とせずに、自動フェイルオーバーと同期レプリケーションを保証します。

ヘルプが必要な場合は、次を使用できます SafeKit AI 🤖.

1. 概要

  • アーキテクチャ: 2ノードシステム(プライマリ/セカンダリ)を採用します。
  • データ保護: リアルタイム同期レプリケーションを実装します。 データ損失ゼロ (RPO=0)。

2. インストール

  • ソフトウェア: SafeKit エンジンを両方のサーバーにインストールします。
  • モジュール: 事前設定されたものをダウンロードする k3s.safe アプリケーションモジュール。

3. 構成

  • ウェブコンソール: Kubernetes ファイルを含む特定のフォルダーを構成します。
  • モニタリング: Kubernetes アプリケーションの監視と保護を開始します。

SafeKit / KubernetesソリューションをLinux ( k3s.safe )にインストールおよび構成する

1. パッケージをダウンロードします

  • LinuxからSafeKit 8.2 の無料版をダウンロードしてください (safekitlinux_xx.bin)
  • k3s.safe Linuxモジュールをダウンロードしてください。
  • k3sconfig.shスクリプトをダウンロードしてください
  • ドキュメント（pptx形式）

注： k3sconfig.shスクリプトは、2 台のLinux Ubuntu 24.04 ノードに K3S、 MariaDB 、NFS、 SafeKitをインストールします。

2. 両方のノードで最初に

2台のLinux Ubuntu 24.04ノードで、rootユーザーとして：

  • ノードがインターネットにアクセスできることを確認してください（プロキシ経由でも構いません）。
  • k3sconfig.sh 、 k3s.safe 、およびsafekit_xx.binパッケージをディレクトリにコピーし、そのディレクトリに移動します。
  • .bin ファイルの名前を「safekit.bin」に変更してください。
  • k3sconfig.shとsafekit.binが実行可能であることを確認してください。
  • k3sconfig.shスクリプトを編集し、環境に合わせて環境変数をカスタマイズしてください（仮想IPアドレスを含む）。
  • 両方のノードで実行: ./k3sconfig.sh prereq

スクリプトは以下のとおりです。

  • 必要な Debian パッケージをインストールします: alien、nfs-kernel-server、nfs-common、mariadb-server
  • MariaDBの安全なインストール
  • ファイル複製用のディレクトリを作成する
  • レプリケートされたディレクトリを共有するためのNFSサーバーの準備
  • SafeKitをインストール

3. 最初のノードで

最初のノードで実行: ./k3sconfig.sh first

スクリプトは以下のとおりです。

  • K3S構成データベースとk3sユーザーを作成します。
  • レプリケートされたストレージボリュームファイル（スパースファイル）を作成し、それをxfsファイルシステムとしてフォーマットします。
  • SafeKitクラスタ構成を作成し、適用する
  • クラスターにk3s.safeモジュールをインストールして構成します。
  • 最初のノードでk3sモジュールを「prim」として起動します。
  • k3sをダウンロード、インストール、起動する
  • nfs-subdir-external-provisioner Helmチャートをダウンロードしてインストールします。
  • K3Sトークンを表示する（第2ノードインストールフェーズで使用）

4. 2番目のノードで

2番目のノードで実行: ./k3sconfig.sh second <token>

  • は、最初のノードでの「 k3sconfig.sh first」実行の最後に表示される文字列です。

スクリプトは以下のとおりです。

  • 最初のノードでk3sモジュールがプリムとして起動されていることを確認してください。
  • 2番目のノードにk3sをインストールします。
  • k3sモジュールを起動します

7.テスト

  • PRIMノードを停止するには、コンテキストメニューをスクロールダウンしてStopをクリックします。
  • 2番目のノードでフェイルオーバーが発生し、そのノードが単独状態（緑色）になることを確認してください。
  • コマンドラインがオンになっている場合 Linuxサービスのフェイルオーバーを確認します（ノード 1 で停止しています） stop_prim スクリプトはノード 2 で開始されました。 start_prim スクリプト）。 MariaDB K3Sはnode2上で動作する必要があります。

ノード2でALONE（緑色）に到達しない場合は、ノード2のモジュールログを使用してその理由を分析してください。

  • モジュールログを表示するには、 node2をクリックしてください。
  • 例 SQL Server モジュールログ サービス名が start_prim 無効です。 sqlserver.exe プロセスは監視されますが、開始されないため、最後にモジュールは停止します。

全て問題がなければ、node1で起動を開始し、node2から複製されたディレクトリを再同期します。

問題が発生した場合は、node2 を停止し、 で node1 プライマリとして強制的に起動します。これにより、停止時のローカルで正常なデータを使用して再起動します。

を入力してください

クラスターでネットワーク分離が発生した場合、どのようなシナリオがありますか？

単一のネットワーク

ネットワーク分離が発生すると、既定では次のように動作します。

  • 各ノードでハートビートが失われるため、それぞれのノードが ALONE になり、自身の仮想 IP アドレスでアプリケーションを実行します（アプリケーションが二重に実行され、それぞれのローカルデータを変更します）。
  • 分離が解消されると、一方の ALONE ノードは強制的に停止し、もう一方のノードからデータを再同期します。
  • 最終的にクラスターは PRIM-SECOND になります（Windows による仮想 IP アドレスの重複検出に応じて SECOND-PRIM になる場合もあります）。

専用のレプリケーションネットワークを持つ 2 つのネットワーク

ネットワーク分離が発生した場合、専用のレプリケーションネットワークがあると次のように動作します。

  • 専用のレプリケーションネットワークをプライベートネットワーク上に構築します。
  • 本番ネットワークのハートビートは失われます（分離されたネットワーク）。
  • レプリケーションネットワークのハートビートは機能します（分離されていないネットワーク）。
  • クラスターは PRIM/SECOND 状態のままです。

単一のネットワークとスプリットブレインチェッカー

ネットワーク分離が発生した場合、スプリットブレインチェッカーがあると次のように動作します。

  • スプリットブレインチェッカーに監視役（通常はルーター）の IP アドレスを設定しておきます。
  • サーバーが PRIM から ALONE、または SECOND から ALONE に移行するときに、スプリットブレインチェッカーが動作します。
  • ネットワーク分離時には、両方のノードが ALONE になる前に IP アドレスをテストします。
  • IP アドレスにアクセスできるノードは ALONE に、もう一方は WAIT に移行します。
  • 分離が解消されると、WAIT ノードがデータを再同期して SECOND になります。

注：監視役が停止または切断されていると、両方のノードが WAIT になり、アプリケーションは実行されなくなります。そのため、ルーターのような信頼性の高い監視役を選ぶ必要があります。
