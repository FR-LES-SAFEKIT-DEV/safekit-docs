## وحدات التطبيق الجاهزة {#pre-built-application-modules}

يتضمن SafeKit وحدات `.safe` جاهزة للاستخدام ومُهيأة مسبقًا. وهي مُنظمة في استراتيجيتين للتوافر العالي: **توافر التطبيقات** (تجميع التطبيقات المباشر باستخدام وحدات mirror أو `farm` ) و **توافر المحاكاة الافتراضية** (تجميع على مستوى الجهاز الظاهري باستخدام hyperv.safe أو kvm.safe ).

 | تطبيق عالي التوفر | عالي التوفر على مستوى الجهاز الظاهري  
---|---|---  
يتطلب التكوين | فهمًا تقنيًا للتطبيق نفسه: أي الخدمات التي تحتاج إلى إعادة تشغيل، ومجلدات التطبيق المحددة التي تحتاج إلى نسخ متماثل فوري، وتكوين عنوان IP افتراضي للتحويل التلقائي في حالة الفشل. أما التكوين | فهو حل عام لأي تطبيق/نظام تشغيل يعمل على الجهاز الظاهري. لا يتطلب فهمًا تقنيًا للتطبيق المثبت داخل الجهاز الظاهري. وهو الحل الأمثل إذا لم تكن على دراية بكيفية عمل التطبيق. كل ما عليك فعله هو تحديد موقع ملفات الجهاز الظاهري.  
مثالي لـ | مثالي لتضمين خاصية التوافر العالي مباشرةً في حل برمجي، بغض النظر عن الأجهزة أو برنامج إدارة الأجهزة الافتراضية. | مثالي لإدارة بيئات معقدة تضم تطبيقات متعددة عبر عدة أجهزة افتراضية من خلال سياسة توافر عالي واحدة.  
  
يسرد الجدول أدناه جميع وحدات `.safe` المتاحة:

تطبيق عالي التوفر (تجميع على مستوى التطبيق) | المحاكاة الافتراضية عالية التوفر (تجميع على مستوى الجهاز الظاهري)  
---|---  
تطبيق Windows الجديد — mirror.safe | جهاز Hyper-V الظاهري — hyperv.safe ( Windows )  
تطبيق Linux الجديد — mirror.safe | و KVM VM — kvm.safe ( Linux )  
موازنة الأحمال Windows — حاوية farm.safe | Docker — mirror.safe ( Linux )  
موازنة الأحمال Linux — حاوية farm.safe | Podman — mirror.safe ( Linux )  
Microsoft SQL Server — sqlserver.safe ( Windows ) | Kubernetes / K3s — k3s.safe ( Linux )  
PostgreSQL — postgresql.safe ( Windows & Linux ) | Bosch AMS — hyperv.safe ( Windows )  
MySQL — mysql.safe ( Windows & Linux ) | بوش BIS — hyperv.safe ( Windows )  
MariaDB — mysql.safe ( Windows & Linux ) | Bosch BVMS — hyperv.safe ( Windows )  
Oracle — oracle.safe ( Windows & Linux ) | رؤية هانوا — hyperv.safe ( Windows )  
Firebird — firebird.safe ( Windows & Linux ) | Hanwha Wisenet — hyperv.safe ( Windows )  
أباتشي — apache_farm.safe ( Windows & Linux ) | مجموعة سيمنز للمراقبة — hyperv.safe ( Windows )  
IIS — iis_farm.safe ( Windows ) | Siemens Desigo CC — hyperv.safe ( Windows )  
NGINX — farm.safe ( Windows & Linux ) | Siemens SiPass — hyperv.safe ( Windows )  
Milestone XProtect — milestone.safe ( Windows ) | سيمنز SIPORT — hyperv.safe ( Windows )  
Nedap AEOS — nedap.safe ( Windows ) | SIMATIC PCS 7 — hyperv.safe ( Windows )  
جينيتيك ( SQL Server ) — sqlserver.safe ( Windows ) | SIMATIC WinCC — hyperv.safe ( Windows )  
نظام مراقبة الفيديو من سيمنز - SiveillanceVMS.safe ( Windows ) |   
السحابة ( AWS ، Azure ، GCP ، عام) — mirror.safe / farm.safe |   
  
## نموذج البنية والنشر {#architecture-deployment-model}

### وحدتان للتجميع: mirror.safe و farm.safe و {#two-cluster-modules}

الوحدة النمطية | النمط | ، حالة الاستخدام  
---|---|---  
mirror.safe | وضع نشط-سلبي مع نسخ متزامن للملفات على مستوى البايت + تجاوز الفشل التلقائي | قواعد البيانات، والتطبيقات ذات الحالة، والخدمات التي تعمل على خادم واحد فقط في كل مرة  
farm.safe | وضع نشط-نشط مع موازنة أحمال الشبكة + تجاوز الفشل التلقائي | خوادم الويب، والخدمات المصغرة عديمة الحالة، وبوابات واجهة برمجة التطبيقات، والخدمات التي تعمل على خوادم متعددة في وقت واحد  
  
### بنية وهيكلية المجموعة {#cluster-infrastructure-architecture}

المتطلبات / المواصفات | SafeKit القدرة / القيمة  
---|---  
هل يلزم وجود وحدة تخزين مشتركة؟ | لا — بنية "لا شيء مشترك" بدون شبكة تخزين. تستخدم الأقراص المحلية فقط.  
هل يتطلب ذلك وجود Active Directory (AD)؟ | ، لا يتطلب ذلك Windows نطاق أو Active Directory. مجموعات العمل مدعومة بالكامل.  
حجم المجموعة | عقدتان ( mirror ) أو عقدتان أو أكثر ( `farm` )  
عنوان IP افتراضي (VIP) | هو عنوان IP افتراضي مُعرَّف برمجياً ينتقل تلقائياً إلى العقدة النشطة عبر بروتوكول ARP المجاني (توفر عالي على مستوى التطبيق). أما بالنسبة للتوفر العالي على مستوى الجهاز الظاهري، فيتم إعادة توجيه عنوان IP الفعلي داخل الجهاز الظاهري بشفافية تامة، دون الحاجة إلى عنوان IP افتراضي. يتطلب ذلك وجود شبكة محلية (LAN) أو شبكة محلية ظاهرية (VLAN) أو شبكة محلية ظاهرية ممتدة بين العقد.  
يغطي تصميم البنية الهجينة ثلاثية العقد | SafeKit طبقة التوافر العالي: مجموعة من عقدتين mirror عبر شبكة محلية أو شبكة VLAN ممتدة مع نسخ متزامن (RPO=0) وتجاوز تلقائي في حالة الفشل. ويكتمل التصميم بحل نسخ احتياطي من طرف ثالث: عقدة بعيدة ثالثة مع نسخ غير متزامن عبر شبكة WAN لاستعادة البيانات إلى نقطة زمنية محددة وحماية من برامج الفدية.  
دور التوافر العالي: يستخدم | SafeKit النسخ المتزامن لضمان تجاوز الأعطال الفوري دون فقدان أي بيانات أثناء أعطال الأجهزة أو البرامج. ومع ذلك، ولأنه يكتب البيانات إلى كلا العقدتين في وقت واحد، فإنه ينسخ الأخطاء المنطقية أو تدهور البيانات أو عمليات الحذف العرضية بدقة إلى العقدة الاحتياطية في الوقت الفعلي.  
دور النسخ الاحتياطي | يوفر حل النسخ الاحتياطي (غير المُطبق بواسطة SafeKit ) إمكانية استعادة البيانات إلى نقطة زمنية محددة عبر النسخ غير المتزامن. وهو يحمي من تهديدات سلامة البيانات (مثل برامج الفدية أو الخطأ البشري) التي لا يمكن لخاصية التوافر العالي (HA) منعها. لا يدعم هذا الحل التبديل التلقائي في حالة الفشل، لأن استعادة البيانات تؤدي بطبيعتها إلى فقدانها.  
الحد الأقصى للوحدات المتزامنة لكل مجموعة | هو 32 — يغطي هذا الحد الأقصى لعدد وحدات SafeKit التي تتم إدارتها بشكل متزامن في مجموعة مكونة من عقدتين، وتُستخدم عادةً في التوافر العالي على مستوى الجهاز الظاهري حيث تقوم كل وحدة بنسخ جهاز ظاهري مختلف وإعادة تشغيله. يمكن تشغيل كل وحدة بشكل مستقل كوحدة أساسية على أي من العقدتين، مما يتيح توزيع عبء العمل على كلا الخادمين. ملاحظة: يؤثر إجمالي حجم البيانات عبر جميع الأجهزة الظاهرية بشكل مباشر على وقت إعادة المزامنة بعد تجاوز الفشل أو إعادة تشغيل العقدة.  
قائم على الوكلاء أم بدون وكلاء؟ | قائم على الوكلاء - برنامج خفيف الوزن مثبت على كل عقدة  
هل هو مستقل عن التطبيق؟ | نعم — يحمي أي خدمة Windows أو برنامج Linux ؛ وحدات مُجهزة مسبقًا لأكثر من 30 تطبيقًا  
  
### النسخ الاحتياطي وحماية البيانات {#replication-data-protection}

المتطلبات / المواصفات | SafeKit القدرة / القيمة

نمط النسخ المتماثل | متزامن (بدون فقدان للبيانات)

حجم البيانات الموصى به | بضعة تيرابايت (وقت إعادة المزامنة)

النسخ الانتقائي | نعم — نسخ مجلدات/ملفات محددة  
التشفير أثناء النقل | نعم — TLS/SSL لحركة النسخ المتماثل  
  
## إمكانيات RPO و RTO {#rpo-rto-capabilities}

### RPO و RTO حسب نوع المجموعة {#rto-rpo-cluster-type}

مجموعة المقاييس | Mirror ( mirror.safe ) | `Farm` ( farm.safe )  
---|---|---  
هدف نقطة الاستعادة (RPO) | 0 (انعدام فقدان البيانات) - نسخ متزامن؛ يتم تأكيد الكتابة فقط بعد تأكيد كلا العقدتين | غير متوفر (بدون حالة؛ تتم معالجة البيانات بواسطة الواجهة الخلفية mirror )  
هدف وقت الاسترداد (RTO) | ~ دقيقة واحدة — مهلة نبضات القلب (افتراضيًا 30 ثانية) + وقت إعادة تشغيل التطبيق | بضع ثوانٍ — يتم إعادة توزيع حركة البيانات فورًا إلى العقد النشطة المتبقية  
نوع النسخ المتماثل | نسخ متماثل متزامن، في الوقت الفعلي، على مستوى البايت. | غير قابل للتطبيق.  
مُشغِّل تجاوز الفشل | تلقائي عند فقدان إشارة النبض، أو تعطل العملية، أو فشل المُدقِّق. | تلقائي عند فقدان إشارة النبض، أو تعطل العملية، أو فشل المُدقِّق.  
هل يلزم تدخل يدوي؟ | لا — تجاوز الفشل والعودة إلى الوضع الطبيعي تلقائيان بالكامل | لا — تجاوز الفشل والعودة إلى الوضع الطبيعي تلقائيان بالكامل  
  
### تعطل RTO ( Mirror - التوافر العالي على مستوى التطبيق) {#rto-breakdown-mirror-application-level-ha}

حساب وقت إعادة التشغيل لنوع الفشل |  
---|---  
عطل في الجهاز | مهلة نبضات القلب (افتراضيًا 30 ثانية) + وقت إعادة تشغيل التطبيق  
عطل في البرنامج/العملية | وقت توقف التطبيق + وقت إعادة تشغيل التطبيق  
عطل على مستوى نظام التشغيل | مهلة نبضات القلب + نظام التشغيل يعمل بالفعل على جهاز ثانوي ← لا توجد عقوبة إعادة تشغيل  
  
### تحليل وقت الاستعادة ( Mirror - مستوى التوافر العالي على مستوى الجهاز الظاهري) {#rto-breakdown-mirror-vm-level-ha}

حساب وقت إعادة التشغيل لنوع الفشل |  
---|---  
أي عطل | اكتشاف العطل + إعادة تشغيل نظام التشغيل بالكامل + إعادة تشغيل التطبيق (عادةً عدة دقائق)  
  
## ملاءمة النشر على الحافة والموزعة {#edge-distributed-deployment-suitability}

تم تصميم SafeKit خصيصًا لسيناريوهات الحافة، وفروع المكاتب، والمؤسسات الموزعة.

متطلبات الحافة | SafeKit الإجابة  
---|---  
لا يوجد موظفون متخصصون في تكنولوجيا المعلومات في الموقع | نعم — تجاوز الأعطال تلقائيًا، بدون تدخل يدوي  
لا توجد بنية تحتية لـ SAN/NAS | نعم — بدون SAN، أقراص محلية فقط  
الإدارة عن بُعد | نعم — إدارة وحدة تحكم الويب  
بصمة أجهزة منخفضة | نعم — خادمان قياسيان أو جهازان افتراضيان، لا حاجة لأجهزة خاصة  
يعمل خلف جدران الحماية/NAT | نعم — منافذ قابلة للتكوين، وحدة تحكم قائمة على HTTPS  
استعادة البيانات في حالات الكوارث بين موقعين جغرافيين عبر شبكة VLAN ممتدة | - نعم mirror )  
نشر OEM/مدمج | نعم — تثبيت صامت، قابل للبرمجة النصية، قابل للتضمين بواسطة ناشري البرامج  
مئات من المجموعات الموزعة | نعم - مصممة للمؤسسات الموزعة ذات الفروع المتعددة  
  
حالات الاستخدام المثالية للحوسبة الطرفية: أي موقع بدون مركز بيانات - حيث لا تزال التوافرية العالية مهمة:

موقع الحافة النموذجي | العمودي | تطبيق حرج  
---|---|---  
الأمن المادي والمراقبة | المباني، الجامعات، المطارات | VMS — Milestone ، Genetec، Hanwha، Siemens Siveillance  
نظام إدارة المباني (BMS) | مباني المكاتب، المستشفيات، المصانع | سيمنز ديزيجو سي سي، بوش BIS/BVMS  
نظام التحكم الإلكتروني بالوصول (EACS) | المرافق الآمنة، الجامعات | سيمنز SiPass، Nedap ، بوش AMS  
أنظمة التحكم الإشرافي وجمع البيانات (SCADA) والتحكم الصناعي | المصانع، المحطات الفرعية، محطات المياه | أي برنامج SCADA أو DCS أو HMI يعمل على Windows أو Linux  
مراقبة الحركة الجوية (ATC) | المطارات، أبراج المراقبة | أنظمة إدارة مراقبة الحركة الجوية والرادار  
مراكز التحكم بالعمليات (OCC) | مترو الأنفاق، والسكك الحديدية، ومراكز النقل | إشارات السكك الحديدية وإدارة المحطات
