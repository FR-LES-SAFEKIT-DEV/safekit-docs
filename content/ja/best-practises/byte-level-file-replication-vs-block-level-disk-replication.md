# HAにおけるバイトレベルファイルレプリケーションとブロックレベルディスクレプリケーションの比較 {#byte-level-file-replication-vs-block-level-disk-replication-for-ha}

## 高可用性クラスタにおけるバイトレベルファイルレプリケーションとブロックレベルディスクレプリケーションの比較 {#byte-level-file-replication-vs-block-level-disk-replication-in-a-high-availability-cluster}

### 概要 {#overview}

この記事では、高可用性クラスタにおけるバイトレベルのファイルレプリケーションとブロックレベルのディスクレプリケーションの長所と短所について考察します。具体的には、レプリケートされるデータ量、アプリケーションデータ構成への影響、復旧時間、実装の容易さなどを検討します。


![バイトレベルのファイル複製とブロックレベルのディスク複製](/wp-content/uploads/2023/02/file-replication-vs-disk-replication.png "w:200")


以下の比較表は、高可用性ソフトウェア製品であるSafeKitによって実装されたバイトレベルのファイルレプリケーションについて詳細に説明しています。

### バイトレベルのファイルレプリケーションとは何ですか？ {#what-is-byte-level-file-replication}

バイトレベルのファイル複製（ [ SafeKit ](</>)など）とは、ファイル内部の変更のみが複製されることを意味します。 

高可用性クラスタでは、障害発生時にデータ損失をゼロにするために、 [同期レプリケーション](</ja/best-practises/synchronous-replication-vs-asynchronous-replication/>)が必要です。非同期レプリケーションはバックアップソリューション向けです。

複製されるデータの量は、アプリケーションがファイル内で変更した情報のみに削減されます。余分なデータは複製されません。

アプリケーションのデータ構成には影響はありません。例えば、アプリケーションのデータがシステムディスクにある場合、バイトレベルのファイルレプリケーションは正常に機能します。

フェイルオーバー発生時の復旧時間（RTO）は、セカンダリサーバーの複製ファイル上でアプリケーションを再起動する時間まで短縮されます。

最後に、このソリューションは設定が非常に簡単で、複製するディレクトリのパスを設定するだけで済みます。

### ブロックレベルのディスクレプリケーションとは何ですか {#what-is-block-level-disk-replication}

ブロックレベルのディスクレプリケーション（ [ DRBD ](<https://linbit.com/drbd/>)など）とは、ディスク内部の変更のみがレプリケートされることを意味します。

複製されるデータの量は、アプリケーションによって変更された情報だけにとどまりません。ディスク管理のためのメタデータ（空きブロックのリスト、ファイルシステムの内部情報など）といった追加データも複製されます。

アプリケーションデータの構成に大きな影響があります。すべてのデータは複製ディスク内に配置する必要があります。少なくとも、アプリケーションの再構成が必要になります。あるいは、複製対象データの一部がシステムディスクにある場合は、このディスクは各サーバー固有のものである必要があるため、再構成は不可能です。

フェイルオーバー後の複製ディスク上でのファイルシステム復旧手順が進むにつれて、復旧時間（RTO）は長くなります。

最後に、このソリューションは設定が容易ではありません。ファイルシステムを備えた特殊なディスクを設定するには専門的なスキルが必要であり、さらに、複製されたディスクにアプリケーションデータを設定するにはアプリケーションに関するスキルも必要となるからです。
