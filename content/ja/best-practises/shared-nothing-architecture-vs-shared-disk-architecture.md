# 共有ディスクなしアーキテクチャと共有ディスクアーキテクチャ：最適なHAクラスタの選択 {#shared-nothing-vs-shared-disk-architecture-choosing-the-best-ha-cluster}

## 高可用性クラスタにおける共有ディスクアーキテクチャと共有ディスクアーキテクチャの比較 {#shared-nothing-architecture-vs-shared-disk-architecture-for-high-availability-clusters}

### 概要 {#overview}

この記事では、高可用性クラスタにおける共有ディスクなしアーキテクチャと共有ディスクアーキテクチャの長所と短所について考察します。具体的には、ハードウェアの制約、アプリケーションデータの構成への影響、復旧時間、実装の容易さなどを検討します。

以下の比較表は、共有ディスクアーキテクチャと、共有ディスクを一切使用しないアーキテクチャを実装したソフトウェアクラスタリング製品であるSafeKitとの違いを詳細に説明しています。

### 共有ディスクアーキテクチャは何ですか？ {#what-is-a-shared-disk-architecture}

共有ディスクアーキテクチャ（ [ Microsoftフェイルオーバークラスタ、 ](<https://learn.microsoft.com/en-us/windows-server/failover-clustering/clustering-requirements>)など）は、2台のサーバーがディスクを共有し、ハードウェアまたはソフトウェアの障害が発生した場合にアプリケーションが自動的にフェイルオーバーする仕組みに基づいています。

このアーキテクチャにはハードウェア上の制約があります。具体的には、特定の外部共有ストレージ、サーバー内部にインストールする特定のカード、そしてサーバーと共有ストレージ間の特定のスイッチです。

共有ディスクアーキテクチャは、アプリケーションデータの構成に大きな影響を与えます。フェイルオーバー後の再起動のために、すべてのアプリケーションデータは共有ディスク上に配置する必要があります。

さらに、フェイルオーバー時には、共有ディスク上でファイルシステムの復旧手順を実行する必要があります。これにより、復旧時間（RTO）が増加します。

最後に、このソリューションは特定のハードウェアを設定するためのスキルが必要となるため、設定が容易ではありません。さらに、共有ディスク上のアプリケーションデータを設定するには、アプリケーションに関するスキルも必要となります。

### 共有なしアーキテクチャとは何ですか？ {#what-is-a-shared-nothing-architecture-}

シェアードナッシングアーキテクチャ（ [ SafeKit ](</>)など）は、2台のサーバーがリアルタイムでデータを複製し、ハードウェアまたはソフトウェアの障害が発生した場合に自動的にアプリケーションがフェイルオーバーする構成に基づいています。

データ複製には、バイトレベルのファイル複製[とブロックレベルのディスク複製](</ja/best-practises/byte-level-file-replication-vs-block-level-disk-replication/>)の2種類があります。ここでは、ブロックレベルのディスク複製に比べて多くの利点があるため、バイトレベルのファイル複製について検討します。

シェアードナッシングアーキテクチャにはハードウェアの制約がありません。サーバーは物理サーバーでも仮想サーバーでも、ディスク構成の種類は問いません。リアルタイムファイルレプリケーション（データ損失ゼロを実現する[ ](</ja/best-practises/synchronous-replication-vs-asynchronous-replication/>) ）は、サーバー間の標準ネットワークを介して行われます。

このアーキテクチャは、アプリケーションのデータ構成に影響を与えません。例えば、アプリケーションのデータがシステムディスクにある場合でも、リアルタイムのファイルレプリケーションは正常に動作します。

フェイルオーバー発生時の復旧時間（RTO）は、セカンダリサーバーの複製ファイル上でアプリケーションを再起動する時間まで短縮されます。

最後に、このソリューションは設定が非常に簡単で、複製するディレクトリのパスを設定するだけで済みます。
