# ネットワーク内のSafeKitミラークラスタの仮想IPアドレスをテストする

このガイドでは、SafeKitミラークラスタ（ミラーモジュール）の仮想IPアドレス（VIP）がネットワーク内で正しく機能していることを確認する方法について説明します。仮想IP（VIP）はプライマリサーバーによって保持され、フェイルオーバー後に新しいプライマリサーバーに再ルーティングされます。

## 1. 基本原則

**前提条件：**ミラークラスタの両方のノードは、同じレイヤ2 IPサブネット（LAN、またはリモートサイト間で拡張されたVLAN）に属している必要があります。

- 仮想 IP (VIP) は**プライマリ サーバー**(PRIM または ALONE 状態) でのみ有効です。モジュールがノード上でプライマリとして起動すると ( `where="one_side_alias"`設定)、そのアドレスのネットワーク カード上の物理 IP アドレスのエイリアスとして設定されます。
- したがって、プライマリサーバーのMACアドレスは、ARPテーブル（ルーター、ゲートウェイ、同一サブネット内のクライアント）において仮想IP（VIP）に関連付けられているアドレスです。仮想IP（VIP）宛てのすべてのトラフィックはプライマリサーバーに送信されます。
- フェイルオーバー（プライマリの停止または障害）が発生すると、仮想IP（VIP）は以前のプライマリから削除され、新しいプライマリにエイリアスとして設定されます。その後、2つのメカニズムによって、ネットワークは仮想IP（VIP）を新しいプライマリのMACアドレスに関連付けることができます。
  - 仮想IP（VIP）がネットワークカードにエイリアスとして追加されたときに、オペレーティングシステムによって送信されるネットワークメッセージ。
  - `<vip>`セクションで`arpreroute="on"`属性が設定されている場合、SafeKit によって送信される**GARP** (gratuitous ARP)。

したがって、テストする必要があるのは以下のとおりです。

1. 仮想IPアドレス（VIP）はプライマリサーバーによって保持され、クライアントからアクセス可能です。
2. プライマリサーバーが変更されると、仮想IP（VIP）に関連付けられたMACアドレスは、ネットワーク内の新しいプライマリ（ルーター、ゲートウェイ、仮想化）に再ルーティングされます。

## 2. 前提条件：仮想IP（VIP）の設定

1. ミラーモジュールの`userconfig.xml`ファイルで、 `<vip>`セクションに仮想IPアドレス（VIP）を設定します。arpreroute `arpreroute="on"`属性を設定すると、フェイルオーバー後に新しいプライマリがGARPパケットを送信します。

   ```xml
   <vip>
     <interface_list>
       <interface arpreroute="on">
         <real_interface>
           <virtual_addr addr="<VIP>" where="one_side_alias"/>
         </real_interface>
       </interface>
     </interface_list>
   </vip>
   ```

2. 両方のノードに設定を適用してください。
3. モジュールを開始するには、一方のノードが**PRIM（準備完了）**で、もう一方のノード**がSECOND（準備完了）**である必要があります。

## 3. テスト1 – プライマリサーバーが保持する仮想IP（VIP）

**手順**

1. プライマリサーバーで、 `ipconfig` （Windows）または`ip addr show` （Linux）を実行します。
   →**期待される結果：**仮想IP（VIP）が、物理IPアドレスのエイリアスとしてネットワークカード上に表示される。
2. セカンダリーサーバーでも、同じコマンドを実行してください。
   →**期待される結果：**仮想IP（VIP）が表示されない。
3. **クラスター外の**クライアントワークステーションから、物理IPアドレスと仮想IP（VIP）の両方に`ping` 。
   →**期待される結果：** 3つの`ping`コマンドすべてが応答する（ファイアウォールによってフィルタリングされない限り）。
4. SafeKit モザイクを使用して仮想 IP (VIP) 経由でのアクセスを確認します。**外部**クライアントのブラウザーから`http://<VIP>:9010/safekit/mosaic.html`に接続し、ミラー**モジュール名**を入力してテストを実行します。
   →**期待される結果:**モザイクのすべてのセルに**プライマリサーバー**の名前が単一の色で表示されます。仮想 IP (VIP) へのすべての TCP 接続はプライマリによって処理されます。
   SafeKitのWebサーバーとコンソールがHTTPSに切り替えられた場合は、9010を9453に置き換えてください。

## 4. テスト2 – 手動フェイルオーバー（プライマリの停止）

このテストでは、プライマリサーバー上のモジュールを停止することによってトリガーされるフェイルオーバー中に、仮想IP（VIP）がプライマリサーバーに追従することを確認します。

**手順**

1. SafeKitコンソールから（またはコマンドラインから`safekit stop -m <module>`を使用して）プライマリ（ノード1）上のモジュールを停止します。
   →**期待される結果：**ノード1はSTOP（NotReady）状態になり、ノード2はALONE（Ready）状態になります。新しいプライマリのログに`Virtual IP <VIP> set`というメッセージが表示されます。
2. 新しいプライマリで、 `ipconfig`または`ip addr show`を実行します。
   →**期待される結果：**仮想IP（VIP）がこのノードのエイリアスとして表示され、以前のプライマリノードには表示されなくなります。
3. クライアントワークステーションから、3つの`ping`コマンドを繰り返し実行し、仮想IP（VIP）上でモザイク処理を再度実行します。
   →**期待される結果：**すべてが反応し、モザイクのすべてのセルに**新しいプライマリ**の名前が単一の色で表示されます。
4. ノード1でモジュールを再起動すると、同期が再行われ、SECOND（準備完了）状態になります。一方、ノード2はPRIM（準備完了）状態になります。

## 5. テスト3 – `arp -a`を使用した MAC リルーティングの確認

フェイルオーバー前に仮想IP（VIP）に関連付けられたMACアドレスを記録し、フェイルオーバー後にそれが変更されていることを確認します。

このテストは、クライアントワークステーションがクラスタと**同じIPサブネット**内にある場合にのみ可能です。

クライアントとクラスタの間にルーターが存在する場合、クライアントのARPテーブルには仮想IPアドレス（VIP）ではなく、クラスタのネットワークに到達するために使用されるゲートウェイのアドレスが含まれます。その場合は、ネットワークチームと協力してルーターまたはゲートウェイのARPテーブルを確認してください。

**手順**

1. 当該モジュールは、ノード1ではPRIM（準備完了）状態、ノード2ではSECOND（準備完了）状態です。
2. クライアントワークステーションで、物理IPアドレスと仮想IP（VIP）の両方に`ping` 、その後`arp -a`を実行します。
   →**期待される結果:**仮想 IP (VIP) は**、プライマリの物理 IP アドレスと同じ MAC アドレス**に関連付けられます。
3. プライマリ（ノード1）上のモジュールを`stop` 。
4. 仮想IP（VIP）に再度`ping` 、その後、再度`arp -a`を実行します。
   →**期待される結果:**仮想 IP (VIP) は、**新しいプライマリの物理 IP アドレスと同じ MAC アドレス**に関連付けられます。

ARP テーブルを読み取る前に、仮想 IP (VIP) に再度`ping` 。エントリが古いものとしてマークされ、 `ping`の後にのみ更新される場合があります。

プライマリが停止する前と後の、想定されるARPテーブルの例：

|アドレス|停止前の MAC アドレス|停止後の MAC アドレス|
|---|---|---|
|ノード 1 の物理 IP アドレス|ノード 1 の MAC アドレス|ノード 1 の MAC アドレス|
|ノード 2 の物理 IP アドレス|ノード 2 の MAC アドレス|ノード 2 の MAC アドレス|
|仮想IP (VIP) |**ノード1 MAC** |**ノード2 MAC** |

## 6. テスト4 – Wireshark（Windows）またはtcpdump（Linux）を使用したエンドツーエンドチェック

クライアント側と両方のノードでパケットをキャプチャすることで、仮想IP（VIP）へのTCP接続を追跡できます。WindowsマシンではWiresharkを、Linuxマシンではtcpdumpを使用します。

**パケットのMAC（イーサネット）ヘッダー**を確認する必要があります。宛先IPアドレスは仮想IP（VIP）のままであり、トラフィックを受信するノードを示すのは宛先MACアドレスです。

**観察すべき点：**

|いつ|どこで|観測された MAC アドレスをキャプチャするか|
|---|---|---|
|フェイルオーバー前|クライアント|クライアントMAC →**ノード1（プライマリ）**のMAC |
|フェイルオーバー前|ノード 1 |仮想 IP (VIP) 宛のパケットが受信されます。ノード 2 は何も受信しません|
|フェイルオーバー中|ネットワーク|仮想 IP (VIP) のノード 2 から送信される MAC リルーティング メッセージ: エイリアスとして設定されているときに OS から送信されるメッセージ、および SafeKit ( `arpreroute="on"` ) から送信される GARPs |
|フェイルオーバー後|クライアント|クライアントMAC →**ノード2（新しいプライマリ）**のMAC |

クライアントワークステーションがクラスタとは異なるサブネットにある場合、ノードに表示される「クライアントMAC」は、クライアントワークステーションのMACアドレスではなく、2つのサブネットを接続する**ゲートウェイ**（ルータ）のMACアドレスです。

## 7. どのワークステーションからテストを行うか

動作はクライアントとクラスタ間のネットワークパスに依存します。ご使用のアーキテクチャに関連する各タイプのクライアントから、テスト1とテスト2を実行してください。

|クライアントの所在地|テストで確認する内容|
|---|---|
|クラスターと**同じサブネット**内のクライアント|クライアントのARPテーブルの更新（テスト3が可能） |
|**別のサブネット**（ルーター、ゲートウェイ、ハイパーバイザー仮想ネットワーク）内のクライアント|ルーターまたはゲートウェイでのクライアントのARPテーブルの更新|
|**ミラークラスタの VM の 1 つもホストするハイパーバイザ上のクライアント**VM |内部スイッチングとルーティングも処理するハイパーバイザの仮想スイッチの動作|

## 8．期待される結果の概要

|テスト|アクション|期待される結果|
|---|---|---|
| 1 | PRIM / SECOND、 `ipconfig` 、 `ping` 、およびmosaic |仮想 IP (VIP) はプライマリのみのエイリアスとして使用されます。3 つの`ping`コマンドは応答します (ファイアウォールによってフィルタリングされない限り)。mosaic にはプライマリのみが表示されます|
| 2 |プライマリの停止|新しいプライマリのエイリアスとしての仮想 IP (VIP)。 `Virtual IP <VIP> set`メッセージ。モザイクには新しいプライマリのみが表示されます|
| 3 |プライマリが停止する前と後の`arp -a` |仮想 IP (VIP) がノード 1 の MAC アドレスからノード 2 の MAC アドレスに移動します|
| 4 |フェイルオーバー前後の Wireshark または tcpdump キャプチャ|クライアントは新しいプライマリの MAC アドレスに送信します|

## 9. トラブルシューティング

- **フェイルオーバー後に仮想IP（VIP）が応答しなくなる原因は、**経路上のデバイス（ルーター、ゲートウェイ、仮想スイッチなど）がMACリルーティングメッセージを考慮せず、以前のプライマリのMACアドレス宛にトラフィックを送信し続けているためです。MACリルーティングメッセージの処理方法については、ネットワークチームにご確認ください。
- **GARP の送信:** `<vip>`セクションの`arpreroute="on"`属性 ( `arpinterval`および`arpelapse`を含む) は、フェイルオーバー後に仮想 IP (VIP) 上で定期的に GARP を送信します。ユーザー ガイドのセクション 13.6.4 " [`<vip>`構文](https://safekit.eviden.com/ja/resources/safekit-user-guide-82/#_%3Cvip%3E_Syntax)" を参照してください。
- **仮想IP（VIP）↔MAC解決の診断：**ユーザーガイドのセクション7.24「[仮想IP（VIP）↔MAC解決のトラブルシューティング](https://safekit.eviden.com/ja/resources/safekit-user-guide-82/#_Issue_with_VIP)」およびセクション7.16「[フェイルオーバー後の仮想IPの問題](https://safekit.eviden.com/ja/resources/safekit-user-guide-82/#_Problem_with_the_1)」を参照してください。

仮想IPアドレスを使用したロードバランシングについては、 [「SafeKit Farmクラスタでのロードバランシング仮想IPアドレスのテスト」を](/ja/best-practises/test-load-balancing-vip-farm/)参照してください。
