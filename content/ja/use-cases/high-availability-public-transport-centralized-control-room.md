# 交通管制室の高可用性 {#high-availability-for-transport-control-rooms}

![公共交通機関の高可用性：集中管理室](/wp-content/uploads/2026/05/safekit-occ-512-512.jpg)

## 公共交通機関の運行管理室 {#public-transport-control-rooms}

集中制御室は、現代の公共交通機関の神経中枢です。制御室は、地下鉄路線全体を監視し、自動化された運用を管理し、乗客の安全を確保します。地下鉄システム、自動化された地下鉄路線、およびバスネットワークの場合、制御室は中断することなく 24 時間年中無休で運用する必要があります。

RATP はパリの地下鉄を管理しています。毎日 1,000 万人以上の乗客を輸送しています。パリメトロ 1 号線は完全に自動化され、運転手はいません。そのため、コントロールルームの役割はさらに重要になります。

## なぜコントロールルームは重要なのでしょうか？ {#why-is-a-centralized-control-room-critical}

地下鉄の運行管理者は、どんなに小さなインシデントにも即座に対応しなければなりません。IT 障害によって運行管理者が路線の状況を把握できなくなることはあってはなりません。

制御室オペレーターの主な業務は以下のとおりです：

  * 線路上の列車の動きを監視する
  * ビデオカメラで自動検出されたインシデントの処理
  * 通信システムと公共アナウンスの管理
  * 安全業務および乗客への情報提供の監督

制御室のシステム障害は、乗客の安全とサービスの継続性に直接影響します。制御室のすべての重要なアプリケーションは、高可用性によって保護されなければなりません。例としては、ゲートウェイ、データベース、Web フロントエンドなどがあります。

## 公共交通機関向け SafeKit 高可用性ソリューション {#safekit-high-availability-for-public-transport}

RATP は、1 号線の自動化プロジェクトにおいて、以下の大きな制約に直面しました：

  * 厳しい導入スケジュール
  * ほとんどのアプリケーションは、もともと高可用性を考慮して設計されたものではありません
  * Windows と Linux サーバーの両方に対応するソリューションが必要でした
  * SAN ストレージやネットワーク負荷分散アプライアンスなどの高価なハードウェアの予算はありませんでした

SafeKit が選ばれた理由は以下の通りです：

  * 共有ディスクや SAN を使用しない、純粋なソフトウェアソリューションです
  * Windows と Linux で同じソリューションを提供します
  * ロードバランシング、自動フェイルオーバー、リアルタイムデータレプリケーションという 3 つの重要な機能を提供します
  * 標準的なサーバーに簡単に実装でき、管理も容易で、汎用性が高い

## RATP における実世界での導入 {#real-world-implementation-at-ratp}

RATP は、2 種類のクラスターで SafeKit を導入しました：

  * **Farm クラスター**：ネットワーク負荷分散と自動フェイルオーバーを備えたアクティブ/アクティブクラスター
  * **Mirror クラスター**：リアルタイムデータレプリケーションと自動フェイルオーバー機能を備えたアクティブ/パッシブクラスター

### 導入アプローチ {#deployment-approach}

まず、RATP は機能要件を定義しました。次に、保護対象の各アプリケーションに対して SafeKit を構成しました。アプリケーション自体は変更されていません。SafeKit サーバーの物理的な変更を必要としません。

SafeKit アプリケーションクラスターには、以下が含まれます：

  * 同じオペレーティングシステムを搭載した 2 台のサーバー
  * 両方のサーバーにインストールされているアプリケーション
  * 両方のサーバーに SafeKit がインストールされています
  * 高可用性と負荷分散のために構成された 1 つ以上のアプリケーションモジュール

複数のアプリケーションモジュールを同じクラスター上で並列実行できます。これにより、サーバーリソースの使用が最適化されます。RATP は、SafeKit モジュールをテスト、プレプロダクション、プロダクションの 3 つのステップで検証しました。

### 日常業務 {#daily-operations}

IT オペレーターは、以下のツールですべてのアプリケーションクラスターを管理します：

  * Windows と Linux で同じ高可用性ソリューション
  * すべてのクラスターで同じ管理コンソールを使用
  * 同じ構成と、同じコマンド
  * ロードバランシング、高可用性、データレプリケーションのための統合監視

重要アプリケーションのバックアップサーバーは、別の機械室に設置されています。これらは、別の電源で稼働しています。インシデントが発生した場合でも、パリの地下鉄の乗客はサービスを中断することなく利用を継続できます。

### 主なメリット {#key-benefits}

  * **コスト削減**：共有ディスクやネットワーク負荷分散アプライアンスといった高価な SAN インフラストラクチャが不要
  * **管理の簡素化**：1 つのコンソールで Windows と Linux 両方のクラスターを管理
  * **高可用性**：ロードバランシング、自動フェイルオーバー、リアルタイムデータレプリケーション
  * **プロジェクトへの影響は最小限**：既存のアプリケーションに変更は不要です
  * **運用上の回復力**：自動復旧により、継続的な旅客サービスを保証します
