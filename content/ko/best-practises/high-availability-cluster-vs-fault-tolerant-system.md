# HA 클러스터 vs. 내결함성 시스템: 올바른 이중화 전략 선택 {#ha-cluster-vs-fault-tolerant-system-choosing-the-right-redundancy-strategy}

## 고가용성과 내결함성의 차이점은 무엇인가요? {#what-is-the-difference-between-high-availability-and-fault-tolerance}

### 개요 {#overview}

이 글에서는 하드웨어 제약, 소프트웨어 오류, RTO, RPO 등을 고려하여 고가용성 클러스터와 내결함성 시스템의 장단점을 비교 분석합니다.

다음 비교표는 내결함성 시스템과 소프트웨어 고가용성 클러스터인 SafeKit 의 차이점을 자세히 설명합니다.

### 고가용성이란 무엇인가요? {#what-is-high-availability}

고가용성 클러스터는 하드웨어 또는 소프트웨어 오류 발생 시 핵심 애플리케이션이 재시작되는 두 대의 서버를 기반으로 합니다. 클러스터에는 하드웨어 클러스터와 소프트웨어 클러스터의 두 가지 유형이 있습니다.

하드웨어 클러스터는 공유 디스크를 기반으로 하므로 서버와 공유 디스크 어레이에 대한 연결 간에 종속성이 발생합니다.

SafeKit 와 같은 소프트웨어 클러스터는 실시간 데이터 복제를 기반으로 하며 하드웨어에 구애받지 않습니다. 물리적 서버, 가상 서버 또는 클라우드에 배포할 수 있습니다.

### 내결함성이란 무엇인가요? {#what-is-fault-tolerance}

내결함성 시스템은 하드웨어 오류를 감지하고 애플리케이션을 다시 시작하지 않고 즉시 예비 하드웨어 구성 요소로 전환하기 위해 특수 하드웨어 또는 특수 하이퍼바이저에 의존합니다.

내결함성 시스템은 하드웨어 오류만 처리하고 시스템 다운타임의 가장 흔한 원인인 소프트웨어 오류는 처리하지 못합니다.

## 고가용성과 내결함성의 장단점 {#pros-and-cons-of-high-availability-and-fault-tolerance}

핵심 애플리케이션을 장애로부터 보호하는 데에는 크게 두 가지 접근 방식이 있습니다. **바로 소프트웨어 고가용성 클러스터링** 과 **내결함성 시스템입니다** . 각 접근 방식은 비용, 유연성, 복구 시간, 하드웨어 요구 사항 측면에서 서로 다른 장단점을 가지고 있습니다. 이러한 차이점을 이해하면 특정 요구 사항에 맞는 최적의 솔루션을 선택하는 데 도움이 됩니다.

**소프트웨어 고가용성 클러스터링과 내결함성 시스템 비교**

기준 | 소프트웨어 고가용성 클러스터 | 내결함성 시스템  
---|---|---  
제품 | [ SafeKit Windows 및 Linux ](</>) | 는 내결함성 제품입니다.  
하드웨어/하이퍼바이저 | 전용 서버나 전용 하이퍼바이저가 없습니다. 서버와 PC용 커널에 포함된 표준 무료 하이퍼바이저인 Hyper-V( Windows )와 함께 작동합니다. 메인라인 커널에 통합된 표준 무료 하이퍼바이저인 KVM(커널 기반 가상 머신)( Linux )과 함께 작동합니다. 각 [ 서버는 여러 애플리케이션 ](</ko/architectures/active-active-cluster-real-time-replication/>) Windows 대해 다른 서버의 장애 조치 서버 역할을 할 수 있습니다. | 전용 하드웨어 또는 전용 하이퍼바이저가 필요합니다. 보조 서버는 명령어 수준에서 동기화된 동일한 애플리케이션 실행 전용입니다.  
소프트웨어 오류 | 다른 OS 환경에서 재시작하면 해결되는 소프트웨어 오류입니다. | 동일한 OS 환경에서 두 서버 모두에서 동시에 발생하는 소프트웨어 예외입니다.  
애플리케이션 및 OS의 원활한 업그레이드/수정 | 예 — 서버별로 애플리케이션 및 OS의 원활한 업그레이드/수정이 가능합니다. N개 버전과 N+1개 버전이 공존할 수 있습니다. | 아니요 — 두 서버에 동일한 애플리케이션 및 OS 이미지가 설치되어 있습니다.  
| 의 RTO/RPO는 SafeKit ( [ RTO, ](</ko/best-practises/what-is-rpo-and-rto-with-examples/>) )에서와 같이 애플리케이션 장애를 감지하고 재시작하는 데 걸리는 시간(약 1분)에 따라 달라집니다. SafeKit ( [ RPO, ](</ko/best-practises/what-is-rpo-and-rto-with-examples/>) )에서는 복제가 동기식으로 이루어지기 때문에 데이터 손실이 없습니다. | 의 경우, 내결함성 시스템의 복구 시간(RTO)은 0입니다. 장애 발생 시 애플리케이션은 재시작되지 않고 보조 서버에서 계속 실행됩니다. 따라서 데이터 손실(RPO) 또한 0입니다.  
유연성 | 표준 Windows 및 Linux 운영 체제가 설치된 모든 유형의 서버에서 실행 가능합니다. | 특정 하드웨어 또는 특정 하이퍼바이저에 따라 달라집니다.  
하드웨어 오류가 주요 문제인 환경에서 애플리케이션에 간단한 고가용성 옵션을 추가하려는 소프트웨어 편집자( | [ ](</ko/use-cases/application-clustering-software/>) | 에게 적합합니다.  
  
요약하자면, **와** SafeKit 통한 소프트웨어 고가용성은 표준 하드웨어에서 실행되고 롤링 업그레이드를 지원하며, 거의 제로에 가까운 다운타임(RTO ~1분)과 데이터 손실이 없는 비용 효율적이고 유연한 솔루션을 제공합니다. 내결함성 시스템은 즉각적인 페일오버(RTO = 0)를 제공하지만 전용 하드웨어가 필요하고 독립적인 소프트웨어 업데이트에 대한 유연성이 부족합니다.
