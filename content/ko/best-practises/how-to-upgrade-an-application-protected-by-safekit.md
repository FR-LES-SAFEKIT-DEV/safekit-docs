# HA 클러스터에서 SafeKit으로 보호된 애플리케이션 업그레이드 {#upgrading-an-application-protected-by-safekit-in-an-ha-cluster}

## SafeKit으로 보호되는 고가용성 애플리케이션 업그레이드 {#upgrading-a-high-availability-application-protected-by-safekit}

비즈니스에 중요한 애플리케이션을 최신 상태로 유지하는 것은 보안, 성능 및 새로운 기능에 대한 접근을 위해 필수적입니다. 애플리케이션이 SafeKit으로 보호되는 경우 업그레이드 절차는 사용 중인 고가용성 아키텍처에 따라 달라집니다.

일반적인 배포 모델은 두 가지가 있습니다:

  * 애플리케이션이 SafeKit이 관리하는 보호된 가상 머신 내에서 실행되는 **가상 머신 고가용성**.
  * **애플리케이션 수준의 고가용성**: 애플리케이션이 두 대의 서버에 설치됩니다.


각 모델은 서로 다른 업그레이드 메커니즘과 롤백 전략을 제공합니다.

## VM 수준의 고가용성 {#vm-level-ha}

**hyperv.safe** 및 **kvm.safe**와 같은 SafeKit VM 장애 조치 솔루션을 사용하면 애플리케이션이 가상 머신 내에 한 번만 설치됩니다.

SafeKit은 애플리케이션 자체가 아닌 전체 VM을 보호합니다. 이를 통해 유지보수 작업이 크게 간소화됩니다.

### 간소화된 업그레이드 프로세스 {#simplified-upgrade-process}

애플리케이션의 단일 VM 인스턴스로 작업하므로 유지 관리는 애플리케이션 수준의 장애 조치 대신 가상화 계층에서 처리됩니다.

업그레이드 절차는 간단합니다:

  1. Hyper-V 또는 KVM 관리 콘솔을 사용하여 가상 머신의 체크포인트 또는 스냅샷을 만듭니다.
  2. 가상 머신 내에서 애플리케이션을 업그레이드하세요.
  3. 업그레이드된 애플리케이션을 검증합니다.
  4. 업그레이드가 성공적으로 완료되면 스냅샷을 제거하고 정상적으로 작동을 계속하십시오.
  5. 문제가 발생하면 스냅샷에서 가상 머신을 복원하여 즉시 이전의 정상 작동 상태로 되돌리십시오.


서비스 중단은 애플리케이션 자체의 업그레이드 절차에 일반적으로 필요한 시간으로 제한됩니다.

### VM 수준 보호의 이점 {#benefits-of-vm-level-protection}

  * 유지 관리할 애플리케이션 인스턴스는 하나뿐입니다.
  * 클러스터별 업그레이드 절차는 없습니다.
  * VM 스냅샷을 통한 빠른 롤백.
  * 운영 복잡성 감소.
  * 보호되는 애플리케이션에 관계없이 일관된 업그레이드 프로세스.


이 접근 방식은 애플리케이션 클러스터링을 사용할 수 없거나 구현하기 어려운 패키지 애플리케이션 및 상용 기성 소프트웨어에 특히 유용합니다.

## 애플리케이션 수준의 고가용성 {#app-level-ha}

기존 SafeKit 클러스터에서는 애플리케이션이 두 노드(노드 1과 노드 2)에 설치됩니다. SafeKit이 노드들 간에 애플리케이션 데이터를 동기화하고 필요 시 자동 장애 조치를 처리합니다.

### 애플리케이션의 마이너 버전 업그레이드 {#app-level-ha-minor}

마이너 업그레이드는 애플리케이션 바이너리만 수정하고 복제된 데이터는 버전 간에 완벽하게 호환되도록 유지합니다. 복제된 데이터 형식이 변경되지 않으므로 SafeKit은 최소한의 다운타임으로 롤링 업그레이드를 지원합니다. 

  1. 클러스터는 처음에 **✅ PRIM (노드 1) / ✅ SECOND (노드 2)** 구성으로 실행됩니다. 애플리케이션은 PRIM 노드에서 실행됩니다. 복제된 데이터는 SECOND 노드에 지속적으로 동기화됩니다.
  2. SECOND 노드에서 SafeKit 모듈을 중지합니다. 상태는 **❌ STOP (노드 2)**이 됩니다. 애플리케이션을 업그레이드하고 모듈을 다시 시작합니다. 이 작업 중에도 애플리케이션은 **✅ ALONE (노드 1)** 상태로 노드 1에서 계속 실행됩니다. 서비스 중단은 발생하지 않습니다.
  3. 재시작 후, 업그레이드된 노드는 **✅ SECOND (노드 2)**로 클러스터에 다시 참여합니다. 복제된 데이터를 재동기화합니다.
  4. PRIM 노드를 중지합니다. 상태가 **❌ STOP (노드 1)**이 됩니다. SafeKit은 자동으로 장애 조치를 수행합니다. 업그레이드된 노드가 **✅ ALONE (노드 2)**이 됩니다. 애플리케이션이 이 노드에서 다시 시작됩니다. 다운타임은 장애 조치 및 애플리케이션 재시작 시간으로 제한됩니다.
  5. 업그레이드된 애플리케이션이 노드 2에서 올바르게 작동하면 나머지 노드(노드 1)를 업그레이드하고 SafeKit 모듈을 다시 시작하십시오.
  6. 재동기화 후 클러스터는 정상적인 **✅ SECOND (노드 1) / ✅ PRIM (노드 2)** 구성으로 돌아갑니다. 원래 역할은 SafeKit 관리 콘솔을 사용하여 수동으로 복원하거나 SafeKit 구성을 통해 자동으로 복원할 수 있습니다.


**롤백 절차**

  * 5단계에서 노드 2를 **✅ ALONE (노드 2)** 상태로 중지합니다.
  * 이전 애플리케이션 버전으로 기본 노드(노드 1)를 다시 시작합니다. 상태는 **✅ ALONE (노드 1)**입니다.
  * 업그레이드된 노드(노드 2)에 이전 버전을 다시 설치합니다.
  * 정상적인 **✅ PRIM (노드 1) / ✅ SECOND (노드 2)** 구성을 복원합니다.


전체 업그레이드를 위한 다운타임은 **✅ PRIM/✅ SECOND**에서 **❌ STOP/✅ ALONE**으로 전환하는 경우로 제한됩니다.

### 애플리케이션의 메이저 버전 업그레이드 {#app-level-ha-major}

메이저 업그레이드는 복제된 데이터의 형식이나 구조를 변경합니다. 새 버전에서 생성된 데이터는 이전 버전과 호환되지 않으므로 롤링 업그레이드를 수행할 수 없습니다.

  1. 클러스터는 처음에 **✅ PRIM (노드 1) / ✅ SECOND (노드 2)** 구성으로 실행됩니다.
  2. SECOND 노드를 중지한 다음 PRIM 노드를 중지합니다. 클러스터는 **❌ STOP (노드 1) / ❌ STOP (노드 2)**로 전환됩니다.
  3. 이전 PRIM 노드를 업그레이드하고 다시 시작합니다. 노드는 새 애플리케이션 버전으로 단독으로 시작됩니다. 상태는 **✅ ALONE (노드 1)**입니다.
  4. 업그레이드된 애플리케이션을 검증하고 올바르게 작동하는지 확인하세요.
  5. 유효성 검사가 성공하면 나머지 노드를 업그레이드하고 SafeKit 모듈을 다시 시작하십시오.
  6. 업그레이드된 노드는 **✅ SECOND (노드 2)**가 됩니다. 애플리케이션 데이터를 재동기화합니다. 클러스터는 정상적인 **✅ PRIM (노드 1) / ✅ SECOND (노드 2)** 구성으로 돌아갑니다.


**롤백 절차**

  * 5단계에서 업그레이드된 노드 1을 **✅ ALONE (노드 1)** 상태에서 중지합니다.
  * 업그레이드되지 않은 노드(노드 2)를 주 노드로 다시 시작합니다. 상태는 **✅ ALONE (노드 2)**입니다.
  * 업그레이드된 노드에 이전 애플리케이션 버전을 다시 설치하십시오.
  * 원래 **✅ SECOND (노드 1) / ✅ PRIM (노드 2)** 구성을 복원합니다.


마이그레이션 중에 복제된 데이터가 수정되므로 다운타임은 **❌ STOP/❌ STOP** 상태와 첫 번째 업그레이드된 노드가 **✅ ALONE**으로 다시 시작되는 시점 사이의 기간에 해당합니다.

### 애플리케이션 업그레이드를 위한 SafeKit의 이점 {#why-safekit-simplifies-application-upgrades}

SafeKit은 운영 위험을 최소화합니다:

  * 관리자는 한 번에 하나의 노드를 업그레이드합니다.
  * SafeKit은 가능한 한 서비스 가용성을 유지합니다.
  * 새 버전은 프로덕션 트래픽을 전환하기 전에 검증됩니다.
  * 관리자는 예상치 못한 문제가 감지되면 이전 노드로 신속하게 되돌릴 수 있습니다.


## 올바른 업그레이드 전략 선택하기 {#choosing-the-right-upgrade-strategy}

배포 모델 | 애플리케이션 인스턴스 | 복제된 데이터의 영향 | 업그레이드 접근 방식  
---|---|---|---  
애플리케이션 수준 HA | 두 개의 노드 | 업그레이드 유형에 따라 다릅니다 | 장애 조치를 통한 롤링 업그레이드  
hyperv.safe 또는 kvm.safe를 사용한 VM 수준 HA | 가상 머신 1개 | VM 내에서 관리됨 | 스냅샷, 업그레이드, 유효성 검사, 필요한 경우 롤백  
  
## 결론 {#conclusion}

SafeKit은 다양한 애플리케이션의 운영 요구 사항에 맞춰 유연한 고가용성 아키텍처를 제공합니다. 두 노드에 걸쳐 클러스터링된 애플리케이션을 보호하든 가상 머신에서 실행되는 단일 애플리케이션 인스턴스를 보호하든, SafeKit은 제어된 업그레이드를 지원하고 다운타임을 최소화하며 유지보수 작업이 필요할 때마다 안정적인 복구 옵션을 제공합니다.
