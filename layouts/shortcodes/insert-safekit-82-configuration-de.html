{{/* translation: translate_md 2026-11-08.9 | glossaire 2026-11-08.25 | Translation LLM | 34 expressions */}} {{/* Shortcode: insert-safekit-82-configuration-en — 15 instances in 15 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-oracle.md */}} ### Voraussetzungen {#prerequisites} * {{ .Get "app" }} Anwendung ist auf 2 Knoten installiert. * Die Gesamtmenge der replizierten Daten ist auf wenige Terabyte begrenzt – darüber hinaus wird die Resynchronisierungszeit erheblich. * Mindestens 1 Gbit/s Interkonnekt zwischen den Knoten (10 Gbit/s für eine schnellere Resynchronisierung empfohlen). * Für das IP-Failover müssen sich beide Knoten im selben LAN oder erweiterten LAN (L2) befinden – geroutete L3-Netzwerke werden nicht unterstützt (außer mit 🛠️ [Cloud Load Balancer](/de/resources/safekit-user-guide-82/#Cloud)). ### 1. Starten Sie die SafeKit Konsole {#1-launch-the-safekit-console} * Starten Sie die Webkonsole in einem Browser auf einem Clusterknoten, indem Sie eine Verbindung zu `http://localhost:9010` herstellen. * Geben Sie als Benutzernamen `admin` und das während der Installation festgelegte Passwort ein. Sie können die Konsole auch in einem Browser auf einer Workstation außerhalb des Clusters ausführen. ⚠️ Die Konfiguration von SafeKit erfolgt auf beiden Knoten über einen einzigen Browser. ℹ️ Um die Webkonsole zu sichern, siehe 🛠️ [11. Sichern des SafeKit Webdienstes](/de/resources/safekit-user-guide-82/#https) im Benutzerhandbuch. ![Starten Sie die SafeKit Webkonsole, um den {{ .Get "app" }} Cluster zu konfigurieren](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Knotenadressen konfigurieren {#2-configure-node-addresses} * Geben Sie die IP-Adressen der Knoten ein, drücken Sie die `Tab key`, um die Konnektivität zu überprüfen und die Knotennamen auszufüllen. Wenn entweder node1 oder node2 rot angezeigt wird, überprüfen Sie die Konnektivität des Browsers zu beiden Knoten und überprüfen Sie die Firewall auf beiden Knoten zur 🛠️ [Fehlerbehebung](/de/resources/safekit-user-guide-82/#Troubleshooting). * Klicken Sie anschließend auf `Save and apply` um die Konfiguration zu speichern. * Überprüfen Sie die `Success` ✅ auf beiden Knoten. * Wenn der `Failure` ❌ auf einem Knoten auftritt, öffnen Sie das ▼ Akkordeon für diesen Knoten und überprüfen Sie die Nachrichten. Beachten Sie, dass Sie die SafeKit AI 🤖 zur Unterstützung verwenden können. ℹ️ Wenn Sie möchten, können Sie ein neues `LAN and nodes` (erstes ➕) hinzufügen, um einen zweiten Heartbeat und ein dediziertes Replikationsnetzwerk zu erstellen. ℹ️ Wenn Sie auf `Advanced configuration` klicken, wird die Datei `cluster.xml` angezeigt. Diese Datei wird automatisch von der Konsole ausgefüllt und auf den Knoten bereitgestellt. ![Geben Sie die Knoten des {{ .Get "app" }} Clusters ein](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Modul auswählen {#3-select-a-module} * Klicken Sie im `New module` auf das Modul `{{ .Get "mod" }}.safe`. ℹ️ Im blauen Banner oben stellt 🛜 `node1` den Konsolenverbindungsknoten dar. Dieser Knoten leitet bei Bedarf Anfragen an `node2` weiter. ℹ️ Die Konsole sucht nach `xxx.safe` im Verzeichnis `Application_Modules/generic/` auf dem Verbindungsknoten (`node1`), wenn Sie dort während der Installation ein Modul platziert haben. ![Modul für die {{ .Get "app" }} auswählen](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Modul konfigurieren {#4-configure-the-module} * Wählen Sie unter `Module startup at boot` einen automatischen Start des Moduls beim Booten ohne Verzögerung. * Geben Sie unter `Macros`/`SERVICES` die Dienstnamen Ihrer Anwendung in der Startreihenfolge durch Kommas getrennt ein. Siehe diesen Screenshot für ein visuelles Beispiel der [Milestone XProtect-Dienste 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * In `Heartbeat networks` sollten Sie ein einzelnes Heartbeat-Netzwerk haben, auf dem die Replikation durchgeführt wird. Wenn Sie in Schritt 2 ein privates LAN hinzugefügt haben, können Sie zwei Heartbeats mit dem Replikationsfluss im privaten LAN konfigurieren. * Geben Sie unter `Virtual IP addresses` eine virtuelle IP-Adresse ein. Eine virtuelle IP-Adresse ist eine Standard-IP-Adresse im selben IP-Netzwerk (dasselbe Subnetz) wie die IP-Adressen beider Knoten. Anwendungsklienten müssen mit der virtuellen IP-Adresse (oder dem mit der virtuellen IP-Adresse verknüpften DNS-Namen) konfiguriert werden. Die virtuelle IP-Adresse wird im Fehlerfall automatisch umgeschaltet. * Legen Sie unter `Replicated directories` die Pfade der zu replizierenden Verzeichnisse fest. Stellen Sie sicher, dass sie auf beiden Knoten vorhanden sind und die Anwendungsdaten enthalten. Daten- und Protokollreplikation sind für eine Datenbank unerlässlich. Sie können bei Bedarf zusätzliche replizierte Verzeichnisse erstellen. Sehen Sie sich diesen Screenshot für ein visuelles Beispiel der [Milestone XProtect SQL-Replikation an 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * In `Checkers` können Sie bei Bedarf Checkers konfigurieren, z. B. Prozessüberwachung, benutzerdefinierte Checkers, TCP, Ping oder Split-Brain-Checkers. Wenn beispielsweise ein Prozessname unter `Monitored processes/services` angezeigt wird, wird er im Fehlerfall mit einer Neustartaktion überwacht. Die Konfiguration eines falschen Prozessnamens führt dazu, dass das Modul direkt nach dem Start beendet wird. ℹ️ Wenn Sie auf `Advanced configuration` klicken, wird die Datei `userconfig.xml` angezeigt. Diese Datei wird automatisch von der Konsole ausgefüllt und mit den Neustartskripten auf den Knoten bereitgestellt. ℹ️ Bei einer Cloud-Bereitstellung müssen Sie keine virtuelle IP-Adresse in SafeKit konfigurieren. Die virtuelle IP wird auf der Ebene des 🛠️ [Cloud Load Balancer](/de/resources/safekit-user-guide-82/#Cloud) verwaltet. ℹ️ Wenn Sie die SafeKit-Konfiguration anwenden, wird der `startup type` der Dienste in Windows-Diensten automatisch auf `Manual` gesetzt. Dies stellt sicher, dass die Dienste nicht automatisch starten, wenn das System hochfährt, sondern erst gestartet werden, wenn das Modul selbst gestartet wird (dasselbe gilt unter Linux). ![{{ .Get "app" }} Modul-Einstellungen aufrufen](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. Skripte bearbeiten (optional) {#5-edit-scripts-optional} * Dieser Schritt ist optional und kann in den meisten Fällen übersprungen werden, da die Neustartskripte bereits so vorkonfiguriert sind, dass sie die im vorherigen Schritt definierten Dienste neu starten. * Klicken Sie also direkt auf `Next step`. * `start_prim.ps1` startet alle Dienste in der in der Liste `SERVICES` angegebenen Reihenfolge, während `stop_prim.ps1` alle Dienste in umgekehrter Reihenfolge stoppt. * Zusätzlich überprüft `start_prim.ps1` den Start jedes Dienstes und stoppt das Modul, wenn ein Dienst nicht korrekt gestartet werden kann. ![{{ .Get "app" }} Modul-Einstellungen aufrufen](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. Kommunikationsverschlüsselung (optional) {#6-communication-encryption-optional} * Verschlüsselung der Kommunikation zwischen den Knoten beibehalten. ![Kommunikationsverschlüsselung des {{ .Get "app" }} Moduls](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Speichern und anwenden {#7-save-and-apply} * `Save and apply` die Konfiguration und die Skripte auf beiden Knoten an. ![{{ .Get "app" }} Modulkonfiguration speichern und anwenden](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Erfolgreiche Konfiguration überprüfen {#8-verify-successful-configuration} * Überprüfen Sie die `Success` ✅ auf beiden Knoten und klicken Sie auf `Monitor modules`. * Wenn der `Failure` ❌ auf einem Knoten auftritt, öffnen Sie das ▼ Akkordeon für diesen Knoten und überprüfen Sie die Nachrichten. Beachten Sie, dass Sie die SafeKit AI 🤖 zur Unterstützung verwenden können. ⚠️ Unter Linux kann in diesem Schritt ein Fehler auftreten, wenn die replizierten Verzeichnisse Einhängepunkte sind. 🛠️ [Siehe SK-0030, um das Problem zu lösen](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf). ![Überprüfen Sie den Erfolg der {{ .Get "app" }}-Modulkonfiguration](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Starten Sie den Knoten mit aktuellen Daten {#9-start-the-node-with-up-to-date-data} * Wenn Knoten 1 über die aktuellsten replizierten Verzeichnisse verfügt, wählen Sie ihn aus und ⋯ `Force start` ▶ `As primary`. Wenn Knoten 2 gestartet wird, werden alle Daten von Knoten 1 auf Knoten 2 kopiert. ⚠️ Wenn Sie die falsche Wahl treffen, laufen Sie Gefahr, veraltete Daten auf beiden Knoten zu synchronisieren. ⚠️ Es wird auch davon ausgegangen, dass die {{ .Get "app" }} Anwendung auf Knoten 1 gestoppt ist, damit SafeKit die Replikationsmechanismen installiert und dann die Anwendung im `start_prim`-Skript startet. ⚠️ Verwenden Sie `Start` für nachfolgende Starts: SafeKit behält den aktuellsten Server bei. Starten `As primary` ist ein spezieller Startvorgang beim ersten Mal oder bei außergewöhnlichen Vorgängen. ![Starten Sie den {{ .Get "app" }} Knoten mit den aktuellen Daten als primären Knoten](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Warten Sie, bis der Übergang zu ALONE (grün) erfolgt {#10-wait-for-the-transition-to-alone-green} * Knoten 1 sollte den ALONE Status (grün) erreichen, was bedeutet, dass die virtuelle IP-Adresse festgelegt wurde und das `start_prim` Skript auf Knoten 1 ausgeführt wurde. ⚠️ Wenn ALONE (grün) nicht erreicht wird oder die Anwendung nicht gestartet wird, analysieren Sie den Grund mit dem [Modulprotokoll 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) von Knoten 1. * Klicken Sie auf das 🔍 **Protokollsymbol** von `node1`, um das Modulprotokoll zu öffnen und nach Fehlermeldungen zu suchen, z. B. wenn ein Prüfer einen Fehler erkennt und das Modul stoppt. * Klicken Sie im Protokoll auf `start_prim`: Die Ausgabemeldungen des Skripts werden rechts angezeigt und Fehler können erkannt werden, z. B. wenn ein Dienst falsch gestartet wurde. * Nutzen Sie die SafeKit AI 🤖 für Unterstützung bei Protokollnachrichten. ⚠️ Wenn sich der Cluster im Zustand `WAIT (red) not uptodate, STOP (red) not uptodate`, stoppen Sie den WAIT Knoten und [erzwingen Sie seinen Start als primär 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![Der erste {{ .Get "app" }} Knoten startet als primärer Knoten und wird ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. Startknoten 2 {#11-start-node-2} * ⋯ `Start` Knoten 2 mit seinem Kontextmenü. * Warten Sie auf den SECOND (grünen) Zustand. ℹ️ Knoten 2 bleibt im SECOND (orangen) Zustand, während die replizierten Verzeichnisse resynchronisiert werden (Kopie von Knoten 1 auf Knoten 2). * Dies kann je nach Größe der in replizierten Verzeichnissen zu resynchronisierenden Dateien und der Netzwerkbandbreite einige Zeit dauern. * Um den Fortschritt der Kopie zu sehen, siehe das [Modulprotokoll 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) und die [Replikationsressourcen 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) von Knoten 2. Verwenden Sie SafeKit AI 🤖 für Unterstützung bei Protokollmeldungen. ![Starten Sie den {{ .Get "app" }} Knoten 2](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 12. Überprüfen Sie, ob der Cluster betriebsbereit ist {#12-verify-that-the-cluster-is-operational} * Überprüfen Sie, ob der Cluster grün/grün ist und {{ .Get "app" }} Dienste auf dem PRIM-Knoten ausgeführt werden und nicht auf dem SECOND-Knoten. In diesem Zustand werden nur Änderungen innerhalb von Dateien in Echtzeit repliziert. ⚠️ Komponenten, die Clients von {{ .Get "app" }} Diensten sind, müssen mit der virtuellen IP-Adresse konfiguriert werden. Die Konfiguration kann mit einem DNS-Namen erfolgen (wenn ein DNS-Name erstellt und der virtuellen IP-Adresse zugeordnet wurde). ![Der {{ .Get "app" }} Knoten 2 ist SECOND (grün)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 13. Tests {#13-testing} * Stoppen Sie den PRIM-Knoten, indem Sie im Kontextmenü nach unten scrollen und auf `Stop` klicken. * Überprüfen Sie, ob auf dem SECOND Knoten ein Failover stattfindet, der ALONE (grün) sein sollte. * Überprüfen Sie mit Microsoft Management Console (MMC) unter Windows oder mit Befehlszeilen unter Linux das Failover der {{ .Get "app" }}-Dienste (gestoppt auf Knoten 1 im `stop_prim`-Skript und gestartet auf Knoten 2 im `start_prim`-Skript). ⚠️ Wenn ALONE (grün) auf node2 nicht erreicht wird oder die Anwendung nicht gestartet wird, analysieren Sie den Grund mit dem [Modulprotokoll 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) von Knoten 2. * Klicken Sie auf das 🔍 **Protokollsymbol** von `node2`, um das Modulprotokoll zu öffnen und nach Fehlermeldungen zu suchen, z. B. wenn ein Prüfer einen Fehler erkennt und das Modul stoppt. * Klicken Sie im Protokoll auf `start_prim`: Die Ausgabemeldungen des Skripts werden rechts angezeigt und Fehler können erkannt werden, z. B. wenn ein Dienst falsch gestartet wurde. * Nutzen Sie die SafeKit AI 🤖 für Unterstützung bei Protokollnachrichten. ⚠️ * Wenn alles in Ordnung ist, starten Sie einen Start auf node1, wodurch die replizierten Verzeichnisse von node2 erneut synchronisiert werden. * Wenn etwas schiefgeht, stoppen Sie node2 und [erzwingen Sie, dass Knoten 1 als primärer Knoten startet 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). Dieser wird dann mit seinen lokal intakten Daten zum Zeitpunkt des Stopps neu gestartet. ℹ️ Weitere Details sowie Videos finden Sie im [SafeKit Online-Training](/de/resources/safekit-on-line-training/). ![Stoppen Sie das {{ .Get "app" }} Modul auf dem PRIM-Server](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 14. Unterstützung {#14-support} * Um Unterstützung zu erhalten, erstellen Sie 2 SafeKit `Snapshots` (2 .zip-Dateien), einen für jeden Knoten. ℹ️ [Weitere Informationen zum Support finden Sie hier](/de/resources/safekit-support/). ![Machen Sie {{ .Get "app" }} Snapshots zur Unterstützung](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
