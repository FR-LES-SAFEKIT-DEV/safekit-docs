{{/* Shortcode: insert-safekit-82-configuration-de */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-oracle.md */}} ### Voraussetzungen * {{ .Get "app" }}-Anwendung auf 2 Knoten installiert. * Die gesamten replizierten Daten sind auf einige Terabyte begrenzt – darüber hinaus wird die Zeit für die Neusynchronisierung erheblich. * Mindestens 1 Gbit/s Verbindung zwischen Knoten (10 Gbit/s empfohlen für eine schnellere Neusynchronisierung). * IP-Failover erfordert beide Knoten auf demselben LAN oder erweiterten LAN (L2) – geroutete L3-Netzwerke werden nicht unterstützt (außer mit 🛠️ [cloud-Lastausgleichsmodulen](/resources/safekit-user-guide-82/#Cloud)). ### 1. Starten Sie die SafeKit-Konsole * Starten Sie die Webkonsole in einem Browser auf einem Clusterknoten, indem Sie eine Verbindung zu `http://localhost:9010` herstellen. * Geben Sie als Benutzernamen `admin` und das bei der Installation festgelegte Passwort ein. Sie können die Konsole auch in einem Browser auf einer Workstation außerhalb des Clusters ausführen. ⚠️ Die Konfiguration von SafeKit erfolgt auf beiden Knoten über einen einzigen Browser. ℹ️ Informationen zum Sichern der Webkonsole finden Sie unter 🛠️ [11\. Sichern des SafeKit-Webdienstes](/resources/safekit-user-guide-82/#https) im Benutzerhandbuch. ![Starten Sie die SafeKit-Webkonsole, um den {{ .Get "app" }}-Cluster zu konfigurieren](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Knotenadressen konfigurieren * Geben Sie die Knotenadressen IP ein, drücken Sie `Tab key`, um die Konnektivität zu überprüfen und Knotennamen einzugeben. Wenn entweder node1 oder node2 eine rote Farbe hat, überprüfen Sie die Konnektivität des Browsers zu beiden Knoten und überprüfen Sie die Firewall auf beiden Knoten auf 🛠️ [Fehlerbehebung](/resources/safekit-user-guide-82/#Troubleshooting). * Klicken Sie dann auf `Save and apply`, um die Konfiguration zu speichern. * Überprüfen Sie die `Success` ✅-Meldung auf beiden Knoten. * Wenn die Konfiguration `Failure` ❌ auf einem Knoten auftritt, öffnen Sie das Akkordeon ▼ für diesen Knoten und überprüfen Sie die Meldungen. Beachten Sie, dass Sie als Hilfe den SafeKit AI 🤖 verwenden können. ℹ️ Wenn Sie möchten, können Sie ein neues `LAN and nodes` (zuerst ➕) hinzufügen, um einen zweiten Heartbeat und ein dediziertes Replikationsnetzwerk zu erstellen. ℹ️ Wenn Sie auf `Advanced configuration` klicken, wird die `cluster.xml`-Datei angezeigt. Diese Datei wird automatisch von der Konsole gefüllt und auf den Knoten bereitgestellt. ![Geben Sie die Knoten des {{ .Get "app" }}-Clusters ein](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Wählen Sie ein Modul aus * Klicken Sie in `New module` auf das Modul `{{ .Get "mod" }}.safe`. ℹ️ Im blauen Banner oben steht 🛜 `node1` für den Konsolenverbindungsknoten. Dieser Knoten leitet Anfragen bei Bedarf an `node2` weiter. ℹ️ Die Konsole sucht `xxx.safe` im `Application_Modules/generic/` Verzeichnis auf dem Verbindungsknoten (`node1`), wenn Sie dort während der Installation ein Modul platziert haben. ![Wählen Sie das Modul für {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Konfigurieren Sie das Modul * Wählen Sie in `Module startup at boot` einen automatischen Start des Moduls beim Booten ohne Verzögerung. * Geben Sie in `Macros` / `SERVICES` die Dienstnamen Ihrer Anwendung in der Startreihenfolge ein, getrennt durch Kommas. Sehen Sie sich diesen Screenshot für ein visuelles Beispiel der [Milestone XProtect-Dienste an 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * In `Heartbeat networks` sollten Sie über ein einzelnes Heartbeat-Netzwerk verfügen, in dem die Replikation durchgeführt wird. Wenn Sie in Schritt 2 einen privaten LAN hinzugefügt haben, können Sie zwei Heartbeats mit dem Replikationsfluss auf dem privaten LAN konfigurieren. * Geben Sie in `Virtual IP addresses` eine virtuelle IP-Adresse ein. Eine virtuelle IP-Adresse ist eine Standard-IP-Adresse im selben IP-Netzwerk (gleiches Subnetz) wie die IP-Adressen beider Knoten. Anwendungsclients müssen mit der virtuellen IP-Adresse (oder dem DNS-Namen, der der virtuellen IP-Adresse zugeordnet ist) konfiguriert werden. Bei einem Ausfall wird die virtuelle IP-Adresse automatisch umgeschaltet. * Legen Sie in `Replicated directories` die Pfade der zu replizierenden Verzeichnisse fest. Überprüfen Sie, ob sie auf beiden Knoten vorhanden sind und die Anwendungsdaten enthalten. Daten- und Protokollreplikation sind für eine Datenbank unerlässlich. Sie können bei Bedarf weitere replizierte Verzeichnisse erstellen. In diesem Screenshot finden Sie ein visuelles Beispiel der [Milestone XProtect SQL-Replikation 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * In `Checkers` können Sie bei Bedarf Prüfer konfigurieren, z. B. Prozessüberwachung, benutzerdefinierte Prüfer, TCP, Ping oder Split-Brain-Prüfer. Wenn beispielsweise ein Prozessname in `Monitored processes/services` angezeigt wird, wird dieser im Fehlerfall mit einer Neustartaktion überwacht. Die Konfiguration eines falschen Prozessnamens führt dazu, dass das Modul direkt nach dem Start stoppt. ℹ️ Wenn Sie auf `Advanced configuration` klicken, wird die `userconfig.xml`-Datei angezeigt. Diese Datei wird automatisch von der Konsole gefüllt und mit den Neustartskripten auf den Knoten bereitgestellt. ℹ️ Bei einer Cloud-Bereitstellung müssen Sie keine virtuelle Konfiguration konfigurieren IP Adresse in SafeKit. Das Virtuelle IP wird am 🛠️ verwaltet [Cloud-Load-Balancer-Ebene](/resources/safekit-user-guide-82/#Cloud). ℹ️ Wenn Sie die SafeKit-Konfiguration anwenden, wird der `startup type` der Dienste automatisch auf `Manual` in Windows-Diensten gesetzt. Dadurch wird sichergestellt, dass Dienste nicht automatisch beim Systemstart gestartet werden, sondern erst beim Start des Moduls selbst (dasselbe gilt für Linux). ![Geben Sie die {{ .Get "app" }}-Moduleinstellungen ein](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. Skripte bearbeiten (optional) * Dieser Schritt ist optional und kann in den meisten Fällen übersprungen werden, da die Neustartskripte bereits vorkonfiguriert sind, um die im vorherigen Schritt definierten Dienste neu zu starten. * Klicken Sie also direkt auf `Next step`. * `start_prim.ps1` startet alle Dienste in der in der `SERVICES`-Liste angegebenen Reihenfolge, während `stop_prim.ps1` alle Dienste in umgekehrter Reihenfolge stoppt. * Darüber hinaus überprüft `start_prim.ps1` den Start jedes Dienstes und stoppt das Modul, wenn ein Dienst nicht ordnungsgemäß gestartet werden kann. ![Geben Sie die {{ .Get "app" }}-Moduleinstellungen ein](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. Kommunikationsverschlüsselung (optional) * Behalten Sie die Verschlüsselung der Kommunikation zwischen Knoten bei. ![Kommunikationsverschlüsselung des {{ .Get "app" }}-Moduls](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Speichern und anwenden * `Save and apply` die Konfiguration und Skripte auf beiden Knoten. ![Speichern Sie die {{ .Get "app" }}-Modulkonfiguration und wenden Sie sie an](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Überprüfen Sie die erfolgreiche Konfiguration * Überprüfen Sie die Meldung `Success` ✅ auf beiden Knoten und klicken Sie auf `Monitor modules`. * Wenn die Konfiguration `Failure` ❌ auf einem Knoten auftritt, öffnen Sie das Akkordeon ▼ für diesen Knoten und überprüfen Sie die Meldungen. Beachten Sie, dass Sie als Hilfe den SafeKit AI 🤖 verwenden können. ⚠️ Unter Linux erhalten Sie in diesem Schritt möglicherweise eine Fehlermeldung, wenn die replizierten Verzeichnisse Einhängepunkte sind.🛠️ [Siehe SK-0030, um das Problem](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf) zu lösen. ![Überprüfen Sie den Erfolg der {{ .Get "app" }}-Modulkonfiguration](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Starten Sie den Knoten mit aktuellen Daten * Wenn Knoten 1 über die aktuellen replizierten Verzeichnisse verfügt, wählen Sie ihn aus und ⋯ `Force start` ▶ `As primary`. Wenn Knoten 2 gestartet wird, werden alle Daten von Knoten 1 auf Knoten 2 kopiert. ⚠️ Wenn Sie die falsche Wahl treffen, besteht die Gefahr, dass veraltete Daten auf beiden Knoten synchronisiert werden. ⚠️ Es wird außerdem davon ausgegangen, dass die {{ .Get "app" }}-Anwendung auf Knoten 1 gestoppt wird, sodass SafeKit die Replikationsmechanismen installiert und dann die Anwendung im `start_prim`-Skript startet. ⚠️ Verwenden Sie `Start` für nachfolgende Starts: SafeKit behält den aktuellsten Server. Der Start von `As primary` ist eine Sonderinbetriebnahme beim ersten Mal oder bei außergewöhnlichen Einsätzen. ![Starten Sie als Primärknoten den {{ .Get "app" }}-Knoten mit den aktuellen Daten](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Warten Sie auf den Übergang zu ALONE (grün) * Knoten 1 sollte den Zustand ALONE (grün) erreichen, was bedeutet, dass der virtuelle IP gesetzt ist und das `start_prim`-Skript auf Knoten 1 ausgeführt wurde. ⚠️ Wenn ALONE (grün) nicht erreicht wird oder die Anwendung nicht gestartet wird, analysieren Sie den Grund mit dem [-Modulprotokoll 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) von Knoten 1. * Klicken Sie auf das Symbol 🔍 **log** von `node1`, um das Modulprotokoll zu öffnen und nach Fehlermeldungen zu suchen, z. B. wenn ein Prüfer einen Fehler erkennt und das Modul stoppt. * Klicken Sie im Protokoll auf `start_prim`: Rechts werden Ausgabemeldungen des Skripts angezeigt und es können Fehler wie ein falsch gestarteter Dienst erkannt werden. * Verwenden Sie SafeKit AI 🤖 für Unterstützung bei Protokollmeldungen. ⚠️ Wenn sich der Cluster im `WAIT (red) not uptodate, STOP (red) not uptodate`-Status befindet, stoppen Sie den WAIT-Knoten und [ erzwingen seinen Start als Primärknoten 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![Der erste {{ .Get "app" }}-Knoten startet als primärer Knoten und wird zu ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. Starten Sie Knoten 2 * ⋯ `Start` Knoten 2 mit seinem Kontextmenü. * Warten Sie auf den Status SECOND (grün). ℹ️ Knoten 2 bleibt im Status SECOND (orange), während die replizierten Verzeichnisse neu synchronisiert werden (Kopieren von Knoten 1 auf Knoten 2). * Dies kann abhängig von der Größe der neu zu synchronisierenden Dateien in replizierten Verzeichnissen und der Netzwerkbandbreite eine Weile dauern. * Um den Fortschritt des Kopierens zu sehen, sehen Sie sich das [module-Protokoll 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) und die [replikationsressourcen 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) von Knoten 2 an. Verwenden Sie SafeKit AI 🤖 für Unterstützung bei Protokollmeldungen. ![Starten Sie den {{ .Get "app" }}-Knoten 2](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 12. Stellen Sie sicher, dass der Cluster betriebsbereit ist * Überprüfen Sie, ob der Cluster grün/grün ist und die {{ .Get "app" }}-Dienste auf dem PRIM-Knoten und nicht auf dem SECOND-Knoten ausgeführt werden. In diesem Zustand werden nur Änderungen innerhalb von Dateien in Echtzeit repliziert. ⚠️ Komponenten, die Clients von {{ .Get "app" }}-Diensten sind, müssen mit der virtuellen IP-Adresse konfiguriert werden. Die Konfiguration kann mit einem DNS-Namen erfolgen (sofern ein DNS-Name erstellt und mit der virtuellen IP-Adresse verknüpft wurde). ![Der {{ .Get "app" }}-Knoten 2 ist SECOND (grün)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 13. Testen * Stoppen Sie den Knoten PRIM, indem Sie im Kontextmenü nach unten scrollen und auf `Stop` klicken. * Stellen Sie sicher, dass auf dem Knoten SECOND ein Failover stattfindet, der zu ALONE (grün) werden sollte. * Überprüfen Sie mit der Microsoft Management Console (MMC) auf Windows oder mit Befehlszeilen auf Linux das Failover der {{ .Get "app" }}-Dienste (im `stop_prim`-Skript auf Knoten 1 gestoppt und im `start_prim`-Skript auf Knoten 2 gestartet). ⚠️ Wenn ALONE (grün) auf node2 nicht erreicht wird oder die Anwendung nicht gestartet wird, analysieren Sie die Ursache mit dem [-Modulprotokoll 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) von Knoten 2. * Klicken Sie auf das Symbol 🔍 **log** von `node2`, um das Modulprotokoll zu öffnen und nach Fehlermeldungen zu suchen, z. B. wenn ein Prüfer einen Fehler erkennt und das Modul stoppt. * Klicken Sie im Protokoll auf `start_prim`: Rechts werden Ausgabemeldungen des Skripts angezeigt und es können Fehler wie ein falsch gestarteter Dienst erkannt werden. * Verwenden Sie SafeKit AI 🤖 für Unterstützung bei Protokollmeldungen. ⚠️ * Wenn alles in Ordnung ist, initiieren Sie einen Start auf node1, wodurch die replizierten Verzeichnisse von node2 neu synchronisiert werden. * Wenn etwas schief geht, stoppen Sie node2 und [. Erzwingen Sie den Start als primäres 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) von node1, das zum Zeitpunkt des Stopps mit seinen lokal gesunden Daten neu startet. ℹ️ Weitere Details und Videos finden Sie im [SafeKit Online Training](/resources/safekit-on-line-training/). ![Stoppen Sie das {{ .Get "app" }}-Modul auf dem PRIM-Server](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 14. Unterstützung * Um Unterstützung zu erhalten, nehmen Sie 2 SafeKit `Snapshots` (2 .zip-Dateien), eine für jeden Knoten. ℹ️ [Weitere Informationen zum Support hier](/resources/safekit-support/). ![Nehmen Sie zur Unterstützung die {{ .Get "app" }}-Snapshots](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
