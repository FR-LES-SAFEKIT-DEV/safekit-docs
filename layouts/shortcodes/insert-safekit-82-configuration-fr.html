{{/* translation: translate_md 2026-11-08.9 | glossaire 2026-11-08.25 | Translation LLM | 32 expressions */}} {{/* Shortcode: insert-safekit-82-configuration-en — 15 instances in 15 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-oracle.md */}} ### Prérequis {#prerequisites} * {{ .Get "app" }} installée sur 2 nœuds. * Les données répliquées sont limitées à quelques téraoctets. Au-delà, le temps de resynchronisation devient important. * Interconnexion d’au moins 1 Gb/s entre les nœuds (10 Gb/s recommandé pour une resynchronisation plus rapide). * Le basculement IP nécessite que les deux nœuds soient sur le même LAN ou LAN étendu (L2) — les réseaux L3 routés ne sont pas pris en charge (sauf avec les équilibreurs de charge 🛠️ [cloud](/fr/resources/safekit-user-guide-82/#Cloud)). ### 1. Lancez la console SafeKit {#1-launch-the-safekit-console} * Lancez la console web dans un navigateur sur un nœud du cluster en vous connectant à `http://localhost:9010`. * Saisissez `admin` comme nom d’utilisateur et le mot de passe défini lors de l’installation. Vous pouvez également exécuter la console dans un navigateur sur un poste de travail externe au cluster. ⚠️ La configuration de SafeKit s’effectue sur les deux nœuds à partir d’un seul navigateur. ℹ️ Pour sécuriser la console web, consultez 🛠️ [11. Sécuriser le service web SafeKit](/fr/resources/safekit-user-guide-82/#https) dans le Guide de l’utilisateur. ![Démarrez la console web SafeKit pour configurer le cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurer les adresses des nœuds {#2-configure-node-addresses} * Entrez les adresses IP des nœuds, appuyez sur la `Tab key` pour vérifier la connectivité et remplissez les noms des nœuds. Si node1 ou node2 est de couleur rouge, vérifiez la connectivité du navigateur aux deux nœuds et vérifiez le pare-feu sur les deux nœuds pour [le dépannage](/fr/resources/safekit-user-guide-82/#Troubleshooting) 🛠️. * Cliquez ensuite sur `Save and apply` pour sauvegarder la configuration. * Vérifiez le message `Success` ✅ sur les deux nœuds. * Si l’ `Failure` de configuration ❌ se produit sur un nœud, ouvrez l’accordéon ▼ pour ce nœud et consultez les messages. Notez que vous pouvez utiliser l’IA SafeKit 🤖 pour obtenir de l’aide. ℹ️ Si vous le souhaitez, vous pouvez ajouter un nouveau `LAN and nodes` (premier ➕) pour créer un deuxième heartbeat et un réseau de réplication dédié. ℹ️ Si vous cliquez sur `Advanced configuration`, le fichier `cluster.xml` s’affiche. Ce fichier est automatiquement renseigné par la console et déployé sur les nœuds. ![Saisissez les nœuds du cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Sélectionnez un module {#3-select-a-module} * Dans `New module`, cliquez sur le module `{{ .Get "mod" }}.safe`. ℹ️ Dans la bannière bleue en haut, le nœud 🛜 `node1` représente le nœud de connexion de la console. Ce nœud relaie les requêtes vers le `node2` si nécessaire. ℹ️ La console recherche `xxx.safe` dans le répertoire `Application_Modules/generic/` sur le nœud de connexion (`node1`) si vous y avez placé un module lors de l’installation. ![Choisissez le module pour {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configurer le module {#4-configure-the-module} * Dans `Module startup at boot`, choisissez un démarrage automatique du module au démarrage sans délai. * Dans `Macros`/`SERVICES`, saisissez les noms des services de votre application, dans l’ordre de démarrage, séparés par des virgules. Consultez cette capture d’écran pour un exemple visuel des [services Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * Dans `Heartbeat networks`, vous devez avoir un seul réseau de pulsation sur lequel la réplication est effectuée. Si vous avez ajouté un LAN local privé à l’étape 2, vous pouvez configurer deux pulsations avec le flux de réplication sur le LAN local privé. * Dans `Virtual IP addresses`, entrez une adresse IP virtuelle. Une adresse IP virtuelle est une adresse IP standard dans le même réseau IP (même sous-réseau) que les adresses IP des deux nœuds. Les clients d’application doivent être configurés avec l’adresse IP virtuelle (ou le nom DNS associé à l’adresse IP virtuelle). L’adresse IP virtuelle est automatiquement commutée en cas de défaillance. * Dans `Replicated directories`, définissez les chemins d’accès des répertoires à répliquer. Vérifiez qu’ils existent sur les deux nœuds et qu’ils contiennent les données de l’application. La réplication des données et des journaux est essentielle pour une base de données. Vous pouvez créer des répertoires répliqués supplémentaires selon vos besoins. Consultez cette capture d’écran pour un exemple visuel de [la réplication SQL Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * Dans `Checkers`, vous pourrez configurer des vérificateurs si nécessaire, tels que la surveillance des processus, les vérificateurs personnalisés, TCP, ping ou les vérificateurs de scission du cerveau. Par exemple, si un nom de processus est affiché dans `Monitored processes/services`, il sera surveillé avec une action de redémarrage en cas de défaillance. La configuration d’un nom de processus incorrect entraînera l’arrêt du module juste après son démarrage. ℹ️ Si vous cliquez sur `Advanced configuration`, le fichier `userconfig.xml` s’affiche. Ce fichier est automatiquement renseigné par la console et déployé sur les nœuds avec les scripts de redémarrage. ℹ️ Dans un déploiement cloud, vous n’avez pas besoin de configurer une adresse IP virtuelle dans SafeKit. L’IP virtuelle est gérée au niveau de l’équilibreur de charge du 🛠️ [cloud](/fr/resources/safekit-user-guide-82/#Cloud). ℹ️ Lorsque vous appliquez la configuration SafeKit, le `startup type` des services est automatiquement défini sur `Manual` dans les services Windows. Cela garantit que les services ne démarrent pas automatiquement au démarrage du système, mais qu’ils ne sont démarrés que lorsque le module lui-même est démarré (il en va de même sous Linux). ![Accéder aux paramètres du module {{ .Get "app" }}](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. Modifier les scripts (facultatif) {#5-edit-scripts-optional} * Cette étape est facultative et peut être ignorée dans la plupart des cas, car les scripts de redémarrage sont déjà préconfigurés pour redémarrer les services définis à l’étape précédente. * Cliquez donc directement sur `Next step`. * `start_prim.ps1` démarre tous les services dans l’ordre spécifié dans la liste `SERVICES`, tandis que `stop_prim.ps1` arrête tous les services dans l’ordre inverse. * De plus, `start_prim.ps1` vérifie le démarrage de chaque service et arrête le module si un service ne démarre pas correctement. ![Accéder aux paramètres du module {{ .Get "app" }}](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. Chiffrement des communications (facultatif) {#6-communication-encryption-optional} * Conservez le chiffrement des communications entre les nœuds. ![Chiffrement de la communication du module de l’ {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Enregistrer et appliquer {#7-save-and-apply} * `Save and apply` la configuration et les scripts sur les deux nœuds. ![Enregistrez et appliquez la configuration du module {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Vérifier la réussite de la configuration {#8-verify-successful-configuration} * Vérifiez le message `Success` ✅ sur les deux nœuds et cliquez sur `Monitor modules`. * Si l’ `Failure` de configuration ❌ se produit sur un nœud, ouvrez l’accordéon ▼ pour ce nœud et consultez les messages. Notez que vous pouvez utiliser l’IA SafeKit 🤖 pour obtenir de l’aide. ⚠️ Sous Linux, vous pouvez obtenir une erreur à cette étape si les répertoires répliqués sont des points de montage. 🛠️ [Consultez SK-0030 pour résoudre le problème](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf). ![Vérifier la réussite de la configuration du module {{ .Get "app" }}](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Démarrer le nœud avec des données à jour {#9-start-the-node-with-up-to-date-data} * Si le nœud 1 possède les répertoires répliqués à jour, sélectionnez-le et ⋯ `Force start` ▶ `As primary`. Lorsque le nœud 2 sera démarré, toutes les données seront copiées du nœud 1 vers le nœud 2. ⚠️ Si vous faites le mauvais choix, vous risquez de synchroniser des données obsolètes sur les deux nœuds. ⚠️ Il est également supposé que l’application {{ .Get "app" }} est arrêtée sur le nœud 1 afin que SafeKit installe les mécanismes de réplication, puis démarre l’application dans le script `start_prim`. ⚠️ Utilisez `Start` pour les démarrages suivants : SafeKit conserve le serveur le plus à jour. Démarrer `As primary` est un démarrage spécial la première fois ou lors d’opérations exceptionnelles. ![Démarrez le nœud {{ .Get "app" }} en tant que nœud principal avec les données à jour](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Attendez la transition vers ALONE (vert) {#10-wait-for-the-transition-to-alone-green} * Le nœud 1 doit atteindre l’état ALONE (vert), ce qui signifie que l’IP virtuelle est définie et que le script `start_prim` a été exécuté sur le nœud 1. ⚠️ Si ALONE (vert) n’est pas atteint ou si l’application n’est pas démarrée, analysez la raison avec le [journal du module 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) du nœud 1. * Cliquez sur l’icône **de journal** 🔍 du `node1` pour ouvrir le journal du module et recherchez les messages d’erreur, tels qu’un vérificateur détectant une erreur et arrêtant le module. * Cliquez sur `start_prim` dans le journal : les messages de sortie du script sont affichés à droite et les erreurs peuvent être détectées, comme un service mal démarré. * Utilisez l’IA SafeKit 🤖 pour obtenir de l’aide concernant les messages du journal. ⚠️ Si le cluster est dans l’état `WAIT (red) not uptodate, STOP (red) not uptodate`, arrêtez le nœud WAIT et [forcez son démarrage en tant que primaire 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![Le premier nœud {{ .Get "app" }} démarre en tant que primaire et devient ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. Démarrer le nœud 2 {#11-start-node-2} * ⋯ `Start` le nœud 2 avec son menu contextuel. * Attendez le SECOND état (vert). ℹ️ Le nœud 2 reste dans le SECOND état (orange) pendant la resynchronisation des répertoires répliqués (copie du nœud 1 vers le nœud 2). * Cette opération peut prendre un certain temps en fonction de la taille des fichiers à resynchroniser dans les répertoires répliqués et de la bande passante du réseau. * Pour voir la progression de la copie, consultez le [journal du module 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) et les [ressources de réplication 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) du nœud 2. Utilisez l’IA SafeKit 🤖 pour obtenir de l’aide concernant les messages du journal. ![Démarrez le nœud 2 {{ .Get "app" }}](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 12. Vérifiez que le cluster est opérationnel {#12-verify-that-the-cluster-is-operational} * Vérifiez que le cluster est vert/vert, que les services {{ .Get "app" }} s’exécutent sur le nœud PRIM et qu’ils ne s’exécutent pas sur le nœud SECOND. Dans cet état, seules les modifications apportées aux fichiers sont répliquées en temps réel. ⚠️ Les composants qui sont des clients des services {{ .Get "app" }} doivent être configurés avec l’adresse IP virtuelle. La configuration peut être effectuée avec un nom DNS (si un nom DNS a été créé et associé à l’adresse IP virtuelle). ![Le nœud {{ .Get "app" }} 2 est SECOND (vert)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 13. Tests {#13-testing} * Arrêtez le nœud PRIM en faisant défiler son menu contextuel vers le bas et en cliquant sur `Stop`. * Vérifiez qu’il y a un basculement sur le SECOND nœud qui devrait devenir ALONE (vert). * Et avec la console d’administration Microsoft (MMC) sous Windows ou avec des lignes de commande sur Linux, vérifiez le basculement des services {{ .Get "app" }} (arrêtés sur le nœud 1 dans le script `stop_prim` et démarrés sur le nœud 2 dans le script `start_prim`). ⚠️ Si ALONE (vert) n’est pas atteint sur node2 ou si l’application n’est pas démarrée, analysez la raison avec le [journal du module 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) du nœud 2. * Cliquez sur l’icône **de journal** 🔍 du `node2` pour ouvrir le journal du module et recherchez les messages d’erreur, tels qu’un vérificateur détectant une erreur et arrêtant le module. * Cliquez sur `start_prim` dans le journal : les messages de sortie du script sont affichés à droite et les erreurs peuvent être détectées, comme un service mal démarré. * Utilisez l’IA SafeKit 🤖 pour obtenir de l’aide concernant les messages du journal. ⚠️ * Si tout est correct, lancez une synchronisation sur node1, ce qui resynchronisera les répertoires répliqués à partir node2. * Si les choses tournent mal, arrêtez node2 et [forcez le nœud 1 à démarrer en tant que primaire 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png), qui redémarrera avec ses données localement saines au moment de l’arrêt. ℹ️ Retrouvez plus de détails, ainsi que des vidéos, dans la [formation en ligne SafeKit](/fr/resources/safekit-on-line-training/). ![Arrêtez le module {{ .Get "app" }} sur le serveur PRIM](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 14. Assistance {#14-support} * Pour obtenir de l’aide, prenez 2 `Snapshots` SafeKit (2 fichiers .zip), un pour chaque nœud. ℹ️ [Plus d’informations sur l’assistance ici](/fr/resources/safekit-support/). ![Prenez des captures d’écran {{ .Get "app" }} pour obtenir de l’aide](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
