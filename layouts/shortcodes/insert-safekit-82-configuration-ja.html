の設定は、単一のブラウザから両方のノードで実行されます。 ℹ️ Web コンソールを保護するには、🛠️ [11\ を参照してください。ユーザーズガイドのSafeKit Webサービス](/resources/safekit-user-guide-82/#https)のセキュリティ保護。 ![SafeKit Web コンソールを起動して、{{ .Get "app" }} クラスターを構成します。](/wp-content/uploads/2024/03/01-login-large.png) ### 2. ノードアドレスを設定する * ノード IP アドレスを入力し、`Tab key` を押して接続を確認し、ノード名を入力します。 node1 または node2 の色が赤色の場合は、両方のノードへのブラウザーの接続を確認し、🛠️ [トラブルシューティング では、起動時に遅延なくモジュールを自動起動するように選択します。 * `Macros` / `SERVICES` には、アプリケーションのサービス名を起動順にカンマで区切って入力します。 [Milestone XProtect サービス 🖼️](/wp-content/uploads/2025/05/milestone-services.png) addresses`、仮想を入力します IP 住所。仮想 IP 住所は標準です IP 同じ住所 IP ネットワーク (同じサブネット) IP 両方のノードのアドレス。 アプリケーションクライアントは仮想 IP 住所 (または DNS 仮想に関連付けられた名前 IP 住所）。 仮想 IP 障害発生時にはアドレスが自動的に切り替わります。 * `Replicated directories` で、レプリケートするディレクトリのパスを設定します。これらが両方のノードに存在し、アプリケーション データが含まれていることを確認します。 データとログのレプリケーションはデータベースにとって不可欠です。 必要に応じて、追加の複製ディレクトリを作成できます。 [Milestone XProtect SQL レプリケーション 🖼️](/wp-content/uploads/2025/05/milestone-replication.png) の視覚的な例については、このスクリーンショットを参照してください。 * `Checkers` では、必要に応じて、プロセス監視、カスタム チェッカー、TCP、ping、スプリット ブレイン チェッカーなどのチェッカーを構成できます。 たとえば、`Monitored processes/services` にプロセス名が表示されている場合、障害が発生した場合は再起動アクションで監視されます。間違ったプロセス名を設定すると、モジュールが開始直後に停止します。 ℹ️ `Advanced configuration`をクリックすると、`userconfig.xml`ファイルが表示されます。このファイルはコンソールによって自動的に設定され、再起動スクリプトを使用してノードにデプロイされます。 ℹ️ クラウド展開では、仮想環境を構成する必要はありません。 IP の住所 SafeKit。仮想 IP 🛠️で管理されています (同じことが当てはまります)。 Linux）。 ![{{ .Get "app" }}モジュール設定を入力します](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. スクリプトの編集 (オプション) * この手順はオプションであり、前の手順で定義したサービスを再起動するように再起動スクリプトがすでに構成されているため、ほとんどの場合はスキップできます。 * したがって、`Next step` を直接クリックしてください。 * `start_prim.ps1` は、`SERVICES` リストで指定された順序ですべてのサービスを開始し、`stop_prim.ps1` は逆の順序ですべてのサービスを停止します。 * さらに、`start_prim.ps1` は各サービスの起動をチェックし、サービスが正しく起動できない場合はモジュールを停止します。 ![{{ .Get "app" }}モジュール設定を入力します](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. 通信の暗号化（オプション） ⚠️ 以降の起動には `Start` を使用します: SafeKit は最新のサーバーを保持します。 `As primary` の起動は、初回または例外的な操作中の特別な起動です。 ![最新のデータを使用して {{ .Get "app" }}
