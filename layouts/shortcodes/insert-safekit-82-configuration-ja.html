SafeKit コンソールを起動します {#1-launch-the-safekit-console} * いずれかのクラスターノードで、`http://localhost:9010` に接続してウェブコンソールをブラウザで起動します。 * ユーザー名に `admin` と入力し、インストール時に定義したパスワードを入力します。 コンソールは、クラスター外部のワークステーションのブラウザーで実行することもできます。 ⚠️ SafeKit の設定は、単一のブラウザから両方のノードで行います。 ℹ️ Web コンソールを保護するには、ユーザーガイドの 🛠️ [11. SafeKit Web サービスの保護を](/ja/resources/safekit-user-guide-82/#https)参照してください。 ![SafeKit ウェブコンソールを起動して、{{ .Get "app" }} クラスターを設定します](/wp-content/uploads/2024/03/01-login-large.png) ### 2. ノードアドレスの設定 {#2-configure-node-addresses} * ノードの IP アドレスを入力し、`Tab key` を押して接続性を確認し、ノード名を入力します。node1 または node2 のいずれかが赤色の場合、両方のノードへのブラウザの接続性を確認し、両方のノードのファイアウォールを 🛠️ [トラブルシューティング](/ja/resources/safekit-user-guide-82/#Troubleshooting)のために確認します。 * 次に、`Save and apply` をクリックして設定を保存します。 * 両方のノードで `Success` ✅ メッセージを確認します。 * あるノードで構成の `Failure` ❌ が発生した場合は、そのノードの▼アコーディオンを開いてメッセージを確認してください。SafeKit AI 🤖 使用して支援を受けることができます。 ℹ️ 必要に応じて、新しい `LAN and nodes`（最初の ➕）を追加して、2 番目のハートビートと専用のレプリケーションネットワークを作成できます。 ℹ️ `Advanced configuration` をクリックすると、`cluster.xml` ファイルが表示されます。このファイルはコンソールによって自動的に作成され、ノードにデプロイされます。 ![{{ .Get "app" }} クラスターのノードを入力します](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. モジュールを選択します {#3-select-a-module} * `New module` で、`{{ .Get "mod" }}.safe` モジュールをクリックします。 ℹ️ 上部の青いバナーで、🛜 `node1` コンソール接続ノードを表します。このノードは、必要に応じて `node2` にリクエストを中継します。 ℹ️ インストール時にモジュールを配置した場合、コンソールは接続ノード (`node1`) の `Application_Modules/generic/` ディレクトリで `xxx.safe` を検索します。 ![{{ .Get "app" }} のモジュールを選択してください](/wp-content/uploads/2024/03/04-module-new.png) ### 4. モジュールを構成する {#4-configure-the-module} * `Module startup at boot` で、遅延なしで起動時にモジュールを自動起動するように選択します。 * `Macros`/`SERVICES` に、アプリケーションのサービス名を起動順にコンマで区切って入力します。Milestone [Milestone XProtect サービスの視覚的な例については、このスクリーンショットを参照してください 🖼️](/wp-content/uploads/2025/05/milestone-services.png)。 * `Heartbeat networks` では、レプリケーションが行われる単一のハートビートネットワークが必要です。ステップ 2 でプライベート LAN を追加した場合は、プライベート LAN でレプリケーションフローを持つ 2 つのハートビートを設定できます。 * `Virtual IP addresses` に、仮想 IP アドレスを入力します。仮想 IP アドレスは、両方のノードの IP アドレスと同じ IP ネットワーク (同じサブネット) 内の標準 IP アドレスです。 アプリケーションクライアントは、仮想 IP アドレス（または仮想 IP アドレスに関連付けられた DNS 名）で設定する必要があります。 障害発生時には、仮想 IP アドレスが自動的に切り替わります。 * `Replicated directories` で、レプリケートするディレクトリのパスを設定します。両方のノードに存在し、アプリケーションデータが含まれていることを確認します。 データとログのレプリケーションは、データベースにとって不可欠です。 必要に応じて、追加のレプリケートディレクトリを作成できます。 [Milestone XProtect SQL レプリケーションの視覚的な例については、こちらのスクリーンショットをご覧ください 🖼️](/wp-content/uploads/2025/05/milestone-replication.png)。 * `Checkers` では、必要に応じて、プロセス監視、カスタムチェッカー、TCP、ping、またはスプリットブレインチェッカーなどのチェッカーを設定できます。 たとえば、プロセス名が `Monitored processes/services` に表示されている場合、障害発生時に再起動アクションで監視されます。誤ったプロセス名を設定すると、モジュールは起動直後に停止します。 ℹ️ `Advanced configuration` をクリックすると、`userconfig.xml` ファイルが表示されます。このファイルはコンソールによって自動的に作成され、再起動スクリプトを使用してノードにデプロイされます。 ℹ️ クラウド展開では、SafeKit で仮想 IP アドレスを設定する必要はありません。仮想 IP は、🛠️ [クラウドロードバランサーレベル](/ja/resources/safekit-user-guide-82/#Cloud)で管理されます。 ℹ️ SafeKit の構成を適用すると、Windows サービスでサービスの `startup type` が自動的に `Manual` に設定されます。これにより、システム起動時にサービスが自動的に開始されることはなく、モジュール自体が開始されたときにのみ開始されます（Linux でも同様です）。 ![{{ .Get "app" }} モジュールの設定を入力します](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. スクリプトを編集する（任意） {#5-edit-scripts-optional} * このステップはオプションであり、ほとんどの場合スキップできます。再起動スクリプトは、前のステップで定義されたサービスを再起動するようにすでに事前設定されています。 * `Next step` を直接クリックしてください。 * `start_prim.ps1`、`SERVICES` リストで指定された順序ですべてのサービスを開始し、`stop_prim.ps1` 逆の順序ですべてのサービスを停止します。 * さらに、`start_prim.ps1` 各サービスの起動をチェックし、いずれかのサービスが正しく起動しなかった場合はモジュールを停止します。 ![{{ .Get "app" }} モジュールの設定を入力します](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. 通信の暗号化（オプション） {#6-communication-encryption-optional} * ノード間の通信の暗号化を維持します。 ![{{ .Get "app" }} モジュールの通信暗号化](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. 保存して適用 {#7-save-and-apply} * 両方のノードで設定とスクリプト `Save and apply`。 ![{{ .Get "app" }} モジュールの構成を保存して適用します](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. 設定が正常に完了したことを確認する {#8-verify-successful-configuration} * 両方のノードで `Success` ✅ メッセージを確認し、`Monitor modules` をクリックします。 * あるノードで構成の `Failure` ❌ が発生した場合は、そのノードの▼アコーディオンを開いてメッセージを確認してください。SafeKit AI 🤖 使用して支援を受けることができます。 ⚠️ Linux では、レプリケートされたディレクトリがマウントポイントの場合、このステップでエラーが発生することがあります。🛠️ [問題を解決するには、SK-0030 を参照してください](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf)。 ![{{ .Get "app" }} モジュールの設定が成功したことを確認します](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. 最新のデータでノードを起動する {#9-start-the-node-with-up-to-date-data} * ノード 1 に最新のレプリケートされたディレクトリがある場合は、それを選択して⋯ `Force start` ▶ `As primary` ] を選択します。 ノード 2 が起動すると、すべてのデータがノード 1 からノード 2 にコピーされます。 ⚠️ 間違った選択をすると、両方のノードで古いデータを同期させてしまう危険性があります。 ⚠️ また、SafeKit はレプリケーションメカニズムをインストールし、`start_prim` スクリプトでアプリケーションを起動できるように、ノード 1 で {{ .Get "app" }} アプリケーションが停止していることも前提としています。 ⚠️ 2 回目以降の起動には `Start` 使用してください。SafeKit は最新のサーバーを保持します。「Starting `As primary` は、初回起動時または例外的な操作時に使用する特別な起動方法です。 ![最新のデータを持つ {{ .Get "app" }} ノードをプライマリとして起動します](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. ALONE（緑）に切り替わるまで待ちます {#10-wait-for-the-transition-to-alone-green} * ノード 1 は ALONE（緑）状態に達する必要があります。これは、仮想 IP が設定され、`start_prim` スクリプトがノード 1 で実行されたことを意味します。 ⚠️ ALONE（緑）に到達しない場合、またはアプリケーションが起動しない場合は、ノード 1 の[モジュールログ 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png)で原因を分析してください。 * `node1` の 🔍**ログ**アイコンをクリックしてモジュールログを開き、チェッカーがエラーを検出してモジュールを停止するなどのエラーメッセージを探します。 * ログの `start_prim` をクリックします。スクリプトの出力メッセージが右側に表示され、サービスが正しく起動していないなどのエラーを検出できます。 * ログメッセージについては、SafeKit AI 🤖 をご利用ください。 ⚠️ クラスターが `WAIT (red) not uptodate, STOP (red) not uptodate` 状態の場合は、WAIT ノードを停止し、[プライマリとして強制的に起動してください 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png)。 ![最初の {{ .Get "app" }} ノードはプライマリとして起動し、ALONE になります](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. ノード 2 を起動する {#11-start-node-2} * ⋯コンテキストメニューからノード 2 `Start`。 * SECOND（緑色）の状態になるまで待ちます。 ℹ️ ノード 2 は、レプリケートされたディレクトリを再同期している間（ノード 1 からノード 2 にコピー）、SECOND（オレンジ色の）状態を維持します。 * レプリケートされたディレクトリで再同期するファイルのサイズやネットワーク帯域幅によっては、これに時間がかかる場合があります。 * コピーの進捗状況を確認するには、ノード 2 の[モジュールログ 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png)と[レプリケーションリソース 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png)を参照してください。ログメッセージのサポートには SafeKit AI 🤖 を使用してください。 ![{{ .Get "app" }} ノード 2 を起動します](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 12. クラスターが動作していることを確認します {#12-verify-that-the-cluster-is-operational} * PRIM ノードで {{ .Get "app" }} サービスが実行され、SECOND ノードでは実行されていない状態で、クラスターが緑/緑であることを確認します。 この状態では、ファイル内の変更のみがリアルタイムで複製されます。 ⚠️ {{ .Get "app" }} サービスのクライアントであるコンポーネントは、仮想 IP アドレスで構成する必要があります。DNS 名で構成することもできます（DNS 名が作成され、仮想 IP アドレスに関連付けられている場合）。 ![{{ .Get "app" }} ノード 2 は SECOND（緑色）です](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 13. テスト {#13-testing} * PRIM ノードのコンテキストメニューを下にスクロールして、`Stop` をクリックして停止します。 * SECOND ノードでフェイルオーバーが発生し、ALONE（緑色）になっていることを確認します。 * Windows の Microsoft 管理コンソール (MMC) または Linux のコマンドラインを使用して、{{ .Get "app" }} サービスのフェイルオーバーを確認します (`stop_prim` スクリプトでノード 1 で停止し、`start_prim` スクリプトでノード 2 で開始します)。 ⚠️ node2 で ALONE（緑）に到達しない場合、またはアプリケーションが起動しない場合は、ノード 2 の[モジュールログ 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png)で原因を分析してください。 * `node2` の 🔍**ログ**アイコンをクリックしてモジュールログを開き、チェッカーがエラーを検出してモジュールを停止するなどのエラーメッセージを探します。 * ログの `start_prim` をクリックします。スクリプトの出力メッセージが右側に表示され、サービスが正しく起動していないなどのエラーを検出できます。 * ログメッセージについては、SafeKit AI 🤖 をご利用ください。 ⚠️ * すべて問題なければ、node1 で開始すると、node2 からレプリケートされたディレクトリが再同期されます。 * 問題が発生した場合は、node2 を停止し、[node1 をプライマリとして強制的に起動します 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png)。これにより、停止時のローカルに正常なデータで再起動します。 ℹ️ 詳細と動画については、[SafeKit オンライン研修](/ja/resources/safekit-on-line-training/)をご覧ください。 ![PRIM サーバーで {{
