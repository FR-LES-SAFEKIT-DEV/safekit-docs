SafeKit 콘솔을 시작합니다 {#1-launch-the-safekit-console} * `http://localhost:9010`에 연결하여 클러스터 노드 중 하나에서 브라우저로 웹 콘솔을 실행합니다. * 사용자 이름에 `admin` 입력하고 설치 시 정의한 암호를 입력합니다. 클러스터 외부의 워크스테이션에 있는 브라우저에서 콘솔을 실행할 수도 있습니다. ⚠️ SafeKit 구성은 단일 브라우저에서 두 노드 모두에 대해 수행됩니다. ℹ️ 웹 콘솔을 보호하려면 사용 설명서의 🛠️ [11. SafeKit 웹 서비스 보안](/ko/resources/safekit-user-guide-82/#https)을 참조하십시오. ![SafeKit 웹 콘솔을 시작하여 {{ .Get "app" }} 클러스터를 구성합니다](/wp-content/uploads/2024/03/01-login-large.png) ### 2. 노드 주소 구성 {#2-configure-node-addresses} * 노드 IP 주소를 입력하고 `Tab key` 눌러 연결을 확인한 후 노드 이름을 입력합니다. node1 또는 node2 빨간색으로 표시되면 브라우저와 두 노드 간의 연결을 확인하고 두 노드의 방화벽에서 🛠️ [문제 해결](/ko/resources/safekit-user-guide-82/#Troubleshooting)을 확인하십시오. * 그런 다음, 구성을 저장하려면 `Save and apply`을 클릭합니다. * 두 노드 모두에서 `Success` ✅ 메시지를 확인하세요. * 한 노드에서 구성 `Failure` ❌ 가 발생하면 해당 노드의 ▼ 아코디언을 열고 메시지를 검토하십시오. SafeKit AI 🤖 를 사용하여 도움을 받을 수 있습니다. ℹ️ 원하는 경우 새 `LAN and nodes` (첫 번째 ➕)를 추가하여 두 번째 하트비트와 전용 복제 네트워크를 만들 수 있습니다. ℹ️ `Advanced configuration` 클릭하면 `cluster.xml` 파일이 표시됩니다. 이 파일은 콘솔에서 자동으로 채워지고 노드에 배포됩니다. ![{{ .Get "app" }} 클러스터의 노드를 입력하세요](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. 모듈 선택 {#3-select-a-module} * `New module`에서 `{{ .Get "mod" }}.safe` 모듈을 클릭합니다. ℹ️ 상단의 파란색 배너에서 🛜 `node1` 콘솔 연결 노드를 나타냅니다. 이 노드는 필요할 때 요청을 `node2`로 전달합니다. ℹ️ 설치 중에 모듈을 해당 디렉터리에 배치한 경우 콘솔은 연결 노드(`node1`)의 `Application_Modules/generic/` 디렉터리에서 `xxx.safe`를 검색합니다. ![{{ .Get "app" }} 모듈을 선택하세요](/wp-content/uploads/2024/03/04-module-new.png) ### 4. 모듈 구성 {#4-configure-the-module} * `Module startup at boot`에서 지연 없이 부팅 시 모듈을 자동으로 시작하도록 선택합니다. * `Macros`/`SERVICES`에 애플리케이션의 서비스 이름을 시작 순서대로 쉼표로 구분하여 입력합니다. [Milestone XProtect 서비스의 시각적 예시는 이 스크린샷을 참조하십시오 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * `Heartbeat networks`에서는 복제가 이루어지는 단일 하트비트 네트워크가 있어야 합니다. 2단계에서 개인 LAN을 추가한 경우 개인 LAN에서 복제 흐름으로 두 개의 하트비트를 구성할 수 있습니다. * `Virtual IP addresses`에 가상 IP 주소를 입력합니다. 가상 IP 주소는 두 노드의 IP 주소와 동일한 IP 네트워크(동일한 서브넷)의 표준 IP 주소입니다. 애플리케이션 클라이언트는 가상 IP 주소(또는 가상 IP 주소와 연결된 DNS 이름)로 구성해야 합니다. 가상 IP 주소는 장애 발생 시 자동으로 전환됩니다. * `Replicated directories`에서 복제할 디렉터리의 경로를 설정합니다. 두 노드 모두에 존재하고 애플리케이션 데이터가 포함되어 있는지 확인합니다. 데이터 및 로그 복제는 데이터베이스에 필수적입니다. 필요에 따라 복제된 디렉터리를 추가로 생성할 수 있습니다. [Milestone XProtect SQL 복제의 시각적 예시는 이 스크린샷을 참조하세요 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * `Checkers`에서 필요한 경우 프로세스 모니터링, 사용자 지정 체커, TCP, ping 또는 분할 브레인 체커와 같은 체커를 구성할 수 있습니다. 예를 들어, 프로세스 이름이 `Monitored processes/services`에 표시되면 실패 시 재시작 작업으로 모니터링됩니다. 잘못된 프로세스 이름을 구성하면 모듈이 시작 직후 중지됩니다. ℹ️ `Advanced configuration` 클릭하면 `userconfig.xml` 파일이 표시됩니다. 이 파일은 콘솔에서 자동으로 채워지며 재시작 스크립트와 함께 노드에 배포됩니다. ℹ️ 클라우드 배포에서는 SafeKit에서 가상 IP 주소를 구성할 필요가 없습니다. 가상 IP는 🛠️ [클라우드 로드 밸런서 수준](/ko/resources/safekit-user-guide-82/#Cloud)에서 관리됩니다. ℹ️ SafeKit 구성을 적용하면 Windows 서비스에서 서비스의 `startup type` 자동으로 `Manual`으로 설정됩니다. 이렇게 하면 시스템 부팅 시 서비스가 자동으로 시작되지 않고 모듈 자체가 시작될 때만 시작됩니다(Linux 에서도 동일하게 적용됩니다). ![{{ .Get "app" }} 모듈 설정으로 이동](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. 스크립트 편집(선택 사항) {#5-edit-scripts-optional} * 이 단계는 선택 사항이며 대부분의 경우 건너뛸 수 있습니다. 재시작 스크립트는 이전 단계에서 정의된 서비스를 재시작하도록 이미 사전 구성되어 있기 때문입니다. * 그러면 `Next step`를 직접 클릭하세요. * `start_prim.ps1` `SERVICES` 목록에 지정된 순서대로 모든 서비스를 시작하고, `stop_prim.ps1` 역순으로 모든 서비스를 중지합니다. * 또한 `start_prim.ps1` 각 서비스의 시작을 확인하고 서비스 중 하나라도 제대로 시작되지 않으면 모듈을 중지합니다. ![{{ .Get "app" }} 모듈 설정으로 이동](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. 통신 암호화(선택 사항) {#6-communication-encryption-optional} * 노드 간 통신 암호화를 유지하세요. ![{{ .Get "app" }} 모듈의 통신 암호화](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. 저장 및 적용 {#7-save-and-apply} * 두 노드 모두에서 구성을 `Save and apply`. ![{{ .Get "app" }} 모듈 구성을 저장하고 적용합니다](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. 구성 성공 여부 확인 {#8-verify-successful-configuration} * 두 노드 모두에서 `Success` ✅ 메시지를 확인하고 `Monitor modules` 클릭하세요. * 한 노드에서 구성 `Failure` ❌ 가 발생하면 해당 노드의 ▼ 아코디언을 열고 메시지를 검토하십시오. SafeKit AI 🤖 를 사용하여 도움을 받을 수 있습니다. ⚠️ Linux에서 복제된 디렉터리가 마운트 지점인 경우 이 단계에서 오류가 발생할 수 있습니다. 🛠️ [문제를 해결하려면 SK-0030을 참조하십시오](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf). ![{{ .Get "app" }} 모듈 구성 성공 여부 확인](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. 최신 데이터로 노드를 시작합니다 {#9-start-the-node-with-up-to-date-data} * 노드 1에 최신 복제 디렉터리가 있는 경우 해당 노드를 선택하고 ⋯ `Force start` ▶ `As primary` 시작을 선택합니다. 노드 2가 시작되면 모든 데이터가 노드 1에서 노드 2로 복사됩니다. ⚠️ 잘못된 선택을 하면 두 노드 모두에서 오래된 데이터를 동기화할 위험이 있습니다. ⚠️ 또한 SafeKit은 복제 메커니즘을 설치한 다음 `start_prim` 스크립트에서 애플리케이션을 시작할 수 있도록 노드 1에서 {{ .Get "app" }} 애플리케이션이 중지되었다고 가정합니다. ⚠️ 후속 시작 시에는 `Start` 사용하십시오. SafeKit은 최신 서버를 유지합니다. `As primary` 시작하는 것은 처음이거나 예외적인 작업 중에 특별히 시작하는 것입니다. ![최신 데이터가 있는 {{ .Get "app" }} 노드를 기본으로 시작합니다](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. ALONE (녹색)로 전환될 때까지 기다리세요 {#10-wait-for-the-transition-to-alone-green} * 노드 1은 ALONE (녹색) 상태에 도달해야 합니다. 이는 가상 IP가 설정되었고 노드 1에서 `start_prim` 스크립트가 실행되었음을 의미합니다. ⚠️ ALONE (녹색)에 도달하지 못했거나 애플리케이션이 시작되지 않은 경우 노드 1의 [모듈 로그 🖼️ 를](/wp-content/uploads/2024/03/24-module-log-script.png) 통해 원인을 분석하십시오. * `node1`의 🔍 **로그** 아이콘을 클릭하여 모듈 로그를 열고, 검사기가 오류를 감지하여 모듈을 중지시키는 등의 오류 메시지를 찾습니다. * 로그에서 `start_prim` 클릭하면 스크립트의 출력 메시지가 오른쪽에 표시되며 서비스가 잘못 시작되는 등의 오류를 감지할 수 있습니다. * 로그 메시지 관련 지원은 SafeKit AI 🤖 이용하세요. ⚠️ 클러스터가 `WAIT (red) not uptodate, STOP (red) not uptodate` 상태인 경우 WAIT 노드를 중지하고 [주 노드로 강제 시작합니다 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![첫 번째 {{ .Get "app" }} 노드는 기본으로 시작하여 ALONE 상태가 됩니다](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. 노드 2 시작 {#11-start-node-2} * ⋯ 컨텍스트 메뉴가 있는 `Start` 노드 2를 선택합니다. * SECOND (녹색) 상태가 될 때까지 기다리세요. ℹ️ 노드 2는 복제된 디렉터리를 재동기화하는 동안(노드 1에서 노드 2로 복사) SECOND (주황색) 상태를 유지합니다. * 복제된 디렉터리에서 다시 동기화할 파일의 크기와 네트워크 대역폭에 따라 시간이 다소 걸릴 수 있습니다. * 복사 진행 상황을 확인하려면 노드 2의 [모듈 로그 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) 및 [복제 리소스 🖼️ 를](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) 참조하십시오. 로그 메시지 지원이 필요한 경우 SafeKit AI 🤖 사용하십시오. ![{{ .Get "app" }} 노드 2를 시작합니다](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 12. 클러스터가 작동 중인지 확인합니다 {#12-verify-that-the-cluster-is-operational} * 클러스터가 녹색/녹색이고 PRIM 노드에서 {{ .Get "app" }} 서비스가 실행 중이며 노드 2는 SECOND (녹색)입니다](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 13. 테스트 {#13-testing} * PRIM 노드의 상황별 메뉴를 아래로 스크롤하여 `Stop` 클릭하여 노드를 중지합니다. * SECOND 노드에 장애 조치가 발생하여 ALONE 작동하는지(녹색)
