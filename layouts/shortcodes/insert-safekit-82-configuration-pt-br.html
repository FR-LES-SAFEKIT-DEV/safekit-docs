{{/* translation: translate_md 2026-11-08.9 | glossaire 2026-11-08.25 | Translation LLM | 24 expressions */}} {{/* Shortcode: insert-safekit-82-configuration-en — 15 instances in 15 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-oracle.md */}} ### Pré-requisitos {#prerequisites} * {{ .Get "app" }} foi instalado em 2 nós. * Os dados replicados totais são limitados a alguns terabytes — além disso, o tempo de resincronização torna-se significativo. * Interconexão mínima de 1 Gb/s entre os nós (10 Gb/s recomendada para resincronização mais rápida). * O failover de IP requer que ambos os nós estejam na mesma LAN ou LAN estendida (L2) — redes L3 roteadas não são suportadas (exceto com [balanceadores de carga em nuvem](/pt-br/resources/safekit-user-guide-82/#Cloud) 🛠️). ### 1. Inicie o console SafeKit {#1-launch-the-safekit-console} * Inicie o console da web em um navegador em um nó do cluster, conectando-se a `http://localhost:9010`. * Insira `admin` como nome de usuário e a senha definida durante a instalação. Você também pode executar o console em um navegador em uma estação de trabalho externa ao cluster. ⚠️ A configuração do SafeKit é feita em ambos os nós a partir de um único navegador. ℹ️ Para proteger o console da web, consulte 🛠️ [11. Protegendo o serviço da web SafeKit](/pt-br/resources/safekit-user-guide-82/#https) no Guia do Usuário. ![Inicie o console web SafeKit para configurar o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar endereços de nós {#2-configure-node-addresses} * Insira os endereços IP do nó, pressione a `Tab key` para verificar a conectividade e preencha os nomes dos nós. Se node1 ou node2 estiverem em vermelho, verifique a conectividade do navegador com ambos os nós e verifique o firewall em ambos os nós para 🛠️ [solucionar problemas](/pt-br/resources/safekit-user-guide-82/#Troubleshooting). * Em seguida, clique em `Save and apply` para salvar a configuração. * Verifique a mensagem `Success` ✅ em ambos os nós. * Se ocorrer uma `Failure` de configuração ❌ em um nó, abra o acordeão ▼ desse nó e revise as mensagens. Observe que você pode usar a IA SafeKit 🤖 para obter assistência. ℹ️ Se desejar, você pode adicionar uma nova `LAN and nodes` (primeiro ➕) para criar um segundo heartbeat e uma rede de replicação dedicada. ℹ️ Se você clicar em `Advanced configuration`, o arquivo `cluster.xml` será exibido. Este arquivo é preenchido automaticamente pelo console e implantado nos nós. ![Insira os nós do cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Selecione um módulo {#3-select-a-module} * No `New module`, clique no módulo `{{ .Get "mod" }}.safe`. ℹ️ No banner azul na parte superior, 🛜 `node1` representa o nó de conexão do console. Este nó retransmite solicitações para `node2` quando necessário. ℹ️ O console procura por `xxx.safe` no diretório `Application_Modules/generic/` no nó de conexão (`node1`) se você colocou um módulo lá durante a instalação. ![Escolha o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configure o módulo {#4-configure-the-module} * Em `Module startup at boot`, escolha o início automático do módulo na inicialização sem atraso. * Em `Macros`/`SERVICES`, insira os nomes dos serviços do seu aplicativo, na ordem de inicialização, separados por vírgulas. Consulte esta captura de tela para obter um exemplo visual dos [serviços Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * Nas `Heartbeat networks`, você deve ter uma única rede de pulsações na qual a replicação é feita. Se você adicionou uma LAN privada na etapa 2, poderá configurar duas pulsações com o fluxo de replicação na LAN privada. * Em `Virtual IP addresses`, insira um endereço IP virtual. Um endereço IP virtual é um endereço IP padrão na mesma rede IP (mesma sub-rede) que os endereços IP de ambos os nós. Os clientes da aplicação devem ser configurados com o endereço IP virtual (ou o nome DNS associado ao endereço IP virtual). O endereço IP virtual é alterado automaticamente em caso de falha. * Em `Replicated directories`, defina os caminhos dos diretórios a serem replicados. Verifique se eles existem em ambos os nós e contêm os dados do aplicativo. A replicação de dados e de logs é essencial para um banco de dados. Você pode criar diretórios replicados adicionais conforme necessário. Veja esta captura de tela para um exemplo visual da [replicação SQL Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * Em `Checkers`, você poderá configurar verificadores, se necessário, como monitoramento de processos, verificadores personalizados, TCP, ping ou verificadores de divisão de cérebro. Por exemplo, se um nome de processo for exibido em `Monitored processes/services`, ele será monitorado com uma ação de reinicialização em caso de falha. A configuração de um nome de processo incorreto fará com que o módulo pare logo após o seu início. ℹ️ Se você clicar em `Advanced configuration`, o arquivo `userconfig.xml` será exibido. Este arquivo é preenchido automaticamente pelo console e implantado nos nós com os scripts de reinicialização. ℹ️ Em uma implantação na nuvem, você não precisa configurar um endereço IP virtual no SafeKit. O IP virtual é gerenciado no [nível do balanceador de carga da nuvem](/pt-br/resources/safekit-user-guide-82/#Cloud) 🛠️ ℹ️ Ao aplicar a configuração SafeKit, o `startup type` dos serviços é automaticamente definido como `Manual` nos serviços Windows. Isso garante que os serviços não sejam iniciados automaticamente quando o sistema é inicializado, mas sim apenas quando o próprio módulo é iniciado (o mesmo se aplica no Linux). ![Acesse as configurações do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. Editar scripts (opcional) {#5-edit-scripts-optional} * Esta etapa é opcional e pode ser ignorada na maioria dos casos, pois os scripts de reinicialização já estão pré-configurados para reiniciar os serviços definidos na etapa anterior. * Então, clique diretamente em `Next step`. * `start_prim.ps1` inicia todos os serviços na ordem especificada na lista `SERVICES`, enquanto `stop_prim.ps1` para todos os serviços na ordem inversa. * Além disso, `start_prim.ps1` verifica a inicialização de cada serviço e interrompe o módulo se algum serviço não for iniciado corretamente. ![Acesse as configurações do módulo {{ .Get "app" }}](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. Criptografia de comunicação (opcional) {#6-communication-encryption-optional} * Mantenha a criptografia da comunicação entre os nós. ![Criptografia de comunicação do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Salvar e aplicar {#7-save-and-apply} * `Save and apply` a configuração e os scripts em ambos os nós. ![Salve e aplique a configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verifique se a configuração foi bem-sucedida {#8-verify-successful-configuration} * Verifique a mensagem `Success` ✅ em ambos os nós e clique em `Monitor modules`. * Se ocorrer uma `Failure` de configuração ❌ em um nó, abra o acordeão ▼ desse nó e revise as mensagens. Observe que você pode usar a IA SafeKit 🤖 para obter assistência. ⚠️ No Linux, você pode receber um erro nesta etapa se os diretórios replicados forem pontos de montagem. 🛠️ [Consulte SK-0030 para resolver o problema](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf). ![Verifique se a configuração do módulo {{ .Get "app" }} foi bem-sucedida](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Inicie o nó com dados atualizados {#9-start-the-node-with-up-to-date-data} * Se o nó 1 tiver os diretórios replicados atualizados, selecione-o e ⋯ `Force start` ▶ `As primary`. Quando o nó 2 for iniciado, todos os dados serão copiados do nó 1 para o nó 2. ⚠️ Se você fizer a escolha errada, corre o risco de sincronizar dados desatualizados em ambos os nós. ⚠️ Também se presume que o aplicativo {{ .Get "app" }} esteja parado no nó 1 para que SafeKit instale os mecanismos de replicação e, em seguida, inicie o aplicativo no script `start_prim`. ⚠️ Use `Start` para inícios subsequentes: SafeKit mantém o servidor mais atualizado. Iniciar `As primary` é um início especial na primeira vez ou durante operações excepcionais. ![Inicie o nó {{ .Get "app" }} como primário com os dados atualizados](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Aguarde a transição para ALONE (verde) {#10-wait-for-the-transition-to-alone-green} * O nó 1 deve atingir o estado ALONE (verde), o que significa que o IP virtual está definido e que o script `start_prim` foi executado no nó 1. ⚠️ Se ALONE (verde) não for atingido ou se o aplicativo não for iniciado, analise o motivo com o [log do módulo 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) do nó 1. * Clique no ícone **de log** 🔍 do `node1` para abrir o log do módulo e procure mensagens de erro, como um verificador que detecta um erro e interrompe o módulo. * Clique em `start_prim` no log: as mensagens de saída do script são exibidas à direita e os erros podem ser detectados, como um serviço iniciado incorretamente. * Use o SafeKit AI 🤖 para obter ajuda com as mensagens de log. ⚠️ Se o cluster estiver no estado `WAIT (red) not uptodate, STOP (red) not uptodate`, pare o nó WAIT e [force o seu início como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![O primeiro nó {{ .Get "app" }} inicia como primário e fica ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. Iniciar nó 2 {#11-start-node-2} * ⋯ `Start` o nó 2 com o seu menu contextual. * Aguarde o SECOND estado (verde). ℹ️ O nó 2 permanece no SECOND estado (laranja) enquanto resincroniza os diretórios replicados (cópia do nó 1 para o nó 2). * Isso pode levar algum tempo, dependendo do tamanho dos arquivos a serem resincronizados nos diretórios replicados e da largura de banda da rede. * Para ver o progresso da cópia, consulte o [log do módulo 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) e os [recursos de replicação 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) do nó 2. Use o SafeKit AI 🤖 para obter assistência com as mensagens de log. ![Inicie o nó 2 {{ .Get "app" }}](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 12. Verifique se o cluster está operacional {#12-verify-that-the-cluster-is-operational} * Verifique se o cluster está verde/verde com os serviços {{ .Get "app" }} em execução no nó PRIM e não em execução no nó SECOND. Apenas as alterações dentro dos arquivos são replicadas em tempo real neste estado. ⚠️ Os componentes que são clientes dos serviços {{ .Get "app" }} devem ser configurados com o endereço IP virtual. A configuração pode ser feita com um nome DNS (se um nome DNS tiver sido criado e associado ao endereço IP virtual). ![O nó {{ .Get "app" }} 2 é SECOND (verde)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 13. Testes {#13-testing} * Pare o nó PRIM rolando para baixo no menu contextual e clicando em `Stop`. * Verifique se há um failover no SECOND nó, que deve ficar ALONE (verde). * E com Microsoft Management Console (MMC) no Windows ou com linhas de comando no Linux, verifique o failover dos serviços {{ .Get "app" }} (parado no nó 1 no script `stop_prim` e iniciado no nó 2 no script `start_prim`). ⚠️ Se ALONE (verde) não for atingido no node2 ou se o aplicativo não for iniciado, analise o motivo com o [log do módulo 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) do nó 2. * Clique no ícone **de log** 🔍 do `node2` para abrir o log do módulo e procure mensagens de erro, como um verificador detectando um erro e interrompendo o módulo. * Clique em `start_prim` no log: as mensagens de saída do script são exibidas à direita e os erros podem ser detectados, como um serviço iniciado incorretamente. * Use o SafeKit AI 🤖 para obter ajuda com as mensagens de log. ⚠️ * Se tudo estiver bem, inicie o node1, que irá ressincronizar os diretórios replicados do node2. * Se as coisas derem errado, pare node2 e [force o nó 1 a iniciar como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png), que será reiniciado com seus dados localmente íntegros no momento da parada. ℹ️ Encontre mais detalhes, juntamente com vídeos, no [Treinamento Online SafeKit](/pt-br/resources/safekit-on-line-training/). ![Pare o módulo {{ .Get "app" }} no servidor PRIM](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 14. Suporte {#14-support} * Para obter suporte, faça 2 `Snapshots` SafeKit (2 arquivos .zip), um para cada nó. ℹ️ [Mais informações sobre o suporte aqui](/pt-br/resources/safekit-support/). ![Tire capturas de tela do {{ .Get "app" }} para obter suporte](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
