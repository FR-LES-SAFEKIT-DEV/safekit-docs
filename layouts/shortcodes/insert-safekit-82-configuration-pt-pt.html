{{/* translation: translate_md 2026-11-08.9 | glossaire 2026-11-08.25 | Translation LLM | 24 expressions */}} {{/* Shortcode: insert-safekit-82-configuration-en — 15 instances in 15 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-oracle.md */}} ### Pré-requisitos {#prerequisites} * {{ .Get "app" }} aplicação foi instalada em 2 nós. * O total de dados replicados é limitado a alguns terabytes — para além disso, o tempo de resincronização torna-se significativo. * Interconexão mínima de 1 Gb/s entre nós (10 Gb/s recomendado para resincronização mais rápida). * A redundância de IP requer que ambos os nós estejam na mesma LAN ou LAN estendida (L2) — redes L3 com encaminhamento não são suportadas (exceto com [balanceadores de carga em nuvem](/pt-pt/resources/safekit-user-guide-82/#Cloud) 🛠️). ### 1. Inicie a consola SafeKit {#1-launch-the-safekit-console} * Inicie a consola web num navegador, num dos nós do cluster, ligando-se a `http://localhost:9010`. * Introduza `admin` como nome de utilizador e a palavra-passe definida durante a instalação. Também é possível executar a consola num navegador, numa estação de trabalho externa ao cluster. ⚠️ A configuração do SafeKit é feita em ambos os nós a partir de um único navegador. ℹ️ Para proteger a consola web, consulte 🛠️ [11. Proteção do serviço web SafeKit](/pt-pt/resources/safekit-user-guide-82/#https) no Guia do Utilizador. ![Inicie a consola web SafeKit para configurar o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar os endereços dos nós {#2-configure-node-addresses} * Introduza os endereços IP dos nós, prima a `Tab key` para verificar a conectividade e preencha os nomes dos nós. Se node1 ou node2 tiverem uma cor vermelha, verifique a conectividade do navegador a ambos os nós e verifique a firewall em ambos os nós para 🛠️ [resolução de problemas](/pt-pt/resources/safekit-user-guide-82/#Troubleshooting). * Em seguida, clique em `Save and apply` para guardar a configuração. * Verifique a mensagem `Success` ✅ em ambos os nós. * Se ocorrer uma `Failure` de configuração ❌ num nó, abra o acordeão ▼ desse nó e reveja as mensagens. Tenha em atenção que pode utilizar a IA SafeKit 🤖 para obter assistência. ℹ️ Se desejar, pode adicionar uma nova `LAN and nodes` (primeiro ➕) para criar um segundo heartbeat e uma rede de replicação dedicada. ℹ️ Se clicar em `Advanced configuration`, o ficheiro `cluster.xml` é apresentado. Este ficheiro é preenchido automaticamente pela consola e implementado nos nós. ![Introduza os nós do cluster da {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Selecione um módulo {#3-select-a-module} * No `New module`, clique no módulo `{{ .Get "mod" }}.safe`. ℹ️ No banner azul no topo, `node1` 🛜 representa o nó de ligação da consola. Este nó reencaminha os pedidos para `node2` quando necessário. ℹ️ A consola procura por `xxx.safe` no diretório `Application_Modules/generic/` no nó de ligação (`node1`) se tiver colocado um módulo lá durante a instalação. ![Escolha o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configure o módulo {#4-configure-the-module} * No `Module startup at boot`, escolha o arranque automático do módulo no arranque sem atraso. * Em `Macros`/`SERVICES`, introduza os nomes dos serviços da sua aplicação, pela ordem de inicialização, separados por vírgulas. Consulte esta captura de ecrã para um exemplo visual dos [serviços Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * Nas `Heartbeat networks`, deve ter uma única rede de pulsações na qual a replicação é feita. Se adicionou uma LAN privada no passo 2, pode configurar duas pulsações com o fluxo de replicação na LAN privada. * Em `Virtual IP addresses`, introduza um endereço IP virtual. Um endereço IP virtual é um endereço IP padrão na mesma rede IP (mesma sub-rede) que os endereços IP de ambos os nós. Os clientes da aplicação devem ser configurados com o endereço IP virtual (ou o nome DNS associado ao endereço IP virtual). O endereço IP virtual é automaticamente alterado em caso de falha. * Em `Replicated directories`, defina os caminhos dos diretórios a replicar. Verifique se eles existem em ambos os nós e contêm os dados da aplicação. A replicação de dados e de registos é essencial para uma base de dados. Pode criar diretórios replicados adicionais conforme necessário. Veja esta captura de ecrã para um exemplo visual da [replicação SQL Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * No `Checkers`, poderá configurar os verificadores, se necessário, como monitorização de processos, verificadores personalizados, TCP, ping ou verificadores de divisão de rede. Por exemplo, se um nome de processo for exibido em `Monitored processes/services`, ele será monitorizado com uma ação de reinicialização em caso de falha. A configuração de um nome de processo incorreto fará com que o módulo pare logo após o seu início. ℹ️ Se clicar em `Advanced configuration`, o ficheiro `userconfig.xml` é apresentado. Este ficheiro é preenchido automaticamente pela consola e implementado nos nós com os scripts de reinicialização. ℹ️ Numa implementação em nuvem, não é necessário configurar um endereço IP virtual no SafeKit. O IP virtual é gerido ao [nível do balanceador de carga da nuvem](/pt-pt/resources/safekit-user-guide-82/#Cloud) 🛠️ ℹ️ Ao aplicar a configuração SafeKit, o `startup type` dos serviços é automaticamente definido como `Manual` nos serviços Windows. Isto garante que os serviços não arrancam automaticamente quando o sistema é iniciado, mas são iniciados apenas quando o próprio módulo é iniciado (o mesmo se aplica no Linux). ![Aceda às definições do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. Editar os scripts (opcional) {#5-edit-scripts-optional} * Este passo é opcional e pode ser ignorado na maioria dos casos, uma vez que os scripts de reinicialização já estão pré-configurados para reiniciar os serviços definidos no passo anterior. * Então, clique diretamente em `Next step`. * `start_prim.ps1` inicia todos os serviços na ordem especificada na lista `SERVICES`, enquanto `stop_prim.ps1` para todos os serviços na ordem inversa. * Adicionalmente, `start_prim.ps1` verifica o arranque de cada serviço e para o módulo se algum serviço não arrancar corretamente. ![Aceda às definições do módulo {{ .Get "app" }}](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. Criptografia da comunicação (opcional) {#6-communication-encryption-optional} * Mantenha a encriptação da comunicação entre os nós. ![Criptografia de comunicação do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Guardar e aplicar {#7-save-and-apply} * `Save and apply` a configuração e os scripts em ambos os nós. ![Guarde e aplique a configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verifique se a configuração foi bem-sucedida {#8-verify-successful-configuration} * Verifique a mensagem `Success` ✅ em ambos os nós e clique em `Monitor modules`. * Se ocorrer uma `Failure` de configuração ❌ num nó, abra o acordeão ▼ desse nó e reveja as mensagens. Tenha em atenção que pode utilizar a IA SafeKit 🤖 para obter assistência. ⚠️ No Linux, poderá obter um erro nesta etapa se os diretórios replicados forem pontos de montagem. 🛠️ [Consulte o SK-0030 para resolver o problema](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf). ![Verifique o sucesso da configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Inicie o nó com dados atualizados {#9-start-the-node-with-up-to-date-data} * Se o nó 1 tiver os diretórios replicados atualizados, selecione-o e ⋯ `Force start` ▶ `As primary`. Quando o nó 2 for iniciado, todos os dados serão copiados do nó 1 para o nó 2. ⚠️ Se fizer a escolha errada, corre o risco de sincronizar dados desatualizados em ambos os nós. ⚠️ Também se assume que a aplicação {{ .Get "app" }} está parada no nó 1 para que SafeKit instale os mecanismos de replicação e, em seguida, inicie a aplicação no script `start_prim`. ⚠️ Utilize `Start` para arranques subsequentes: SafeKit mantém o servidor mais atualizado. Iniciar `As primary` é um arranque especial na primeira vez ou durante operações excecionais. ![Inicie como primário o nó {{ .Get "app" }} com os dados atualizados](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Aguarde a transição para ALONE (verde) {#10-wait-for-the-transition-to-alone-green} * O nó 1 deve atingir o estado ALONE (verde), o que significa que o IP virtual está definido e que o script `start_prim` foi executado no nó 1. ⚠️ Se ALONE (verde) não for atingido ou se a aplicação não for iniciada, analise o motivo com o [registo do módulo 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) do nó 1. * Clique no ícone **de registo** 🔍 do `node1` para abrir o registo do módulo e procure mensagens de erro, como um verificador que deteta um erro e para o módulo. * Clique em `start_prim` no registo: as mensagens de saída do script são exibidas à direita e os erros podem ser detetados, como um serviço iniciado incorretamente. * Utilize o SafeKit AI 🤖 para obter assistência com as mensagens de registo. ⚠️ Se o cluster estiver no estado `WAIT (red) not uptodate, STOP (red) not uptodate`, pare o nó WAIT e [force o seu arranque como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![O primeiro nó {{ .Get "app" }} inicia como primário e fica ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. Iniciar o nó 2 {#11-start-node-2} * ⋯ `Start` o nó 2 com o seu menu contextual. * Aguarde o SECOND estado (verde). ℹ️ O nó 2 permanece no SECOND estado (laranja) enquanto resincroniza os diretórios replicados (cópia do nó 1 para o nó 2). * Isto pode demorar algum tempo, dependendo do tamanho dos ficheiros a resincronizar nos diretórios replicados e da largura de banda da rede. * Para ver o progresso da cópia, consulte o [registo do módulo 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) e os [recursos de replicação 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) do nó 2. Utilize a IA SafeKit 🤖 para obter assistência com as mensagens de registo. ![Inicie o nó 2 {{ .Get "app" }}](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 12. Verifique se o cluster está operacional {#12-verify-that-the-cluster-is-operational} * Verifique se o cluster está verde/verde com os serviços {{ .Get "app" }} a serem executados no nó PRIM e não no nó SECOND. Apenas as alterações dentro dos ficheiros são replicadas em tempo real neste estado. ⚠️ Os componentes que são clientes dos serviços {{ .Get "app" }} devem ser configurados com o endereço IP virtual. A configuração pode ser feita com um nome DNS (se um nome DNS tiver sido criado e associado ao endereço IP virtual). ![O nó {{ .Get "app" }} 2 é SECOND (verde)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 13. Testes {#13-testing} * Pare o nó PRIM, percorrendo o menu contextual e clicando em `Stop`. * Verifique se existe um failover no SECOND nó, que deverá ficar ALONE (verde). * E com Microsoft Management Console (MMC) no Windows ou com linhas de comando no Linux, verifique a comutação por falha dos serviços {{ .Get "app" }} (parados no nó 1 no script `stop_prim` e iniciados no nó 2 no script `start_prim`). ⚠️ Se ALONE (verde) não for atingido no node2 ou se a aplicação não for iniciada, analise o motivo com o [registo do módulo 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) do nó 2. * Clique no ícone **de registo** 🔍 do `node2` para abrir o registo do módulo e procure mensagens de erro, como um verificador que deteta um erro e para o módulo. * Clique em `start_prim` no registo: as mensagens de saída do script são exibidas à direita e os erros podem ser detetados, como um serviço iniciado incorretamente. * Utilize o SafeKit AI 🤖 para obter assistência com as mensagens de registo. ⚠️ * Se tudo estiver bem, inicie o node1, que irá ressincronizar os diretórios replicados do node2. * Se as coisas correrem mal, pare node2 e [force o nó 1 a iniciar como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png), que será reiniciado com os seus dados localmente íntegros no momento da paragem. ℹ️ Encontre mais detalhes, juntamente com vídeos, no [Treinamento Online SafeKit](/pt-pt/resources/safekit-on-line-training/). ![Parar o módulo {{ .Get "app" }} no servidor PRIM](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 14. Apoio {#14-support} * Para obter suporte, faça 2 `Snapshots` SafeKit (2 ficheiros .zip), uma para cada nó. ℹ️ [Mais informações sobre o apoio aqui](/pt-pt/resources/safekit-support/). ![Tire capturas de ecrã da {{ .Get "app" }} para obter suporte](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
