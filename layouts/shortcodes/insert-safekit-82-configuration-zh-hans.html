{{/* Shortcode: insert-safekit-82-configuration-zh-hans */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-oracle.md */}} ### 先决条件 * {{ .Get "app" }} 应用程序安装在 2 个节点上。 * 总复制数据限制为几 TB — 除此之外，重新同步时间变得很重要。 * 节点之间至少 1Gb/s 互连（建议使用 10Gb/s 以加快重新同步速度）。 * IP 故障转移需要同一 LAN 或扩展 LAN (L2) 上的两个节点 — 不支持路由 L3 网络（🛠️ 除外） [云负载均衡器](/resources/safekit-user-guide-82/#Cloud)). ### 1.启动SafeKit控制台 * 通过连接到在一个集群节点上的浏览器中启动 Web 控制台 `http://localhost:9010`. * 输入 `admin` 作为安装期间定义的用户名和密码。 您还可以在集群外部工作站上的浏览器中运行控制台。 ⚠️ SafeKit 的配置是通过单个浏览器在两个节点上完成的。 ℹ️ 要保护 Web 控制台的安全，请参阅 🛠️ [11\.保护 SafeKit Web 服务的安全](/resources/safekit-user-guide-82/#https) 在用户指南中。 ![启动 SafeKit Web 控制台来配置 {{ .Get "app" }} 集群](/wp-content/uploads/2024/03/01-login-large.png) ### 2.配置节点地址 * 输入节点IP地址，按 `Tab key` 检查连接性并填写节点名称。如果 node1 或 node2 为红色，请检查浏览器与两个节点的连接，并检查两个节点上的防火墙是否有🛠️ [故障排除](/resources/safekit-user-guide-82/#Troubleshooting). * 然后，单击 `Save and apply` 保存配置。 * 检查 `Success` ✅ 两个节点上的消息。 * 如果配置 `Failure` ❌ 发生在一个节点上，打开该节点的 ▼ 折叠面板并查看消息。请注意，您可以使用 SafeKit AI 🤖 寻求帮助。 ℹ️如果你愿意，你可以添加一个新的 `LAN and nodes` （第一个 ➕）创建第二个心跳和专用复制网络。 ℹ️如果你点击 `Advanced configuration`, 的 `cluster.xml` 显示文件。该文件由控制台自动填充并部署在节点上。 ![输入{{ .Get "app" }}集群的节点](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. 选择模块 * 在 `New module`，单击 `{{ .Get "mod" }}.safe` 模块。 ℹ️ 在顶部的蓝色横幅中，🛜 `node1` 代表控制台连接节点。该节点将请求转发到 `node2` 当需要时。 ℹ️ 控制台寻找 `xxx.safe` 在 `Application_Modules/generic/` 连接节点上的目录（`node1`）如果您在安装过程中放置了一个模块。 ![选择{{ .Get "app" }}的模块](/wp-content/uploads/2024/03/04-module-new.png) ### 4. 配置模块 * 在 `Module startup at boot`，选择开机时自动启动模块，无延迟。 * 在 `Macros` / `SERVICES`，按启动顺序输入应用程序的服务名称，以逗号分隔。请参阅此屏幕截图以获取直观示例 [Milestone XProtect 服务🖼️](/wp-content/uploads/2025/05/milestone-services.png). * 在 `Heartbeat networks`，您应该有一个用于进行复制的心跳网络。如果您在步骤 2 中添加了专用 LAN，则可以在专用 LAN 上使用复制流配置两个心跳。 * 在 `Virtual IP addresses`，输入虚拟 IP 地址。一个虚拟的 IP 地址是一个标准 IP 地址在同一个 IP 网络（同一子网）作为 IP 两个节点的地址。 应用程序客户端必须配置虚拟 IP 地址（或 DNS 与虚拟关联的名称 IP 地址）。 虚拟IP地址发生故障时自动切换。 * 在 `Replicated directories`，设置要复制的目录的路径。检查它们是否存在于两个节点上并包含应用程序数据。 数据和日志复制对于数据库至关重要。 您可以根据需要创建其他复制目录。 请参阅此屏幕截图以获取直观示例 [Milestone XProtect SQL 复制 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * 在 `Checkers`，您将能够根据需要配置检查器，例如进程监控、自定义检查器、TCP、ping 或裂脑检查器。 例如，如果进程名称显示在 `Monitored processes/services`，如果发生故障，将通过重新启动操作进行监视。配置错误的进程名称将导致模块启动后立即停止。 ℹ️如果你点击 `Advanced configuration`, 的 `userconfig.xml` 显示文件。该文件由控制台自动填充，并使用重新启动脚本部署在节点上。 ℹ️ 在云部署中，您不需要配置虚拟 IP 地址在 SafeKit。虚拟的 IP 由 🛠️ 管理 [云负载均衡器级别](/resources/safekit-user-guide-82/#Cloud). ℹ️ 当您应用 SafeKit 配置时， `startup type` 服务的数量自动设置为 `Manual` 在Windows服务中。这样可以确保服务不会在系统启动时自动启动，而是仅在模块本身启动时启动（Linux 也是如此）。 ![输入{{ .Get "app" }}模块设置](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. 编辑脚本（可选） * 此步骤是可选的，在大多数情况下可以跳过，因为重新启动脚本已预先配置为重新启动上一步中定义的服务。 * 所以，直接点击 `Next step`. * `start_prim.ps1` 按照指定的顺序启动所有服务 `SERVICES` 列出，同时 `stop_prim.ps1` 按相反顺序停止所有服务。 * 另外， `start_prim.ps1` 检查每个服务的启动情况，如果有服务无法正常启动，则停止该模块。 ![输入{{ .Get "app" }}模块设置](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6.通讯加密（可选） * 保持节点之间的通信加密。 ![{{ .Get "app" }}模块的通信加密](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7.保存并应用 * `Save and apply` 两个节点上的配置和脚本。 ![保存并应用 {{ .Get "app" }} 模块配置](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8.验证配置成功 * 检查 `Success` ✅ 在两个节点上发送消息并点击 `Monitor modules`. * 如果配置 `Failure` ❌ 发生在一个节点上，打开该节点的 ▼ 折叠面板并查看消息。请注意，您可以使用 SafeKit AI 🤖 寻求帮助。 ⚠️在Linux上，如果复制的目录是挂载点，这一步可能会报错。🛠️ [参见SK-0030解决问题](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf). ![检查{{ .Get "app" }}模块配置是否成功](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. 使用最新数据启动节点 * 如果节点 1 具有最新的复制目录，请选择它并⋯ `Force start` ▶ `As primary`. 当节点2启动时，所有数据将从节点1复制到节点2。 ⚠️ 如果您做出错误的选择，您将面临在两个节点上同步过时数据的风险。 ⚠️ 还假设 {{ .Get "app" }} 应用程序在节点 1 上停止，以便 SafeKit 安装复制机制，然后在节点 1 中启动应用程序 `start_prim` 脚本。 ⚠️使用 `Start` 对于后续启动：SafeKit 保留最新的服务器。开始 `As primary` 是第一次或特殊操作期间的特殊启动。 ![使用最新数据作为主节点启动 {{ .Get "app" }}](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10.等待过渡到ALONE（绿色） * 节点 1 应达到 ALONE（绿色）状态，这意味着虚拟 IP 已设置并且 `start_prim` 脚本已在节点 1 上执行。 ⚠️如果未达到ALONE（绿色）或应用程序未启动，请使用以下命令分析原因 [模块日志🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) 节点 1 的。 * 点击🔍 **日志** 的图标 `node1` 打开模块日志并查找错误消息，例如检查器检测到错误并停止模块。 * 点击 `start_prim` 日志中：右侧显示脚本的输出消息，可以检测到服务错误启动等错误。 * 使用 SafeKit AI 🤖 获取日志消息方面的帮助。 ⚠️如果集群在 `WAIT (red) not uptodate, STOP (red) not uptodate` 状态，停止 WAIT 节点并 [强制其作为主要启动 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![第一个 {{ .Get "app" }} 节点作为主节点启动并成为 ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11.启动节点2 * ⋯ `Start` 节点 2 及其上下文菜单。 * 等待 SECOND（绿色）状态。 ℹ️ 节点 2 保持 SECOND（橙色）状态，同时重新同步复制的目录（从节点 1 复制到节点 2）。 * 这可能需要一段时间，具体取决于复制目录中要重新同步的文件大小和网络带宽。 * 要查看复制进度，请参阅 [模块日志🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) 和 [复制资源🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) 节点 2 的。使用 SafeKit AI 🤖 获取日志消息帮助。 ![启动{{ .Get "app" }}节点2](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 12. 验证集群是否正常运行 * 检查集群是否为绿色/绿色，其中 {{ .Get "app" }} 服务在 PRIM 节点上运行，而不在 SECOND 节点上运行。 在此状态下，仅实时复制文件内部的更改。 ⚠️ 作为 {{ .Get "app" }} 服务客户端的组件必须配置虚拟 IP 地址。可以使用 DNS 名称完成配置（如果已创建 DNS 名称并与虚拟 IP 地址关联）。 ![{{ .Get "app" }} 节点 2 是 SECOND（绿色）](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 13. 测试 * 通过向下滚动其上下文菜单并单击来停止 PRIM 节点 `Stop`. * 验证 SECOND 节点上是否存在故障转移，该节点应变为 ALONE（绿色）。 * 并使用 Microsoft 管理控制台 (MMC) 上 Windows 或使用命令行 Linux，检查故障转移 {{ .Get "app" }} 服务（在节点 1 上停止） `stop_prim` 脚本并在节点 2 上启动 `start_prim` 脚本）。 ⚠️如果 ALONE （绿色）未达到 node2 或者如果应用程序未启动，请使用以下命令分析原因 [模块日志🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) 节点 2 的。 * 点击🔍 **日志** 的图标 `node2` 打开模块日志并查找错误消息，例如检查器检测到错误并停止模块。 * 点击 `start_prim` 日志中：右侧显示脚本的输出消息，可以检测到服务错误启动等错误。 * 使用 SafeKit AI 🤖 获取日志消息方面的帮助。 ⚠️ * 如果一切正常，则启动 node1，这将重新同步 node2 的复制目录。 * 如果出现问题，停止 node2 并 [强制启动作为主要🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) node1，它将以其停止时的本地健康数据重新启动。 ℹ️ 在以下位置查找更多详细信息以及视频 [SafeKit 在线培训](/resources/safekit-on-line-training/). ![停止 {{ .Get "app" }} 模块上的 PRIM 服务器](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 14. 支持 * 要获得支持，请获取 2 SafeKit `Snapshots` （2 个 .zip 文件），每个节点一个。 ℹ️ [有关支持的更多信息请参见此处](/resources/safekit-support/). ![拍摄 {{ .Get "app" }} 快照以获取支持](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
