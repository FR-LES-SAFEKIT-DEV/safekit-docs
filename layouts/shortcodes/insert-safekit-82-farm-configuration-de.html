{{/* Shortcode: insert-safekit-82-farm-configuration-de — 9 instances in 9 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-network-load-balancing-and-failover.md */}} ### Voraussetzungen * Die Anwendung {{ .Get "app" }} ist auf mindestens zwei Knoten installiert. * Für den virtuellen IP-Lastausgleich müssen sich die Knoten im selben LAN oder in einem erweiterten LAN (L2) befinden — geroutete L3-Netzwerke werden nicht unterstützt (außer mit 🛠️ [Cloud-Load-Balancern](/de/resources/safekit-user-guide-82/#Cloud)). ### 1. SafeKit-Konsole starten * Starten Sie die Webkonsole in einem Browser auf einem Clusterknoten, indem Sie eine Verbindung zu `http://localhost:9010` herstellen. * Geben Sie `admin` als Benutzernamen und das während der Installation festgelegte Passwort ein. Sie können die Konsole auch in einem Browser auf einer Workstation außerhalb des Clusters ausführen. ⚠️ Die SafeKit-Konfiguration erfolgt auf beiden Knoten über einen einzigen Browser. ℹ️ Informationen zum Absichern der Webkonsole finden Sie im Benutzerhandbuch unter 🛠️ [11\. SafeKit-Webdienst absichern](/de/resources/safekit-user-guide-82/#https). ![SafeKit-Webkonsole starten, um den {{ .Get "app" }}-Cluster zu konfigurieren](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Knotenadressen konfigurieren * Geben Sie die IP-Adressen der Knoten ein, drücken Sie `Tab key`, um die Verbindung zu prüfen, und geben Sie die Knotennamen ein. Wenn node1 oder node2 rot angezeigt wird, prüfen Sie die Verbindung des Browsers zu beiden Knoten und die Firewalls auf beiden Knoten; weitere Hinweise finden Sie unter 🛠️ [Fehlerbehebung](/de/resources/safekit-user-guide-82/#Troubleshooting). * Klicken Sie anschließend auf `Save and apply`, um die Konfiguration zu speichern. * Prüfen Sie die Meldung `Success` ✅ auf beiden Knoten. * Tritt bei der Konfiguration auf einem Knoten `Failure` ❌ auf, öffnen Sie das ▼-Akkordeon dieses Knotens und prüfen Sie die Meldungen. Bei Bedarf können Sie SafeKit AI 🤖 um Hilfe bitten. ℹ️ Bei Bedarf können Sie ein neues `LAN and nodes` (erstes ➕) hinzufügen, um einen zweiten Heartbeat und ein dediziertes Replikationsnetzwerk einzurichten. ℹ️ Wenn Sie auf `Advanced configuration` klicken, wird die Datei `cluster.xml` angezeigt. Die Konsole füllt diese Datei automatisch aus und stellt sie auf den Knoten bereit. ![Knoten des {{ .Get "app" }}-Clusters eingeben](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Modul auswählen * Klicken Sie unter `New module` auf das Modul `{{ .Get "mod" }}.safe`. ℹ️ Im blauen Banner oben steht 🛜 `node1` für den Knoten, mit dem die Konsole verbunden ist. Dieser Knoten leitet Anfragen bei Bedarf an `node2` weiter. ℹ️ Die Konsole sucht nach `xxx.safe` im Verzeichnis `Application_Modules/generic/` auf dem Verbindungsknoten (`node1`), sofern Sie während der Installation dort ein Modul abgelegt haben. ![Modul für {{ .Get "app" }} auswählen](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Modul konfigurieren * Wählen Sie unter `Module startup at boot` den automatischen und verzögerungsfreien Modulstart beim Systemstart aus. * Geben Sie unter `Macros` / `SERVICES` die Namen der Anwendungsdienste in Startreihenfolge und durch Kommas getrennt ein. * Unter `Heartbeat networks` sollte ein einzelnes Heartbeat-Netzwerk vorhanden sein, sofern Sie in Schritt 2 kein LAN hinzugefügt haben. * Geben Sie unter `Virtual IP addresses` eine virtuelle IP-Adresse ein. Eine virtuelle IP-Adresse ist eine normale IP-Adresse im selben IP-Netzwerk (Subnetz) wie die IP-Adressen beider Knoten. Anwendungclients müssen für die virtuelle IP-Adresse (oder den zugehörigen DNS-Namen) konfiguriert werden. * Legen Sie unter `Load balancing rules` den auszugleichenden Dienstport fest (z. B. TCP 9010 im Beispiel). * Legen Sie unter `Load balancing rules` die Lastverteilungsregel `Source address` oder `Source port` fest: * Bei Verwendung der Quell-IP-Adresse des Clients wird derselbe Client über mehrere TCP-Sitzungen mit demselben Knoten in der `farm` verbunden und kann seinen Kontext auf diesem Knoten abrufen. * Bei Verwendung des TCP-Quellports des Clients wird derselbe Client über mehrere TCP-Sitzungen mit verschiedenen Knoten in der `farm` verbunden (ohne einen Kontext abzurufen). * Unter `Checkers` können Sie bei Bedarf Prüfmechanismen konfigurieren, etwa Prozessüberwachung, benutzerdefinierte Prüfungen, TCP-, Ping- oder Split-Brain-Prüfungen. Wird beispielsweise ein Prozessname unter `Monitored processes/services` angezeigt, wird der Prozess überwacht und bei einem Fehler neu gestartet. Ein falscher Prozessname führt dazu, dass das Modul direkt nach dem Start beendet wird. ℹ️ Wenn Sie auf `Advanced configuration` klicken, wird die Datei `userconfig.xml` angezeigt. Die Konsole füllt diese Datei automatisch aus und stellt sie zusammen mit den Neustartskripten auf den Knoten bereit. ℹ️ Bei einer Cloud-Bereitstellung müssen Sie keine virtuelle IP-Adresse und keine Lastverteilungsregeln in SafeKit konfigurieren. Die virtuelle IP-Adresse und die Lastverteilungsregeln werden auf Ebene des 🛠️ [Cloud-Load-Balancers](/de/resources/safekit-user-guide-82/#Cloud) verwaltet. ℹ️ Beim Anwenden der SafeKit-Konfiguration wird der `startup type` der Dienste in den Windows-Diensten automatisch auf `Manual` gesetzt. So werden die Dienste beim Systemstart nicht automatisch, sondern erst beim Start des Moduls gestartet (dies gilt auch für Linux). ![Einstellungen des {{ .Get "app" }}-Moduls `farm` eingeben](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Skripte bearbeiten (optional) * Dieser Schritt ist optional und kann meistens übersprungen werden, da die Neustartskripte bereits für den Neustart der im vorherigen Schritt festgelegten Dienste konfiguriert sind. * Klicken Sie direkt auf `Next step`. * `start_both.ps1` startet alle Dienste in der Reihenfolge der Liste `SERVICES`, während `stop_both.ps1` alle Dienste in umgekehrter Reihenfolge stoppt. * Außerdem prüft `start_both.ps1`, ob jeder Dienst startet, und stoppt das Modul, wenn ein Dienst nicht korrekt gestartet werden kann. ![Einstellungen des {{ .Get "app" }}-Moduls eingeben](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Kommunikationsverschlüsselung (optional) * Lassen Sie die Kommunikation zwischen den Knoten verschlüsselt. ![Kommunikationsverschlüsselung des {{ .Get "app" }}-Moduls](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Speichern und anwenden * Wenden Sie mit `Save and apply` die Konfiguration und Skripte auf beiden Knoten an. ![Konfiguration des {{ .Get "app" }}-Moduls speichern und anwenden](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Erfolgreiche Konfiguration überprüfen * Prüfen Sie die Meldung `Success` ✅ auf beiden Knoten und klicken Sie auf `Monitor modules`. * Tritt bei der Konfiguration auf einem Knoten `Failure` ❌ auf, öffnen Sie das ▼-Akkordeon dieses Knotens und prüfen Sie die Meldungen. Bei Bedarf können Sie SafeKit AI 🤖 um Hilfe bitten. ![Erfolgreiche Konfiguration des {{ .Get "app" }}-Moduls überprüfen](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Den `farm`-Cluster auf Knoten 1 und Knoten 2 starten * Klicken Sie wie in der Abbildung gezeigt auf ⋯ `Start`, um den `farm`-Cluster zu starten. ![{{ .Get "app" }}-Cluster auf beiden Knoten starten](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Warten, bis beide Knoten UP (grün) anzeigen Knoten 1 und Knoten 2 sollten den Zustand UP (grün) erreichen. Das bedeutet, dass das Skript `start_both` auf beiden Knoten ausgeführt wurde. ⚠️ Wird UP (grün) nicht erreicht oder startet die Anwendung nicht, untersuchen Sie die Ursache anhand des [Modulprotokolls 🖼️](/wp-content/uploads/2024/03/37-module-log-farm-script.png) von Knoten 1 oder Knoten 2. * Klicken Sie auf das 🔍-Symbol **log** für `node1` oder `node2`, um das Modulprotokoll zu öffnen und nach Fehlermeldungen zu suchen, etwa nach einer Prüfung, die einen Fehler erkennt und das Modul stoppt. * Klicken Sie im Protokoll auf `start_both`: Die Ausgaben des Skripts erscheinen rechts. Dort lassen sich beispielsweise Fehler beim Starten eines Dienstes erkennen. * Verwenden Sie SafeKit AI 🤖, um Hilfe zu den Protokollmeldungen zu erhalten. ℹ️ Eine 🕒 **[Zeitleiste 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** kann hilfreich sein, um die Vorgänge im Cluster nachzuvollziehen. ![Der {{ .Get "app" }}-Cluster ist gestartet](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. Testen SafeKit enthält einen integrierten Produkttest: * Konfigurieren Sie eine Regel für TCP-Port 9010 mit Lastverteilung nach TCP-Quellport. * Verbinden Sie eine externe Workstation außerhalb der `farm`-Knoten. * Öffnen Sie einen Browser unter http://virtual-ip:9010/safekit/mosaic.html. Je nach Knoten, die auf HTTP-Anfragen antworten, sollte ein Mosaik aus Farben angezeigt werden. * Stoppen Sie einen Knoten im Zustand UP (grün), indem Sie im Kontextmenü nach unten scrollen und auf Stop klicken. * Prüfen Sie, ob auf dem gestoppten Knoten und der virtuellen IP-Adresse keine TCP-Verbindungen mehr bestehen. ℹ️ Weitere Informationen und Videos finden Sie in der [SafeKit-Online-Schulung](/de/resources/safekit-on-line-training/). ![Virtuelle IP-Adresse von {{ .Get "app" }} mit dem Mosaik testen](/wp-content/uploads/2024/03/appli-19.png) ### 12. Support * Erstellen Sie für den Support zwei SafeKit-`Snapshots` (zwei .zip-Dateien), einen für jeden Knoten. ℹ️ [Weitere Informationen zum Support finden Sie hier](/de/resources/safekit-support/). ![{{ .Get "app" }}-Snapshots für den Support erstellen](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
