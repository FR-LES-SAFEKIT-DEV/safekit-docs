Geroutete Layer-3-Netzwerke erfordern 🛠️ [Cloud-Load-Balancer ](/resources/safekit-user-guide-82/#Cloud) . ### 1. Starten Sie die SafeKit Konsole. * Öffnen Sie auf einem Clusterknoten einen Browser und stellen Sie eine Verbindung zu `http://localhost:9010` . * Melden Sie sich mit dem Benutzernamen `admin` und dem während der Installation festgelegten Passwort an. Sie können die Konsole auch von einer Workstation außerhalb des Clusters aus öffnen. ⚠️ Verwenden Sie einen einzigen Browser, um beide Knoten mit SafeKit zu konfigurieren. ℹ️ Informationen zur Sicherung der Webkonsole finden Sie unter 🛠️ [11. Absicherung des SafeKit -Webdienstes ](/resources/safekit-user-guide-82/#https) im Benutzerhandbuch. ![ SafeKit Webkonsole für den {{ .Get "app" }} Cluster ](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Knotenadressen konfigurieren * Geben Sie die IP Adresse jedes Knotens ein. Drücken Sie die Tabulatortaste, um die Verbindung zu überprüfen und die Knotennamen einzugeben. * Wenn `node1` oder `node2` rot angezeigt wird, überprüfen Sie, ob der Browser beide Knoten erreichen kann. Überprüfen Sie die Firewall auf jedem Knoten. Siehe 🛠️ [Fehlerbehebung ](/resources/safekit-user-guide-82/#Troubleshooting) . * Klicken Sie auf `Save and apply` um die Konfiguration zu speichern. * Prüfen Sie, ob auf beiden Knoten ✅ `Success` angezeigt wird. * Wenn ein Knoten die Meldung „❌ `Failure` anzeigt, öffnen Sie sein ▼-Fenster und lesen Sie die Meldungen. Nutzen Sie die SafeKit -KI 🤖, falls Sie Hilfe benötigen. ℹ️ Um ein zweites Heartbeat-Netzwerk und ein dediziertes Replikationsnetzwerk hinzuzufügen, klicken Sie auf die erste ➕-Schaltfläche unter `LAN and nodes` . ℹ️ Klicken Sie auf `Advanced configuration` , um die Datei `cluster.xml` anzuzeigen. Die Konsole füllt diese Datei aus und stellt sie auf beiden Knoten bereit. ![Knotenadressen für den {{ .Get "app" }} Cluster ](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Wählen Sie ein Modul aus * Im Menü `New module` “ wählen Sie das Modul `{{ .Get "mod" }}.safe` . ℹ️ Im blauen Banner ist 🛜 `node1` der mit der Konsole verbundene Knoten. Er leitet Anfragen bei Bedarf an `node2` weiter. ℹ️ Wenn Sie während der Installation eine Moduldatei `xxx.safe` hinzugefügt haben, sucht die Konsole auf `node1` im Verzeichnis `Application_Modules/generic/` danach. ![Wähle das Modul für {{ .Get "app" }} ](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Modul konfigurieren * Unter `Module startup at boot` können Sie festlegen, dass das Modul beim Systemstart automatisch und ohne Verzögerung gestartet wird. * Unter `Macros` / `SERVICES` listen Sie die Anwendungsdienste in der Reihenfolge ihres Starts auf. Trennen Sie die Namen durch Kommas. * Bei `Heartbeat networks` sollte nur ein Heartbeat-Netzwerk verwendet werden, es sei denn, in Schritt 2 wurde ein LAN hinzugefügt. * Geben Sie unter `Virtual IP addresses` eine virtuelle IP -Adresse im selben Subnetz wie beide Knoten ein. * Konfigurieren Sie die Anwendungsclients so, dass sie diese virtuelle IP Adresse oder ihren DNS Namen verwenden. * Geben Sie unter `Load balancing rules` den zu verteilenden Dienstport ein, z. B. TCP Port 9010. * Wählen Sie unter `Load balancing rules` `Source address` oder `Source port` aus: * `Source address` : Alle TCP Verbindungen desselben Clients werden an denselben Knoten in der farm geleitet. Dadurch bleibt der Sitzungskontext des Clients auf diesem Knoten erhalten. * `Source port` : TCP Verbindungen vom selben Client können zu verschiedenen Knoten in der farm geleitet werden. Der Sitzungskontext wird nicht zwischen den Knoten geteilt. * Fügen Sie in `Checkers` bei Bedarf weitere Prüfungen hinzu: Prozessüberwachung, benutzerdefinierte Prüfungen, TCP , Ping- oder Split-Brain-Prüfungen. * Ein in der Liste `Monitored processes/services` aufgeführter Prozess wird überwacht und bei einem Fehler neu gestartet. Ein falscher Prozessname führt dazu, dass das Modul unmittelbar nach dem Start beendet wird. ℹ️ Klicken Sie auf `Advanced configuration` , um die Datei `userconfig.xml` anzuzeigen. Die Konsole füllt diese Datei aus und stellt sie zusammen mit den Neustartskripten auf beiden Knoten bereit. ℹ️ In einer Cloud-Bereitstellung verwaltet der 🛠️ [Cloud Load Balancer ](/resources/safekit-user-guide-82/#Cloud) die virtuelle IP Adresse und die Load-Balancing-Regeln. Konfigurieren Sie diese nicht in SafeKit . ℹ️ Bei der Konfiguration stellt SafeKit den Windows Dienststarttyp auf `Manual` ein. Die Dienste starten mit dem Modul, nicht beim Systemstart. SafeKit verhindert auch unter Linux , dass diese Dienste beim Systemstart gestartet werden. ![Moduleinstellungen für die {{ .Get "app" }} farm ](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Skripte bearbeiten (optional) * In den meisten Fällen können Sie diesen Schritt überspringen. Die Skripte sind bereits so konfiguriert, dass sie die im vorherigen Schritt aufgeführten Dienste neu starten. * Klicken Sie auf `Next step` , wenn keine Änderungen erforderlich sind. * Das Skript `start_both.ps1` startet die Dienste in der Reihenfolge der Liste `SERVICES` . * Das Skript `stop_both.ps1` stoppt die Dienste in umgekehrter Reihenfolge. * Das Skript `start_both.ps1` überprüft ebenfalls jeden Dienst. Es stoppt das Modul, falls ein Dienst nicht gestartet werden kann. ![Neustart-Skripte für das Modul {{ .Get "app" }} ](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Kommunikationsverschlüsselung (optional) * Die Kommunikationsverschlüsselung zwischen den Knoten muss aktiviert bleiben. ![Kommunikationsverschlüsselung für das {{ .Get "app" }} Modul ](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Speichern und anwenden * Klicken Sie auf `Save and apply` , um die Konfiguration und die Skripte auf beiden Knoten bereitzustellen. ![Konfigurationsbereitstellung für das {{ .Get "app" }} Modul ](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Überprüfen Sie das Konfigurationsergebnis. * Prüfen Sie, ob auf beiden Knoten ✅ `Success` angezeigt wird. Klicken Sie anschließend auf `Monitor modules` . * Wenn ein Knoten die Meldung „❌ `Failure` anzeigt, öffnen Sie sein ▼-Fenster und lesen Sie die Meldungen. Nutzen Sie die SafeKit -KI 🤖, falls Sie Hilfe benötigen. ![Konfigurationsergebnis für das Modul {{ .Get "app" }} ](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Starten Sie den farm auf Knoten 1 und Knoten 2. * Öffnen Sie das ⋯-Menü und wählen Sie auf beiden Knoten `Start` , wie in der Abbildung gezeigt. ![Starten Sie den {{ .Get "app" }} Cluster auf beiden Knoten ](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Warten Sie, bis beide Knoten `UP` (grün) sind.

Beide Knoten müssen den Status UP (grün) erreichen. Dies bedeutet, dass das Skript start_both auf beiden Knoten ausgeführt wurde.

⚠️ Falls ein Knoten UP (grün) nicht erreicht oder die Anwendung nicht startet, überprüfen Sie das Modulprotokoll 🖼️ .

* Klicken Sie auf das 🔍-Symbol für `node1` oder `node2` , um das Modulprotokoll zu öffnen. Suchen Sie nach Fehlern, z. B. nach einer Prüfung, die das Modul gestoppt hat. * Klicken Sie im Protokoll auf `start_both` . Die Skriptausgabe wird rechts angezeigt. Prüfen Sie, ob beim Start des Dienstes Fehler aufgetreten sind. * Nutzen Sie die SafeKit -KI 🤖, um Hilfe bei Protokollmeldungen zu erhalten. ℹ️ Verwenden Sie die 🕒 ** [timeline 🖼️ ](/wp-content/uploads/2026/05/safekit-console-timeline.png) ** um die Abfolge der Ereignisse im Cluster zu verstehen. ![Beide Knoten des {{ .Get "app" }} Clusters laufen ](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11.
