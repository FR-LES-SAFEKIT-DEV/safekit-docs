{{/* Shortcode: insert-safekit-82-farm-configuration-en — 9 instances in 9 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-network-load-balancing-and-failover.md */}} ### Prerequisites * Install {{ .Get "app" }} on at least 2 nodes. * For virtual IP load balancing, all nodes must be on the same LAN or extended LAN (layer 2). Routed layer 3 networks require 🛠️ [cloud load balancers](/resources/safekit-user-guide-82/#Cloud). ### 1. Launch the SafeKit console * On one cluster node, open a browser and connect to `http://localhost:9010`. * Sign in with the user name `admin` and the password set during installation. You can also open the console from a workstation outside the cluster. ⚠️ Use a single browser to configure both nodes with SafeKit. ℹ️ To secure the web console, see 🛠️ [11\. Securing the SafeKit web service](/resources/safekit-user-guide-82/#https) in the User's Guide. ![SafeKit web console for the {{ .Get "app" }} cluster](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configure node addresses * Enter the IP address of each node. Press the Tab key to check the connection and fill in the node names. * If `node1` or `node2` is red, check that the browser can reach both nodes. Check the firewall on each node. See 🛠️ [troubleshooting](/resources/safekit-user-guide-82/#Troubleshooting). * Click `Save and apply` to save the configuration. * Check that both nodes display ✅ `Success`. * If a node displays ❌ `Failure`, expand its ▼ panel and read the messages. Use the SafeKit AI 🤖 if you need help. ℹ️ To add a second heartbeat network and a dedicated replication network, click the first ➕ button in `LAN and nodes`. ℹ️ Click `Advanced configuration` to view the file `cluster.xml`. The console fills in this file and deploys it on both nodes. ![Node addresses for the {{ .Get "app" }} cluster](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Select a module * In `New module`, select the module `{{ .Get "mod" }}.safe`. ℹ️ In the blue banner, 🛜 `node1` is the node connected to the console. It forwards requests to `node2` when needed. ℹ️ If you added a module file `xxx.safe` during installation, the console looks for it in the directory `Application_Modules/generic/` on `node1`. ![Choose the module for {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configure the module * In `Module startup at boot`, set the module to start automatically at boot, without delay. * In `Macros` / `SERVICES`, list the application services in startup order. Separate the names with commas. * In `Heartbeat networks`, keep one heartbeat network unless you added a LAN in step 2. * In `Virtual IP addresses`, enter a virtual IP address in the same subnet as both nodes. * Configure application clients to use this virtual IP address or its DNS name. * In `Load balancing rules`, enter the service port to balance, for example TCP port 9010. * In `Load balancing rules`, select `Source address` or `Source port`: * `Source address`: all TCP connections from the same client go to the same node in the farm. This preserves the client's session context on that node. * `Source port`: TCP connections from the same client can go to different nodes in the farm. Session context is not shared between nodes. * In `Checkers`, add checks if needed: process monitoring, custom checks, TCP, ping, or split-brain checks. * A process listed in `Monitored processes/services` is monitored and restarted if it fails. An incorrect process name causes the module to stop immediately after startup. ℹ️ Click `Advanced configuration` to view the file `userconfig.xml`. The console fills in this file and deploys it on both nodes with the restart scripts. ℹ️ In a cloud deployment, the 🛠️ [cloud load balancer](/resources/safekit-user-guide-82/#Cloud) manages the virtual IP address and load balancing rules. Do not configure them in SafeKit. ℹ️ When you apply the configuration, SafeKit sets the Windows service startup type to `Manual`. Services start with the module, not at system boot. SafeKit also prevents these services from starting at system boot on Linux. ![Module settings for the {{ .Get "app" }} farm](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Edit scripts (optional) * In most cases, you can skip this step. The scripts are already configured to restart the services listed in the previous step. * Click `Next step` if no changes are needed. * The script `start_both.ps1` starts services in the order of the list `SERVICES`. * The script `stop_both.ps1` stops services in reverse order. * The script `start_both.ps1` also checks each service. It stops the module if a service fails to start. ![Restart scripts for the {{ .Get "app" }} module](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Communication encryption (optional) * Keep communication encryption enabled between nodes. ![Communication encryption for the {{ .Get "app" }} module](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Save and apply * Click `Save and apply` to deploy the configuration and scripts on both nodes. ![Configuration deployment for the {{ .Get "app" }} module](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Check the configuration result * Check that both nodes display ✅ `Success`. Then click `Monitor modules`. * If a node displays ❌ `Failure`, expand its ▼ panel and read the messages. Use the SafeKit AI 🤖 if you need help. ![Configuration result for the {{ .Get "app" }} module](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Start the farm cluster on node 1 and node 2 * Open the ⋯ menu and select `Start` on both nodes, as shown in the image. ![Start the {{ .Get "app" }} cluster on both nodes](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Wait until both nodes are `UP` (green)

Both nodes must reach the state UP (green). This means that the script start_both has run on both nodes.

⚠️ If a node does not reach UP (green), or if the application does not start, check its module log 🖼️.

* Click the 🔍 icon for `node1` or `node2` to open the module log. Look for errors, such as a check that stopped the module. * In the log, click `start_both`. The script output appears on the right. Check for service startup errors. * Use the SafeKit AI 🤖 for help with log messages. ℹ️ Use the 🕒 **[timeline 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** to understand the sequence of events in the cluster. ![Both nodes of the {{ .Get "app" }} cluster are running](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. Testing SafeKit includes a built-in mosaic test. See [Testing the load balancing virtual IP address in a SafeKit farm cluster](/best-practises/test-load-balancing-vip-farm/). ![Test the virtual IP address of {{ .Get "app" }} with the mosaic](/wp-content/uploads/2024/03/appli-19.png) ℹ️ See the [SafeKit Online Training](/resources/safekit-on-line-training/) for more details and videos. ### 12. Support * For support, create one SafeKit `Snapshot` per node. Collect the 2 .zip files. ℹ️ See [SafeKit Support](/resources/safekit-support/) for more information. ![Support snapshots for the {{ .Get "app" }} cluster](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
