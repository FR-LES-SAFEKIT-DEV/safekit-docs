Lancez le SafeKit console * Lancez la console Web dans un navigateur sur un nœud du cluster en vous connectant à `http://localhost:9010`. * Entrer `admin` comme nom d'utilisateur et mot de passe définis lors de l'installation. Vous pouvez également exécuter la console dans un navigateur sur un poste de travail externe au cluster. ⚠️ La configuration de SafeKit L'opération est effectuée sur les deux nœuds à partir d'un seul navigateur. ℹ️ Pour sécuriser la console Web, voir 🛠️ [11. Sécuriser le SafeKit service web](/resources/safekit-user-guide-82/#https) dans le Guide de l'utilisateur. ![Commencez le SafeKit console web pour configurer la {{ .Get "app" }} grappe](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurer les adresses des nœuds * Saisissez les adresses IP des nœuds, appuyez sur `Tab key` Pour vérifier la connectivité et renseigner les noms des nœuds. Si le nœud 1 ou le nœud 2 est rouge, vérifiez la connectivité du navigateur aux deux nœuds et vérifiez le pare-feu sur les deux nœuds pour 🛠️ [dépannage](/resources/safekit-user-guide-82/#Troubleshooting). * Ensuite, cliquez sur `Save and apply` pour enregistrer la configuration. * Vérifiez le `Success` ✅ Message sur les deux nœuds. * Si la configuration `Failure` L'erreur ❌ apparaît sur un nœud ; ouvrez le panneau d'accordéon ▼ correspondant et consultez les messages. Notez que vous pouvez utiliser… SafeKit L'IA 🤖 demande de l'aide. ℹ️ Si vous le souhaitez, vous pouvez en ajouter un nouveau `LAN and nodes` (premièrement ➕) pour créer un deuxième signal de présence et un réseau de réplication dédié. ℹ️ Si vous cliquez sur `Advanced configuration`, le `cluster.xml` Le fichier s'affiche. Ce fichier est automatiquement rempli par la console et déployé sur les nœuds. ![Entrez les nœuds de la {{ .Get "app" }} grappe](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Sélectionnez un module * Dans `New module`, cliquez sur le `{{ .Get "mod" }}.safe` module. ℹ️ Dans la bannière bleue en haut, 🛜 `node1` représente le nœud de connexion à la console. Ce nœud relaie les requêtes vers `node2` lorsque nécessaire. ℹ️ La console recherche `xxx.safe` dans le `Application_Modules/generic/` répertoire sur le nœud de connexion (`node1`) si vous avez placé un module à cet endroit lors de l'installation. ![Choisissez le module pour {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configurer le module * Dans `Module startup at boot`, choisissez un démarrage automatique du module au démarrage du système, sans délai. * Dans `Macros` / `SERVICES`, saisissez les noms des services de votre application, dans l'ordre de démarrage, séparés par des virgules. * Dans `Heartbeat networks`, vous devriez avoir un seul réseau de pulsation, sauf si vous avez ajouté un réseau local à l'étape 2. * Dans `Virtual IP addresses`Saisissez une adresse IP virtuelle. Une adresse IP virtuelle est une adresse IP standard appartenant au même réseau IP (même sous-réseau) que les adresses IP des deux nœuds. Les clients d'application doivent être configurés avec l'adresse IP virtuelle (ou le nom DNS associé à l'adresse IP virtuelle). * Dans `Load balancing rules`, configurez le port de service pour l'équilibrage de charge (ex : TCP 9010 dans l'exemple). * Dans `Load balancing rules`, définir la règle d'équilibrage de charge, `Source address` ou `Source port`: * avec l'adresse IP source du client, ce même client sera connecté au même nœud dans le farm sur plusieurs sessions TCP et récupérer son contexte sur le nœud. * Avec le port TCP source du client, ce même client sera connecté à différents nœuds du réseau. farm sur plusieurs sessions TCP (sans récupération de contexte). * Dans `Checkers`Vous pourrez configurer des vérificateurs si nécessaire, tels que la surveillance des processus, des vérificateurs personnalisés, TCP, ping ou des vérificateurs de type split-brain. Par exemple, si le nom d'un processus est affiché dans `Monitored processes/services`Un système de surveillance sera mis en place, avec une action de redémarrage en cas de défaillance. Une configuration incorrecte du nom du processus entraînera l'arrêt immédiat du module après son démarrage. ℹ️ Si vous cliquez sur `Advanced configuration`, le `userconfig.xml` Le fichier s'affiche. Ce fichier est automatiquement rempli par la console et déployé sur les nœuds contenant les scripts de redémarrage. ℹ️ Dans un déploiement cloud, vous n'avez pas besoin de configurer une adresse IP virtuelle ni des règles d'équilibrage de charge. SafeKit. L'adresse IP virtuelle et les règles d'équilibrage de charge sont gérées au niveau du 🛠️ [niveau d'équilibrage de charge cloud](/resources/safekit-user-guide-82/#Cloud). ℹ️ Lorsque vous appliquez le SafeKit configuration, la `startup type` le service est automatiquement configuré pour `Manual` dans Windows services. Cela garantit que les services ne démarrent pas automatiquement au démarrage du système, mais uniquement lorsque le module lui-même est lancé (le même principe s'applique à Linux). ![Entrez dans {{ .Get "app" }} farm paramètres du module](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Modifier les scripts (facultatif) * Cette étape est facultative et peut être ignorée dans la plupart des cas, car les scripts de redémarrage sont déjà préconfigurés pour redémarrer les services définis à l'étape précédente. * Cliquez donc directement sur `Next step`. * `start_both.ps1` démarre tous les services dans l'ordre spécifié dans le `SERVICES` liste, tandis que `stop_both.ps1` interrompt tous les services dans l'ordre inverse. * En plus, `start_both.ps1` vérifie le démarrage de chaque service et arrête le module si un service ne démarre pas correctement. ![Entrez dans {{ .Get "app" }} paramètres du module](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Chiffrement des communications (facultatif) * Maintenir le chiffrement des communications entre les nœuds. ![Cryptage des communications {{ .Get "app" }} module](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Enregistrer et appliquer * `Save and apply` la configuration et les scripts sur les deux nœuds. ![Enregistrez et appliquez le {{ .Get "app" }} configuration du module](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Vérifier la configuration réussie * Vérifiez le `Success` ✅ Message sur les deux nœuds et cliquez sur `Monitor modules`. * Si la configuration `Failure` L'erreur ❌ apparaît sur un nœud ; ouvrez le panneau d'accordéon ▼ correspondant et consultez les messages. Notez que vous pouvez utiliser… SafeKit L'IA 🤖 demande de l'aide. ![Vérifiez le {{ .Get "app" }} configuration du module réussie](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Commencez le farm cluster sur le nœud 1 et le nœud 2 * ⋯ `Start` le farm groupe tel qu'illustré sur l'image. ![Commencez le {{ .Get "app" }} cluster sur les deux nœuds](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Attendez la transition vers le haut (vert) / haut (vert)

Les nœuds 1 et 2 devraient atteindre l'état UP (vert), ce qui signifie que le start_both Le script a été exécuté sur les nœuds 1 et 2.

⚠️ Si le voyant UP (vert) n'est pas atteint ou si l'application ne démarre pas, analysez pourquoi avec le Journal du module 🖼️ du nœud 1 ou du nœud 2.

* Cliquez sur la 🔍 **enregistrer** icône de `node1` ou `node2` ouvrir le journal du module et rechercher les messages d'erreur, par exemple lorsqu'un vérificateur détecte une erreur et arrête le module. * Cliquez sur `start_both` Dans le journal : les messages de sortie du script sont affichés à droite et les erreurs, comme un service mal démarré, peuvent être détectées. * Utilisez le SafeKit L'IA 🤖 demande de l'aide pour les messages de journalisation. ℹ️ Notez que vous avez un 🕒 **[Chronologie 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** Cela peut être utile pour comprendre ce qui se passe dans le cluster. ![Le {{ .Get "app" }} Le cluster a démarré](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11.
