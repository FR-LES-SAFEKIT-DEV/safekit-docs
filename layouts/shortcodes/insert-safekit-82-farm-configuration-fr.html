Les réseaux routés de couche 3 nécessitent des 🛠️ [équilibreurs de charge cloud](/fr/resources/safekit-user-guide-82/#Cloud). ### 1. Lancez la console SafeKit {#1-launch-the-safekit-console} * Sur un nœud du cluster, ouvrez un navigateur et connectez-vous à `http://localhost:9010`. * Connectez-vous avec le nom d’utilisateur `admin` et le mot de passe défini lors de l’installation. Vous pouvez également ouvrir la console à partir d’un poste de travail situé en dehors du cluster. ⚠️ Utilisez un seul navigateur pour configurer les deux nœuds avec SafeKit. ℹ️ Pour sécuriser la console web, consultez 🛠️ [11. Sécuriser le service web SafeKit](/fr/resources/safekit-user-guide-82/#https) dans le Guide de l’utilisateur. ![Console web SafeKit pour le cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurer les adresses des nœuds {#2-configure-node-addresses} * Saisissez l’adresse IP de chaque nœud. Appuyez sur la touche Tabulation pour vérifier la connexion et remplir les noms des nœuds. * Si `node1` ou `node2` est rouge, vérifiez que le navigateur peut atteindre les deux nœuds. Vérifiez le pare-feu sur chaque nœud. Voir 🛠️ [dépannage](/fr/resources/safekit-user-guide-82/#Troubleshooting). * Cliquez sur `Save and apply` pour enregistrer la configuration. * Vérifiez que les deux nœuds affichent ✅ `Success`. * Si un nœud affiche ❌ `Failure`, développez son panneau ▼ et lisez les messages. Utilisez l’IA SafeKit 🤖 si vous avez besoin d’aide. ℹ️ Pour ajouter un deuxième réseau heartbeat et un réseau de réplication dédié, cliquez sur le premier bouton ➕ dans `LAN and nodes`. ℹ️ Cliquez sur `Advanced configuration` pour afficher le fichier `cluster.xml`. La console remplit ce fichier et le déploie sur les deux nœuds. ![Adresses des nœuds pour le cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Sélectionnez un module {#3-select-a-module} * Dans `New module`, sélectionnez le module `{{ .Get "mod" }}.safe`. ℹ️ Dans la bannière bleue, 🛜 `node1` est le nœud connecté à la console. Il transmet les requêtes à `node2` si nécessaire. ℹ️ Si vous avez ajouté un fichier de module `xxx.safe` pendant l’installation, la console le recherche dans le répertoire `Application_Modules/generic/` sur `node1`. ![Choisissez le module pour {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configurer le module {#4-configure-the-module} * Dans `Module startup at boot`, configurez le module pour qu’il démarre automatiquement au démarrage, sans délai. * Dans `Macros`/`SERVICES`, répertoriez les services d’application dans l’ordre de démarrage. Séparez les noms par des virgules. * Dans `Heartbeat networks`, conservez un réseau de pulsation, sauf si vous avez ajouté un LAN à l’étape 2. * Dans `Virtual IP addresses`, saisissez une adresse IP virtuelle dans le même sous-réseau que les deux nœuds. * Configurez les clients de l’application pour qu’ils utilisent cette adresse IP virtuelle ou son nom DNS. * Dans `Load balancing rules`, saisissez le port de service à équilibrer, par exemple le port TCP 9010. * Dans `Load balancing rules`, sélectionnez `Source address` ou `Source port` : * `Source address` : toutes les connexions TCP d’un même client sont acheminées vers le même nœud de la farm. Cela préserve le contexte de la session du client sur ce nœud. * `Source port` : les connexions TCP d’un même client peuvent être dirigées vers différents nœuds de la farm. Le contexte de la session n’est pas partagé entre les nœuds. * Dans `Checkers`, ajoutez des vérifications si nécessaire : surveillance des processus, vérifications personnalisées, TCP, ping ou vérifications de scission du cerveau. * Un processus répertorié dans `Monitored processes/services` est surveillé et redémarré en cas d’échec. Un nom de processus incorrect entraîne l’arrêt immédiat du module après le démarrage. ℹ️ Cliquez sur `Advanced configuration` pour afficher le fichier `userconfig.xml`. La console remplit ce fichier et le déploie sur les deux nœuds avec les scripts de redémarrage. ℹ️ Dans un déploiement cloud, l’[équilibreur de charge cloud](/fr/resources/safekit-user-guide-82/#Cloud) 🛠️ gère l’adresse IP virtuelle et les règles d’équilibrage de charge. Ne les configurez pas dans SafeKit. ℹ️ Lorsque vous appliquez la configuration, SafeKit définit le type de démarrage du service Windows sur `Manual`. Les services démarrent avec le module, et non au démarrage du système. SafeKit empêche également ces services de démarrer au démarrage du système sous Linux. ![Paramètres du module pour la farm {{ .Get "app" }}](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Modifier les scripts (facultatif) {#5-edit-scripts-optional} * Dans la plupart des cas, vous pouvez ignorer cette étape. Les scripts sont déjà configurés pour redémarrer les services répertoriés à l’étape précédente. * Cliquez sur `Next step` si aucune modification n’est nécessaire. * Le script `start_both.ps1` démarre les services dans l’ordre de la liste `SERVICES`. * Le script `stop_both.ps1` arrête les services dans l’ordre inverse. * Le script `start_both.ps1` vérifie également chaque service. Il arrête le module si un service ne parvient pas à démarrer. ![Redémarrer les scripts pour le module {{ .Get "app" }}](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Chiffrement des communications (facultatif) {#6-communication-encryption-optional} * Maintenez le chiffrement des communications activé entre les nœuds. ![Chiffrement des communications pour le module {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Enregistrer et appliquer {#7-save-and-apply} * Cliquez sur `Save and apply` pour déployer la configuration et les scripts sur les deux nœuds. ![Déploiement de la configuration pour le module {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Vérifier le résultat de la configuration {#8-check-the-configuration-result} * Vérifiez que les deux nœuds affichent ✅ `Success`. Ensuite, cliquez sur `Monitor modules`. * Si un nœud affiche ❌ `Failure`, développez son panneau ▼ et lisez les messages. Utilisez l’IA SafeKit 🤖 si vous avez besoin d’aide. ![Résultat de la configuration pour le module {{ .Get "app" }}](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Démarrez le cluster farm sur le nœud 1 et le nœud 2 {#9-start-the-farm-cluster-on-node-1-and-node-2} * Ouvrez le menu ⋯ et sélectionnez `Start` sur les deux nœuds, comme indiqué sur l’image. ![Démarrez le cluster {{ .Get "app" }} sur les deux nœuds](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Attendez que les deux nœuds soient `UP` (verts) {#10-wait-until-both-nodes-are-up-green}

Les deux nœuds doivent atteindre l’état UP (vert). Cela signifie que le script start_both a été exécuté sur les deux nœuds.

⚠️ Si un nœud n’atteint pas l’état UP (vert), ou si l’application ne démarre pas, vérifiez son journal de module 🖼️.

* Cliquez sur l’icône 🔍 pour `node1` ou `node2` afin d’ouvrir le journal du module. Recherchez les erreurs, telles qu’une vérification qui a arrêté le module. * Dans le journal, cliquez sur `start_both`. La sortie du script apparaît à droite. Vérifiez la présence d’erreurs de démarrage du service. * Utilisez l’IA SafeKit 🤖 pour obtenir de l’aide concernant les messages du journal. ℹ️ Utilisez la chronologie 🕒 **[🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** pour comprendre la séquence des événements dans le cluster. ![Les deux nœuds du cluster {{ .Get "app" }} sont en cours d’exécution](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. Tests {#11-testing} SafeKit inclut un test en mosaïque intégré. Voir [Test de l’adresse IP virtuelle d’équilibrage de charge dans un cluster farm SafeKit](/fr/best-practises/test-load-balancing-vip-farm/). ![Testez l’adresse IP virtuelle de {{ .Get "app" }} avec la mosaïque](/wp-content/uploads/2024/03/appli-19.png) ℹ️ Consultez la [formation en ligne SafeKit](/fr/resources/safekit-on-line-training/) pour plus de détails et de vidéos. ### 12. Collectez les 2 fichiers .zip. ℹ️ Consultez [l’assistance SafeKit](/fr/resources/safekit-support/) pour plus d’informations. ![Prise en charge des instantanés pour le cluster {{ .Get "app" }}](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
