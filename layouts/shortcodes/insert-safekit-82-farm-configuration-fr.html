{{/* Shortcode: insert-safekit-82-farm-configuration-fr — 9 instances in 9 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-network-load-balancing-and-failover.md */}} ### Prérequis * Installez {{ .Get "app" }} sur au moins 2 nœuds. * Pour l'équilibrage de charge sur une adresse IP virtuelle, tous les nœuds doivent être sur le même LAN ou LAN étendu (couche 2). Les réseaux routés de couche 3 nécessitent des 🛠️ [répartiteurs de charge cloud](/resources/safekit-user-guide-82/#Cloud). ### 1. Ouvrir la console SafeKit * Sur un nœud du cluster, ouvrez un navigateur et connectez-vous à `http://localhost:9010`. * Connectez-vous avec le nom d'utilisateur `admin` et le mot de passe défini lors de l'installation. Vous pouvez aussi ouvrir la console depuis un poste de travail externe au cluster. ⚠️ Utilisez un seul navigateur pour configurer les deux nœuds avec SafeKit. ℹ️ Pour sécuriser la console web, consultez 🛠️ [11\. Sécurisation du service web SafeKit](/resources/safekit-user-guide-82/#https) dans le guide utilisateur. ![Console web SafeKit pour le cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurer les adresses des nœuds * Saisissez l'adresse IP de chaque nœud. Appuyez sur la touche Tab pour vérifier la connexion et renseigner les noms des nœuds. * Si `node1` ou `node2` est rouge, vérifiez que le navigateur peut joindre les deux nœuds. Vérifiez le pare-feu de chaque nœud. Consultez les conseils de 🛠️ [dépannage](/resources/safekit-user-guide-82/#Troubleshooting). * Cliquez sur `Save and apply` pour enregistrer la configuration. * Vérifiez que les deux nœuds affichent ✅ `Success`. * Si un nœud affiche ❌ `Failure`, développez son panneau ▼ et lisez les messages. Utilisez l'IA SafeKit 🤖 si vous avez besoin d'aide. ℹ️ Pour ajouter un second réseau de heartbeat et un réseau de réplication dédié, cliquez sur le premier bouton ➕ dans `LAN and nodes`. ℹ️ Cliquez sur `Advanced configuration` pour afficher le fichier `cluster.xml`. La console remplit ce fichier et le déploie sur les deux nœuds. ![Adresses des nœuds du cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Sélectionner un module * Dans `New module`, sélectionnez le module `{{ .Get "mod" }}.safe`. ℹ️ Dans le bandeau bleu, 🛜 `node1` est le nœud connecté à la console. Il transmet les requêtes à `node2` si nécessaire. ℹ️ Si vous avez ajouté un fichier de module `xxx.safe` lors de l'installation, la console le recherche dans le répertoire `Application_Modules/generic/` de `node1`. ![Choix du module pour {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configurer le module * Dans `Module startup at boot`, configurez le démarrage automatique du module au démarrage du système, sans délai. * Dans `Macros` / `SERVICES`, listez les services de l'application dans l'ordre de démarrage. Séparez les noms par des virgules. * Dans `Heartbeat networks`, conservez un seul réseau de heartbeat, sauf si vous avez ajouté un LAN à l'étape 2. * Dans `Virtual IP addresses`, saisissez une adresse IP virtuelle dans le même sous-réseau que les deux nœuds. * Configurez les clients de l'application pour utiliser cette adresse IP virtuelle ou son nom DNS. * Dans `Load balancing rules`, saisissez le port du service à répartir, par exemple le port TCP 9010. * Dans `Load balancing rules`, sélectionnez `Source address` ou `Source port` : * `Source address` : toutes les connexions TCP d'un même client vont vers le même nœud du cluster farm. Le contexte de session du client est ainsi conservé sur ce nœud. * `Source port` : les connexions TCP d'un même client peuvent aller vers différents nœuds du cluster farm. Le contexte de session n'est pas partagé entre les nœuds. * Dans `Checkers`, ajoutez des contrôles si nécessaire : surveillance de processus, contrôles personnalisés, TCP, ping ou détection de split-brain. * Un processus listé dans `Monitored processes/services` est surveillé et redémarré en cas de défaillance. Un nom de processus incorrect provoque l'arrêt du module immédiatement après son démarrage. ℹ️ Cliquez sur `Advanced configuration` pour afficher le fichier `userconfig.xml`. La console remplit ce fichier et le déploie sur les deux nœuds avec les scripts de redémarrage. ℹ️ Dans un déploiement cloud, le 🛠️ [répartiteur de charge cloud](/resources/safekit-user-guide-82/#Cloud) gère l'adresse IP virtuelle et les règles d'équilibrage de charge. Ne les configurez pas dans SafeKit. ℹ️ Lorsque vous appliquez la configuration, SafeKit définit le type de démarrage des services Windows sur `Manual`. Les services démarrent avec le module, et non au démarrage du système. Sous Linux, SafeKit empêche également ces services de démarrer avec le système. ![Paramètres du module {{ .Get "app" }} farm](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Modifier les scripts (facultatif) * Dans la plupart des cas, vous pouvez ignorer cette étape. Les scripts sont déjà configurés pour redémarrer les services listés à l'étape précédente. * Cliquez sur `Next step` si aucune modification n'est nécessaire. * Le script `start_both.ps1` démarre les services dans l'ordre de la liste `SERVICES`. * Le script `stop_both.ps1` arrête les services dans l'ordre inverse. * Le script `start_both.ps1` vérifie aussi chaque service. Il arrête le module si un service ne démarre pas. ![Scripts de redémarrage du module {{ .Get "app" }}](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Chiffrement des communications (facultatif) * Conservez le chiffrement des communications entre les nœuds. ![Chiffrement des communications du module {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Enregistrer et appliquer * Cliquez sur `Save and apply` pour déployer la configuration et les scripts sur les deux nœuds. ![Déploiement de la configuration du module {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Vérifier le résultat de la configuration * Vérifiez que les deux nœuds affichent ✅ `Success`. Cliquez ensuite sur `Monitor modules`. * Si un nœud affiche ❌ `Failure`, développez son panneau ▼ et lisez les messages. Utilisez l'IA SafeKit 🤖 si vous avez besoin d'aide. ![Résultat de la configuration du module {{ .Get "app" }}](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Démarrer le cluster farm sur les nœuds 1 et 2 * Ouvrez le menu ⋯ et sélectionnez `Start` sur les deux nœuds, comme sur l'image. ![Démarrage du cluster {{ .Get "app" }} sur les deux nœuds](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Attendre que les deux nœuds soient `UP` (vert)

Les deux nœuds doivent atteindre l'état UP (vert). Cela signifie que le script start_both a été exécuté sur les deux nœuds.

⚠️ Si un nœud n'atteint pas l'état UP (vert), ou si l'application ne démarre pas, consultez son journal du module 🖼️.

* Cliquez sur l'icône 🔍 de `node1` ou `node2` pour ouvrir le journal du module. Recherchez les erreurs, par exemple un contrôle ayant arrêté le module. * Dans le journal, cliquez sur `start_both`. Les messages du script s'affichent à droite. Recherchez les erreurs de démarrage des services. * Utilisez l'IA SafeKit 🤖 pour vous aider à comprendre les messages du journal. ℹ️ Utilisez la 🕒 **[chronologie 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** pour comprendre la succession des événements dans le cluster. ![Les deux nœuds du cluster {{ .Get "app" }} sont démarrés](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. Tests SafeKit intègre un test de mosaïque. Consultez [Test de l'adresse IP virtuelle d'équilibrage de charge d'un cluster SafeKit farm](/fr/best-practises/test-load-balancing-vip-farm/). ![Test de l'adresse IP virtuelle de {{ .Get "app" }} avec la mosaïque](/wp-content/uploads/2024/03/appli-19.png) ℹ️ Consultez la [formation en ligne SafeKit](/resources/safekit-on-line-training/) pour plus de détails et de vidéos. ### 12. Support * Pour le support, créez un `Snapshot` SafeKit par nœud. Récupérez les 2 fichiers .zip. ℹ️ Consultez le [support SafeKit](/resources/safekit-support/) pour plus d'informations. ![Snapshots du cluster {{ .Get "app" }} pour le support](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
