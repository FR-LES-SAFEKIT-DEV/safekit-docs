をクリックして、`cluster.xml`。ファイルを表示します。コンソールはこのファイルを埋めて、両方のノードにデプロイします。 ![{{ .Get "app" }} クラスターのノードアドレス](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. モジュールを選択します {#3-select-a-module} * `New boot` に遅延なく自動的に起動するように設定します。 * `Macros`/`SERVICES` で、アプリケーションサービスを起動順にリストします。名前はコンマで区切ります。 * `Heartbeat networks` では、ステップ 2 で LAN を追加した場合を除き、ハートビートネットワークを 1 つ維持してください。 * `Virtual IP addresses` に、両方のノードと同じサブネットの仮想 IP アドレスを入力します。 * アプリケーションクライアントがこの仮想 IP アドレスまたはその DNS 名を使用するように設定します。 * `Load balancing rules` で、負荷分散するサービスポート (例：TCP ポート 9010) を入力します。 * `Load balancing rules` で、`Source address` または `Source port` を選択します * `Source address` : 同じクライアントからのすべての TCP 接続は、farm 内の同じノードに送られます。これにより、そのノード上のクライアントのセッションコンテキストが保持されます。 * `Source port`：同じクライアントからの TCP 接続は、farm 内の異なるノードに送信できます。セッションコンテキストはノード間で共有されません。 * `Checkers` では、必要に応じてチェックを追加します。プロセス監視、カスタムチェック、TCP、ping、またはスプリットブレインチェックなどです。 * `Monitored processes/services` にリストされているプロセスは、監視され、失敗した場合は再起動されます。プロセス名が正しくないと、モジュールは起動直後に停止します。 ℹ️ `Advanced configuration` をクリックして、ファイル `userconfig.xml` を表示します。コンソールは、このファイルを記入し、再起動スクリプトを使用して両方のノードにデプロイします。 ℹ️ 展開では、🛠️ [クラウドロードバランサーが](/ja/resources/safekit-user-guide-82/#Cloud)仮想 IP アドレスとロードバランシングルールを管理します。SafeKit でそれらを構成しないでください。 ℹ️ 設定を適用すると、SafeKit Windows サービスの起動の種類を `Manual` に設定します。サービスはシステム起動時ではなく、モジュールと共に起動します。また、SafeKit Linux でこれらのサービスがシステム起動時に起動するのを防ぎます。 ![{{ .Get "app" }} farm のモジュール設定](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. スクリプト `stop_both.ps1`、サービスを逆順に停止します。 * スクリプト `start_both.ps1` 各サービスもチェックします。サービスが起動に失敗した場合、モジュールを停止します。 ![{{ .Get "app" }} モジュールのスクリプトを再起動](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) 両方のノードが UP（緑）の状態に達している必要があります。これは、両方のノードで start_both スクリプトが実行されたことを意味します。

⚠️ ノードが UP（緑）に到達しない場合、またはアプリケーションが起動しない場合は、その ログを確認してください 🖼️。

* `node1` または `node2` の 🔍 アイコンをクリックして、モジュールログを開きます。モジュールを停止させたチェックなどのエラーを探します。 * ログで `start_both` をクリックします。スクリプトの出力が右側に表示されます。サービス起動エラーがないか確認します。 * ログメッセージについては、SafeKit AI 🤖 をご利用ください。 ℹ️ 🕒**[タイムライン 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** を使用して、クラスター内のイベントの順序を理解します。 ![{{ .Get "app" }} クラスターの両方のノードが稼働しています](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. テスト {#11-testing} SafeKit にはモザイクテストが組み込まれています。[SafeKit farm クラスターにおけるロードバランシング仮想 IP アドレスのテストを](/ja/best-practises/test-load-balancing-vip-farm/)参照してください。 ![モザイクで {{ .Get "app" }} の仮想 IP アドレスをテストする](/wp-content/uploads/2024/03/appli-19.png) ℹ️ 詳細と動画については、[SafeKit オンライン研修を](/ja/resources/safekit-on-line-training/)ご覧ください。 ### 12. サポート {#12-support} * サポートが必要な場合は、ノードごとに 1 つの SafeKit `Snapshot` を作成してください。2 つの .zip ファイルを収集してください。 ℹ️ 詳細については、[SafeKit サポートを](/ja/resources/safekit-support/)ご覧ください。 ![{{ .Get "app" }} クラスターのスナップショットをサポート](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
