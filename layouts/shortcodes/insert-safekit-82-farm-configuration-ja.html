boot`では、起動時にモジュールを遅延なく自動起動するように選択します。 * `Macros` / `SERVICES` には、アプリケーションのサービス名を起動順にカンマで区切って入力してください。 * `Heartbeat networks`では、ステップ2で LAN を追加していない限り、単一のハートビートネットワークが存在するはずです。 * で `Virtual IP addresses`仮想空間に入る IP 仮想アドレス。 IP 住所は標準です IP 同じ住所 IP ネットワーク（同じサブネット） IP 両ノードのアドレス。アプリケーションクライアントは仮想アドレスで構成する必要があります。 IP アドレス（または仮想アドレスに関連付けられた DNS 名） IP 住所）。 * In `Load balancing rules`では、サービスポートをロードバランシングするように設定します（例：TCP 9010）。 * `Load balancing rules`では、負荷分散ルール `Source address` または `Source port`を設定します。 * クライアントの送信元アドレス IP を使用して、同じクライアントは複数のTCPセッションで farm 内の同じノードに接続し、ノード上のコンテキストを取得します。 * クライアントの送信元 TCP ポートを使用すると、同じクライアントが複数の TCP セッションで farm 内の異なるノードに接続されます (コンテキストを取得せずに)。 * In `Checkers`では、必要に応じて、プロセス監視、カスタムチェッカー、TCP、ping、スプリットブレインチェッカーなどのチェッカーを設定できます。たとえば、プロセス名がIn `Monitored processes/services`に表示される場合、そのプロセスは監視され、障害が発生した場合は再起動アクションが実行されます。誤ったプロセス名を設定すると、モジュールは起動直後に停止します。 ℹ️ クリックすると `Advanced configuration`、 `userconfig.xml` ファイルが表示されます。このファイルはコンソールによって自動的に作成され、再起動スクリプトとともにノードにデプロイされます。 ℹ️ クラウド展開では、仮想環境を構成する必要はありません。 IP アドレスとロードバランシングルール SafeKit仮想 IP 負荷分散ルールは 🛠️ [cloud load balancer level](/resources/safekit-user-guide-82/#Cloud)。 ℹ️ 構成を適用すると、 SafeKit サービスの `startup type` がWindowsサービスで自動的に `Manual` ### 5. スクリプトの編集（任意） * この手順は任意であり、ほとんどの場合省略できます。なぜなら、再起動スクリプトは既に前の手順で定義されたサービスを再起動するように事前設定されているからです。 * それでは、 `Next step`を直接クリックしてください。 * `start_both.ps1` は `SERVICES` リストで指定された順序で全てのサービスを開始し、 `stop_both.ps1` は逆の順序で全てのサービスを停止します。 * さらに、 `start_both.ps1` は各サービスの起動をチェックし、いずれかのサービスが正しく起動しなかった場合はモジュールを停止します。 ![ {{ .Get "app" }} UP（緑）/ UP（緑）への遷移を待ちます ノード1とノード2はUP（緑色）状態になるはずです。これは、 `start_both` スクリプトがノード1とノード2で実行されたことを意味します。 ⚠️ UP（緑）に到達しない場合、またはアプリケーションが起動しない場合は、ノード 1 またはノード 2 の [module log 🖼️](/wp-content/uploads/2024/03/37-module-log-farm-script.png) を使用して理由を分析します。 * 🔍 **log** アイコンまたは `node1` または `node2` をクリックしてモジュールログを開き、チェッカーがエラーを検出してモジュールを停止したなどのエラーメッセージを探します。 * ログ内の `start_both` をクリックすると、スクリプトの出力メッセージが右側に表示され、サービスが正しく起動されていないなどのエラーを検出できます。 * ログメッセージに関するサポートについては、 SafeKit AI 🤖 を使用してください。 ℹ️ クラスターで何が起こるかを理解するのに役立つ 🕒 **[timeline 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** があることに注意してください。 ![ {{ .Get "app" }} クラスターが起動しました](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. テスト SafeKit は製品にテスト機能を内蔵しています。 * TCPポート9010に対して、送信元TCPポートでのロードバランシングを行うルールを設定します。 * farm ノードの外部に外部ワークステーションを接続します。 * http://virtual-ip:9010/safekit/mosaic.html にアクセスしてブラウザを起動してください。 HTTPリクエストに応答するノードに応じて、さまざまな色のモザイクが表示されるはずです。 * コンテキストメニューをスクロールダウンして「停止」をクリックすると、UP（緑色）ノードが停止します。 * 停止したノードと仮想アドレス IP にTCP接続が残っていないことを確認してください。 ℹ️ 詳細情報と動画は [SafeKit Online Training](/resources/safekit-on-line-training/)をご覧ください。 ![ {{ .Get "app" }} の仮想アドレス IP をモザイクでテストする](/wp-content/uploads/2024/03/appli-19.png) ### 12. サポート * サポートを受けるには、2 SafeKit `Snapshots` （2つの.zipファイル）を、ノードごとに1つずつ入手してください。 ℹ️ [More information on the support here](/resources/safekit-support/). ![サポートのために {{ .Get "app" }} のスナップショットを撮ってください](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
