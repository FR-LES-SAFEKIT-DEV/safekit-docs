SafeKit コンソールを起動する * クラスターのいずれかのノードでブラウザーを開き、`http://localhost:9010` に接続して Web コンソールを起動します。 * ユーザー名に `admin`、パスワードにインストール時に設定したパスワードを入力します。 クラスター外のワークステーションにあるブラウザーでコンソールを実行することもできます。 ⚠️ SafeKit の構成は、1つのブラウザーから両方のノードに対して行います。 ℹ️ Web コンソールのセキュリティ保護については、ユーザーガイドの 🛠️ [11\. SafeKit Web サービスの保護](/resources/safekit-user-guide-82/#https)を参照してください。 ![SafeKit Web コンソールを起動して {{ .Get "app" }} クラスターを構成する](/wp-content/uploads/2024/03/01-login-large.png) ### 2. ノードのアドレスを構成する * ノードの IP アドレスを入力し、`Tab key` を押して接続を確認してからノード名を入力します。node1 または node2 が赤色の場合は、ブラウザーから両方のノードへの接続と、両方のノードのファイアウォールを確認し、🛠️ [トラブルシューティング](/resources/safekit-user-guide-82/#Troubleshooting)を参照してください。 * 次に、`Save and apply` をクリックして構成を保存します。 * 両方のノードで `Success` ✅ メッセージが表示されることを確認します。 * いずれかのノードで構成が `Failure` ❌ になった場合は、そのノードの ▼ アコーディオンを開いてメッセージを確認します。SafeKit AI 🤖 を使用してサポートを受けることもできます。 ℹ️ 必要に応じて、新しい `LAN and nodes`（最初の ➕）を追加し、2つ目のハートビートと専用のレプリケーションネットワークを作成できます。 ℹ️ `Advanced configuration` をクリックすると、`cluster.xml` ファイルが表示されます。このファイルはコンソールによって自動的に生成され、ノードに展開されます。 ![{{ .Get "app" }} クラスターのノードを入力する](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. モジュールを選択する * `New module` で `{{ .Get "mod" }}.safe` モジュールをクリックします。 ℹ️ 上部の青いバナーにある 🛜 `node1` は、コンソールが接続されているノードを示します。このノードは必要に応じて `node2` に要求を中継します。 ℹ️ インストール中にモジュールを配置した場合、コンソールは `xxx.safe` を `Application_Modules/generic/` ディレクトリ内の接続ノード（`node1`）で検索します。 ![{{ .Get "app" }} 用のモジュールを選択する](/wp-content/uploads/2024/03/04-module-new.png) ### 4. モジュールを構成する * `Module startup at boot` で、システム起動時に遅延なくモジュールを自動起動するように設定します。 * `Macros` / `SERVICES` に、アプリケーションのサービス名を起動順にカンマ区切りで入力します。 * `Heartbeat networks` は、手順2で LAN を追加していない限り、1つだけにします。 * `Virtual IP addresses` に仮想 IP アドレスを入力します。仮想 IP アドレスは、両ノードの IP アドレスと同じ IP ネットワーク（同じサブネット）内の標準的な IP アドレスです。アプリケーションクライアントには、仮想 IP アドレス（またはそれに関連付けられた DNS 名）を設定します。 * `Load balancing rules` で、負荷分散するサービスのポートを設定します（例: TCP 9010）。 * `Load balancing rules` で、`Source address` または `Source port` の負荷分散ルールを設定します。 * クライアントの送信元 IP アドレスを使うと、同じクライアントは複数の TCP セッションで `farm` 内の同じノードに接続され、そのノード上のコンテキストを取得できます。 * クライアントの送信元 TCP ポートを使うと、同じクライアントは複数の TCP セッションで `farm` 内の異なるノードに接続されます（コンテキストは取得されません）。 * `Checkers` では、必要に応じてプロセス監視、カスタムチェッカー、TCP、ping、スプリットブレインチェッカーなどを構成できます。たとえば、`Monitored processes/services` にプロセス名が表示されると、そのプロセスが監視され、障害時に再起動されます。誤ったプロセス名を設定すると、モジュールは起動直後に停止します。 ℹ️ `Advanced configuration` をクリックすると、`userconfig.xml` ファイルが表示されます。このファイルはコンソールによって自動的に生成され、再起動スクリプトとともにノードに展開されます。 ℹ️ クラウド環境では、SafeKit に仮想 IP アドレスや負荷分散ルールを設定する必要はありません。仮想 IP と負荷分散ルールは 🛠️ [クラウド ロードバランサー](/resources/safekit-user-guide-82/#Cloud)で管理されます。 ℹ️ SafeKit の構成を適用すると、Windows サービスの `startup type` は自動的に `Manual` に設定されます。これにより、システム起動時にサービスが自動起動せず、モジュール自体の起動時にのみ開始されます（Linux でも同様です）。 ![{{ .Get "app" }} の `farm` モジュール設定を入力する](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. スクリプトを編集する（任意） * この手順は任意で、ほとんどの場合は省略できます。再起動スクリプトは、前の手順で定義したサービスを再起動するようにあらかじめ設定されています。 * `Next step` を直接クリックします。 * `start_both.ps1` は `SERVICES` リストで指定した順番ですべてのサービスを開始し、`stop_both.ps1` は逆の順番ですべてのサービスを停止します。 * また、`start_both.ps1` は各サービスの起動を確認し、サービスが正しく起動しない場合はモジュールを停止します。 ![{{ .Get "app" }} のモジュール設定を入力する](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. 通信を暗号化する（任意） * ノード間の通信は暗号化したままにします。 ![{{ .Get "app" }} モジュールの通信暗号化](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. 保存して適用する * `Save and apply` で、両方のノードに構成とスクリプトを適用します。 ![{{ .Get "app" }} モジュールの構成を保存して適用する](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. 構成が成功したことを確認する * 両方のノードで `Success` ✅ メッセージを確認し、`Monitor modules` をクリックします。 * いずれかのノードで構成が `Failure` ❌ になった場合は、そのノードの ▼ アコーディオンを開いてメッセージを確認します。SafeKit AI 🤖 を使用してサポートを受けることもできます。 ![{{ .Get "app" }} モジュールの構成が成功したことを確認する](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. ノード1とノード2で `farm` クラスターを起動する * 画像のように ⋯ `Start` をクリックして `farm` クラスターを起動します。 ![両方のノードで {{ .Get "app" }} クラスターを起動する](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. 両方のノードが UP (緑) になるまで待つ ノード1とノード2が UP (緑) の状態になれば、両方のノードで `start_both` スクリプトが実行されたことを意味します。 ⚠️ UP (緑) にならない場合、またはアプリケーションが起動しない場合は、ノード1またはノード2の[モジュールログ 🖼️](/wp-content/uploads/2024/03/37-module-log-farm-script.png)で原因を調べてください。 * `node1` または `node2` の 🔍 **log** アイコンをクリックしてモジュールログを開き、チェッカーがエラーを検出してモジュールを停止した場合などのエラーメッセージを探します。 * ログの `start_both` をクリックすると、スクリプトの出力が右側に表示されます。サービスが正しく起動しなかった場合などのエラーを確認できます。 * ログメッセージについては SafeKit AI 🤖 を利用してください。 ℹ️ 🕒 **[タイムライン 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** を使うと、クラスター内の動作を把握しやすくなります。 ![{{ .Get "app" }} クラスターが起動しました](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. テスト SafeKit には製品に組み込まれたテスト機能があります。 * TCP ポート 9010 に対し、送信元 TCP ポートに基づく負荷分散ルールを設定します。 * `farm` ノードの外部にあるワークステーションを接続します。 * ブラウザーで次のアドレスを開きます: http://virtual-ip:9010/safekit/mosaic.html HTTP 要求に応答するノードに応じて、色のモザイクが表示されます。 * コンテキストメニューを下にスクロールして Stop をクリックし、UP (緑) のノードを1つ停止します。 * 停止したノードと仮想 IP アドレスに TCP 接続が残っていないことを確認します。 ℹ️ 詳細と動画については、[SafeKit オンライン トレーニング](/ja/resources/safekit-on-line-training/)を参照してください。 ![モザイクを使って {{ .Get "app" }} の仮想 IP アドレスをテストする](/wp-content/uploads/2024/03/appli-19.png) ### 12. サポート *
