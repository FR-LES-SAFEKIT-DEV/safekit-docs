{{/* Shortcode: insert-safekit-82-farm-configuration-ko — 9 instances in 9 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-network-load-balancing-and-failover.md */}} ### 필수 조건 * {{ .Get "app" }} 애플리케이션이 2개 이상의 노드에 설치되어 있어야 합니다. * 가상 IP 부하 분산을 사용하려면 노드가 동일한 LAN 또는 확장 LAN(L2)에 있어야 합니다. 라우팅된 L3 네트워크는 지원되지 않습니다(🛠️ [클라우드 로드 밸런서](/ko/resources/safekit-user-guide-82/#Cloud)를 사용하는 경우 제외). ### 1. SafeKit 콘솔 시작 * 클러스터 노드 중 하나에서 브라우저를 열고 `http://localhost:9010`에 연결하여 웹 콘솔을 시작합니다. * 사용자 이름으로 `admin`을 입력하고 설치 중에 설정한 암호를 입력합니다. 클러스터 외부의 워크스테이션에서 브라우저를 사용해 콘솔을 실행할 수도 있습니다. ⚠️ SafeKit 구성은 하나의 브라우저에서 두 노드 모두에 대해 수행합니다. ℹ️ 웹 콘솔을 보호하려면 사용자 가이드의 🛠️ [11\. SafeKit 웹 서비스 보안](/ko/resources/safekit-user-guide-82/#https)을 참조하세요. ![SafeKit 웹 콘솔을 시작하여 {{ .Get "app" }} 클러스터 구성](/wp-content/uploads/2024/03/01-login-large.png) ### 2. 노드 주소 구성 * 노드의 IP 주소를 입력하고 `Tab key`를 눌러 연결을 확인한 다음 노드 이름을 입력합니다. node1 또는 node2가 빨간색으로 표시되면 브라우저와 두 노드의 연결 및 양쪽 노드의 방화벽을 확인하고 🛠️ [문제 해결](/ko/resources/safekit-user-guide-82/#Troubleshooting)을 참조하세요. * 그런 다음 `Save and apply`를 클릭하여 구성을 저장합니다. * 두 노드에서 `Success` ✅ 메시지가 표시되는지 확인합니다. * 한 노드에서 구성 `Failure` ❌가 발생하면 해당 노드의 ▼ 아코디언을 열고 메시지를 확인합니다. SafeKit AI 🤖를 사용해 도움을 받을 수도 있습니다. ℹ️ 필요하면 새 `LAN and nodes`(첫 번째 ➕)를 추가하여 두 번째 하트비트와 전용 복제 네트워크를 만들 수 있습니다. ℹ️ `Advanced configuration`을 클릭하면 `cluster.xml` 파일이 표시됩니다. 콘솔이 이 파일을 자동으로 채우고 노드에 배포합니다. ![{{ .Get "app" }} 클러스터의 노드 입력](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. 모듈 선택 * `New module`에서 `{{ .Get "mod" }}.safe` 모듈을 클릭합니다. ℹ️ 상단의 파란색 배너에서 🛜 `node1`은 콘솔이 연결된 노드를 나타냅니다. 필요한 경우 이 노드가 요청을 `node2`로 전달합니다. ℹ️ 설치 중 모듈을 배치했다면 콘솔은 `xxx.safe`를 `Application_Modules/generic/` 디렉터리의 연결 노드(`node1`)에서 찾습니다. ![{{ .Get "app" }}용 모듈 선택](/wp-content/uploads/2024/03/04-module-new.png) ### 4. 모듈 구성 * `Module startup at boot`에서 시스템 부팅 시 지연 없이 모듈이 자동으로 시작되도록 선택합니다. * `Macros` / `SERVICES`에 애플리케이션 서비스 이름을 시작 순서대로 입력하고 쉼표로 구분합니다. * `Heartbeat networks`에는 2단계에서 LAN을 추가하지 않았다면 하나의 하트비트 네트워크만 있어야 합니다. * `Virtual IP addresses`에 가상 IP 주소를 입력합니다. 가상 IP 주소는 두 노드의 IP 주소와 동일한 IP 네트워크(동일한 서브넷)에 속하는 표준 IP 주소입니다. 애플리케이션 클라이언트는 가상 IP 주소(또는 연결된 DNS 이름)를 사용하도록 구성해야 합니다. * `Load balancing rules`에서 부하 분산할 서비스 포트를 설정합니다(예: TCP 9010). * `Load balancing rules`에서 `Source address` 또는 `Source port` 부하 분산 규칙을 설정합니다. * 클라이언트의 원본 IP 주소를 사용하면 동일한 클라이언트가 여러 TCP 세션에서 `farm`의 동일한 노드에 연결되고 해당 노드의 컨텍스트를 가져옵니다. * 클라이언트의 원본 TCP 포트를 사용하면 동일한 클라이언트가 여러 TCP 세션에서 `farm`의 서로 다른 노드에 연결됩니다(컨텍스트를 가져오지 않음). * `Checkers`에서 프로세스 모니터링, 사용자 지정 검사기, TCP, ping 또는 split-brain 검사기 등을 필요에 따라 구성할 수 있습니다. 예를 들어 `Monitored processes/services`에 프로세스 이름이 표시되면 해당 프로세스를 모니터링하고 장애 발생 시 재시작합니다. 잘못된 프로세스 이름을 구성하면 모듈이 시작 직후 중지됩니다. ℹ️ `Advanced configuration`을 클릭하면 `userconfig.xml` 파일이 표시됩니다. 콘솔이 이 파일을 자동으로 채우고 재시작 스크립트와 함께 노드에 배포합니다. ℹ️ 클라우드 배포에서는 SafeKit에 가상 IP 주소나 부하 분산 규칙을 구성할 필요가 없습니다. 가상 IP와 부하 분산 규칙은 🛠️ [클라우드 로드 밸런서](/ko/resources/safekit-user-guide-82/#Cloud)에서 관리합니다. ℹ️ SafeKit 구성을 적용하면 Windows 서비스의 `startup type`이 자동으로 `Manual`로 설정됩니다. 따라서 시스템 부팅 시 서비스가 자동으로 시작되지 않고 모듈을 시작할 때만 시작됩니다(Linux도 동일). ![{{ .Get "app" }} `farm` 모듈 설정 입력](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. 스크립트 편집(선택 사항) * 이 단계는 선택 사항이며 대부분의 경우 건너뛸 수 있습니다. 재시작 스크립트는 이전 단계에서 정의한 서비스를 재시작하도록 미리 구성되어 있습니다. * 바로 `Next step`을 클릭합니다. * `start_both.ps1`은 `SERVICES` 목록에 지정된 순서로 모든 서비스를 시작하고, `stop_both.ps1`은 역순으로 중지합니다. * 또한 `start_both.ps1`은 각 서비스의 시작 여부를 확인하고 서비스가 정상적으로 시작되지 않으면 모듈을 중지합니다. ![{{ .Get "app" }} 모듈 설정 입력](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. 통신 암호화(선택 사항) * 노드 간 통신을 암호화된 상태로 유지합니다. ![{{ .Get "app" }} 모듈의 통신 암호화](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. 저장 및 적용 * `Save and apply`를 사용해 두 노드에 구성과 스크립트를 적용합니다. ![{{ .Get "app" }} 모듈 구성 저장 및 적용](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. 구성이 성공했는지 확인 * 두 노드에서 `Success` ✅ 메시지를 확인하고 `Monitor modules`를 클릭합니다. * 한 노드에서 구성 `Failure` ❌가 발생하면 해당 노드의 ▼ 아코디언을 열고 메시지를 확인합니다. SafeKit AI 🤖를 사용해 도움을 받을 수도 있습니다. ![{{ .Get "app" }} 모듈 구성이 성공했는지 확인](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. 노드 1과 노드 2에서 `farm` 클러스터 시작 * 이미지에 표시된 대로 ⋯ `Start`를 클릭하여 `farm` 클러스터를 시작합니다. ![두 노드에서 {{ .Get "app" }} 클러스터 시작](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. 두 노드가 UP(녹색) 상태가 될 때까지 대기 노드 1과 노드 2가 UP(녹색) 상태에 도달해야 합니다. 이는 두 노드에서 `start_both` 스크립트가 실행되었음을 의미합니다. ⚠️ UP(녹색) 상태에 도달하지 않거나 애플리케이션이 시작되지 않으면 노드 1 또는 노드 2의 [모듈 로그 🖼️](/wp-content/uploads/2024/03/37-module-log-farm-script.png)를 확인하여 원인을 분석합니다. * `node1` 또는 `node2`의 🔍 **log** 아이콘을 클릭하여 모듈 로그를 열고 검사기가 오류를 감지해 모듈을 중지하는 등의 오류 메시지를 확인합니다. * 로그에서 `start_both`를 클릭하면 스크립트 출력이 오른쪽에 표시됩니다. 서비스가 잘못 시작된 경우와 같은 오류를 확인할 수 있습니다. * 로그 메시지에 대한 도움은 SafeKit AI 🤖를 이용하세요. ℹ️ 🕒 **[타임라인 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)**을 사용하면 클러스터에서 발생하는 상황을 이해하는 데 도움이 됩니다. ![{{ .Get "app" }} 클러스터가 시작됨](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. 테스트 SafeKit에는 제품에 내장된 테스트가 있습니다. * TCP 포트 9010에 대해 TCP 원본 포트를 기준으로 부하 분산하는 규칙을 구성합니다. * `farm` 노드 외부에 있는 워크스테이션을 연결합니다. * 브라우저에서 다음 주소를 엽니다: http://virtual-ip:9010/safekit/mosaic.html HTTP 요청에 응답하는 노드에 따라 색상 모자이크가 표시됩니다. * 컨텍스트 메뉴를 아래로 스크롤하고 Stop을 클릭하여 UP(녹색) 노드 하나를 중지합니다. * 중지된 노드와 가상 IP 주소에 더 이상 TCP 연결이 없는지 확인합니다. ℹ️ 자세한 정보와 동영상은 [SafeKit 온라인 교육](/ko/resources/safekit-on-line-training/)에서 확인할 수 있습니다. ![모자이크로 {{ .Get "app" }}의 가상 IP 주소 테스트](/wp-content/uploads/2024/03/appli-19.png) ### 12. 지원 * 지원을 받으려면 SafeKit `Snapshots` 2개(.zip 파일 2개)를 준비합니다. 노드마다 하나씩 필요합니다. ℹ️ [지원에 대한 자세한 정보](/ko/resources/safekit-support/). ![지원을 위해 {{ .Get "app" }} 스냅샷 확보](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
