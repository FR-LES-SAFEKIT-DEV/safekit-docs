SafeKit 콘솔을 시작합니다 {#1-launch-the-safekit-console} * 클러스터 노드 중 하나에서 브라우저를 열고 `http://localhost:9010`에 연결합니다. * 사용자 이름 `admin`과 설치 시 설정한 비밀번호로 로그인하세요. 클러스터 외부의 워크스테이션에서 콘솔을 열 수도 있습니다. ⚠️ SafeKit로 두 노드를 모두 구성하려면 단일 브라우저를 사용하십시오. ℹ️ 웹 콘솔을 보호하려면 사용 설명서의 🛠️ [11. SafeKit 웹 서비스 보안](/ko/resources/safekit-user-guide-82/#https)을 참조하십시오. ![{{ .Get "app" }} 클러스터용 SafeKit 웹 콘솔](/wp-content/uploads/2024/03/01-login-large.png) ### 2. 노드 주소 구성 {#2-configure-node-addresses} * 각 노드의 IP 주소를 입력합니다. 탭 키를 눌러 연결을 확인하고 노드 이름을 입력합니다. * `node1` 또는 `node2` 빨간색이면 브라우저가 두 노드에 모두 도달할 수 있는지 확인합니다. 각 노드의 방화벽을 확인합니다. 🛠️ [문제 해결](/ko/resources/safekit-user-guide-82/#Troubleshooting)을 참조하십시오. * 구성을 저장하려면 `Save and apply`. * 두 노드 모두 ✅ `Success` 표시되는지 확인하세요. * 노드에 ❌ `Failure` 표시되면 ▼ 패널을 확장하고 메시지를 읽으십시오. 도움이 필요하면 SafeKit AI 🤖 사용하십시오. ℹ️ 두 번째 하트비트 네트워크와 전용 복제 네트워크를 추가하려면 `LAN and nodes`에서 첫 번째 ➕ 버튼을 클릭합니다. ℹ️ `Advanced configuration` 클릭하여 file `cluster.xml` 봅니다. 콘솔이 이 파일을 채우고 두 노드 모두에 배포합니다. ![{{ .Get "app" }} 클러스터의 노드 주소](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. 모듈 선택 {#3-select-a-module} * `New module`에서 모듈 `{{ .Get "mod" }}.safe` 선택하십시오. ℹ️ 파란색 배너에서 🛜 `node1`은 콘솔에 연결된 노드입니다. 필요한 경우 요청을 `node2`로 전달합니다. ℹ️ 설치 중에 모듈 파일 `xxx.safe`를 추가한 경우 콘솔은 `node1`의 `Application_Modules/generic/` 디렉터리에서 해당 파일을 찾습니다. ![{{ .Get "app" }} 모듈을 선택하세요](/wp-content/uploads/2024/03/04-module-new.png) ### 4. 모듈 구성 {#4-configure-the-module} * `Module startup at boot` 모듈이 지연 없이 부팅 시 자동으로 시작되도록 설정합니다. * `Macros`/`SERVICES`에서 애플리케이션 서비스를 시작 순서대로 나열합니다. 이름은 쉼표로 구분합니다. * `Heartbeat networks`에서는 2단계에서 LAN을 추가하지 않은 경우 하트비트 네트워크를 하나 유지하세요. * `Virtual IP addresses`에 두 노드 모두와 동일한 서브넷의 가상 IP 주소를 입력합니다. * 애플리케이션 클라이언트가 이 가상 IP 주소 또는 DNS 이름을 사용하도록 구성합니다. * `Load balancing rules`에서 밸런싱할 서비스 포트(예: TCP 포트 9010)를 입력합니다. * `Load balancing rules`에서 `Source address` 또는 `Source port` 선택합니다 * `Source address`: 동일한 클라이언트의 모든 TCP 연결은 farm의 동일한 노드로 이동합니다. 이렇게 하면 해당 노드에서 클라이언트의 세션 컨텍스트가 유지됩니다. * `Source port`: 동일한 클라이언트의 TCP 연결은 farm 내의 다른 노드로 이동할 수 있습니다. 세션 컨텍스트는 노드 간에 공유되지 않습니다. * `Checkers`에서 필요한 경우 검사를 추가하세요. 프로세스 모니터링, 사용자 지정 검사, TCP, 핑 또는 스플릿 브레인 검사 등이 있습니다. * `Monitored processes/services`에 나열된 프로세스는 모니터링되며 실패하면 다시 시작됩니다. 프로세스 이름이 잘못되면 모듈이 시작 직후 중지됩니다. ℹ️ `Advanced configuration` 클릭하여 `userconfig.xml` 파일을 봅니다. 콘솔은 이 파일을 채우고 재시작 스크립트를 사용하여 두 노드 모두에 배포합니다. ℹ️ 클라우드 배포에서 🛠️ [클라우드 로드 밸런서는](/ko/resources/safekit-user-guide-82/#Cloud) 가상 IP 주소와 로드 밸런싱 규칙을 관리합니다. SafeKit에서 구성하지 마십시오. ℹ️ 구성을 적용하면 SafeKit Windows 서비스 시작 유형을 `Manual`으로 설정합니다. 서비스는 시스템 부팅 시가 아닌 모듈과 함께 시작됩니다. SafeKit은 또한 Linux에서 이러한 서비스가 시스템 부팅 시 시작되는 것을 방지합니다. ![{{ .Get "app" }} farm의 모듈 설정](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. 스크립트 편집(선택 사항) {#5-edit-scripts-optional} * 대부분의 경우 이 단계를 건너뛸 수 있습니다. 스크립트는 이미 이전 단계에 나열된 서비스를 다시 시작하도록 구성되어 있습니다. * 변경할 사항이 없으면 `Next step` 클릭하세요. * `start_both.ps1` 스크립트는 `SERVICES` 목록의 순서대로 서비스를 시작합니다. * `stop_both.ps1` 스크립트는 서비스를 역순으로 중지합니다. * `start_both.ps1` 스크립트는 각 서비스도 확인합니다. 서비스 시작에 실패하면 모듈을 중지합니다. ![{{ .Get "app" }} 모듈용 스크립트 다시 시작](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. 통신 암호화(선택 사항) {#6-communication-encryption-optional} * 노드 간 통신 암호화를 활성화 상태로 유지하세요. ![{{ .Get "app" }} 모듈의 통신 암호화](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. 저장 및 적용 {#7-save-and-apply} * `Save and apply` 클릭하여 두 노드 모두에 구성과 스크립트를 배포합니다. ![{{ .Get "app" }} 모듈에 대한 구성 배포](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. 구성 결과 확인 {#8-check-the-configuration-result} * 두 노드 모두 ✅ `Success` 표시되는지 확인합니다. 그런 다음 `Monitor modules` 클릭합니다. * 노드에 ❌ `Failure` 표시되면 ▼ 패널을 확장하고 메시지를 읽으십시오. 도움이 필요하면 SafeKit AI 🤖 사용하십시오. ![{{ .Get "app" }} 모듈 구성 결과](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. 노드 1과 노드 2에서 farm 클러스터 시작합니다 {#9-start-the-farm-cluster-on-node-1-and-node-2} * 이미지와 같이 ⋯ 메뉴를 열고 두 노드 모두에서 `Start` 선택합니다. ![두 노드에서 {{ .Get "app" }} 클러스터를 시작합니다](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. 두 노드 모두 `UP` (녹색) 상태가 될 때까지 기다립니다 {#10-wait-until-both-nodes-are-up-green}

두 노드 모두 UP (녹색) 상태에 도달해야 합니다. 이는 start_both 스크립트가 두 노드 모두에서 실행되었음을 의미합니다.

⚠️ 노드가 UP (녹색) 상태에 도달하지 않거나 애플리케이션이 시작되지 않으면 모듈 로그 🖼️ 를 확인하십시오.

* 모듈 로그를 열려면 `node1` 또는 `node2`의 🔍 아이콘을 클릭합니다. 모듈을 중지시킨 검사와 같은 오류를 찾습니다. * 로그에서 `start_both` 클릭합니다. 스크립트 출력이 오른쪽에 나타납니다. 서비스 시작 오류가 있는지 확인합니다. * 로그 메시지 관련 도움말은 SafeKit AI 🤖 이용하세요. ℹ️ 🕒 **[타임라인 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** 사용하여 클러스터의 이벤트 순서를 파악하세요. ![{{ .Get "app" }} 클러스터의 두 노드 모두 실행 중입니다](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. 테스트 {#11-testing} SafeKit은 모자이크 테스트가 내장되어 있습니다. [SafeKit farm 클러스터에서 부하 분산 가상 IP 주소 테스트](/ko/best-practises/test-load-balancing-vip-farm/)를 참조하십시오. ![모자이크 로 {{ .Get "app" }}의 가상 IP 주소를 테스트하세요](/wp-content/uploads/2024/03/appli-19.png) ℹ️ 자세한 내용과 동영상은 [SafeKit 온라인 교육](/ko/resources/safekit-on-line-training/)을 참조하세요. ### 12. 지원 {#12-support} * 지원을 받으려면 노드당 SafeKit `Snapshot` 하나씩 생성하세요. 2개의 .zip 파일을 수집하세요. ℹ️ 자세한 내용은 [SafeKit 지원팀에](/ko/resources/safekit-support/) 문의하세요. ![{{ .Get "app" }} 클러스터 스냅샷 지원](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
