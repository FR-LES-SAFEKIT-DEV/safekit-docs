SafeKit 웹 서비스 보안 ](/resources/safekit-user-guide-82/#https) 참조하세요. ![ {{ .Get "app" }} 클러스터용 SafeKit 웹 콘솔 ](/wp-content/uploads/2024/03/01-login-large.png) ### 2. 노드 주소 구성 * 각 노드의 IP 주소를 입력하십시오. Tab 키를 눌러 연결 상태를 확인하고 노드 이름을 입력하십시오. * `node1` 또는 `node2` 빨간색으로 표시되면 브라우저가 두 노드 모두에 연결할 수 있는지 확인하십시오. 각 노드의 방화벽을 확인하십시오. 🛠️ [문제 해결 ](/resources/safekit-user-guide-82/#Troubleshooting) 참조하십시오. * 설정을 저장하려면 `Save and apply` 클릭하세요. * 두 노드 모두 ✅ `Success` 표시되는지 확인하십시오. * 노드에 ❌ `Failure` 표시가 나타나면 ▼ 패널을 확장하여 메시지를 읽으세요. 도움이 필요하면 SafeKit AI 🤖를 사용하세요. ℹ️ 두 번째 하트비트 네트워크와 전용 복제 네트워크를 추가하려면 `LAN and nodes` 에서 선택하세요 * `New module` 에서 모듈 `{{ .Get "mod" }}.safe` 선택합니다. ℹ️ 파란색 배너에서 🛜 `node1` 은 콘솔에 연결된 노드입니다. 필요에 따라 `node2` 로 요청을 전달합니다. ℹ️ 설치 중에 `xxx.safe` 라는 모듈 파일을 추가했다면 콘솔은 `node1` 의 `Application_Modules/generic/` 디렉토리에서 해당 파일을 찾습니다. ![ {{ .Get "app" }} 에 대한 모듈을 선택하세요 ](/wp-content/uploads/2024/03/04-module-new.png) ### 4. 모듈을 구성합니다. * `Module startup at boot` 에서 모듈이 지연 없이 부팅 시 자동으로 시작되도록 설정합니다. * `Macros` / `SERVICES` 에서 애플리케이션 서비스를 시작 순서대로 나열합니다. 이름은 쉼표로 구분합니다. * `Heartbeat networks` 에서는 2단계에서 LAN 추가하지 않은 경우 하나의 하트비트 네트워크만 유지하십시오. * `Virtual IP addresses` 필드에는 두 노드와 동일한 서브넷에 있는 가상 IP 주소를 입력하십시오. * 애플리케이션 클라이언트가 이 가상 IP 주소 또는 DNS 이름을 사용하도록 구성하십시오. * `Load balancing rules` 에서 밸런싱할 서비스 포트를 입력합니다. 예를 들어 TCP 포트 9010을 입력합니다. * `Load balancing rules` 에서 `Source address` 또는 `Source port` 선택하십시오. * `Source address` : 동일한 클라이언트에서 발생하는 모든 TCP 연결은 farm 내의 동일한 노드로 이동합니다. 이렇게 하면 해당 노드에서 클라이언트의 세션 컨텍스트가 유지됩니다. * `Source port` : 동일한 클라이언트에서 발생하는 TCP 연결은 farm 내의 서로 다른 노드로 전송될 수 있습니다. 세션 컨텍스트는 노드 간에 공유되지 않습니다. * `Checkers` 에서 필요에 따라 프로세스 모니터링, 사용자 지정 검사, TCP , ping 또는 스플릿 브레인 검사와 같은 검사를 추가하십시오. * `Monitored processes/services` 목록에 있는 프로세스는 모니터링되며, 오류가 발생하면 다시 시작됩니다. 프로세스 이름이 잘못되면 모듈은 시작 직후 즉시 중지됩니다. ℹ️ `Advanced configuration` 클릭하여 `userconfig.xml` 파일을 확인하세요. 콘솔은 이 파일을 채우고 재시작 스크립트를 사용하여 두 노드 모두에 배포합니다. ℹ️ 클라우드 배포 환경에서는 🛠️ [클라우드 로드 밸런서 ](/resources/safekit-user-guide-82/#Cloud) 가 가상 IP 주소와 로드 밸런싱 규칙을 관리합니다. SafeKit 에서 이러한 설정을 구성하지 마십시오. ℹ️ 설정을 적용하면 SafeKit Windows 서비스 시작 유형을 `Manual` 으로 설정합니다. 서비스는 시스템 부팅 시가 아닌 모듈 실행 시에 시작됩니다. SafeKit 또한 Linux 에서 이러한 서비스가 시스템 부팅 시 시작되는 것을 방지합니다. ![모듈 설정 {{ .Get "app" }} farm ](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. 스크립트 편집 (선택 사항) * 대부분의 경우 이 단계를 건너뛸 수 있습니다. 스크립트는 이미 이전 단계에서 나열된 서비스를 다시 시작하도록 구성되어 있습니다. * 변경할 사항이 없으면 `Next step` 클릭하세요. * `start_both.ps1` 스크립트는 `SERVICES` 목록에 있는 순서대로 서비스를 시작합니다. * `stop_both.ps1` 스크립트는 서비스를 역순으로 중지합니다. * `start_both.ps1` 스크립트는 각 서비스를 점검합니다. 서비스 시작에 실패하면 모듈을 중지합니다. ![ {{ .Get "app" }} 모듈에 대한 재시작 스크립트 ](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. 통신 암호화 (선택 사항) * 노드 간 통신 암호화를 활성화 상태로 유지하십시오. ![ {{ .Get "app" }} 모듈에 대한 통신 암호화 ](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. 저장 후 적용 * `Save and apply` 클릭하여 구성 및 스크립트를 두 노드 모두에 배포하십시오. ![모듈 {{ .Get "app" }} 에 대한 구성 배포 ](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. 구성 결과를 확인합니다. * 두 노드 모두 ✅ `Success` 표시되는지 확인한 다음, `Monitor modules` 클릭하세요. * 노드에 ❌ `Failure` 표시가 나타나면 ▼ 패널을 확장하여 메시지를 읽으세요. 도움이 필요하면 SafeKit AI 🤖를 사용하세요. ![모듈 {{ .Get "app" }} 에 대한 구성 결과 ](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. 노드 1과 노드 2에서 farm 클러스터를 시작합니다. * ⋯ 메뉴를 열고 이미지에 표시된 대로 두 노드 모두에서 `Start` 선택합니다. ![두 노드 모두에서 {{ .Get "app" }} 클러스터를 시작합니다 ](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. 두 노드 모두 `UP` (녹색)될 때까지 기다립니다.

두 노드 모두 UP (녹색) 상태에 도달해야 합니다. 이는 start_both 스크립트가 두 노드 모두에서 실행되었음을 의미합니다.

⚠️ 노드가 UP (녹색) 상태가 되지 않거나 애플리케이션이 시작되지 않으면 해당 모듈 로그 🖼️ 를 확인하세요.

* `node1` 또는 `node2` 의 🔍 아이콘을 클릭하여 모듈 로그를 엽니다. 모듈 실행을 중단시킨 검사 오류와 같은 오류를 찾아보세요. * 로그에서 `start_both` 클릭합니다. 스크립트 출력 결과가 오른쪽에 나타납니다. 서비스 시작 오류를 확인하십시오. * 로그 메시지 관련 도움을 받으려면 SafeKit AI 🤖를 사용하세요. ℹ️ 클러스터에서 발생한 일련의 사건들을 이해하려면 🕒 ** [타임라인 🖼️ ](/wp-content/uploads/2026/05/safekit-console-timeline.png) ** 을 사용하세요. ![ {{ .Get "app" }} 클러스터의 두 노드가 모두 실행 중입니다 ](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. 테스트 SafeKit 내장된 모자이크 테스트가 포함되어 있습니다.
