{{/* Shortcode: insert-safekit-82-farm-configuration-pt-br — 9 instances in 9 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-network-load-balancing-and-failover.md */}} ### Pré-requisitos * Aplicativo {{ .Get "app" }} instalado em 2 nós (ou mais). * O balanceamento de carga por IP virtual exige que os nós estejam na mesma LAN ou em uma LAN estendida (L2) — redes L3 roteadas não são compatíveis (exceto com 🛠️ [balanceadores de carga na nuvem](/pt-br/resources/safekit-user-guide-82/#Cloud)). ### 1. Iniciar o console SafeKit * Inicie o console Web em um navegador em um nó do cluster, conectando-se a `http://localhost:9010`. * Digite `admin` como nome de usuário e a senha definida durante a instalação. Você também pode executar o console em um navegador em uma estação de trabalho fora do cluster. ⚠️ A configuração do SafeKit é feita nos dois nós usando um único navegador. ℹ️ Para proteger o console Web, consulte 🛠️ [11\. Proteção do serviço Web SafeKit](/pt-br/resources/safekit-user-guide-82/#https) no Guia do usuário. ![Inicie o console Web do SafeKit para configurar o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar os endereços dos nós * Digite os endereços IP dos nós, pressione `Tab key` para verificar a conectividade e preencha os nomes dos nós. Se node1 ou node2 aparecer em vermelho, verifique a conectividade do navegador com os dois nós e os firewalls de ambos; consulte 🛠️ [solução de problemas](/pt-br/resources/safekit-user-guide-82/#Troubleshooting). * Em seguida, clique em `Save and apply` para salvar a configuração. * Verifique se a mensagem `Success` ✅ aparece nos dois nós. * Se ocorrer `Failure` ❌ em um nó, abra o acordeão ▼ desse nó e examine as mensagens. Você também pode usar o SafeKit AI 🤖 para obter ajuda. ℹ️ Se desejar, você pode adicionar um novo `LAN and nodes` (o primeiro ➕) para criar um segundo heartbeat e uma rede de replicação dedicada. ℹ️ Ao clicar em `Advanced configuration`, o arquivo `cluster.xml` é exibido. O console preenche esse arquivo automaticamente e o implanta nos nós. ![Insira os nós do cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Selecionar um módulo * Em `New module`, clique no módulo `{{ .Get "mod" }}.safe`. ℹ️ No banner azul na parte superior, 🛜 `node1` representa o nó conectado ao console. Esse nó encaminha as solicitações para `node2` quando necessário. ℹ️ O console procura `xxx.safe` no diretório `Application_Modules/generic/` do nó de conexão (`node1`) se você tiver colocado um módulo ali durante a instalação. ![Selecione o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configurar o módulo * Em `Module startup at boot`, escolha a inicialização automática do módulo sem atraso durante a inicialização do sistema. * Em `Macros` / `SERVICES`, insira os nomes dos serviços do aplicativo na ordem de inicialização, separados por vírgulas. * Em `Heartbeat networks`, deve haver uma única rede de heartbeat, a menos que você tenha adicionado uma LAN na etapa 2. * Em `Virtual IP addresses`, insira um endereço IP virtual. Trata-se de um endereço IP padrão na mesma rede IP (sub-rede) que os endereços IP dos dois nós. Os clientes do aplicativo devem ser configurados com o endereço IP virtual (ou o nome DNS associado a ele). * Em `Load balancing rules`, defina a porta do serviço para balanceamento de carga (por exemplo, TCP 9010). * Em `Load balancing rules`, defina a regra de balanceamento de carga `Source address` ou `Source port`: * Com o endereço IP de origem do cliente, o mesmo cliente se conectará ao mesmo nó na `farm` em várias sessões TCP e recuperará o contexto nesse nó. * Com a porta TCP de origem do cliente, o mesmo cliente se conectará a nós diferentes na `farm` em várias sessões TCP (sem recuperar um contexto). * Em `Checkers`, você pode configurar verificadores quando necessário, como monitoramento de processos, verificadores personalizados, TCP, ping ou verificadores de split-brain. Por exemplo, se um nome de processo aparecer em `Monitored processes/services`, ele será monitorado e reiniciado em caso de falha. Um nome de processo incorreto fará o módulo parar logo após a inicialização. ℹ️ Ao clicar em `Advanced configuration`, o arquivo `userconfig.xml` é exibido. O console preenche esse arquivo automaticamente e o implanta nos nós junto com os scripts de reinicialização. ℹ️ Em uma implantação na nuvem, não é necessário configurar um endereço IP virtual nem regras de balanceamento de carga no SafeKit. O IP virtual e as regras de balanceamento são gerenciados no nível do 🛠️ [balanceador de carga na nuvem](/pt-br/resources/safekit-user-guide-82/#Cloud). ℹ️ Ao aplicar a configuração do SafeKit, o `startup type` dos serviços é definido automaticamente como `Manual` nos serviços do Windows. Assim, os serviços não são iniciados automaticamente com o sistema, mas somente quando o próprio módulo é iniciado (o mesmo se aplica ao Linux). ![Insira as configurações do módulo `farm` de {{ .Get "app" }}](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Editar scripts (opcional) * Esta etapa é opcional e pode ser ignorada na maioria dos casos, pois os scripts de reinicialização já estão configurados para reiniciar os serviços definidos na etapa anterior. * Clique diretamente em `Next step`. * `start_both.ps1` inicia todos os serviços na ordem especificada na lista `SERVICES`, enquanto `stop_both.ps1` os interrompe na ordem inversa. * Além disso, `start_both.ps1` verifica a inicialização de cada serviço e interrompe o módulo se algum serviço não iniciar corretamente. ![Insira as configurações do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Criptografia das comunicações (opcional) * Mantenha criptografadas as comunicações entre os nós. ![Criptografia das comunicações do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Salvar e aplicar * Use `Save and apply` para aplicar a configuração e os scripts nos dois nós. ![Salve e aplique a configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verificar se a configuração foi bem-sucedida * Verifique a mensagem `Success` ✅ nos dois nós e clique em `Monitor modules`. * Se ocorrer `Failure` ❌ em um nó, abra o acordeão ▼ desse nó e examine as mensagens. Você também pode usar o SafeKit AI 🤖 para obter ajuda. ![Verifique se a configuração do módulo {{ .Get "app" }} foi bem-sucedida](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Iniciar o cluster `farm` nos nós 1 e 2 * Clique em ⋯ `Start` para iniciar o cluster `farm`, conforme mostrado na imagem. ![Inicie o cluster {{ .Get "app" }} nos dois nós](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Aguardar os dois nós atingirem o estado UP (verde) Os nós 1 e 2 devem atingir o estado UP (verde), o que significa que o script `start_both` foi executado nos dois nós. ⚠️ Se o estado UP (verde) não for atingido ou se o aplicativo não iniciar, analise o motivo usando o [log do módulo 🖼️](/wp-content/uploads/2024/03/37-module-log-farm-script.png) do nó 1 ou do nó 2. * Clique no ícone 🔍 **log** de `node1` ou `node2` para abrir o log do módulo e procurar mensagens de erro, como um verificador que detecta um erro e interrompe o módulo. * Clique em `start_both` no log: as mensagens de saída do script aparecem à direita e podem revelar erros, como um serviço iniciado incorretamente. * Use o SafeKit AI 🤖 para obter ajuda com as mensagens do log. ℹ️ A 🕒 **[linha do tempo 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** também pode ajudar a entender o que acontece no cluster. ![O cluster {{ .Get "app" }} foi iniciado](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. Testes O SafeKit inclui um teste integrado ao produto: * Configure uma regra para a porta TCP 9010 com balanceamento de carga pela porta TCP de origem. * Conecte uma estação de trabalho externa, fora dos nós da `farm`. * Abra um navegador em http://virtual-ip:9010/safekit/mosaic.html. Você deverá ver um mosaico de cores, dependendo dos nós que responderem às solicitações HTTP. * Pare um nó UP (verde), rolando para baixo no menu de contexto e clicando em Stop. * Verifique se não há mais conexões TCP no nó parado nem no endereço IP virtual. ℹ️ Encontre mais detalhes e vídeos no [treinamento on-line do SafeKit](/pt-br/resources/safekit-on-line-training/). ![Teste o endereço IP virtual de {{ .Get "app" }} com o mosaico](/wp-content/uploads/2024/03/appli-19.png) ### 12. Suporte * Para obter suporte, tire 2 SafeKit `Snapshots` (2 arquivos .zip), um para cada nó. ℹ️ [Mais informações sobre o suporte aqui](/pt-br/resources/safekit-support/). ![Tire snapshots de {{ .Get "app" }} para obter suporte](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
