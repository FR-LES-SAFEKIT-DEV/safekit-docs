Redes roteadas de camada 3 requerem 🛠️ [balanceadores de carga em nuvem ](/resources/safekit-user-guide-82/#Cloud) . ### 1. Inicie o console SafeKit * Em um nó do cluster, abra um navegador e conecte-se a `http://localhost:9010` . * Faça login com o nome de usuário `admin` e a senha definida durante a instalação. Você também pode abrir o console a partir de uma estação de trabalho fora do cluster. ⚠️ Use um único navegador para configurar ambos os nós com SafeKit . ℹ️ Para proteger o console da web, consulte 🛠️ [11\. Protegendo o serviço web SafeKit ](/resources/safekit-user-guide-82/#https) no Guia do Usuário. ![ Console web SafeKit para o cluster {{ .Get "app" }} ](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar endereços de nó * Insira o endereço IP de cada nó. Pressione a tecla Tab para verificar a conexão e preencha os nomes dos nós. * Se `node1` ou `node2` estiver vermelho, verifique se o navegador consegue acessar ambos os nós. Verifique o firewall em cada nó. Consulte 🛠️ [solução de problemas ](/resources/safekit-user-guide-82/#Troubleshooting) . * Clique em `Save and apply` para salvar a configuração. * Verifique se ambos os nós exibem ✅ `Success` . * Se um nó exibir ❌ `Failure` , expanda o painel ▼ e leia as mensagens. Use a IA SafeKit 🤖 se precisar de ajuda. ℹ️ Para adicionar uma segunda rede de heartbeat e uma rede de replicação dedicada, clique no primeiro botão ➕ em `LAN and nodes` . ℹ️ Clique em `Advanced configuration` para visualizar o arquivo `cluster.xml` . O console preenche este arquivo e o implanta em ambos os nós. ![Endereços de nós para o cluster {{ .Get "app" }} ](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Selecione um módulo * Em `New module` , selecione o módulo `{{ .Get "mod" }}.safe` . ℹ️ Na faixa azul, 🛜 `node1` é o nó conectado ao console. Ele encaminha as solicitações para `node2` quando necessário. ℹ️ Se você adicionou um arquivo de módulo `xxx.safe` durante a instalação, o console o procura no diretório `Application_Modules/generic/` no `node1` . ![Escolha o módulo para {{ .Get "app" }} ](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configure o módulo * Em `Module startup at boot` , configure o módulo para iniciar automaticamente na inicialização do sistema, sem demora. * Em `Macros` / `SERVICES` , liste os serviços do aplicativo na ordem de inicialização. Separe os nomes com vírgulas. * Em `Heartbeat networks` , mantenha uma única rede Heartbeat, a menos que você tenha adicionado uma LAN na etapa 2. * Em `Virtual IP addresses` , insira um endereço IP virtual na mesma sub-rede que ambos os nós. * Configure os clientes da aplicação para usarem este endereço IP virtual ou o seu nome DNS . * Nas `Load balancing rules` , insira a porta de serviço a ser balanceada, por exemplo, a porta TCP 9010. * Nas `Load balancing rules` , selecione `Source address` ou `Source port` : * `Source address` : todas as conexões TCP do mesmo cliente são direcionadas para o mesmo nó no farm . Isso preserva o contexto da sessão do cliente nesse nó. * `Source port` : as conexões TCP do mesmo cliente podem ser direcionadas para diferentes nós no farm . O contexto da sessão não é compartilhado entre os nós. * Em `Checkers` , adicione verificações conforme necessário: monitoramento de processos, verificações personalizadas, TCP , ping ou verificações de split-brain. * Um processo listado em `Monitored processes/services` é monitorado e reiniciado caso apresente falha. Um nome de processo incorreto faz com que o módulo seja interrompido imediatamente após a inicialização. ℹ️ Clique em `Advanced configuration` para visualizar o arquivo `userconfig.xml` . O console preenche este arquivo e o implanta em ambos os nós com os scripts de reinicialização. ℹ️ Em uma implantação na nuvem, o 🛠️ [balanceador de carga na nuvem ](/resources/safekit-user-guide-82/#Cloud) gerencia o endereço IP virtual e as regras de balanceamento de carga. Não os configure no SafeKit . ℹ️ Ao aplicar a configuração, SafeKit define o tipo de inicialização do serviço Windows como `Manual` . Os serviços são iniciados com o módulo, e não na inicialização do sistema. SafeKit também impede que esses serviços sejam iniciados na inicialização do sistema no Linux . ![Configurações do módulo para o farm {{ .Get "app" }} ](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Editar scripts (opcional) * Na maioria dos casos, você pode pular esta etapa. Os scripts já estão configurados para reiniciar os serviços listados na etapa anterior. * Clique em `Next step` se não forem necessárias alterações. * O script `start_both.ps1` inicia os serviços na ordem da lista `SERVICES` . * O script `stop_both.ps1` interrompe os serviços na ordem inversa. * O script `start_both.ps1` também verifica cada serviço. Ele interrompe o módulo se um serviço não for iniciado. ![Reiniciar scripts para o módulo {{ .Get "app" }} ](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Criptografia de comunicação (opcional) * Mantenha a criptografia de comunicação ativada entre os nós. ![Criptografia de comunicação para o módulo {{ .Get "app" }} ](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Salvar e aplicar * Clique em `Save and apply` para implantar a configuração e os scripts em ambos os nós. ![Implantação da configuração para o módulo {{ .Get "app" }} ](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verifique o resultado da configuração * Verifique se ambos os nós exibem ✅ `Success` . Em seguida, clique em `Monitor modules` . * Se um nó exibir ❌ `Failure` , expanda o painel ▼ e leia as mensagens. Use a IA SafeKit 🤖 se precisar de ajuda. ![Resultado da configuração para o módulo {{ .Get "app" }} ](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Inicie o cluster farm no nó 1 e no nó 2. * Abra o menu ⋯ e selecione `Start` em ambos os nós, como mostrado na imagem. ![Iniciar o cluster {{ .Get "app" }} em ambos os nós ](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Aguarde até que ambos os nós estejam `UP` (verdes).

Ambos os nós devem atingir o estado UP (verde). Isso significa que o script start_both foi executado em ambos os nós.

⚠️ Se um nó não atingir UP (verde) ou se o aplicativo não iniciar, verifique o log do módulo 🖼️ .

* Clique no ícone 🔍 do `node1` ou `node2` para abrir o registro do módulo. Procure por erros, como uma verificação que interrompeu o módulo. * No registro, clique em `start_both` . A saída do script aparecerá à direita. Verifique se há erros de inicialização do serviço. * Use a IA SafeKit 🤖 para obter ajuda com as mensagens de registro. ℹ️ Use a 🕒 ** [linha do tempo 🖼️ ](/wp-content/uploads/2026/05/safekit-console-timeline.png) ** para entender a sequência de eventos no cluster. ![Ambos os nós do cluster {{ .Get "app" }} estão em execução ](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11.
