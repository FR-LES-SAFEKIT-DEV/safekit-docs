{{/* Shortcode: insert-safekit-82-farm-configuration-pt-pt — 9 instances in 9 files */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-network-load-balancing-and-failover.md */}} ### Pré-requisitos * Aplicação {{ .Get "app" }} instalada em 2 nós (ou mais). * O balanceamento de carga por IP virtual exige que os nós estejam na mesma LAN ou numa LAN alargada (L2) — as redes L3 encaminhadas não são suportadas (exceto com 🛠️ [balanceadores de carga na nuvem](/resources/safekit-user-guide-82/#Cloud)). ### 1. Iniciar a consola SafeKit * Inicie a consola Web num navegador num nó do cluster, ligando-se a `http://localhost:9010`. * Introduza `admin` como nome de utilizador e a palavra-passe definida durante a instalação. Também pode utilizar a consola num navegador numa estação de trabalho externa ao cluster. ⚠️ A configuração do SafeKit é efetuada nos dois nós a partir de um único navegador. ℹ️ Para proteger a consola Web, consulte 🛠️ [11\. Proteger o serviço Web SafeKit](/resources/safekit-user-guide-82/#https) no Manual do utilizador. ![Inicie a consola Web SafeKit para configurar o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar os endereços dos nós * Introduza os endereços IP dos nós, prima `Tab key` para verificar a conectividade e indique os nomes dos nós. Se node1 ou node2 aparecer a vermelho, verifique a ligação do navegador a ambos os nós e as firewalls dos dois; consulte a 🛠️ [resolução de problemas](/resources/safekit-user-guide-82/#Troubleshooting). * Em seguida, clique em `Save and apply` para guardar a configuração. * Confirme que a mensagem `Success` ✅ aparece nos dois nós. * Se ocorrer `Failure` ❌ num nó, abra o painel ▼ desse nó e reveja as mensagens. Também pode utilizar o SafeKit AI 🤖 para obter ajuda. ℹ️ Se necessário, pode adicionar um novo `LAN and nodes` (o primeiro ➕) para criar um segundo heartbeat e uma rede de replicação dedicada. ℹ️ Ao clicar em `Advanced configuration`, é apresentado o ficheiro `cluster.xml`. A consola preenche-o automaticamente e implementa-o nos nós. ![Introduza os nós do cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Selecionar um módulo * Em `New module`, clique no módulo `{{ .Get "mod" }}.safe`. ℹ️ Na faixa azul no topo, 🛜 `node1` representa o nó ao qual a consola está ligada. Este nó encaminha os pedidos para `node2` quando necessário. ℹ️ A consola procura `xxx.safe` no diretório `Application_Modules/generic/` do nó de ligação (`node1`), caso tenha colocado aí um módulo durante a instalação. ![Escolha o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configurar o módulo * Em `Module startup at boot`, escolha o arranque automático do módulo sem atraso durante o arranque do sistema. * Em `Macros` / `SERVICES`, introduza os nomes dos serviços da aplicação pela ordem de arranque, separados por vírgulas. * Em `Heartbeat networks`, deverá existir uma única rede heartbeat, exceto se tiver adicionado uma LAN no passo 2. * Em `Virtual IP addresses`, introduza um endereço IP virtual. Trata-se de um endereço IP normal na mesma rede IP (sub-rede) que os endereços IP dos dois nós. Os clientes da aplicação devem ser configurados com o endereço IP virtual (ou o nome DNS associado). * Em `Load balancing rules`, defina a porta de serviço a equilibrar (por exemplo, TCP 9010). * Em `Load balancing rules`, defina a regra de balanceamento de carga `Source address` ou `Source port`: * Com o endereço IP de origem do cliente, o mesmo cliente será ligado ao mesmo nó na `farm` em várias sessões TCP e recuperará o seu contexto nesse nó. * Com a porta TCP de origem do cliente, o mesmo cliente será ligado a nós diferentes na `farm` em várias sessões TCP (sem recuperar um contexto). * Em `Checkers`, pode configurar verificações, se necessário, como monitorização de processos, verificações personalizadas, TCP, ping ou verificações de split-brain. Por exemplo, se for apresentado um nome de processo em `Monitored processes/services`, este será monitorizado e reiniciado em caso de falha. Um nome de processo incorreto fará com que o módulo pare imediatamente após o arranque. ℹ️ Ao clicar em `Advanced configuration`, é apresentado o ficheiro `userconfig.xml`. A consola preenche-o automaticamente e implementa-o nos nós juntamente com os scripts de reinício. ℹ️ Numa implementação na nuvem, não é necessário configurar um endereço IP virtual nem regras de balanceamento de carga no SafeKit. O IP virtual e as regras são geridos ao nível do 🛠️ [balanceador de carga na nuvem](/resources/safekit-user-guide-82/#Cloud). ℹ️ Ao aplicar a configuração do SafeKit, o `startup type` dos serviços é automaticamente definido como `Manual` nos serviços do Windows. Assim, os serviços não arrancam automaticamente com o sistema, mas apenas quando o próprio módulo é iniciado (o mesmo se aplica ao Linux). ![Introduza as definições do módulo `farm` de {{ .Get "app" }}](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Editar scripts (opcional) * Este passo é opcional e pode ser ignorado na maioria dos casos, uma vez que os scripts de reinício já estão configurados para reiniciar os serviços definidos no passo anterior. * Clique diretamente em `Next step`. * `start_both.ps1` inicia todos os serviços pela ordem indicada na lista `SERVICES`, enquanto `stop_both.ps1` os para pela ordem inversa. * Além disso, `start_both.ps1` verifica o arranque de cada serviço e para o módulo se algum serviço não arrancar corretamente. ![Introduza as definições do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Encriptação das comunicações (opcional) * Mantenha encriptadas as comunicações entre os nós. ![Encriptação das comunicações do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Guardar e aplicar * Utilize `Save and apply` para aplicar a configuração e os scripts nos dois nós. ![Guarde e aplique a configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verificar se a configuração foi bem-sucedida * Verifique a mensagem `Success` ✅ nos dois nós e clique em `Monitor modules`. * Se ocorrer `Failure` ❌ num nó, abra o painel ▼ desse nó e reveja as mensagens. Também pode utilizar o SafeKit AI 🤖 para obter ajuda. ![Verifique se a configuração do módulo {{ .Get "app" }} foi bem-sucedida](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Iniciar o cluster `farm` nos nós 1 e 2 * Clique em ⋯ `Start` para iniciar o cluster `farm`, conforme apresentado na imagem. ![Inicie o cluster {{ .Get "app" }} nos dois nós](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Aguardar que ambos os nós atinjam o estado UP (verde) Os nós 1 e 2 deverão atingir o estado UP (verde), o que significa que o script `start_both` foi executado nos dois nós. ⚠️ Se o estado UP (verde) não for atingido ou se a aplicação não arrancar, analise a causa utilizando o [registo do módulo 🖼️](/wp-content/uploads/2024/03/37-module-log-farm-script.png) do nó 1 ou do nó 2. * Clique no ícone 🔍 **log** de `node1` ou `node2` para abrir o registo do módulo e procurar mensagens de erro, por exemplo, um verificador que deteta um erro e para o módulo. * Clique em `start_both` no registo: as mensagens de saída do script são apresentadas à direita e permitem detetar erros, como um serviço iniciado incorretamente. * Utilize o SafeKit AI 🤖 para obter ajuda com as mensagens do registo. ℹ️ A 🕒 **[linha cronológica 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** também pode ajudar a compreender o que acontece no cluster. ![O cluster {{ .Get "app" }} foi iniciado](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. Testes O SafeKit inclui um teste integrado no produto: * Configure uma regra para a porta TCP 9010 com balanceamento de carga pela porta TCP de origem. * Ligue uma estação de trabalho externa, fora dos nós da `farm`. * Abra um navegador em http://virtual-ip:9010/safekit/mosaic.html. Deverá ver um mosaico de cores, consoante os nós que respondem aos pedidos HTTP. * Pare um nó UP (verde), percorrendo para baixo o respetivo menu contextual e clicando em Stop. * Verifique se já não existem ligações TCP no nó parado nem no endereço IP virtual. ℹ️ Encontre mais informações e vídeos na [formação online SafeKit](/pt-pt/resources/safekit-on-line-training/). ![Teste o endereço IP virtual de {{ .Get "app" }} com o mosaico](/wp-content/uploads/2024/03/appli-19.png) ### 12. Suporte * Para obter suporte, recolha 2 SafeKit `Snapshots` (2 ficheiros .zip), um por cada nó. ℹ️ [Mais informações sobre o suporte aqui](/pt-pt/resources/safekit-support/). ![Recolha snapshots de {{ .Get "app" }} para obter suporte](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
