As redes de camada 3 roteadas requerem [balanceadores de carga em nuvem](/pt-pt/resources/safekit-user-guide-82/#Cloud) 🛠️. ### 1. Inicie a consola SafeKit {#1-launch-the-safekit-console} * Num nó do cluster, abra um navegador e ligue-se a `http://localhost:9010`. * Inicie sessão com o nome de utilizador `admin` e a palavra-passe definida durante a instalação. Também é possível abrir a consola a partir de uma estação de trabalho externa ao cluster. ⚠️ Utilize um único navegador para configurar ambos os nós com SafeKit. ℹ️ Para proteger a consola web, consulte 🛠️ [11. Proteção do serviço web SafeKit](/pt-pt/resources/safekit-user-guide-82/#https) no Guia do Utilizador. ![Consola web SafeKit para o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar os endereços dos nós {#2-configure-node-addresses} * Introduza o endereço IP de cada nó. Pressione a tecla Tab para verificar a ligação e preencher os nomes dos nós. * Se `node1` ou `node2` estiverem vermelhos, verifique se o navegador consegue aceder a ambos os nós. Verifique a firewall em cada nó. Consulte a secção 🛠️ [resolução de problemas](/pt-pt/resources/safekit-user-guide-82/#Troubleshooting). * Clique em `Save and apply` para guardar a configuração. * Verifique se ambos os nós exibem ✅ `Success`. * Se um nó apresentar ❌ `Failure`, expanda o seu painel ▼ e leia as mensagens. Utilize a IA SafeKit 🤖 se precisar de ajuda. ℹ️ Para adicionar uma segunda rede de pulsações e uma rede de replicação dedicada, clique no primeiro botão ➕ em `LAN and nodes`. ℹ️ Clique em `Advanced configuration` para visualizar o ficheiro `cluster.xml`. A consola preenche este ficheiro e implementa-o em ambos os nós. ![Endereços dos nós para o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Selecione um módulo {#3-select-a-module} * No `New module`, selecione o módulo `{{ .Get "mod" }}.safe`. ℹ️ Na faixa azul, 🛜 `node1` é o nó ligado à consola. Ele encaminha os pedidos para `node2` quando necessário. ℹ️ Se adicionou um ficheiro de módulo `xxx.safe` durante a instalação, a consola procura-o no diretório `Application_Modules/generic/` no `node1`. ![Escolha o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configure o módulo {#4-configure-the-module} * No `Module startup at boot`, defina o módulo para iniciar automaticamente no arranque, sem demora. * Em `Macros`/`SERVICES`, liste os serviços da aplicação por ordem de inicialização. Separe os nomes com vírgulas. * Nas `Heartbeat networks`, mantenha uma rede de pulsações, a menos que tenha adicionado uma LAN no passo 2. * Em `Virtual IP addresses`, introduza um endereço IP virtual na mesma sub-rede que ambos os nós. * Configure os clientes da aplicação para usar este endereço IP virtual ou o seu nome DNS. * Em `Load balancing rules`, introduza a porta de serviço a balancear, por exemplo, a porta TCP 9010. * Em `Load balancing rules`, selecione `Source address` ou `Source port`: * `Source address`: todas as ligações TCP do mesmo cliente vão para o mesmo nó na farm. Isto preserva o contexto da sessão do cliente nesse nó. * `Source port`: As ligações TCP do mesmo cliente podem ir para diferentes nós na farm. O contexto da sessão não é partilhado entre os nós. * Em `Checkers`, adicione verificações se necessário: monitorização de processos, verificações personalizadas, TCP, ping ou verificações de divisão de rede. * Um processo listado em `Monitored processes/services` é monitorizado e reiniciado se falhar. Um nome de processo incorreto faz com que o módulo pare imediatamente após o arranque. ℹ️ Clique em `Advanced configuration` para visualizar o ficheiro `userconfig.xml`. A consola preenche este ficheiro e implementa-o em ambos os nós com os scripts de reinicialização. ℹ️ Numa implementação em nuvem, o [balanceador de carga da nuvem](/pt-pt/resources/safekit-user-guide-82/#Cloud) 🛠️ gere o endereço IP virtual e as regras de balanceamento de carga. Não os configure no SafeKit. ℹ️ Ao aplicar a configuração, SafeKit define o tipo de arranque do serviço Windows como `Manual`. Os serviços iniciam com o módulo, não no arranque do sistema. SafeKit também impede que estes serviços iniciem no arranque do sistema no Linux. ![Definições do módulo para o farm {{ .Get "app" }}](/wp-content/uploads/2025/05/36-module-farm-config-edit-1.jpg) ### 5. Editar os scripts (opcional) {#5-edit-scripts-optional} * Na maioria dos casos, pode ignorar este passo. Os scripts já estão configurados para reiniciar os serviços listados no passo anterior. * Clique em `Next step` se não forem necessárias alterações. * O script `start_both.ps1` inicia os serviços na ordem da lista `SERVICES`. * O script `stop_both.ps1` para os serviços em ordem inversa. * O script `start_both.ps1` também verifica cada serviço. Ele para o módulo se um serviço não conseguir iniciar. ![Reiniciar os scripts para o módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/35-module-iis-edit-script-1.png) ### 6. Criptografia da comunicação (opcional) {#6-communication-encryption-optional} * Mantenha a encriptação da comunicação ativada entre os nós. ![Criptografia de comunicação para o módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Guardar e aplicar {#7-save-and-apply} * Clique em `Save and apply` para implementar a configuração e os scripts em ambos os nós. ![Implementação da configuração para o módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verifique o resultado da configuração {#8-check-the-configuration-result} * Verifique se ambos os nós exibem ✅ `Success`. Em seguida, clique em `Monitor modules`. * Se um nó apresentar ❌ `Failure`, expanda o seu painel ▼ e leia as mensagens. Utilize a IA SafeKit 🤖 se precisar de ajuda. ![Resultado da configuração para o módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Inicie o cluster farm no nó 1 e no nó 2 {#9-start-the-farm-cluster-on-node-1-and-node-2} * Abra o menu ⋯ e selecione `Start` em ambos os nós, como mostrado na imagem. ![Inicie o cluster {{ .Get "app" }} em ambos os nós](/wp-content/uploads/2024/03/11-monitoring-farm-stop-stop-start.png) ### 10. Aguarde até que ambos os nós estejam `UP` (verdes) {#10-wait-until-both-nodes-are-up-green}

Ambos os nós devem atingir o estado UP (verde). Isto significa que o script start_both foi executado em ambos os nós.

⚠️ Se um nó não atingir UP (verde), ou se a aplicação não iniciar, verifique o registo do seu módulo 🖼️.

* Clique no ícone 🔍 do `node1` ou `node2` para abrir o registo do módulo. Procure erros, como uma verificação que parou o módulo. * No registo, clique em `start_both`. O resultado do script aparece à direita. Verifique se existem erros de inicialização do serviço. * Use o SafeKit AI 🤖 para obter ajuda com as mensagens de registo. ℹ️ Utilize a **[🖼️ do tempo](/wp-content/uploads/2026/05/safekit-console-timeline.png)** 🕒 para compreender a sequência de eventos no cluster. ![Ambos os nós do cluster {{ .Get "app" }} estão em execução](/wp-content/uploads/2024/03/15-monitoring-up-up.png) ### 11. Testes {#11-testing} SafeKit inclui um teste mosaico integrado. Consulte [Testar o endereço IP virtual de balanceamento de carga num cluster farm SafeKit](/pt-pt/best-practises/test-load-balancing-vip-farm/). ![Teste o endereço IP virtual da {{ .Get "app" }} com o mosaico](/wp-content/uploads/2024/03/appli-19.png) ℹ️ Consulte a [Formação Online SafeKit](/pt-pt/resources/safekit-on-line-training/) para mais detalhes e vídeos. ### 12. Apoio {#12-support} * Para obter suporte, crie uma `Snapshot` SafeKit por cada nó. Recolha os 2 ficheiros .zip. ℹ️ Consulte [o Suporte SafeKit](/pt-pt/resources/safekit-support/) para obter mais informações. ![Suporte para instantâneos do cluster {{ .Get "app" }}](/wp-content/uploads/2026/09/32-snapshots-network-load-balancing-cluster.png)
