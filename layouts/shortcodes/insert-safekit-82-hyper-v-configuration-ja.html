VM 内で重要なサービスに障害が発生した場合の自動再起動 {#17-automatic-restart-if-a-critical-service-fails-inside-the-vm} VM 内の重要なサービスに障害が発生した場合に自動再起動またはフェイルオーバーを行う場合は、サービスのリカバリプロパティを設定します（画像を参照）。 まず、前述の[VM カスタムチェッカー](#vm-checker)を設定する必要があります。 次に、VM 内の Microsoft Service Manager で、重要なサービスを選択し、そのサービスの回復プロパティで、重要なサービスが失敗したときに VM をシャットダウンするように構成します。 これを行うには、重要なサービスの回復オプションで、障害発生時に「**プログラムを実行する**」を選択します。プログラムの実行オプションで、プログラムとして `C:/Windows/System32/shutdown.exe` を設定し、コマンドラインパラメータとして `/s /c "service fails"` を設定します。 もちろん、独自のスクリプトでよりきめ細やかなリカバリを実装することも可能です。ただし、VM をシャットダウンすると、ホストでカスタムチェッカーが有効になることに注意してください。カスタムチェッカーは、{{ .Get "app" }}ハートビートが応答しなくなったことを検出します。その後、同じ {{ .Get "app" }} サーバーで VM を再起動するか、別の {{ .Get "app" }} サーバーにフェイルオーバーします（構成によって異なります）。 この機能をテストするには、タスクマネージャーを使用して、重要なサービスに関連付けられたプロセスを強制終了します (タスクの終了)。サービスマネージャーまたは「net stop」コマンドを使用してサービスを正常に停止しても、Windows サービスマネージャー内の回復アクションはトリガーされません。 ![重要なサービスに障害が発生した場合の {{ .Get "app" }} VM のフェイルオーバー](/wp-content/uploads/2023/11/hyperv-critical-service.png) ### 18. サポート {#18-support} * サポートを受けるには、ノードごとに 1 つずつ、合計 2 つの SafeKit `Snapshots`（2 つの .zip ファイル）を取得してください。 ℹ️ [サポートに関する詳細はこちら](/ja/resources/safekit-support/)。 ![サポートのために {{ .Get "app" }} スナップショットを撮る](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
