VM 내부에서 중요한 서비스에 장애가 발생하면 자동으로 다시 시작 VM 내부의 중요한 서비스에 오류가 발생할 때 자동으로 다시 시작하거나 장애 조치(failover)를 수행하려는 경우 서비스의 복구 속성을 구성할 수 있습니다(이미지 참조). 먼저 다음을 구성해야 합니다. [VM 커스텀 검사기](#vm-checker) 이전에 설명했습니다. 그런 다음 VM 내부의 Microsoft Service Manager에서 중요한 서비스를 선택하고 서비스의 복구 속성에서 중요한 서비스가 실패할 경우 VM 종료를 구성하기만 하면 됩니다. 이를 위해 중요한 서비스의 복구 옵션에서 "**프로그램 실행** "실패 시 프로그램 실행 옵션에서 설정"**C:/Windows/System32/shutdown.exe** " 및 "명령줄 매개변수"에서 설정합니다. **/s /c "서비스 실패"**. 물론, 자신만의 스크립트를 사용하여 보다 미묘한 복구를 구현할 수도 있습니다. 그러나 VM을 종료하면 호스트에서 사용자 지정 검사기가 활성화된다는 점에 유의하세요. 사용자 지정 검사기는 {{ .Get "app" }} 하트비트가 더 이상 응답하지 않음을 감지하고 동일한 {{ .Get "app" }} 서버에서 VM을 다시 시작하거나 다른 {{ .Get "app" }} 서버에서 장애 조치(failover)를 수행합니다(해당 구성에 따라 다름). 기능을 테스트하려면 작업 관리자를 사용하고 중요한 서비스와 관련된 프로세스(작업 종료)를 종료하십시오. Service Manager 또는 "net stop" 명령을 통한 서비스의 완전한 중지는 Windows Service Manager 내부의 복구 작업을 트리거하지 않습니다. ![{{ .Get "app" }} {{ .Get "app" }} 모듈의 VM 중요 서비스 장애 조치](/wp-content/uploads/2023/11/hyperv-critical-service.png) ### 18. 지원 * 지원을 받으려면 2 SafeKit를 이용하세요. `Snapshots` (2개의 .zip 파일), 각 노드당 하나씩. ℹ️ [지원에 대한 자세한 내용은 여기를 참조하세요.](/resources/safekit-support/). ![지원을 위해 {{ .Get "app" }} 스냅샷 가져오기](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
