心跳服务未响应该消息（VM 锁定、崩溃或停止运行），则自定义检查器将执行操作以在同一 {{ .Get "app" }} 节点或另一个节点上重新启动 VM。 * 点击 `Checkers / Custom` （见图）。 * 只需在其中设置您选择的名称即可 `Resource name` （例如 VM1）。 `Resource name` 标识资源名称为 SafeKit 的虚拟机： `custom.VM1`. * 与 `restart` 在 `Action`，VM 在同一 {{ .Get "app" }} 节点上重新启动。 24 小时内 3 次重启失败后，SafeKit {{ .Get "mod" }} 模块在主节点上停止，并且辅助节点上的虚拟机发生故障转移。 * 如果你设置 `stopstart` 在 `Action`，一旦 VM 不响应心跳，就会在另一个 {{ .Get "app" }} 节点上直接进行故障转移。 ℹ️为了维护，如果您想停止虚拟机，自定义检查器会自动重新启动它。为了避免这种情况，您可以暂时 [暂停检查器🖼️](/wp-content/uploads/2024/04/safekit-disable-checkers.png)。或者您可以通过删除控制台中的配置行来将其删除。 ℹ️当你想要恢复一个检查点时也是一样的。 {{ .Get "app" }} 将停止 VM 来执行该操作，并且 VM 检查器可能会通过自动重新启动 VM 来做出负面反应。为了避免这种情况， [暂停检查器🖼️](/wp-content/uploads/2024/04/safekit-disable-checkers.png) 在继续操作之前。 ℹ️ 默认情况下，自定义检查器允许虚拟机启动 50 秒，然后才认为其不可用。如果你的 {{ .Get "app" }} VM 需要更多时间来启动，您可以通过添加 - 来增加此延迟InitialGrace 到 vmcheck.ps1 自定义检查器 userconfig.xml。该值以 5 秒增量表示。例如，-InitialGrace 20 允许 100 秒的宽限期： ``. ![输入{{ .Get "app" 17. 如果虚拟机内关键服务出现故障，自动重启 如果您希望在虚拟机内的关键服务发生故障时自动重新启动或故障转移，您可以配置该服务的恢复属性（参见图片）。 首先您必须配置 [VM自定义检查器](#vm-checker) 前面已经描述过。 然后在虚拟机内的 Microsoft 服务管理器中，选择关键服务，并在服务的恢复属性中，只需配置关键服务失败时关闭虚拟机即可。 为此，在关键服务的恢复选项中，选择“**运行程序** “失败时并在运行程序选项中设置”**C:/Windows/System32/shutdown.exe** ”并在“命令行参数”中设置 **/s /c“服务失败”**. 当然，您可以使用自己的脚本实现更微妙的恢复。但请注意，关闭虚拟机将启用主机中的自定义检查器。自定义检查器将检测到 {{ .Get "app" }} 心跳不再响应，并将在同一 {{ .Get "app" }} 服务器上重新启动 VM，或在其他 {{ .Get "app" }} 服务器上进行故障转移（取决于其配置）。 要测试该功能，请使用任务管理器并终止与关键服务关联的进程（结束任务）。通过服务管理器或“net stop”命令彻底停止服务不会触发 Windows 服务管理器内的恢复操作。 ![{{ .Get "app" }} {{ .Get "app" }} 模块的 VM 关键服务故障转移](/wp-content/uploads/2023/11/hyperv-critical-service.png) ### 18. 支持 * 要获得支持，请获取 2 SafeKit `Snapshots` （2 个 .zip 文件），每个节点一个。 ℹ️ [有关支持的更多信息请参见此处](/resources/safekit-support/). ![拍摄 {{ .Get
