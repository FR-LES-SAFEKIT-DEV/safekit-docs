Hyper-V 节点之间的兼容性问题（硬件、网络、配置），请参阅本文档中的 🛠️ [KB SK-0088](https://github.com/FR-LES-SAFEKIT-DEV/safekit-packages/releases/download/v8.2/SafeKit_8.2_Knowledge_Base.pdf)。 ### 2. 启动 SafeKit 控制台 来增加此延迟。该值以 5 秒为增量表示。例如，-InitialGrace 20 允许 100 秒的宽限期：``。 ![输入 {{ .Get "app" }} 自定义检查器参数](/wp-content/uploads/2024/04/safekit-custom-checker-hyperv.png) ### 7. 编辑脚本（可选） {#7-edit-scripts-optional} * 虚拟机内关键服务发生故障时自动重启 {#17-automatic-restart-if-a-critical-service-fails-inside-the-vm} 如果虚拟机中的关键服务出现故障，您希望自动重启或故障转移，则可以配置服务的恢复属性（见图）。 首先，您必须配置前面描述的[VM 自定义检查器](#vm-checker)。 然后在虚拟机中的 Microsoft 服务管理器中，选择您的关键服务，并在服务的恢复属性中，您只需在关键服务失败时配置虚拟机的关闭。 为此，在关键服务的“恢复选项”中，选择“失败时**运行程序**”，在“运行程序选项”中，设置“**C:/Windows/System32/shutdown.exe**”，并在“命令行参数”中设置 **/s /c "service fails"**。 当然，您可以使用自己的脚本实现更精细的恢复。但请注意，关闭虚拟机将启用主机中的自定义检查器。自定义检查器将检测到 {{ .Get "app" }} 心跳不再响应，并将在同一 {{ .Get "app" }} 服务器上重新启动虚拟机，或在另一个 {{ .Get "app" }} 服务器上进行故障转移（具体取决于其配置）。 要测试此功能，请使用任务管理器并终止与关键服务关联的进程（结束任务）。通过服务管理器或“net stop”命令干净地停止服务不会触发 Windows 服务管理器中的恢复操作。 ![{{ .Get "app" }} 模块的 {{ .Get "app" }} 虚拟机关键服务故障转移](/wp-content/uploads/2023/11/hyperv-critical-service.png)
