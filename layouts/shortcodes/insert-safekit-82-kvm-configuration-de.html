Voraussetzungen {#prerequisite} Das VM1 Image der virtuellen Maschine befindet sich in der Datei `/var/lib/libvirt/images/vm1.qcow2`. Vor der Konfiguration SafeKit müssen Sie die folgende Konfiguration durchführen, um die virtuelle Maschine in ein vm1-spezifisches Verzeichnis zu legen, das von SafeKit repliziert wird. Auf Knoten 1: * vm1 stoppen: virsh shutdown vm1 * Erstellen Sie ein Verzeichnis `vm1/`: mkdir -p /var/lib/libvirt/images/vm1/ * Kopieren Sie das vm1 Image an den neuen Speicherort: cp -a /var/lib/libvirt/images/vm1.qcow2 /var/lib/libvirt/images/vm1/ Das ursprüngliche vm1 Image kann gelöscht werden, sobald die Tests mit dem neuen Speicherort erfolgreich waren. * Bearbeiten Sie die Konfigurationsdatei vm1: EDITOR=vi virsh edit vm1 Und ändern Sie die Zeile: von: * Stellen Sie in derselben Datei die [Cache-Option auf „keine“](/wp-content/uploads/2022/07/kvm-2.png), um die Datenintegrität im Falle eines Absturzes zu gewährleisten: * Schließen Sie die Konfigurationsdatei vm1 * [Automatischen Start vm1](/wp-content/uploads/2022/07/kvm-3.png) deaktivieren: virsh autostart vm1 --disable * Erstellen Sie eine Konfigurationsdatei `vm1.xml` für vm1: virsh dumpxml vm1 > vm1.xml Auf Knoten 2: * Kopieren Sie die Konfigurationsdatei `vm1.xml` von Knoten 1. Hinweis: Jedes Mal, wenn vm1 Konfiguration auf Knoten 1 geändert wird, müssen Sie die neue Konfiguration auf Knoten 2 erneut anwenden. * vm1 erstellen, aber nicht starten: virsh define vm1.xml * Automatischer Start vm1 deaktivieren: virsh autostart vm1 --disable * Erstellen Sie das Verzeichnis für den Bildspeicherort: mkdir -p /var/lib/libvirt/images/vm1/ ### 2. Starten Sie die SafeKit Konsole {#2-launch-the-safekit-console} * Starten Sie die Webkonsole in einem Browser auf einem Clusterknoten, indem Sie eine Verbindung zu `http://localhost:9010` herstellen. * Geben Sie als Benutzernamen `admin` und das während der Installation festgelegte Passwort ein. Sie können die Konsole auch in einem Browser auf einer Workstation außerhalb des Clusters ausführen. ⚠️ Die Konfiguration von SafeKit erfolgt auf beiden Knoten über einen einzigen Browser. ℹ️ Um die Webkonsole zu sichern, siehe 🛠️ [11. Sichern des SafeKit Webdienstes](/de/resources/safekit-user-guide-82/#https) im Benutzerhandbuch. ![Starten Sie die SafeKit Webkonsole, um den {{ .Get "app" }} Cluster zu konfigurieren](/wp-content/uploads/2024/03/01-login-large.png) ### 3. Knotenadressen konfigurieren {#3-configure-node-addresses} * Geben Sie die IP-Adressen der Knoten ein, drücken Sie die `Tab key`, um die Konnektivität zu überprüfen und die Knotennamen auszufüllen. Wenn entweder node1 oder node2 rot angezeigt wird, überprüfen Sie die Konnektivität des Browsers zu beiden Knoten und überprüfen Sie die Firewall auf beiden Knoten zur 🛠️ [Fehlerbehebung](/de/resources/safekit-user-guide-82/#Troubleshooting). * Klicken Sie anschließend auf `Save and apply` um die Konfiguration zu speichern. * Überprüfen Sie die `Success` ✅ auf beiden Knoten. * Wenn der `Failure` ❌ auf einem Knoten auftritt, öffnen Sie das ▼ Akkordeon für diesen Knoten und überprüfen Sie die Nachrichten. Beachten Sie, dass Sie die SafeKit AI 🤖 zur Unterstützung verwenden können. ℹ️ Wenn Sie möchten, können Sie ein neues `LAN and nodes` (erstes ➕) hinzufügen, um einen zweiten Heartbeat und ein dediziertes Replikationsnetzwerk zu erstellen. ℹ️ Wenn Sie auf `Advanced configuration` klicken, wird die Datei `cluster.xml` angezeigt. Diese Datei wird automatisch von der Konsole ausgefüllt und auf den Knoten bereitgestellt. ![Geben Sie die Knoten des {{ .Get "app" }} Clusters ein](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 4. Wählen Sie ein Modul aus {#4-select-a-module} * Klicken Sie im `New module` auf das Modul `{{ .Get "mod" }}.safe`. ℹ️ Im blauen Banner oben stellt 🛜 `node1` den Konsolenverbindungsknoten dar. Dieser Knoten leitet bei Bedarf Anfragen an `node2` weiter. ℹ️ Die Konsole sucht nach `xxx.safe` im Verzeichnis `Application_Modules/generic/` auf dem Verbindungsknoten (`node1`), wenn Sie dort während der Installation ein Modul platziert haben. ![Modul für die {{ .Get "app" }} auswählen](/wp-content/uploads/2024/03/04-module-new.png) ### 5. Modul konfigurieren {#5-configure-the-module} * Wählen Sie einen `Automatic` Start des Moduls beim Hochfahren ohne Verzögerung. * Normalerweise haben Sie ein einzelnes `Heartbeat` Netzwerk, auf dem die Replikation durchgeführt wird. Bei Bedarf können Sie jedoch ein privates Netzwerk definieren (indem Sie in Schritt 3 ein LAN hinzufügen). * Geben Sie unter `VM_PATH` den Stammverzeichnispfad des replizierten Verzeichnisses (`/var/lib/libvirt/images`) ein. * Geben Sie `VM_NAME`, den Namen der virtuellen Maschine (`vm1`), ein. Wir gehen davon aus, dass sich die VM1 Dateien in `/var/lib/libvirt/images/vm1/` befinden (siehe [Voraussetzungen](#prerequisite)). Dieses Verzeichnis wird von SafeKit in Echtzeit repliziert. ℹ️ Sie müssen keine virtuelle IP-Adresse konfigurieren. VM1 wird auf der sekundären {{ .Get "app" }} mit seiner physischen IP-Adresse neu gestartet, und diese IP-Adresse wird umgeleitet. ![Geben Sie die {{ .Get "app" }} Parameter ein](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png) ### 6. Benutzerdefinierter Prüfer zur Erkennung von VM-Fehlfunktionen {#6-custom-checker-to-detect-vm-malfunction} Der benutzerdefinierte Checker prüft, ob die VM läuft (mit dem Befehl ' virsh domstate'). Wenn die VM nicht läuft, startet der benutzerdefinierte Checker die VM automatisch auf demselben {{ .Get "app" }} Knoten oder auf dem anderen. * Klicken Sie auf `Checkers / Custom` (siehe Abbildung). * `Resource name` identifiziert die virtuelle Maschine mit einem Ressourcennamen in SafeKit: `custom.VM_NAME_check`. * Bei `restart` in `Action` wird die VM auf demselben {{ .Get "app" }} Knoten neu gestartet. Nach 3 erfolglosen Neustarts innerhalb von 24 Stunden stoppt das SafeKit {{ .Get "mod" }} Modul auf dem primären Knoten und es erfolgt ein Failover der VM auf den sekundären Knoten. * Wenn Sie `stopstart` in `Action` einstellen, erfolgt ein direkter Failover auf dem anderen {{ .Get "app" }} Knoten, sobald die VM nicht mehr läuft. ℹ️ Wenn Sie die virtuelle Maschine für Wartungszwecke anhalten möchten, startet der benutzerdefinierte Checker sie automatisch neu. Um dies zu vermeiden, können Sie [den Checker vorübergehend anhalten 🖼️](/wp-content/uploads/2024/04/safekit-disable-checkers.png). Oder Sie können ihn entfernen, indem Sie die Konfigurationszeile in der Konsole löschen. ![Geben Sie die Parameter für die benutzerdefinierte {{ .Get "app" }} Prüfung ein](/wp-content/uploads/2024/12/custom-kvm-checker-2.png) ### 7. Erfolgreiche Konfiguration überprüfen {#10-verify-successful-configuration} * Überprüfen Sie die `Success` ✅ auf beiden Knoten und klicken Sie auf `Monitor modules`. * Wenn der `Failure` ❌ auf einem Knoten auftritt, öffnen Sie das ▼ Akkordeon für diesen Knoten und überprüfen Sie die Nachrichten. Beachten Sie, dass Sie die SafeKit AI 🤖 zur Unterstützung verwenden können. ![Überprüfen Sie den Erfolg der {{ .Get "app" }}-Modulkonfiguration](/wp-content/uploads/2024/03/09-module-save-check.png) ### 11. Starten Sie den Knoten mit aktuellen Daten {#11-start-the-node-with-up-to-date-data} * Wenn Knoten 1 das aktuelle replizierte Verzeichnis für `vm1/` hat, wählen Sie es aus und ⋯ `Force start` ▶ `As primary`. Wenn Knoten 2 gestartet wird, werden alle Daten von Knoten 1 auf Knoten 2 kopiert. ⚠️ Wenn Sie die falsche Wahl treffen, laufen Sie Gefahr, veraltete Daten auf beiden Knoten zu synchronisieren. ⚠️ Es wird auch davon ausgegangen, dass `VM1` auf Knoten 1 gestoppt ist, sodass SafeKit die Replikationsmechanismen installiert und dann `VM1` im `start_prim`-Skript startet. ⚠️ Verwenden Sie `Start` für nachfolgende Starts: SafeKit behält den aktuellsten Server bei. Starten `As primary` ist ein spezieller Startvorgang beim ersten Mal oder bei außergewöhnlichen Vorgängen. ![Starten Sie den {{ .Get "app" }} Knoten mit den aktuellen Daten als primären Knoten](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 12. Warten Sie, bis die Anzeige auf ALONE (grün) wechselt {#12-wait-for-the-transition-to-alone-green} * Knoten 1 sollte den ALONE Zustand (grün) erreichen, was bedeutet, dass das `start_prim`-Skript auf Knoten 1 ausgeführt wurde. ⚠️ Wenn ALONE (grün) nicht erreicht wird oder wenn VM1 nicht gestartet wird, analysieren Sie den Grund mit dem [Modulprotokoll 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) von Knoten 1. * Klicken Sie auf das 🔍 **Protokollsymbol** von `node1`, um das Modulprotokoll zu öffnen und nach Fehlermeldungen zu suchen, z. B. wenn ein Prüfer einen Fehler erkennt und das Modul stoppt. * Klicken Sie im Protokoll auf `start_prim`: Die Ausgabemeldungen des Skripts werden rechts angezeigt und Fehler wie z. B. VM1 die nicht korrekt gestartet wurde, können erkannt werden. * Nutzen Sie die SafeKit AI 🤖 für Unterstützung bei Protokollnachrichten. ⚠️ Wenn sich der Cluster im Zustand `WAIT (red) not uptodate, STOP (red) not uptodate`, stoppen Sie den WAIT Knoten und [erzwingen Sie seinen Start als primär 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![Der erste {{ .Get "app" }} Knoten startet als primärer Knoten und wird ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 13. Startknoten 2 {#13-start-node-2} * ⋯ `Start` Knoten 2 mit seinem Kontextmenü. * Warten Sie auf den SECOND (grünen) Zustand. ℹ️ * Knoten 2 verbleibt im SECOND (orangen) Zustand, während die replizierten Verzeichnisse resynchronisiert werden (Kopie von Knoten 1 auf Knoten 2). * Dies kann je nach Größe der in replizierten Verzeichnissen zu resynchronisierenden Dateien und der Netzwerkbandbreite einige Zeit dauern. * Um den Fortschritt der Kopie zu sehen, siehe das [Modulprotokoll 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) und die [Replikationsressourcen 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) von Knoten 2. Verwenden Sie SafeKit AI 🤖 für Unterstützung bei Protokollmeldungen. ![Starten Sie den {{ .Get "app" }} Knoten 2](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 14. Überprüfen Sie, ob der Cluster betriebsbereit ist {#14-verify-that-the-cluster-is-operational} * Überprüfen Sie, ob der Cluster grün/grün ist, `VM1` auf dem PRIM Knoten läuft und nicht auf dem SECOND-Knoten. In diesem Zustand werden nur Änderungen innerhalb von Dateien in Echtzeit repliziert. ![Der {{ .Get "app" }} Knoten 2 ist SECOND (grün)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 15. Tests {#15-testing} * Stoppen Sie den PRIM-Knoten, indem Sie im Kontextmenü nach unten scrollen und auf `Stop` klicken. * Überprüfen Sie, ob auf dem SECOND Knoten ein Failover stattfindet, der ALONE (grün) sein sollte. * Überprüfen Sie mit {{ .Get "app" }} Tools, ob `VM1` auf Knoten 2 läuft. ⚠️ Wenn ALONE (grün) auf node2 nicht erreicht wird oder wenn VM1 nicht gestartet wird, analysieren Sie den Grund mit dem [Modulprotokoll 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) von Knoten 2. * Klicken Sie auf das 🔍 **Protokollsymbol** von `node2`, um das Modulprotokoll zu öffnen und nach Fehlermeldungen zu suchen, z. B. wenn ein Prüfer einen Fehler erkennt und das Modul stoppt. * Klicken Sie im Protokoll auf `start_prim`: Die Ausgabemeldungen des Skripts werden rechts angezeigt und Fehler wie z. B. VM1 die nicht korrekt gestartet wurde, können erkannt werden. * Nutzen Sie die SafeKit AI 🤖 für Unterstützung bei Protokollnachrichten. ⚠️ * Wenn alles in Ordnung ist, starten Sie einen Start auf node1, wodurch die replizierten Verzeichnisse von node2 erneut synchronisiert werden. * Wenn etwas schiefgeht, stoppen Sie node2 und [erzwingen Sie, dass Knoten 1 als primärer Knoten startet 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). Dieser wird dann mit seinen lokal intakten Daten zum Zeitpunkt des Stopps neu gestartet. ℹ️ Beachten Sie, dass Sie eine 🕒 **[Zeitleiste 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** haben, die hilfreich sein kann, um zu verstehen, was im Cluster passiert. ![Stoppen Sie das {{ .Get "app" }} Modul auf dem PRIM-Server](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 16. Konfigurieren Sie bei Bedarf einen Splitbrain-Checker {#16-if-necessary-configure-a-splitbrain-checker} * Informationen darüber, ob Sie einen Split-Brain-Checker konfigurieren müssen, finden Sie unter [„Welche verschiedenen Szenarien gibt es bei Netzwerktrennung in einem Cluster?“](/de/best-practises/power-outage-and-network-isolation-in-a-cluster/). * Gehen Sie zur Modulkonfiguration und klicken Sie auf `Checkers / Splitbrain` (siehe Abbildung), um die Splitbrain-Parameter zu bearbeiten. * `Save and apply` die neue Konfiguration an, um sie auf beiden Knoten erneut bereitzustellen (das Modul muss auf beiden Knoten gestoppt werden, um es zu speichern und anzuwenden). **Parameter**: * `Resource name` identifiziert den Witness mit einem Ressourcennamen: `splitbrain.witness`. Sie können diesen Wert ändern, um den Witness zu identifizieren. * `Witness address` ist das Argument für einen Ping, wenn ein Knoten von PRIM zu ALONE oder von SECOND zu ALONE wechselt. Ändern Sie diesen Wert mit der IP-Adresse des Witness (ein robustes Element, typischerweise ein Router). * Hinweis: Sie können mehrere IPs durch Leerzeichen getrennt einstellen. Achten Sie darauf, dass die IP-Adressen von einem Knoten aus zugänglich sein müssen, aber nicht von dem anderen im Falle einer Netzwerktrennung. ![Geben Sie die {{ .Get "app" }} Splitbrain-Parameter ein](/wp-content/uploads/2024/04/safekit-split-brain-checker.png) ### 17. Snapshots replizieren {#17-replicating-snapshots} Das Verzeichnis, das die XML-Dateien der Snapshots enthält, ist: /var/lib/libvirt/qemu/snapshot/%VM_NAME% wobei `VM_NAME` der Name der virtuellen Maschine (vm1) ist. Hinweis: Wenn kein Snapshot erstellt wurde, erstellen Sie einen, um das Verzeichnis zu generieren (andernfalls schlägt die SafeKit-Konfiguration fehl). So replizieren Sie es: * Klicken Sie in der Modulkonfiguration auf `Advanced Configuration` (siehe Abbildung), um `userconfig.xml` zu bearbeiten. * Fügen Sie die folgenden Zeilen in den ``-Abschnitt von userconfig.xml ein: * `Save and apply` die neue Konfiguration an, um die geänderte Datei userconfig.xml auf beiden Knoten erneut bereitzustellen (das Modul muss auf beiden Knoten gestoppt werden, um zu speichern und anzuwenden). * Erstellen Sie Snapshots auf dem PRIM Knoten entweder über virt-manager oder über die Befehlszeile: virsh snapshot-create-as vm1 snapshot-name Hinweis: Wenn Sie einen Snapshot über die Befehlszeile erstellen, müssen Sie die Snapshot-Ansicht in virt-manager aktualisieren. Auf dem PRIM Knoten erstellte Snapshots sind nach dem Failover auf Knoten 2 funktionsfähig, werden aber auf Knoten 2 nicht aufgelistet. * Um einen Snapshot auf Knoten 2 zu importieren, müssen Sie den folgenden Befehl ausführen: virsh snapshot-create --redefine vm1 /var/lib/libvirt/qemu/snapshot/vm1/snapshot-name * Die Befehlszeile zum Auflisten aller Snapshots von vm1 lautet: virsh snapshot-list vm1 ![Geben Sie die {{ .Get "app" }} Parameter ein](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png) ### 18.
