VM 오작동 감지를 위한 맞춤형 검사기 사용자 지정 검사기는 VM이 실행 중인지 확인합니다('virsh domstate' 명령 사용). VM이 실행되고 있지 않으면 사용자 지정 검사기가 동일한 {{ .Get "app" }} 노드 또는 다른 노드에서 VM을 자동으로 다시 시작합니다. * 클릭하세요 `Checkers / Custom` (이미지 참조). * `Resource name` SafeKit의 리소스 이름으로 가상 머신을 식별합니다. `custom.VM_NAME_check`. * 와 `restart` 안으로 `Action`, VM은 동일한 {{ .Get "app" }} 노드에서 다시 시작됩니다. 24시간 동안 3번의 재시작 실패 후 SafeKit {{ .Get "mod" }} 모듈이 기본 노드에서 중지되고 보조 노드에서 VM 장애 조치가 발생합니다. * 설정하면 `stopstart` 안으로 `Action`, VM이 실행되지 않는 즉시 다른 {{ .Get "app" }} 노드에서 직접 장애 조치가 수행됩니다. ℹ️ 유지 관리를 위해 가상 머신을 중지하려는 경우 사용자 지정 검사기가 자동으로 다시 시작합니다. 이를 방지하려면 일시적으로 [검사기 🖼️ 일시 중지](/wp-content/uploads/2024/04/safekit-disable-checkers.png). 또는 콘솔에서 구성 줄을 삭제하여 제거할 수 있습니다. ![{{ .Get "app" }} 사용자 정의 검사기 매개변수를 입력하세요.](/wp-content/uploads/2024/12/custom-kvm-checker-2.png) ### 7. 스크립트 편집(선택 사항) * 스크립트를 편집하지 마십시오. ### 8. 통신 암호화(선택) * 노드 간 통신 암호화를 유지합니다. ![{{ .Get "app" }} 모듈의 통신 암호화](/wp-content/uploads/2024/03/07-module-encryption.png) ### 9. 저장 및 적용 * `Save and apply` 두 노드 모두의 구성 및 스크립트. ![{{ .Get "app" }} 모듈 구성 저장 및 적용](/wp-content/uploads/2024/03/08-module-save.png) ### 10. 성공적인 구성 확인 * 확인해보세요 `Success` 두 노드 모두에 ✅ 메시지를 표시하고 다음을 클릭합니다. `Monitor modules`. * 구성의 경우 `Failure` ❌는 한 노드에서 발생하며 해당 노드에 대한 ▼ 아코디언을 열고 메시지를 검토합니다. 도움을 받으려면 SafeKit AI 🤖를 사용할 수 있습니다. ![{{ .Get "app" }} 모듈 구성 성공 확인](/wp-content/uploads/2024/03/09-module-save-check.png) ### 11. 최신 데이터로 노드 시작 * 노드 1에 대한 최신 복제 디렉터리가 있는 경우 `vm1/`, 그것을 선택하고 ⋯ `Force start` ▶ `As primary`. 노드 2가 시작되면 모든 데이터가 노드 1에서 노드 2로 복사됩니다. ⚠️ 잘못된 선택을 하면 두 노드에서 오래된 데이터가 동기화될 위험이 있습니다. ⚠️ 또한 다음과 같이 가정됩니다. `VM1` SafeKit가 복제 메커니즘을 설치한 다음 시작되도록 노드 1에서 중지되었습니다. `VM1` 에서 `start_prim` 스크립트. ⚠️ 사용 `Start` 후속 시작을 위해: SafeKit는 최신 서버를 유지합니다. 시작 `As primary` 특별한 스타트업이 처음으로 또는 예외적인 운영 중에 있는 경우입니다. ![최신 데이터를 사용하여 {{ .Get "app" }} 노드를 기본 노드로 시작합니다.](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 12.
