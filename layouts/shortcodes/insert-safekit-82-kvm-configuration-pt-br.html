Pré-requisitos {#prerequisite} A imagem da máquina virtual VM1 está no arquivo `/var/lib/libvirt/images/vm1.qcow2`. Antes de configurar SafeKit, você deve executar a seguinte configuração para colocar a máquina virtual em um diretório específico da vm1 que será replicado pelo SafeKit. No nó 1: * Parar vm1: virsh shutdown vm1 * Crie um diretório `vm1/`: mkdir -p /var/lib/libvirt/images/vm1/ * Copie a imagem vm1 para o novo local: cp -a /var/lib/libvirt/images/vm1.qcow2 /var/lib/libvirt/images/vm1/ A imagem original vm1 pode ser excluída assim que os testes com o novo local forem bem-sucedidos. * Edite o arquivo de configuração vm1: EDITOR=vi virsh edit vm1 E altere a linha: por: * Defina a [opção de cache como "nenhuma"](/wp-content/uploads/2022/07/kvm-2.png) no mesmo arquivo, para garantir a integridade dos dados em caso de falha: * Feche o arquivo de configuração vm1 * Desativar [o início automático da vm1](/wp-content/uploads/2022/07/kvm-3.png): virsh autostart vm1 --disable * Crie um arquivo de configuração `vm1.xml` para vm1: virsh dumpxml vm1 > vm1.xml No nó 2: * Copie o arquivo de configuração `vm1.xml` do nó 1. Observação: sempre que a configuração vm1 for alterada no nó 1, você deverá reaplicar a nova configuração no nó 2. * Crie vm1, mas não a inicie: virsh define vm1.xml * Desativar o início automático vm1: virsh autostart vm1 --disable * Crie o diretório para o local da imagem: mkdir -p /var/lib/libvirt/images/vm1/ ### 2. Inicie o console SafeKit {#2-launch-the-safekit-console} * Inicie o console da web em um navegador em um nó do cluster, conectando-se a `http://localhost:9010`. * Insira `admin` como nome de usuário e a senha definida durante a instalação. Você também pode executar o console em um navegador em uma estação de trabalho externa ao cluster. ⚠️ A configuração do SafeKit é feita em ambos os nós a partir de um único navegador. ℹ️ Para proteger o console da web, consulte 🛠️ [11. Protegendo o serviço da web SafeKit](/pt-br/resources/safekit-user-guide-82/#https) no Guia do Usuário. ![Inicie o console web SafeKit para configurar o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 3. Configurar endereços de nós {#3-configure-node-addresses} * Insira os endereços IP do nó, pressione a `Tab key` para verificar a conectividade e preencha os nomes dos nós. Se node1 ou node2 estiverem em vermelho, verifique a conectividade do navegador com ambos os nós e verifique o firewall em ambos os nós para 🛠️ [solucionar problemas](/pt-br/resources/safekit-user-guide-82/#Troubleshooting). * Em seguida, clique em `Save and apply` para salvar a configuração. * Verifique a mensagem `Success` ✅ em ambos os nós. * Se ocorrer uma `Failure` de configuração ❌ em um nó, abra o acordeão ▼ desse nó e revise as mensagens. Observe que você pode usar a IA SafeKit 🤖 para obter assistência. ℹ️ Se desejar, você pode adicionar uma nova `LAN and nodes` (primeiro ➕) para criar um segundo heartbeat e uma rede de replicação dedicada. ℹ️ Se você clicar em `Advanced configuration`, o arquivo `cluster.xml` será exibido. Este arquivo é preenchido automaticamente pelo console e implantado nos nós. ![Insira os nós do cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 4. Selecione um módulo {#4-select-a-module} * No `New module`, clique no módulo `{{ .Get "mod" }}.safe`. ℹ️ No banner azul na parte superior, 🛜 `node1` representa o nó de conexão do console. Este nó retransmite solicitações para `node2` quando necessário. ℹ️ O console procura por `xxx.safe` no diretório `Application_Modules/generic/` no nó de conexão (`node1`) se você colocou um módulo lá durante a instalação. ![Escolha o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 5. Configure o módulo {#5-configure-the-module} * Escolha o início `Automatic` do módulo na inicialização sem atraso. * Normalmente, você tem uma única rede `Heartbeat` na qual a replicação é feita. Mas, você pode definir uma rede privada, se necessário (adicionando uma LAN na etapa 3). * Insira em `VM_PATH` o caminho raiz do diretório replicado (`/var/lib/libvirt/images`). * Insira em `VM_NAME` o nome da máquina virtual (`vm1`). Assumimos que os arquivos VM1 estão em `/var/lib/libvirt/images/vm1/` (consulte [os pré-requisitos](#prerequisite)). Este diretório será replicado em tempo real pelo SafeKit. ℹ️ Você não precisa configurar um endereço IP virtual. VM1 será reiniciada no {{ .Get "app" }} secundário com seu endereço IP físico, e esse endereço IP será redirecionado. ![Insira os parâmetros {{ .Get "app" }}](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png) ### 6. Verificador personalizado para detetar o mau funcionamento da máquina virtual {#6-custom-checker-to-detect-vm-malfunction} O verificador personalizado verifica se a VM está em execução (com o comando ’virsh domstate’). Se a VM não estiver em execução, o verificador personalizado reinicia automaticamente a VM no mesmo nó {{ .Get "app" }} ou no outro. * Clique em `Checkers / Custom` (veja a imagem). * `Resource name` identifica a máquina virtual com um nome de recurso no SafeKit: `custom.VM_NAME_check`. * Com `restart` em `Action`, a VM é reiniciada no mesmo nó {{ .Get "app" }}. Após 3 reinicializações malsucedidas em 24 horas, o módulo SafeKit {{ .Get "mod" }} para no nó primário e ocorre um failover da VM no nó secundário. * Se você definir `stopstart` em `Action`, haverá um failover direto no outro nó {{ .Get "app" }} assim que a VM não estiver em execução. ℹ️ Para manutenção, se você quiser parar a máquina virtual, o verificador personalizado a reiniciará automaticamente. Para evitar isso, você pode [suspender temporariamente o verificador 🖼️](/wp-content/uploads/2024/04/safekit-disable-checkers.png). Ou você pode removê-lo excluindo a linha de configuração no console. ![Insira os parâmetros do verificador personalizado {{ .Get "app" }}](/wp-content/uploads/2024/12/custom-kvm-checker-2.png) ### 7. Editar scripts (opcional) {#7-edit-scripts-optional} * Não edite os scripts. ### 8. Salvar e aplicar {#9-save-and-apply} * `Save and apply` a configuração e os scripts em ambos os nós. ![Salve e aplique a configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2024/03/08-module-save.png) ### 10. Verifique se a configuração foi bem-sucedida {#10-verify-successful-configuration} * Verifique a mensagem `Success` ✅ em ambos os nós e clique em `Monitor modules`. * Se ocorrer uma `Failure` de configuração ❌ em um nó, abra o acordeão ▼ desse nó e revise as mensagens. Observe que você pode usar a IA SafeKit 🤖 para obter assistência. ![Verifique se a configuração do módulo {{ .Get "app" }} foi bem-sucedida](/wp-content/uploads/2024/03/09-module-save-check.png) ### 11. Inicie o nó com dados atualizados {#11-start-the-node-with-up-to-date-data} * Se o nó 1 tiver o diretório replicado atualizado para `vm1/`, selecione-o e ⋯ `Force start` ▶ `As primary`. Quando o nó 2 for iniciado, todos os dados serão copiados do nó 1 para o nó 2. ⚠️ Se você fizer a escolha errada, corre o risco de sincronizar dados desatualizados em ambos os nós. ⚠️ Também se presume que `VM1` está parada no nó 1 para que SafeKit instale os mecanismos de replicação e, em seguida, inicie `VM1` no script `start_prim`. ⚠️ Use `Start` para inícios subsequentes: SafeKit mantém o servidor mais atualizado. Iniciar `As primary` é um início especial na primeira vez ou durante operações excepcionais. ![Inicie o nó {{ .Get "app" }} como primário com os dados atualizados](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 12. Aguarde a transição para ALONE (verde) {#12-wait-for-the-transition-to-alone-green} * O nó 1 deve atingir o estado ALONE (verde), o que significa que o script `start_prim` foi executado no nó 1. ⚠️ Se ALONE (verde) não for atingido ou se VM1 não for iniciado, analise o motivo com o [log do módulo 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) do nó 1. * Clique no ícone **de log** 🔍 do `node1` para abrir o log do módulo e procure mensagens de erro, como um verificador que detecta um erro e interrompe o módulo. * Clique em `start_prim` no log: as mensagens de saída do script são exibidas à direita e os erros podem ser detectados, como VM1 iniciada incorretamente. * Use o SafeKit AI 🤖 para obter ajuda com as mensagens de log. ⚠️ Se o cluster estiver no estado `WAIT (red) not uptodate, STOP (red) not uptodate`, pare o nó WAIT e [force o seu início como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![O primeiro nó {{ .Get "app" }} inicia como primário e fica ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 13. Iniciar o nó 2 {#13-start-node-2} * ⋯ `Start` o nó 2 com o seu menu contextual. * Aguarde o SECOND estado (verde). ℹ️ * O nó 2 permanece no SECOND estado (laranja) enquanto resincroniza os diretórios replicados (cópia do nó 1 para o nó 2). * Isso pode levar algum tempo, dependendo do tamanho dos arquivos a serem resincronizados nos diretórios replicados e da largura de banda da rede. * Para ver o progresso da cópia, consulte o [log do módulo 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) e os [recursos de replicação 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) do nó 2. Use o SafeKit AI 🤖 para obter assistência com as mensagens de log. ![Inicie o nó 2 {{ .Get "app" }}](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 14. Verifique se o cluster está operacional {#14-verify-that-the-cluster-is-operational} * Verifique se o cluster está verde/verde com `VM1` em execução no nó PRIM e não em execução no nó SECOND. Apenas as alterações dentro dos arquivos são replicadas em tempo real neste estado. ![O nó {{ .Get "app" }} 2 é SECOND (verde)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 15. Testes {#15-testing} * Pare o nó PRIM rolando para baixo no menu contextual e clicando em `Stop`. * Verifique se há um failover no SECOND nó, que deve ficar ALONE (verde). * Verifique com as ferramentas {{ .Get "app" }} se `VM1` está sendo executada no nó 2. ⚠️ Se ALONE (verde) não for atingido no node2 ou se VM1 não for iniciada, analise o motivo com o [log do módulo 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) do nó 2. * Clique no ícone **de log** 🔍 do `node2` para abrir o log do módulo e procure mensagens de erro, como um verificador detectando um erro e interrompendo o módulo. * Clique em `start_prim` no log: as mensagens de saída do script são exibidas à direita e os erros podem ser detectados, como VM1 iniciada incorretamente. * Use o SafeKit AI 🤖 para obter ajuda com as mensagens de log. ⚠️ * Se tudo estiver bem, inicie o node1, que irá ressincronizar os diretórios replicados do node2. * Se as coisas derem errado, pare node2 e [force o nó 1 a iniciar como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png), que será reiniciado com seus dados localmente íntegros no momento da parada. ℹ️ Observe que você tem uma **[🖼️ linha do tempo](/wp-content/uploads/2026/05/safekit-console-timeline.png)** 🕒 que pode ser útil para entender o que acontece no cluster. ![Pare o módulo {{ .Get "app" }} no servidor PRIM](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 16. Se necessário, configure um verificador de divisão de cluster {#16-if-necessary-configure-a-splitbrain-checker} * Consulte ["Quais são os diferentes cenários em caso de isolamento de rede em um cluster?"](/pt-br/best-practises/power-outage-and-network-isolation-in-a-cluster/) para saber se você precisa configurar um verificador de divisão de rede. * Acesse a configuração do módulo e clique em `Checkers / Splitbrain` (veja a imagem) para editar os parâmetros do splitbrain. * `Save and apply` a nova configuração para reimplementá-la em ambos os nós (o módulo deve ser interrompido em ambos os nós para salvar e aplicar). **Parâmetros** : * `Resource name` identifica a testemunha com um nome de recurso: `splitbrain.witness`. Você pode alterar esse valor para identificar a testemunha. * `Witness address` é o argumento para um ping quando um nó passa de PRIM para ALONE ou de SECOND para ALONE. Altere este valor com o IP da testemunha (um elemento robusto, normalmente um roteador). * Observação: você pode definir vários IPs separados por espaços em branco. Observe que os endereços IP devem ser acessíveis a partir de um nó, mas não do outro, no caso de isolamento de rede. ![Insira os parâmetros de divisão de rede {{ .Get "app" }}](/wp-content/uploads/2024/04/safekit-split-brain-checker.png) ### 17.
