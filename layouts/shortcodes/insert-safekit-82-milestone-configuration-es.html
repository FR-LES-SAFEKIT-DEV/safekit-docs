Para versiones anteriores, 🛠️ [consulte este artículo](/es/quick-install/safekit-quick-installation-guide-old-milestone-configuration/). ### 1. Inicie la consola SafeKit {#1-launch-the-safekit-console} * Inicie la consola web en un navegador en un nodo del clúster conectándose a `http://localhost:9010`. * Introduzca `admin` como nombre de usuario y la contraseña definida durante la instalación. También puede ejecutar la consola en un navegador en una estación de trabajo externa al clúster. ⚠️ La configuración de SafeKit se realiza en ambos nodos desde un único navegador. ℹ️ Para proteger la consola web, consulte 🛠️ [11. Protección del servicio web SafeKit](/es/resources/safekit-user-guide-82/#https) en la Guía del usuario. ![Inicie la consola web SafeKit para configurar el clúster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar las direcciones de los nodos {#2-configure-node-addresses} * Introduzca las direcciones IP de los nodos, pulse la `Tab key` para comprobar la conectividad y rellene los nombres de los nodos. Si node1 o node2 tienen un color rojo, compruebe la conectividad del navegador con ambos nodos y compruebe el cortafuegos en ambos nodos para [solucionar problemas](/es/resources/safekit-user-guide-82/#Troubleshooting) 🛠️. * A continuación, haga clic en `Save and apply` para guardar la configuración. * Compruebe el mensaje `Success` ✅ en ambos nodos. * Si se muestra un mensaje `Failure` de configuración ❌ en un nodo, abra el acordeón ▼ de ese nodo y revise los mensajes. Tenga en cuenta que puede utilizar la IA SafeKit 🤖 para obtener ayuda. ℹ️ Si lo desea, puede agregar una nueva `LAN and nodes` (el primer ➕) para crear un segundo heartbeat y una red de replicación dedicada. ℹ️ Si hace clic en `Advanced configuration`, se mostrará el archivo `cluster.xml`. Este archivo se rellena automáticamente mediante la consola y se implementa en los nodos. ![Introduzca los nodos del clúster de la {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Seleccione un módulo {#3-select-a-module} * En `New module`, haga clic en el módulo `{{ .Get "mod" }}.safe`. ℹ️ En el banner azul de la parte superior, el nodo 🛜 `node1` representa el nodo de conexión de la consola. Este nodo retransmite las solicitudes al `node2` cuando es necesario. ℹ️ La consola busca `xxx.safe` en el directorio `Application_Modules/generic/` en el nodo de conexión (`node1`) si colocó un módulo allí durante la instalación. ![Selecciona el módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configurar el módulo {#4-configure-the-module} * En `Module startup at boot`, elija un inicio automático del módulo al arrancar sin demora. * En `Macros`/`SERVICES`, introduzca los nombres de los servicios de su aplicación, en el orden de inicio, separados por comas. Consulte esta captura de pantalla para ver un ejemplo visual de [los servicios Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * En `Heartbeat networks`, debe tener una única red heartbeat en la que se realiza la replicación. Si ha añadido una red privada en el paso 2, puede configurar dos heartbeats, con el flujo de replicación en la red privada. * En `Virtual IP addresses`, introduzca una dirección IP virtual. Una dirección IP virtual es una dirección IP estándar en la misma red IP (misma subred) que las direcciones IP de ambos nodos. Los clientes de la aplicación deben configurarse con la dirección IP virtual (o el nombre DNS asociado a la dirección IP virtual). La dirección IP virtual se conmuta automáticamente en caso de fallo. * En `Replicated directories`, establezca las rutas de los directorios que se van a replicar. Compruebe que existen en ambos nodos y que contienen los datos de la aplicación. La replicación de datos y de registros es esencial para una base de datos. Puede crear directorios replicados adicionales según sea necesario. Consulte esta captura de pantalla para ver un ejemplo visual de [la replicación SQL Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * En `Checkers`, puede configurar los comprobadores si es necesario, como la supervisión de procesos, los comprobadores personalizados, los comprobadores TCP, los comprobadores de ping o los comprobadores split brain. Por ejemplo, si un nombre de proceso se muestra en `Monitored processes/services`, se supervisará con una acción de reinicio en caso de fallo. La configuración de un nombre de proceso incorrecto hará que el módulo se detenga justo después de su inicio. ⚠️ Si SQL está en el servidor de administración: * Las [bases de datos del sistema SQL](https://learn.microsoft.com/en-us/sql/relational-databases/databases/system-databases) (como master.mdf y mastlog.ldf) deben estar ubicadas en los mismos directorios en ambos nodos. Los directorios deben configurarse como replicados. * SQL también debe estar instalado en la misma ubicación en el sistema de archivos de ambos nodos porque la [base de datos de recursos SQL](https://learn.microsoft.com/en-us/sql/relational-databases/databases/resource-database) de solo lectura se encuentra en el directorio binario de SQL y es necesaria para la conmutación por error. Esta base de datos no necesita ser replicada. * Las bases de datos SQL Milestone (.mdf y .ldf) deben estar ubicadas en los mismos directorios en ambos nodos. Los directorios deben configurarse como replicados. La lista de bases de datos Milestone se proporciona en este [artículo](https://doc.milestonesys.com/xprotect/xprotect-management-client/2026r1/en/change-the-location-and-name-of-a-sql-server-database.html). ℹ️ Si hace clic en `Advanced configuration`, se mostrará el archivo `userconfig.xml`. Este archivo se rellena automáticamente en la consola y se implementa en los nodos con los scripts de reinicio. ℹ️ Cuando se aplica la configuración SafeKit, el `startup type` de los servicios se establece automáticamente en `Manual` en los Servicios Windows. Esto garantiza que los servicios no se inicien automáticamente cuando el sistema arranca, sino que se inicien solo cuando se inicia el propio módulo. ![Acceda a la configuración del módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. Editar guiones (opcional) {#5-edit-scripts-optional} * Este paso es opcional y se puede omitir en la mayoría de los casos, ya que los scripts de reinicio ya están preconfigurados para reiniciar los servicios definidos en el paso anterior. * Por lo tanto, haga clic directamente en `Next step`. * `start_prim.ps1` inicia todos los servicios en el orden especificado en la lista `SERVICES` e inicia los `IIS application pools` utilizados por Milestone. `stop_prim.ps1` detiene todos los servicios en orden inverso. * Además, `start_prim.ps1` comprueba el inicio de cada servicio y detiene el módulo si algún servicio no se inicia correctamente. ![Acceda a la configuración del módulo {{ .Get "app" }}](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. Cifrado de la comunicación (opcional) {#6-communication-encryption-optional} * Mantenga el cifrado de la comunicación entre los nodos. ![Cifrado de la comunicación del módulo de la {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Guardar y aplicar {#7-save-and-apply} * Haga clic en `Save and apply` para guardar la configuración y los scripts en ambos nodos. ![Guarda y aplica la configuración del módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verifique que la configuración se haya realizado correctamente {#8-verify-successful-configuration} * Compruebe el mensaje `Success` ✅ en ambos nodos y haga clic en `Monitor modules`. * Si se muestra un mensaje `Failure` de configuración ❌ en un nodo, abra el acordeón ▼ de ese nodo y revise los mensajes. Tenga en cuenta que puede utilizar la IA SafeKit 🤖 para obtener ayuda. ![Compruebe que la configuración del módulo {{ .Get "app" }} se ha realizado correctamente](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Inicie el nodo con los datos actualizados {#9-start-the-node-with-up-to-date-data} * Si el nodo 1 tiene los directorios replicados actualizados, selecciónelo y ⋯ `Force start` ▶ `As primary`. Cuando se inicie el nodo 2, todos los datos se copiarán del nodo 1 al nodo 2. ⚠️ Si elige la opción incorrecta, corre el riesgo de sincronizar datos obsoletos en ambos nodos. ⚠️ También se supone que la aplicación {{ .Get "app" }} está detenida en el nodo 1 para que SafeKit instale los mecanismos de replicación y luego inicie la aplicación en el script `start_prim`. ⚠️ Utilice `Start` para los inicios posteriores: SafeKit conserva el servidor más actualizado. Utilice `As primary` solo para el primer inicio o durante operaciones excepcionales. ![Inicie el nodo {{ .Get "app" }} como primario con los datos actualizados](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Espere a que la transición sea a ALONE (verde) {#10-wait-for-the-transition-to-alone-green} * El nodo 1 debe alcanzar el estado ALONE (verde), lo que significa que la IP virtual está configurada y que el script `start_prim` se ha ejecutado en el nodo 1. ⚠️ Si no se alcanza ALONE (verde) o si no se inicia la aplicación, analice el motivo con el [registro del módulo 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) del nodo 1. * Haga clic en el icono **de registro** 🔍 del `node1` para abrir el registro del módulo y buscar mensajes de error, como un verificador que detecta un error y detiene el módulo. * Haga clic en `start_prim` en el registro: los mensajes de salida del script se muestran a la derecha y puede detectar errores, por ejemplo, si un servicio no se inició correctamente. * Utiliza la IA SafeKit 🤖 para obtener ayuda con los mensajes de registro. ⚠️ Si el estado del clúster es `WAIT (red) not uptodate, STOP (red) not uptodate`, detenga el nodo WAIT y [fuerce su inicio como primario 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![El primer nodo {{ .Get "app" }} se inicia como primario y se convierte en ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. Resolver el problema de autenticación Windows en la conmutación por error {#role} Cuando inicie el Management Client Milestone XProtect, deberá autenticarse utilizando uno de los siguientes métodos. Dependiendo de su elección, se requieren pasos específicos para asegurar que el inicio de sesión funcione después de una conmutación por error SafeKit. Consulte la [captura de pantalla de inicio de sesión 🖼️](/wp-content/uploads/2022/07/milestone-management-server-connect.png). #### Autenticación Windows con Active Directory (AD) {#windows-authentication-with-active-directory-ad} **Configuración:** No se requiere ninguna configuración especial. Si la autenticación Windows Milestone está configurada con un Active Directory, la información de usuario y contraseña se recupera del AD externo. Después de una conmutación por error, el nodo secundario se conecta al mismo AD, por lo que la autenticación funciona automáticamente. #### Autenticación Windows en grupo de trabajo {#windows-authentication-in-workgroup} **Configuración:** Debe agregar el grupo **BUILTIN/Administrators** en "Seguridad / Roles". **Advertencia:** En un grupo de trabajo, los usuarios locales tienen diferentes identificadores de seguridad (SID) en cada nodo, incluso si los nombres son idénticos. Solo el grupo BUILTIN/Administrators tiene el mismo SID en ambos nodos. * Al agregar este grupo, podrá autenticarse en el nodo secundario con cualquier cuenta de administrador local después de una conmutación por error. * Sin esto, la autenticación local Windows fallará en el nodo secundario porque los SID no coincidirán. #### Autenticación básica con base de datos SQL {#basic-authentication-with-sql-database} **Configuración:** cree un usuario con "autenticación básica" (por ejemplo, " Admin "). Para la "autenticación básica", las credenciales del usuario se almacenan directamente en la base de datos SQL. Debido a que SafeKit replica la base de datos SQL al nodo secundario en tiempo real, estos usuarios siempre están disponibles inmediatamente después de una conmutación por error. ![Establecer roles en el Management Client Milestone](/wp-content/uploads/2022/07/milestone-management-server-roles.png) ### 14. Iniciar nodo 2 {#14-start-node-2} * Inicie el nodo 2 con ⋯ `Start` en su menú contextual. * Espere al SECOND estado (verde). ℹ️ * El nodo 2 permanece en el SECOND estado (naranja) mientras se resincronizan los directorios replicados (copia del nodo 1 al nodo 2). * Esto puede tardar un tiempo, dependiendo del tamaño de los archivos que se van a resincronizar en los directorios replicados y del ancho de banda de la red. * Para ver el progreso de la copia, consulte el [registro del módulo 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) y los [recursos de replicación 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) del nodo 2. Utilice la IA SafeKit 🤖 para obtener ayuda con los mensajes de registro. ![Inicie el nodo 2 {{ .Get "app" }}](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 15. Compruebe que el clúster esté operativo {#15-verify-that-the-cluster-is-operational} * Compruebe que el clúster esté en verde/verde con los servicios {{ .Get "app" }} ejecutándose en el nodo PRIM y no en el nodo SECOND. * En este estado, solo los cambios dentro de los archivos se replican en tiempo real. ⚠️ * Registre los **servidores de grabación** con la dirección IP virtual. * Conecte el **Milestone Management Client** y el **Milestone Smart Client** en la dirección IP virtual. * Los componentes que son clientes de los servicios {{ .Get "app" }} deben configurarse con la dirección IP virtual. La configuración se puede realizar con un nombre DNS (si se ha creado un nombre DNS y se ha asociado con la dirección IP virtual). ![El nodo {{ .Get "app" }} 2 es SECOND (verde)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 16. Pruebas {#16-testing} * Detenga el nodo PRIM desplazándose hacia abajo en su menú contextual y haciendo clic en `Stop`. * Verifique que se produzca una conmutación por error en el nodo SECOND, que se convierte en ALONE (verde). * Con Microsoft Management Console (MMC) en Windows o con líneas de comando en Linux, compruebe la conmutación por error de los servicios {{ .Get "app" }} (detenidos en el nodo 1 en el script `stop_prim` e iniciados en el nodo 2 en el script `start_prim`). ⚠️ Si no se alcanza ALONE (verde) en el node2 o si la aplicación no se inicia, analice el motivo con el [registro del módulo 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) del nodo 2. * Haga clic en el icono **de registro** 🔍 del `node2` para abrir el registro del módulo y buscar mensajes de error, como un verificador que detecta un error y detiene el módulo. * Haga clic en `start_prim` en el registro: los mensajes de salida del script se muestran a la derecha y puede detectar errores, por ejemplo, si un servicio no se inició correctamente. * Utiliza la IA SafeKit 🤖 para obtener ayuda con los mensajes de registro. ⚠️ * Si todo está bien, inicie node1. Node1 resincronizará los directorios replicados desde node2. * Si algo sale mal, detenga node2 y [fuerce node1 a iniciarse como primario 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). Node1 se reinicia entonces con los datos locales que estaban sanos cuando se detuvo. ℹ️ Ten en cuenta que tienes una 🕒 **[línea de tiempo 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** que puede ser útil para entender lo que sucede en el clúster. ℹ️ Encuentre más detalles, junto con vídeos, en la [formación en línea SafeKit](/es/resources/safekit-on-line-training/). ![Detenga el módulo {{ .Get "app" }} en el servidor PRIM](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 17. Soporte {#17-support} * Para obtener soporte, haga dos `Snapshots` SafeKit (dos archivos .zip), una para cada nodo. ℹ️ [Más información sobre el soporte aquí](/es/resources/safekit-support/). ![Realice SafeKit snapshots del clúster {{ .Get "app" }} para obtener soporte](/wp-content/uploads/2024/03/30-snapshots-mirror.png)
