の起動時には、以下のいずれかの方法で認証する必要があります。選択した方法に応じて、SafeKit のフェイルオーバー後もログインできるようにするための手順が必要です。参考：[ログイン画面を表示 🖼️](/wp-content/uploads/2022/07/milestone-management-server-connect.png)。 #### Active Directory (AD) を使用した Windows 認証 **構成：** 特別な構成は必要ありません。 Milestone の "Windows authentication" が Active Directory を使用するよう構成されている場合、ユーザー名とパスワードの情報は外部 AD から取得されます。フェイルオーバー後、セカンダリノードは同じ AD に接続するため、認証は自動的に機能します。 #### ワークグループでの Windows 認証 **構成：** "Security / Roles" に **BUILTIN/Administrators** グループを追加する必要があります。 **警告：** ワークグループでは、名前が同一でも、ローカルユーザーのセキュリティ識別子（SID）はノードごとに異なります。両方のノードで同じ SID を持つのは BUILTIN/Administrators グループだけです。 * このグループを追加すると、フェイルオーバー後に任意のローカル管理者アカウントでセカンダリノードに認証できます。 * 追加しない場合、SID が一致しないため、セカンダリノードでのローカル Windows 認証は失敗します。 #### SQL データベースによる基本認証 **構成：** "Basic authentication" を使用するユーザー（例："Admin"）を作成します。 "Basic authentication" では、ユーザーの資格情報は SQL データベースに直接保存されます。SafeKit が SQL データベースをセカンダリノードへリアルタイムに複製するため、これらのユーザーはフェイルオーバー直後から常に利用できます。 ![Milestone Management Client でロールを設定](/wp-content/uploads/2022/07/milestone-management-server-roles.png) ### 14. ノード 2 を開始します * ⋯ `Start` ノード 2 とそのコンテキスト メニュー。 * SECOND (緑色) 状態になるまで待ちます。 ℹ️ * 複製されたディレクトリ (ノード 1 からノード 2 へのコピー)
