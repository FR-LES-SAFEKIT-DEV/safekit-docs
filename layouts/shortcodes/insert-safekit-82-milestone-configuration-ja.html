が一致しないため、セカンダリノードでローカルの Windows 認証が失敗します。 #### SQL データベースによる基本認証 {#basic-authentication-with-sql-database} **設定：**「基本認証」でユーザーを作成します (例：「Admin」)。 「基本認証」の場合、ユーザー認証情報は SQL データベースに直接保存されます。SafeKit SQL で開始します)。 ⚠️ node2 で ALONE（緑）に到達しない場合、またはアプリケーションが起動しない場合は、ノード 2 の[モジュールログ 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png)で原因を分析してください。 * `node2` の 🔍**ログ**アイコンをクリックしてモジュールログを開き、チェッカーがエラーを検出してモジュールを停止するなどのエラーメッセージを探します。 * ログの `start_prim` をクリックします。スクリプトの出力メッセージが右側に表示され、サービスが正しく起動していないなどのエラーを検出できます。 * ログメッセージについては、SafeKit AI 🤖 をご利用ください。 ⚠️ * すべて問題なければ、node1 で開始すると、node2 からレプリケートされたディレクトリが再同期されます。 * 問題が発生した場合は、node2 停止し、node1 を[プライマリとして強制的に起動します 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png)。これにより、停止時のローカルに正常なデータで再起動します。 ℹ️ クラスターで何が起こっているかを理解するのに役立つ 🕒**[タイムライン 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** があることに注意してください。 ℹ️ 詳細と動画については、[SafeKit オンライン研修](/ja/resources/safekit-on-line-training/)をご覧ください。 ![PRIM サーバーで {{ .Get "app" }}
