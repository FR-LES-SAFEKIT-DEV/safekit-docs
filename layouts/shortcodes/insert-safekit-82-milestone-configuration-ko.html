SafeKit 웹 서비스 보안](/ko/resources/safekit-user-guide-82/#https)을 참조하십시오. ![SafeKit 웹 콘솔을 시작하여 {{ .Get "app" }} 클러스터를 구성합니다](/wp-content/uploads/2024/03/01-login-large.png) ### 2. 노드 주소 구성 {#2-configure-node-addresses} * 노드 IP 주소를 입력하고 `Tab key` 눌러 연결을 확인한 후 노드 이름을 입력합니다. node1 또는 node2 빨간색으로 표시되면 브라우저와 두 노드 간의 연결을 확인하고 두 노드의 방화벽에서 🛠️ [문제 해결](/ko/resources/safekit-user-guide-82/#Troubleshooting)을 확인하십시오. * 그런 다음, 구성을 저장하려면 `Save and apply`을 클릭합니다. * 두 노드 모두에서 `Success` ✅ 메시지를 확인하세요. * 한 노드에서 구성 `Failure` ❌ 가 발생하면 해당 노드의 ▼ 아코디언을 열고 메시지를 검토하십시오. [Milestone XProtect SQL 복제의 시각적 예시는 이 스크린샷을 참조하세요 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * `Checkers`에서 필요한 경우 프로세스 모니터링, 사용자 지정 체커, TCP, ping 또는 분할 브레인 체커와 같은 체커를 구성할 수 있습니다. 예를 데이터베이스](https://learn.microsoft.com/en-us/sql/relational-databases/databases/system-databases) (master.mdf 및 mastlog.ldf 등)는 두 노드 모두에서 동일한 디렉터리에 있어야 합니다. 디렉터리는 복제되도록 구성되어야 합니다. * 읽기 전용 [SQL 리소스 데이터베이스는](https://learn.microsoft.com/en-us/sql/relational-databases/databases/resource-database) 바이너리에 있으며 장애 조치에 필요하므로 SQL은 두 노드 모두의 파일 시스템에서 동일한 위치에 설치되어야 합니다. 이 데이터베이스는 복제할 필요가 없습니다. * SQL Milestone 데이터베이스(.mdf 및 .ldf)는 두 노드 모두에서 동일한 디렉터리에 있어야 합니다. 디렉터리는 복제되도록 구성되어야 합니다. 이 [문서](https://doc.milestonesys.com/xprotect/xprotect-management-client/2026r1/en/change-the-location-and-name-of-a-sql-server-database.html)에 따르면 Milestone 데이터베이스는 다음과 같습니다. ℹ️ `Advanced configuration` 클릭하면 `userconfig.xml` 파일이 표시됩니다. 이 파일은 콘솔에서 자동으로 채워지며 재시작 스크립트와 함께 노드에 배포됩니다. ℹ️ SafeKit 구성을 적용하면 Windows 서비스에서 서비스의 `startup type` 자동으로 `Manual`으로 설정됩니다. 이렇게 하면 시스템 부팅 시 서비스가 자동으로 시작되지 않고 모듈 자체가 시작될 따라 SafeKit 장애 조치 후 로그인이 작동하도록 특정 단계가 필요합니다. 참조: [로그인 스크린샷 보기 🖼️](/wp-content/uploads/2022/07/milestone-management-server-connect.png). #### Active Directory(AD)를 사용한 Windows 인증 {#windows-authentication-with-active-directory-ad} **구성:** 특별한 구성은 필요하지 않습니다. Milestone " Windows 인증"이 Active Directory로 구성된 경우 사용자 및 암호 정보는 외부 AD에서 검색됩니다. 장애 조치 후 보조 노드는 동일한 AD에 연결되므로 인증이 자동으로 작동합니다. #### 워크그룹의 Windows 인증 {#windows-authentication-in-workgroup} **구성:** "보안/역할"에 **BUILTIN/Administrators** 그룹을 추가해야 합니다. **경고:** 작업 그룹에서 로컬 사용자는 이름이 동일하더라도 각 노드에서 서로 다른 보안 식별자(SID)를 갖습니다. BUILTIN/Administrators 그룹만 두 노드에서 동일한 SID를 갖습니다. * 이 그룹을 추가하면 장애 조치 후 모든 로컬 관리자 계정으로 보조 노드에서 인증할 수 있습니다. * 이것이 없으면 SID가 일치하지 않아 보조 노드에서 로컬 Windows 인증이 실패합니다. #### SQL 데이터베이스를 사용한 기본 인증 {#basic-authentication-with-sql-database} **구성:** "기본 인증"으로 사용자를 만듭니다(예: " Admin "). "기본 인증"의 경우 사용자 자격 증명은 SQL 데이터베이스에 직접 저장됩니다. SafeKit SQL 데이터베이스를 보조 노드에 실시간으로 복제하므로, 장애 조치 후 즉시 이러한 사용자를 사용할 수 있습니다. ![Milestone Management Client에서 역할 설정](/wp-content/uploads/2022/07/milestone-management-server-roles.png) ### 14. 노드 2 시작
