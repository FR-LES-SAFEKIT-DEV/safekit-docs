Para versões anteriores, 🛠️ [este artigo](/pt-br/quick-install/safekit-quick-installation-guide-old-milestone-configuration/). ### 1. Inicie o console SafeKit {#1-launch-the-safekit-console} * Inicie o console da web em um navegador em um nó do cluster, conectando-se a `http://localhost:9010`. * Insira `admin` como nome de usuário e a senha definida durante a instalação. Você também pode executar o console em um navegador em uma estação de trabalho externa ao cluster. ⚠️ A configuração do SafeKit é feita em ambos os nós a partir de um único navegador. ℹ️ Para proteger o console da web, consulte 🛠️ [11. Protegendo o serviço da web SafeKit](/pt-br/resources/safekit-user-guide-82/#https) no Guia do Usuário. ![Inicie o console web SafeKit para configurar o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar endereços de nós {#2-configure-node-addresses} * Insira os endereços IP do nó, pressione a `Tab key` para verificar a conectividade e preencha os nomes dos nós. Se node1 ou node2 estiverem em vermelho, verifique a conectividade do navegador com ambos os nós e verifique o firewall em ambos os nós para 🛠️ [solucionar problemas](/pt-br/resources/safekit-user-guide-82/#Troubleshooting). * Em seguida, clique em `Save and apply` para salvar a configuração. * Verifique a mensagem `Success` ✅ em ambos os nós. * Se ocorrer uma `Failure` de configuração ❌ em um nó, abra o acordeão ▼ desse nó e revise as mensagens. Observe que você pode usar a IA SafeKit 🤖 para obter assistência. ℹ️ Se desejar, você pode adicionar uma nova `LAN and nodes` (primeiro ➕) para criar um segundo heartbeat e uma rede de replicação dedicada. ℹ️ Se você clicar em `Advanced configuration`, o arquivo `cluster.xml` será exibido. Este arquivo é preenchido automaticamente pelo console e implantado nos nós. ![Insira os nós do cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Selecione um módulo {#3-select-a-module} * No `New module`, clique no módulo `{{ .Get "mod" }}.safe`. ℹ️ No banner azul na parte superior, 🛜 `node1` representa o nó de conexão do console. Este nó retransmite solicitações para `node2` quando necessário. ℹ️ O console procura por `xxx.safe` no diretório `Application_Modules/generic/` no nó de conexão (`node1`) se você colocou um módulo lá durante a instalação. ![Escolha o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configure o módulo {#4-configure-the-module} * Em `Module startup at boot`, escolha o início automático do módulo na inicialização sem atraso. * Em `Macros`/`SERVICES`, insira os nomes dos serviços do seu aplicativo, na ordem de inicialização, separados por vírgulas. Consulte esta captura de tela para obter um exemplo visual dos [serviços Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * Nas `Heartbeat networks`, você deve ter uma única rede heartbeat na qual a replicação é feita. Se você adicionou uma LAN privada na etapa 2, poderá configurar duas heartbeats com o fluxo de replicação na LAN privada. * Em `Virtual IP addresses`, insira um endereço IP virtual. Um endereço IP virtual é um endereço IP padrão na mesma rede IP (mesma sub-rede) que os endereços IP de ambos os nós. Os clientes da aplicação devem ser configurados com o endereço IP virtual (ou o nome DNS associado ao endereço IP virtual). O endereço IP virtual é alterado automaticamente em caso de falha. * Em `Replicated directories`, defina os caminhos dos diretórios a serem replicados. Verifique se eles existem em ambos os nós e contêm os dados do aplicativo. A replicação de dados e de logs é essencial para um banco de dados. Você pode criar diretórios replicados adicionais conforme necessário. Veja esta captura de tela para um exemplo visual da [replicação SQL Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * Em `Checkers`, você poderá configurar verificadores, se necessário, como monitoramento de processos, verificadores personalizados, TCP, ping ou verificadores de divisão de cérebro. Por exemplo, se um nome de processo for exibido em `Monitored processes/services`, ele será monitorado com uma ação de reinicialização em caso de falha. A configuração de um nome de processo incorreto fará com que o módulo pare logo após o seu início. ⚠️ Se o SQL estiver no servidor de gerenciamento: * Os [bancos de dados do sistema SQL](https://learn.microsoft.com/en-us/sql/relational-databases/databases/system-databases) (como master.mdf e mastlog.ldf) devem estar localizados nos mesmos diretórios em ambos os nós. Os diretórios devem ser configurados como replicados. * O SQL também deve ser instalado no mesmo local no sistema de arquivos em ambos os nós, porque o [banco de dados de recursos SQL](https://learn.microsoft.com/en-us/sql/relational-databases/databases/resource-database) somente leitura está localizado no binário e é necessário para o failover. Este banco de dados não precisa ser replicado. * Os bancos de dados SQL Milestone (.mdf e .ldf) devem estar localizados nos mesmos diretórios em ambos os nós. Os diretórios devem ser configurados como replicados. Os bancos de dados Milestone são os seguintes, de acordo com este [artigo](https://doc.milestonesys.com/xprotect/xprotect-management-client/2026r1/en/change-the-location-and-name-of-a-sql-server-database.html). ℹ️ Se você clicar em `Advanced configuration`, o arquivo `userconfig.xml` será exibido. Este arquivo é preenchido automaticamente pelo console e implantado nos nós com os scripts de reinicialização. ℹ️ Ao aplicar a configuração SafeKit, o `startup type` dos serviços é automaticamente definido como `Manual` nos Serviços Windows. Isso garante que os serviços não sejam iniciados automaticamente quando o sistema é inicializado, mas sim apenas quando o próprio módulo é iniciado. ![Acesse as configurações do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. Editar scripts (opcional) {#5-edit-scripts-optional} * Esta etapa é opcional e pode ser ignorada na maioria dos casos, pois os scripts de reinicialização já estão pré-configurados para reiniciar os serviços definidos na etapa anterior. * Então, clique diretamente em `Next step`. * `start_prim.ps1` inicia todos os serviços na ordem especificada na lista `SERVICES` e inicia os `IIS application pools` usados pelo Milestone. `stop_prim.ps1` para todos os serviços na ordem inversa. * Além disso, `start_prim.ps1` verifica a inicialização de cada serviço e interrompe o módulo se algum serviço não for iniciado corretamente. ![Acesse as configurações do módulo {{ .Get "app" }}](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. Criptografia de comunicação (opcional) {#6-communication-encryption-optional} * Mantenha a criptografia da comunicação entre os nós. ![Criptografia de comunicação do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Salvar e aplicar {#7-save-and-apply} * `Save and apply` a configuração e os scripts em ambos os nós. ![Salve e aplique a configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verifique se a configuração foi bem-sucedida {#8-verify-successful-configuration} * Verifique a mensagem `Success` ✅ em ambos os nós e clique em `Monitor modules`. * Se ocorrer uma `Failure` de configuração ❌ em um nó, abra o acordeão ▼ desse nó e revise as mensagens. Observe que você pode usar a IA SafeKit 🤖 para obter assistência. ![Verifique se a configuração do módulo {{ .Get "app" }} foi bem-sucedida](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Inicie o nó com dados atualizados {#9-start-the-node-with-up-to-date-data} * Se o nó 1 tiver os diretórios replicados atualizados, selecione-o e ⋯ `Force start` ▶ `As primary`. Quando o nó 2 for iniciado, todos os dados serão copiados do nó 1 para o nó 2. ⚠️ Se você fizer a escolha errada, corre o risco de sincronizar dados desatualizados em ambos os nós. ⚠️ Também se presume que o aplicativo {{ .Get "app" }} esteja parado no nó 1 para que SafeKit instale os mecanismos de replicação e, em seguida, inicie o aplicativo no script `start_prim`. ⚠️ Use `Start` para inícios subsequentes: SafeKit mantém o servidor mais atualizado. Iniciar `As primary` é um início especial na primeira vez ou durante operações excepcionais. ![Inicie o nó {{ .Get "app" }} como primário com os dados atualizados](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Aguarde a transição para ALONE (verde) {#10-wait-for-the-transition-to-alone-green} * O nó 1 deve atingir o estado ALONE (verde), o que significa que o IP virtual está definido e que o script `start_prim` foi executado no nó 1. ⚠️ Se ALONE (verde) não for atingido ou se o aplicativo não for iniciado, analise o motivo com o [log do módulo 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) do nó 1. * Clique no ícone **de log** 🔍 do `node1` para abrir o log do módulo e procure mensagens de erro, como um verificador que detecta um erro e interrompe o módulo. * Clique em `start_prim` no log: as mensagens de saída do script são exibidas à direita e os erros podem ser detectados, como um serviço iniciado incorretamente. * Use o SafeKit AI 🤖 para obter ajuda com as mensagens de log. ⚠️ Se o cluster estiver no estado `WAIT (red) not uptodate, STOP (red) not uptodate`, pare o nó WAIT e [force o seu início como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![O primeiro nó {{ .Get "app" }} inicia como primário e fica ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. Resolva o problema de autenticação Windows em caso de falha {#role} Ao iniciar o Milestone XProtect Management Client, você deve se autenticar usando um dos seguintes métodos. Dependendo da sua escolha, etapas específicas são necessárias para garantir que o login funcione após um failover SafeKit. Referência: [Ver Captura de Tela de Login 🖼️](/wp-content/uploads/2022/07/milestone-management-server-connect.png). #### Autenticação Windows com o Active Directory (AD) {#windows-authentication-with-active-directory-ad} **Configuração:** Nenhuma configuração especial é necessária. Se a autenticação Windows Milestone estiver configurada com um Active Directory, as informações de usuário e senha serão recuperadas do AD externo. Após um failover, o nó secundário se conecta ao mesmo AD, portanto, a autenticação funciona automaticamente. #### Autenticação Windows em Grupo de Trabalho {#windows-authentication-in-workgroup} **Configuração:** Você deve adicionar o grupo **BUILTIN/Administrators** em "Segurança / Funções". **Aviso:** Em um Grupo de Trabalho, os usuários locais têm Identificadores de Segurança (SIDs) diferentes em cada nó, mesmo que os nomes sejam idênticos. Somente o grupo BUILTIN/Administrators tem o mesmo SID em ambos os nós. * Ao adicionar este grupo, você pode se autenticar no nó secundário com qualquer conta de administrador local após uma falha. * Sem isso, a autenticação local Windows falhará no nó secundário porque os SIDs não serão compatíveis. #### Autenticação básica com banco de dados SQL {#basic-authentication-with-sql-database} **Configuração:** Crie um usuário com "Autenticação básica" (por exemplo, " Admin "). Para a "Autenticação básica", as credenciais do usuário são armazenadas diretamente no banco de dados SQL. Como SafeKit replica o banco de dados SQL para o nó secundário em tempo real, esses usuários estão sempre disponíveis imediatamente após um failover. ![Definir funções no Management Client Milestone](/wp-content/uploads/2022/07/milestone-management-server-roles.png) ### 14. Iniciar nó 2 {#14-start-node-2} * ⋯ `Start` o nó 2 com o seu menu contextual. * Aguarde o SECOND estado (verde). ℹ️ * O nó 2 permanece no SECOND estado (laranja) enquanto resincroniza os diretórios replicados (cópia do nó 1 para o nó 2). * Isso pode levar algum tempo, dependendo do tamanho dos arquivos a serem resincronizados nos diretórios replicados e da largura de banda da rede. * Para ver o progresso da cópia, consulte o [log do módulo 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) e os [recursos de replicação 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) do nó 2. Use o SafeKit AI 🤖 para obter assistência com as mensagens de log. ![Inicie o nó 2 {{ .Get "app" }}](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 15. Verifique se o cluster está operacional {#15-verify-that-the-cluster-is-operational} * Verifique se o cluster está verde/verde com os serviços {{ .Get "app" }} em execução no nó PRIM e não em execução no nó SECOND. * Apenas as alterações dentro dos arquivos são replicadas em tempo real neste estado. ⚠️ * Registe os **servidores de gravação** com o endereço IP virtual. * Conecte o **Milestone Management Client** e o **Milestone Smart Client** no endereço IP virtual. * Os componentes que são clientes dos serviços {{ .Get "app" }} devem ser configurados com o endereço IP virtual. A configuração pode ser feita com um nome DNS (se um nome DNS tiver sido criado e associado ao endereço IP virtual). ![O nó {{ .Get "app" }} 2 é SECOND (verde)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 16. Testes {#16-testing} * Pare o nó PRIM rolando para baixo no menu contextual e clicando em `Stop`. * Verifique se há um failover no SECOND nó, que deve ficar ALONE (verde). * E com Microsoft Management Console (MMC) no Windows ou com linhas de comando no Linux, verifique o failover dos serviços {{ .Get "app" }} (parado no nó 1 no script `stop_prim` e iniciado no nó 2 no script `start_prim`). ⚠️ Se ALONE (verde) não for atingido no node2 ou se o aplicativo não for iniciado, analise o motivo com o [log do módulo 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) do nó 2. * Clique no ícone **de log** 🔍 do `node2` para abrir o log do módulo e procure mensagens de erro, como um verificador detectando um erro e interrompendo o módulo. * Clique em `start_prim` no log: as mensagens de saída do script são exibidas à direita e os erros podem ser detectados, como um serviço iniciado incorretamente. * Use o SafeKit AI 🤖 para obter ajuda com as mensagens de log. ⚠️ * Se tudo estiver bem, inicie o node1, que irá ressincronizar os diretórios replicados do node2. * Se as coisas derem errado, pare node2 e [force o início como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) do node1, que será reiniciado com seus dados localmente íntegros no momento da parada. ℹ️ Observe que você tem uma **[🖼️ linha do tempo](/wp-content/uploads/2026/05/safekit-console-timeline.png)** 🕒 que pode ser útil para entender o que acontece no cluster. ℹ️ Encontre mais detalhes, juntamente com vídeos, no [Treinamento Online SafeKit](/pt-br/resources/safekit-on-line-training/). ![Pare o módulo {{ .Get "app" }} no servidor PRIM](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 17.
