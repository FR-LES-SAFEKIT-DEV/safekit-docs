{{/* Shortcode: insert-safekit-82-milestone-configuration-pt-pt */}} {{/* Parameters: app, mod */}} {{/* Source: content\quick-install\safekit-quick-installation-guide-with-milestone-xprotect-management-server.md */}} ### Pré-requisitos * Aplicação {{ .Get "app" }} instalada em 2 nós. * Total de dados replicados limitado a alguns terabytes — além disso, o tempo de ressincronização torna-se significativo. * Interligação mínima de 1 Gb/s entre nós (recomenda-se 10 Gb/s para uma ressincronização mais rápida). * O failover IP requer ambos os nós na mesma LAN ou LAN alargada (L2) — as redes L3 encaminhadas não são suportadas. ⚠️ Esta configuração requer **pelo menos Milestone XProtect 2023 R3**. Para versões anteriores, 🛠️ [consulte este artigo](/quick-install/safekit-quick-installation-guide-old-milestone-configuration/). ### 1. Inicie a consola SafeKit * Inicie a consola web num navegador num nó do cluster, conectando-se ao `http://localhost:9010`. * Introduza `admin` como nome de utilizador e palavra-passe definidos durante a instalação. Também é possível executar a consola num browser numa estação de trabalho externa ao cluster. ⚠️ A configuração do SafeKit é feita em ambos os nós a partir de um único browser. ℹ️ Para proteger a consola web, consulte 🛠️ [11\. Proteger o serviço web SafeKit](/resources/safekit-user-guide-82/#https) no Manual do utilizador. ![Inicie a consola web SafeKit para configurar o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2.º Configure endereços de nós * Introduza os endereços dos nós IP, prima `Tab key` para verificar a conectividade e preencher os nomes dos nós. Se node1 ou node2 tiver uma cor vermelha, verifique a conectividade do browser com ambos os nós e verifique a firewall em ambos os nós para 🛠️ [ resolução de problemas](/resources/safekit-user-guide-82/#Troubleshooting). * Em seguida, clique em `Save and apply` para guardar a configuração. * Verifique a mensagem `Success` ✅ em ambos os nós. * Se a configuração `Failure` ❌ ocorrer num nó, abra o acordeão ▼ desse nó e reveja as mensagens. Note que pode utilizar SafeKit AI 🤖 para obter assistência. ℹ️ Se desejar, pode adicionar um novo `LAN and nodes` (primeiro ➕) para criar uma segunda pulsação e uma rede de replicação dedicada. ℹ️ Se clicar em `Advanced configuration`, é apresentado o ficheiro `cluster.xml`. Este ficheiro é preenchido automaticamente pela consola e implementado nos nós. ![Introduza os nós do cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3.º Selecione um módulo * Em `New module`, clique no módulo `{{ .Get "mod" }}.safe`. ℹ️ No banner azul na parte superior, 🛜 `node1` representa o nó de ligação da consola. Este nó retransmite pedidos para `node2` quando necessário. ℹ️ A consola procura `xxx.safe` no diretório `Application_Modules/generic/` no nó de ligação (`node1`) se tiver colocado lá um módulo durante a instalação. ![Escolha o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4.º Configure o módulo * Em `Module startup at boot`, escolha um arranque automático do módulo no arranque sem demora. * Em `Macros`/`SERVICES`, introduza os nomes dos serviços da sua aplicação, pela ordem de arranque, separados por vírgulas. Veja esta captura de ecrã para um exemplo visual dos serviços [Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * Em `Heartbeat networks`, deve ter uma rede de pulsação única na qual a replicação é feita. Se tiver adicionado um LAN privado no passo 2, pode configurar duas pulsações com o fluxo de replicação no LAN privado. * Em `Virtual IP addresses`, introduza um endereço IP virtual. Um endereço IP virtual é um endereço IP padrão na mesma rede IP (mesma sub-rede) que os endereços IP de ambos os nós. Os clientes aplicações devem ser configurados com o endereço IP virtual (ou o nome DNS associado ao endereço IP virtual). O endereço virtual IP é alternado automaticamente em caso de falha. * Em `Replicated directories`, defina os caminhos dos diretórios a replicar. Verifique se existem em ambos os nós e se contêm os dados da aplicação. A replicação de dados e de logs é essencial para uma base de dados. Pode criar diretórios replicados adicionais conforme necessário. Veja esta captura de ecrã para um exemplo visual da replicação [Milestone XProtect SQL 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * No `Checkers`, poderá configurar verificadores, se necessário, como monitorização de processos, verificadores personalizados, TCP, ping ou verificadores de cérebro dividido. Por exemplo, se um nome de processo for apresentado em `Monitored processes/services`, será monitorizado com uma ação de reinicialização em caso de falha. A configuração de um nome de processo incorreto fará com que o módulo pare logo após o seu início. ⚠️ Se o SQL estiver no servidor de gestão: * As [bases de dados de sistema SQL](https://learn.microsoft.com/en-us/sql/relational-databases/databases/system-databases) (como master.mdf e mastlog.ldf) devem estar nos mesmos diretórios em ambos os nós. Os diretórios devem ser configurados como replicados. * O SQL também deve ser instalado no mesmo local do sistema de ficheiros em ambos os nós, pois a [base de dados de recursos SQL](https://learn.microsoft.com/en-us/sql/relational-databases/databases/resource-database), só de leitura, encontra-se junto dos binários e é necessária para o failover. Esta base de dados não precisa de ser replicada. * As bases de dados SQL do Milestone (.mdf e .ldf) devem estar nos mesmos diretórios em ambos os nós. Os diretórios devem ser configurados como replicados. As bases de dados do Milestone estão indicadas neste [artigo](https://doc.milestonesys.com/xprotect/xprotect-management-client/2026r1/en/change-the-location-and-name-of-a-sql-server-database.html). ℹ️ Se clicar em `Advanced configuration`, é apresentado o ficheiro `userconfig.xml`. Este ficheiro é preenchido automaticamente pela consola e implementado nos nós com os scripts de reinicialização. ℹ️ Quando aplica a configuração SafeKit, o `startup type` dos serviços é automaticamente definido como `Manual` nos serviços Windows. Isto garante que os serviços não são iniciados automaticamente no arranque do sistema, mas apenas quando o próprio módulo é iniciado. ![Introduza as definições do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5.º Edite scripts (opcional) * Este passo é opcional e pode ser ignorado na maioria dos casos, uma vez que os scripts de reinicialização já estão pré-configurados para reiniciar os serviços definidos no passo anterior. * Assim, clique diretamente em `Next step`. * `start_prim.ps1` inicia todos os serviços pela ordem especificada na lista `SERVICES` e inicia os `IIS application pools` utilizados pelo Milestone. `stop_prim.ps1` para todos os serviços pela ordem inversa. * Além disso, o `start_prim.ps1` verifica a inicialização de cada serviço e pára o módulo se algum serviço não iniciar corretamente. ![Introduza as definições do módulo {{ .Get "app" }}](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6.º Encriptação de comunicação (opcional) * Mantenha a encriptação da comunicação entre os nós. ![Encriptação de comunicação do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7.º Guarde e aplique * `Save and apply` a configuração e os scripts em ambos os nós. ![Guarde e aplique a configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verifique a configuração bem-sucedida * Verifique a mensagem `Success` ✅ em ambos os nós e clique em `Monitor modules`. * Se a configuração `Failure` ❌ ocorrer num nó, abra o acordeão ▼ desse nó e reveja as mensagens. Note que pode utilizar SafeKit AI 🤖 para obter assistência. ![Verifique o sucesso da configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Inicie o nó com os dados atualizados * Se o nó 1 tiver diretórios replicados atualizados, selecione-o e ⋯ `Force start` ▶ `As primary`. Quando o nó 2 for iniciado, todos os dados serão copiados do nó 1 para o nó 2. ⚠️ Se fizer a escolha errada, corre o risco de sincronizar dados desatualizados em ambos os nós. ⚠️ Supõe-se também que a aplicação {{ .Get "app" }} é parada no nó 1 para que SafeKit instale os mecanismos de replicação e depois inicie a aplicação no script `start_prim`. ⚠️ Utilize `Start` para arranques subsequentes: SafeKit mantém o servidor mais atualizado. A inicialização do `As primary` é uma inicialização especial à primeira ou durante operações excecionais. ![Inicie como primário o nó {{ .Get "app" }} com os dados atualizados](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Aguarde a transição para ALONE (verde) * O nó 1 deve atingir o estado ALONE (verde), o que significa que o IP virtual está configurado e que o script `start_prim` foi executado no nó 1. ⚠️ Se ALONE (verde) não for atingido ou se a aplicação não for iniciada, analise o porquê com o registo do módulo [ 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) do nó 1. * Clique no ícone 🔍 **log** de `node1` para abrir o registo do módulo e procurar mensagens de erro, como um verificador que deteta um erro e interrompe o módulo. * Clique em `start_prim` no registo: as mensagens de saída do script são apresentadas à direita e podem ser detetados erros, como um serviço iniciado incorretamente. * Utilize SafeKit AI 🤖 para obter assistência com mensagens de registo. ⚠️ Se o cluster estiver no estado `WAIT (red) not uptodate, STOP (red) not uptodate`, pare o nó WAIT e [ force o seu arranque como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![O primeiro nó {{ .Get "app" }} começa como primário e passa a ser ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. No ambiente de trabalho do nó 2, registar o servidor de gestão no endereço IP virtual * Escolha **Server Configurator** na barra de tarefas do nó 2 e registe-o no endereço IP virtual (ver imagem). * Em seguida, **Stop Management Server Service**. * **Edite o ServerConfig.xml** no nó 2. * Aceda a "C:/ProgramData/Milestone/XProtect Management Server" e faça uma cópia de segurança do ficheiro ServerConfig.xml original. * Abra o ServerConfig.xml com qualquer editor de texto (com direitos de administrador). * Substitua `XXX.XXX.XXX.XXX` pelo endereço IP virtual real em: * `...` * `` * `XXX.XXX.XXX.XXX` * `` * `...` * Altere `false` para `true` * Defina `http://NODE2_FQDN:9010` (ou o nome de anfitrião de NODE2 num grupo de trabalho) em: * `` * `http://NODE2_FQDN:9010` * `` * Para mais informações, consulte este **[artigo da base de conhecimentos Milestone](https://milestonesys.my.site.com/developer/s/article/Management-Client-and-Smart-Client-are-not-functioning-properly-after-node-switch-in-a-clustered-Management-Server-setup)**. ⚠️ Atenção: * A conta do utilizador que efetua o registo no nó 2 deve ter a função de administrador no Milestone do nó 1. * Se o administrador local do nó 2 efetuar o registo, o grupo incorporado do Windows `BUILTIN/Administrators` deve ter sido definido em Management Client / Security / Roles no [passo 13](#role). Caso contrário, o registo não funcionará. ℹ️ Este procedimento regista o servidor de gestão do nó 2 na base de dados SQL (em execução no nó 1) através de uma ligação ao endereço virtual. ![Registar o servidor de gestão com Milestone 2020+](/wp-content/uploads/2022/07/milestone-management-server-register-2020.png) ### 13. Resolver o problema de autenticação Windows no failover {#role} Ao iniciar o Milestone XProtect Management Client, deve autenticar-se através de um dos métodos seguintes. Consoante a sua escolha, são necessários passos específicos para garantir que o início de sessão funciona após um failover SafeKit. Referência: [ver captura do ecrã de início de sessão 🖼️](/wp-content/uploads/2022/07/milestone-management-server-connect.png). #### Autenticação Windows com Active Directory (AD) **Configuração:** Não é necessária qualquer configuração especial. Se a "Windows authentication" do Milestone estiver configurada com Active Directory, os dados de utilizador e palavra-passe são obtidos do AD externo. Após um failover, o nó secundário liga-se ao mesmo AD, pelo que a autenticação funciona automaticamente. #### Autenticação Windows num grupo de trabalho **Configuração:** Deve adicionar o grupo **BUILTIN/Administrators** em "Security / Roles". **Aviso:** Num grupo de trabalho, os utilizadores locais têm identificadores de segurança (SIDs) diferentes em cada nó, mesmo com nomes idênticos. Apenas o grupo BUILTIN/Administrators tem o mesmo SID nos dois nós. * Ao adicionar este grupo, pode autenticar-se no nó secundário com qualquer conta de administrador local após um failover. * Sem isto, a autenticação Windows local falhará no nó secundário porque os SIDs não corresponderão. #### Autenticação básica com base de dados SQL **Configuração:** Crie um utilizador com "Basic authentication" (por exemplo, "Admin"). Com "Basic authentication", as credenciais do utilizador são armazenadas diretamente na base de dados SQL. Como o SafeKit replica a base de dados SQL para o nó secundário em tempo real, estes utilizadores estão sempre disponíveis imediatamente após um failover. ![Definir funções no Milestone Management Client](/wp-content/uploads/2022/07/milestone-management-server-roles.png) ### 14. Iniciar nó 2 * ⋯ Nó `Start` 2 com o seu menu contextual. * Aguarde o estado SECOND (verde). ℹ️ * O nó 2 permanece no estado SECOND (laranja) enquanto ressincroniza os diretórios replicados (copia do nó 1 para o nó 2). * Isto pode demorar um pouco, dependendo do tamanho dos ficheiros a ressincronizar nos diretórios replicados e da largura de banda da rede. * Para ver o progresso da cópia, consulte o registo do módulo [ 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) e as características de replicação [ 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) do nó 2. Utilize o SafeKit AI 🤖 para obter assistência com as mensagens de registo. ![Inicie o nó {{ .Get "app" }} 2](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 15. Verifique se o cluster está operacional * Verifique se o cluster está verde/verde com os serviços {{ .Get "app" }} em execução no nó PRIM e não em execução no nó SECOND. * Apenas as alterações dentro dos ficheiros são replicadas em tempo real neste estado. ⚠️ * Registe os **servidores de gravação** com o endereço IP virtual. * Ligue o **Milestone Management Client** e o **Milestone Smart Client** ao endereço IP virtual. * Os componentes clientes dos serviços {{ .Get "app" }} devem ser configurados com o endereço virtual IP. A configuração pode ser feita com um nome DNS (caso tenha sido criado um nome DNS e associado ao endereço virtual IP). ![O nó {{ .Get "app" }} 2 é SECOND (verde)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 16. Teste * Pare o nó PRIM fazendo scroll para baixo no seu menu contextual e clicando em `Stop`. * Verifique se existe um failover no nó SECOND que se deve tornar ALONE (verde). * E com o Microsoft Management Console (MMC) em Windows ou com linhas de comando em Linux, verifique o failover dos serviços {{ .Get "app" }} (interrompido no nó 1 no script `stop_prim` e iniciado no nó 2 no script `start_prim`). ⚠️ Se ALONE (verde) não for atingido em node2 ou se a aplicação não for iniciada, analise o porquê com o registo do módulo [ 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) do nó 2. * Clique no ícone 🔍 **log** de `node2` para abrir o registo do módulo e procurar mensagens de erro, como um verificador que deteta um erro e interrompe o módulo. * Clique em `start_prim` no registo: as mensagens de saída do script são apresentadas à direita e podem ser detetados erros, como um serviço iniciado incorretamente. * Utilize SafeKit AI 🤖 para obter assistência com mensagens de registo. ⚠️ * Se tudo estiver bem, inicie o node1, que irá voltar a sincronizar os diretórios replicados do node2. * Se algo correr mal, pare node2 e [ force o arranque como 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) primário de node1, que será reiniciado com os seus dados localmente íntegros no momento da paragem. ℹ️ Dispõe de uma 🕒 **[cronologia 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** que pode ajudar a compreender o que acontece no cluster. ℹ️ Encontre mais detalhes e vídeos na [formação online SafeKit](/pt-pt/resources/safekit-on-line-training/). ![Pare o módulo {{ .Get "app" }} no servidor PRIM](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 17.
