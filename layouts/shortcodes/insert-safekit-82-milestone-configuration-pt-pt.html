Para versões anteriores, consulte 🛠️ [este artigo](/pt-pt/quick-install/safekit-quick-installation-guide-old-milestone-configuration/). ### 1. Inicie a consola SafeKit {#1-launch-the-safekit-console} * Inicie a consola web num navegador, num dos nós do cluster, ligando-se a `http://localhost:9010`. * Introduza `admin` como nome de utilizador e a palavra-passe definida durante a instalação. Também é possível executar a consola num navegador, numa estação de trabalho externa ao cluster. ⚠️ A configuração do SafeKit é feita em ambos os nós a partir de um único navegador. ℹ️ Para proteger a consola web, consulte 🛠️ [11. Proteção do serviço web SafeKit](/pt-pt/resources/safekit-user-guide-82/#https) no Guia do Utilizador. ![Inicie a consola web SafeKit para configurar o cluster {{ .Get "app" }}](/wp-content/uploads/2024/03/01-login-large.png) ### 2. Configurar os endereços dos nós {#2-configure-node-addresses} * Introduza os endereços IP dos nós, prima a `Tab key` para verificar a conectividade e preencha os nomes dos nós. Se node1 ou node2 tiverem uma cor vermelha, verifique a conectividade do navegador a ambos os nós e verifique a firewall em ambos os nós para 🛠️ [resolução de problemas](/pt-pt/resources/safekit-user-guide-82/#Troubleshooting). * Em seguida, clique em `Save and apply` para guardar a configuração. * Verifique a mensagem `Success` ✅ em ambos os nós. * Se ocorrer uma `Failure` de configuração ❌ num nó, abra o acordeão ▼ desse nó e reveja as mensagens. Tenha em atenção que pode utilizar a IA SafeKit 🤖 para obter assistência. ℹ️ Se desejar, pode adicionar uma nova `LAN and nodes` (primeiro ➕) para criar um segundo heartbeat e uma rede de replicação dedicada. ℹ️ Se clicar em `Advanced configuration`, o ficheiro `cluster.xml` é apresentado. Este ficheiro é preenchido automaticamente pela consola e implementado nos nós. ![Introduza os nós do cluster da {{ .Get "app" }}](/wp-content/uploads/2024/03/02-cluster-edit.png) ### 3. Selecione um módulo {#3-select-a-module} * No `New module`, clique no módulo `{{ .Get "mod" }}.safe`. ℹ️ No banner azul no topo, `node1` 🛜 representa o nó de ligação da consola. Este nó reencaminha os pedidos para `node2` quando necessário. ℹ️ A consola procura por `xxx.safe` no diretório `Application_Modules/generic/` no nó de ligação (`node1`) se tiver colocado um módulo lá durante a instalação. ![Escolha o módulo para {{ .Get "app" }}](/wp-content/uploads/2024/03/04-module-new.png) ### 4. Configure o módulo {#4-configure-the-module} * No `Module startup at boot`, escolha o arranque automático do módulo no arranque sem atraso. * Em `Macros`/`SERVICES`, introduza os nomes dos serviços da sua aplicação, pela ordem de inicialização, separados por vírgulas. Consulte esta captura de ecrã para um exemplo visual dos [serviços Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-services.png). * Nas `Heartbeat networks`, deve ter uma única rede heartbeat na qual a replicação é feita. Se adicionou uma LAN privada no passo 2, pode configurar duas heartbeats com o fluxo de replicação na LAN privada. * Em `Virtual IP addresses`, introduza um endereço IP virtual. Um endereço IP virtual é um endereço IP padrão na mesma rede IP (mesma sub-rede) que os endereços IP de ambos os nós. Os clientes da aplicação devem ser configurados com o endereço IP virtual (ou o nome DNS associado ao endereço IP virtual). O endereço IP virtual é automaticamente alterado em caso de falha. * Em `Replicated directories`, defina os caminhos dos diretórios a replicar. Verifique se eles existem em ambos os nós e contêm os dados da aplicação. A replicação de dados e de registos é essencial para uma base de dados. Pode criar diretórios replicados adicionais conforme necessário. Veja esta captura de ecrã para um exemplo visual da [replicação SQL Milestone XProtect 🖼️](/wp-content/uploads/2025/05/milestone-replication.png). * No `Checkers`, poderá configurar os verificadores, se necessário, como monitorização de processos, verificadores personalizados, TCP, ping ou verificadores de divisão de rede. Por exemplo, se um nome de processo for exibido em `Monitored processes/services`, ele será monitorizado com uma ação de reinicialização em caso de falha. A configuração de um nome de processo incorreto fará com que o módulo pare logo após o seu início. ⚠️ Se o SQL estiver no servidor de gestão: * As [bases de dados do sistema SQL](https://learn.microsoft.com/en-us/sql/relational-databases/databases/system-databases) (como master.mdf e mastlog.ldf) devem estar localizadas nos mesmos diretórios em ambos os nós. Os diretórios devem ser configurados como replicados. * O SQL também deve ser instalado no mesmo local no sistema de ficheiros em ambos os nós, porque a [base de dados de recursos SQL](https://learn.microsoft.com/en-us/sql/relational-databases/databases/resource-database) de apenas leitura está localizada no binário e é necessária para a comutação de falha. Esta base de dados não precisa de ser replicada. * As bases de dados SQL Milestone (.mdf e .ldf) devem estar localizadas nos mesmos diretórios em ambos os nós. Os diretórios devem ser configurados como replicados. As bases de dados Milestone são as seguintes, de acordo com este [artigo](https://doc.milestonesys.com/xprotect/xprotect-management-client/2026r1/en/change-the-location-and-name-of-a-sql-server-database.html). ℹ️ Se clicar em `Advanced configuration`, o ficheiro `userconfig.xml` é apresentado. Este ficheiro é preenchido automaticamente pela consola e implementado nos nós com os scripts de reinicialização. ℹ️ Ao aplicar a configuração SafeKit, o `startup type` dos serviços é automaticamente definido como `Manual` nos Serviços Windows. Isto garante que os serviços não arrancam automaticamente quando o sistema é iniciado, mas são iniciados apenas quando o próprio módulo é iniciado. ![Aceda às definições do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/05-module-mirror-edit-config-3.png) ### 5. Editar os scripts (opcional) {#5-edit-scripts-optional} * Este passo é opcional e pode ser ignorado na maioria dos casos, uma vez que os scripts de reinicialização já estão pré-configurados para reiniciar os serviços definidos no passo anterior. * Então, clique diretamente em `Next step`. * `start_prim.ps1` inicia todos os serviços na ordem especificada na lista `SERVICES` e inicia os `IIS application pools` utilizados pelo Milestone. `stop_prim.ps1` para todos os serviços na ordem inversa. * Adicionalmente, `start_prim.ps1` verifica o arranque de cada serviço e para o módulo se algum serviço não arrancar corretamente. ![Aceda às definições do módulo {{ .Get "app" }}](/wp-content/uploads/2026/09/28-module-edit-script.png) ### 6. Criptografia da comunicação (opcional) {#6-communication-encryption-optional} * Mantenha a encriptação da comunicação entre os nós. ![Criptografia de comunicação do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/07-module-encryption-1.png) ### 7. Guardar e aplicar {#7-save-and-apply} * `Save and apply` a configuração e os scripts em ambos os nós. ![Guarde e aplique a configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/08-module-save-1.png) ### 8. Verifique se a configuração foi bem-sucedida {#8-verify-successful-configuration} * Verifique a mensagem `Success` ✅ em ambos os nós e clique em `Monitor modules`. * Se ocorrer uma `Failure` de configuração ❌ num nó, abra o acordeão ▼ desse nó e reveja as mensagens. Tenha em atenção que pode utilizar a IA SafeKit 🤖 para obter assistência. ![Verifique o sucesso da configuração do módulo {{ .Get "app" }}](/wp-content/uploads/2025/05/09-module-save-check-1.png) ### 9. Inicie o nó com dados atualizados {#9-start-the-node-with-up-to-date-data} * Se o nó 1 tiver os diretórios replicados atualizados, selecione-o e ⋯ `Force start` ▶ `As primary`. Quando o nó 2 for iniciado, todos os dados serão copiados do nó 1 para o nó 2. ⚠️ Se fizer a escolha errada, corre o risco de sincronizar dados desatualizados em ambos os nós. ⚠️ Também se assume que a aplicação {{ .Get "app" }} está parada no nó 1 para que SafeKit instale os mecanismos de replicação e, em seguida, inicie a aplicação no script `start_prim`. ⚠️ Utilize `Start` para arranques subsequentes: SafeKit mantém o servidor mais atualizado. Iniciar `As primary` é um arranque especial na primeira vez ou durante operações excecionais. ![Inicie como primário o nó {{ .Get "app" }} com os dados atualizados](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) ### 10. Aguarde a transição para ALONE (verde) {#10-wait-for-the-transition-to-alone-green} * O nó 1 deve atingir o estado ALONE (verde), o que significa que o IP virtual está definido e que o script `start_prim` foi executado no nó 1. ⚠️ Se ALONE (verde) não for atingido ou se a aplicação não for iniciada, analise o motivo com o [registo do módulo 🖼️](/wp-content/uploads/2024/03/24-module-log-script.png) do nó 1. * Clique no ícone **de registo** 🔍 do `node1` para abrir o registo do módulo e procure mensagens de erro, como um verificador que deteta um erro e para o módulo. * Clique em `start_prim` no registo: as mensagens de saída do script são exibidas à direita e os erros podem ser detetados, como um serviço iniciado incorretamente. * Utilize o SafeKit AI 🤖 para obter assistência com as mensagens de registo. ⚠️ Se o cluster estiver no estado `WAIT (red) not uptodate, STOP (red) not uptodate`, pare o nó WAIT e [force o seu arranque como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png). ![O primeiro nó {{ .Get "app" }} inicia como primário e fica ALONE](/wp-content/uploads/2024/03/12-monitoring-alone-stop.png) ### 11. Resolver o problema de autenticação Windows em caso de falha {#role} Ao iniciar o Milestone XProtect Management Client, tem de se autenticar utilizando um dos seguintes métodos. Dependendo da sua escolha, são necessários passos específicos para garantir que o início de sessão funciona após uma falha SafeKit. Referência: [Ver Captura de Ecrã de Início de Sessão 🖼️](/wp-content/uploads/2022/07/milestone-management-server-connect.png). #### Autenticação Windows com o Active Directory (AD) {#windows-authentication-with-active-directory-ad} **Configuração:** Não é necessária nenhuma configuração especial. Se a autenticação Windows Milestone estiver configurada com um Active Directory, as informações de utilizador e palavra-passe são obtidas do AD externo. Após uma falha, o nó secundário liga-se ao mesmo AD, pelo que a autenticação funciona automaticamente. #### Autenticação Windows em Grupo de Trabalho {#windows-authentication-in-workgroup} **Configuração:** É necessário adicionar o grupo **BUILTIN/Administrators** em "Segurança / Funções". **Aviso:** Num Grupo de Trabalho, os utilizadores locais têm diferentes Identificadores de Segurança (SIDs) em cada nó, mesmo que os nomes sejam idênticos. Apenas o grupo BUILTIN/Administrators tem o mesmo SID em ambos os nós. * Ao adicionar este grupo, poderá autenticar-se no nó secundário com qualquer conta de administrador local após uma falha. * Sem isso, a autenticação local Windows falhará no nó secundário porque os SIDs não corresponderão. #### Autenticação básica com base de dados SQL {#basic-authentication-with-sql-database} **Configuração:** Crie um utilizador com "Autenticação básica" (por exemplo, " Admin "). Para a "Autenticação básica", as credenciais do utilizador são armazenadas diretamente na base de dados SQL. Como SafeKit replica a base de dados SQL para o nó secundário em tempo real, estes utilizadores estão sempre disponíveis imediatamente após uma falha. ![Definir funções no Management Client Milestone](/wp-content/uploads/2022/07/milestone-management-server-roles.png) ### 14. Iniciar nó 2 {#14-start-node-2} * ⋯ `Start` o nó 2 com o seu menu contextual. * Aguarde o SECOND estado (verde). ℹ️ * O nó 2 permanece no SECOND estado (laranja) enquanto resincroniza os diretórios replicados (cópia do nó 1 para o nó 2). * Isto pode demorar algum tempo, dependendo do tamanho dos ficheiros a resincronizar nos diretórios replicados e da largura de banda da rede. * Para ver o progresso da cópia, consulte o [registo do módulo 🖼️](/wp-content/uploads/2024/03/27-module-log-reintegration.png) e os [recursos de replicação 🖼️](/wp-content/uploads/2024/03/26-replication-resources-reintegration.png) do nó 2. Utilize a IA SafeKit 🤖 para obter assistência com as mensagens de registo. ![Inicie o nó 2 {{ .Get "app" }}](/wp-content/uploads/2024/03/13-monitoring-alone-stop-start.png) ### 15. Verifique se o cluster está operacional {#15-verify-that-the-cluster-is-operational} * Verifique se o cluster está verde/verde com os serviços {{ .Get "app" }} a serem executados no nó PRIM e não no nó SECOND. * Apenas as alterações dentro dos ficheiros são replicadas em tempo real neste estado. ⚠️ * Registe os **servidores de gravação** com o endereço IP virtual. * Ligue o **Milestone Management Client** e o **Milestone Smart Client** ao endereço IP virtual. * Os componentes que são clientes dos serviços {{ .Get "app" }} devem ser configurados com o endereço IP virtual. A configuração pode ser feita com um nome DNS (se um nome DNS tiver sido criado e associado ao endereço IP virtual). ![O nó {{ .Get "app" }} 2 é SECOND (verde)](/wp-content/uploads/2024/03/14-monitoring-prim-second.png) ### 16. Testes {#16-testing} * Pare o nó PRIM, percorrendo o menu contextual e clicando em `Stop`. * Verifique se existe um failover no SECOND nó, que deverá ficar ALONE (verde). * E com Microsoft Management Console (MMC) no Windows ou com linhas de comando no Linux, verifique a comutação por falha dos serviços {{ .Get "app" }} (parados no nó 1 no script `stop_prim` e iniciados no nó 2 no script `start_prim`). ⚠️ Se ALONE (verde) não for atingido no node2 ou se a aplicação não for iniciada, analise o motivo com o [registo do módulo 🖼️](/wp-content/uploads/2024/03/38-module-log-script-second.png) do nó 2. * Clique no ícone **de registo** 🔍 do `node2` para abrir o registo do módulo e procure mensagens de erro, como um verificador que deteta um erro e para o módulo. * Clique em `start_prim` no registo: as mensagens de saída do script são exibidas à direita e os erros podem ser detetados, como um serviço iniciado incorretamente. * Utilize o SafeKit AI 🤖 para obter assistência com as mensagens de registo. ⚠️ * Se tudo estiver bem, inicie o node1, que irá ressincronizar os diretórios replicados do node2. * Se as coisas correrem mal, pare node2 e [force o arranque como primário 🖼️](/wp-content/uploads/2024/03/10-monitoring-mirror-stop-stop-prim.png) do node1, que será reiniciado com os seus dados localmente íntegros no momento da paragem. ℹ️ Tenha em atenção que tem uma **[linha do 🖼️](/wp-content/uploads/2026/05/safekit-console-timeline.png)** 🕒 que pode ser útil para entender o que acontece no cluster. ℹ️ Encontre mais detalhes, juntamente com vídeos, no [Treinamento Online SafeKit](/pt-pt/resources/safekit-on-line-training/). ![Parar o módulo {{ .Get "app" }} no servidor PRIM](/wp-content/uploads/2024/03/16-monitoring-prim-second-stop.png) ### 17.
