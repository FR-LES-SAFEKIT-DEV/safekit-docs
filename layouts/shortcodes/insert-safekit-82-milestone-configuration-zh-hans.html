请参阅此屏幕截图，了解[Milestone XProtect SQL 复制的可视化示例 🖼️](/wp-content/uploads/2025/05/milestone-replication.png)。 * 在 `Checkers` 中，您可以根据需要配置检查器，例如进程监控、自定义检查器、TCP 检查器、ping 检查器或裂脑检查器。 例如，如果进程名称显示在 `Monitored processes/services` 中，则在发生故障时，它将通过重启操作进行监控。配置错误的进程名称将导致模块在启动后立即停止。 ⚠️ 如果 SQL 位于管理服务器上： * [SQL 系统数据库](https://learn.microsoft.com/en-us/sql/relational-databases/databases/system-databases)（如 master.mdf 和 mastlog.ldf）必须位于两个节点上的同一目录中。这些目录必须配置为可复制。 * SQL 也必须安装在两个节点的文件系统的同一位置，因为只读[SQL 资源数据库](https://learn.microsoft.com/en-us/sql/relational-databases/databases/resource-database)位于 SQL 二进制目录中，并且是故障转移所必需的。此数据库不需要复制。 * SQL Milestone 数据库（.mdf 和 .ldf）必须位于两个节点上的同一目录中。这些目录必须配置为复制。Milestone Client 时，您必须使用以下方法之一进行身份验证。根据您的选择，需要采取具体步骤来确保 SafeKit 故障转移后登录正常工作。请参阅[登录屏幕截图 🖼️](/wp-content/uploads/2022/07/milestone-management-server-connect.png)。 #### 使用 Active Directory (AD) 进行 Windows 身份验证 {#windows-authentication-with-active-directory-ad} **配置：** 无需特殊配置。 如果 Milestone “ Windows 身份验证”配置为使用 Active Directory，则用户和密码信息将从外部 AD 中检索。故障转移后，辅助节点连接到相同的 AD，因此身份验证会自动工作。 #### 工作组中的 Windows 身份验证 {#windows-authentication-in-workgroup} **配置：** 您必须在“安全/角色”中添加 **BUILTIN/Administrators** 组。 **警告：** 在工作组中，即使名称相同，本地用户在每个节点上的安全标识符 (SID) 也不同。只有 BUILTIN/Administrators 组在两个节点上具有相同的 SID。 * 添加此组后，您可以在故障转移后使用任何本地管理员帐户在辅助节点上进行身份验证。 * 如果没有此设置，辅助节点上的本地 Windows 身份验证将失败，因为 SID 不匹配。 #### 使用 SQL 数据库进行基本身份验证 {#basic-authentication-with-sql-database} **配置：** 创建一个使用“基本身份验证”的用户（例如，“ Admin ”）。 对于“基本身份验证”，用户凭据直接存储在 SQL 数据库中。由于 SafeKit 会将 SQL 数据库实时复制到辅助节点，因此这些用户在故障转移后始终立即可用。 ![在 Milestone Management Client 中设置角色](/wp-content/uploads/2022/07/milestone-management-server-roles.png) ### 14. 启动节点
