{#safekit-farm-cluster} ### `farm` 模式集群中的虚拟 IP 地址 {#virtual-ip-address-farm} ![SafeKit 集群如何为 {{ .Get "app" }} 实现网络负载均衡和故障转移](/wp-content/uploads/2023/02/safekit-up-up-up-300.png "w:300") 在上图中，{{ .Get "app" }} 应用程序在 3 台服务器上运行（3 仅为示例，实际可以是 2 台或更多）。用户连接到一个虚拟 IP 地址。 [虚拟 IP 地址](/zh-hans/best-practises/how-a-virtual-ip-address-works/)在 `farm` 模式集群的每台服务器上本地配置。\ 所有服务器都会接收发往虚拟 IP 地址的输入流量，并通过各服务器内核中的网络过滤器在服务器之间分流。 SafeKit 能够检测硬件和软件故障，在发生故障时重新配置网络过滤器，并提供可配置的应用程序检查器及恢复脚本。 ### 网络过滤器中的负载均衡 {#network-load-balancing} 网络过滤器中的网络负载均衡算法基于客户端数据包的身份（客户端 IP 地址、客户端 TCP 端口）。根据输入客户端数据包的身份，只有一台服务器上的一个过滤器会接收该数据包，其他服务器上的过滤器则会拒绝它。 数据包被某台服务器上的过滤器接收后，响应客户端请求的 {{ .Get "app" }} 应用程序只会使用该服务器的 CPU 和内存。输出消息会直接从应用服务器发送给客户端。 如果某台服务器发生故障，`farm` 心跳协议会重新配置网络负载均衡集群中的过滤器，将流量重新分配到其余可用服务器上。 ### 有状态或无状态应用程序 {#stateful-stateless} 对于有状态的 {{ .Get "app" }} 应用程序，存在会话亲和性。同一个客户端在多个 TCP 会话中必须连接到同一台服务器，以便获取该服务器上的上下文。在这种情况下，SafeKit 负载均衡规则基于客户端 IP 地址配置。因此，同一个客户端在多个 TCP 会话中始终连接到同一台服务器，而不同客户端则分配到 `farm` 中的不同服务器。 对于无状态的 {{ .Get "app" }} 应用程序，不存在会话亲和性。同一个客户端在多个 TCP 会话中可以连接到 `farm` 中的不同服务器。服务器本地不会跨会话存储上下文。在这种情况下，SafeKit 负载均衡规则基于 TCP 客户端会话身份配置。这种配置最适合在服务器之间分配会话，但要求 TCP 服务不依赖会话亲和性。 ### 如何为 {{ .Get "app" }} 配置 `farm` 模式的 SafeKit 集群？ {#safekit-farm-cluster-configuration} ![SafeKit Web 控制台：用于 {{ .Get "app" }} 网络负载均衡和虚拟 IP 管理的 farm 模式集群配置。](/wp-content/uploads/2026/01/safekit-farm-cluster-config.png "w:966") **`farm` 模式的 SafeKit 集群**专为服务的高可用性和可扩展性而设计。其配置重点在于将传入流量同时分配到两个节点： * **负载均衡服务（Macros 标签页）：**定义要在所有节点上保持活动状态的特定应用程序服务（例如 Apache、IIS、Nginx）。 * **心跳网络：**用于检测节点是否已离开 `farm` 的通信路径，一旦检测到离开便立即触发负载重新分配。 * **虚拟 IP（`Farm` VIP）：**与 `Mirror` 集群不同，`Farm` VIP 通过内核过滤算法在节点之间共享，以分配网络流量。 * **负载均衡规则：**根据源 IP 地址或端口定义流量分配策略。 * **检查器：**监控应用程序的运行状况，并在检测到进程故障时触发自动重启。 ### 如何监控 {{ .Get "app" }} 的 `farm` 模式 SafeKit 集群？ {#safekit-farm-cluster-monitoring} ![SafeKit 控制台：监控 2 节点 farm 模式集群，显示两个 {{ .Get "app" }} 节点均处于 UP 状态且负载均衡已启用。](/wp-content/uploads/2026/01/safekit-farm-cluster-monitor.png "w:473") 监控 `farm` 模式集群可以了解其**双活**架构的运行情况，在此架构中所有节点都会为应用程序性能做出贡献（本例中显示 2 个节点）： * **UP 状态（2 个节点各占 50%）：**在运行正常的 `farm` 中，两个节点都处于“UP”（50%）状态，这意味着它们都通过共享的虚拟 IP 主动接收并处理客户端请求。 * **自动重新均衡：**如果某个节点发生故障，控制台会直观地显示剩余节点接管 100% 的流量。存活节点本身已处于活动状态，因此不存在故障转移延迟（检测时间约为几秒）。 * **添加节点：**修复后的节点重新启动时，会从“STOP”状态转为“UP”，并自动开始接收分配给它的负载，无需管理员干预。 * **无数据同步：**请注意，`farm` 模式集群中不存在“橙色”重新同步状态，因为各节点通常是无状态的，或者共享同一个后端数据库（该数据库可以在 `Mirror` 集群中单独受到保护）。 除了简单的状态图标外，该界面还提供一键式节点管理功能，允许您在计划维护时手动停止或启动某个节点；与此同时，共享虚拟 IP 会自动重新分配流量，不会中断用户活动。
