{#safekit-hyperv-ha-cluster} ### {{ .Get "app" }} 用の SafeKit HA ソリューションとは何ですか? SafeKit は、あらゆるブランドの 2 台のサーバー間で {{ .Get "app" }} に高可用性をもたらします。 この記事では、SAN 上の共有ストレージを使用せず、特別なスキルを必要とせずに、{{ .Get "app" }} クラスターを迅速に実装する方法について説明します。 ソリューションの原理は、重要なアプリケーションを Hyper-V 下の仮想マシンに配置することです。 SafeKit の実装 **仮想マシンのリアルタイム レプリケーションと自動フェイルオーバー**. Hyper-V は、すべての Windows バージョン (Windows for PC も含む) に含まれる無料のハイパーバイザーであることに注意してください。 ### SAN を使用せずに高可用性 {{ .Get "app" }} クラスターで複数のアプリケーションを実行するにはどうすればよいですか? いくつかのアプリケーションを入れることができます **SafeKit によって複数の仮想マシンが複製され、再起動されました**。 SafeKit コンソールを使用して両方のサーバー間で各仮想マシンを移行し、負荷のバランスを取ることができます。 **アクティブ/アクティブクラスター**. ### 高可用性をアプリケーション レベルで選択するか、それとも仮想マシン (VM) レベルで選択する必要がありますか? SafeKit を使用すると、ニーズに合った冗長モデルを柔軟に選択できます。 **VMレベルの冗長性** (Hyper-V または KVM の場合) は、仮想マシン全体をレプリケートするため、内部アプリケーションの知識を必要とせずに実装するのが最も簡単です。 あるいは、 **アプリケーションレベルの冗長性** より細分化されています。特定のデータ フォルダーのみを複製し、OS 全体ではなくアプリケーション サービスを再起動します。 VM レベルの HA はセットアップが簡単ですが、アプリケーション レベルの HA はハイパーバイザーに依存せず、物理、仮想、またはクラウド環境全体で実行できます。 ### 競合他社と比較した、SafeKit for Hyper-V の高可用性の際立った利点は何ですか? SafeKit は、次の点で従来の Hyper-V クラスタリング ソリューションとは異なります。 **シェアードナッシングアーキテクチャ** そして管理の簡素化。ほとんどの競合他社は VM フェイルオーバーを管理するために中央の SAN または vSAN を必要としますが、SafeKit は以下を提供します。 * **統合されたリアルタイム レプリケーション:** データ同期はソリューションに直接組み込まれており、別のストレージ レイヤーを管理するオーバーヘッドなしで、{{ .Get "app" }} 仮想マシンが同期的にミラーリングされます。 * **簡素化された 2 ノード クラスタリング:** 3 ノードの「監視」クォーラムを推奨するエンタープライズ スタックとは異なり、SafeKit はわずか 2 台の冗長サーバーで完全な高可用性を実現します。 [ハートビートとクォーラムのメカニズムの詳細をご覧ください](/ja/best-practises/heartbeat-failover-quorum-windows-linux-cluster/). * **統合管理:** 管理者は単一の SafeKit コンソールを通じて VM のフェイルオーバー、レプリケーション、負荷分散を管理できるため、クラスタリングの専門知識を持たないチームでもこのコンソールにアクセスできるようになります。 * **カスタム チェッカー:** SafeKit はハードウェアの監視を超えています。それは利用します **カスタムチェッカー** VM がクラッシュしたかどうかを検出し、ローカルの再起動または冗長ノードへのフェイルオーバーを自動的にトリガーします。このシステムは拡張性も高く、特定の環境に合わせてカスタマイズされた新しいユーザー定義のカスタム チェッカーを簡単に統合できます。 ### SafeKit は VMware タイプのソリューションと比較して TCO (総所有コスト) をどのように削減しますか? 市場のほとんどの高可用性ソリューションとは異なり、SafeKit は **絶対最小のハードウェアオーバーヘッド** セキュリティや信頼性を損なうことなく。 VMware や複雑なオープンソースの代替手段と比較した主な節約方法は次のとおりです。 * **真の 2 ノード効率:** ほとんどのエンタープライズ スタックやオープンソース ソリューションでは、スプリット ブレインを防ぐために 3 ノードの「監視」クォーラムが必要ですが、SafeKit は、 **2 台の冗長サーバー**. * **ストレージコストゼロ:** SafeKit は、ローカル ディスクで動作するシェアードナッシング アーキテクチャを使用しており、高価な SAN または vSAN ハードウェアや特殊なストレージ ネットワークが不要になります。 * **強制的な購読はありません:** 最新のサブスクリプションのみのモデルとは異なり、SafeKit は **永久ライセンス**。あなたはソフトウェアを所有し、「サブスクリプションの罠」や予測できない毎年の価格上昇を回避します。 * **低い運営費 (OPEX):** プラグアンドプレイ ソリューションであるため、複雑なオープンソース クラスタリング ツールとは異なり、専門的なトレーニングやメンテナンスのための高価な外部コンサルティングは必要ありません。 * **CPU に依存しない価格:** ライセンスは CPU やコアの数には関係ありません。 2 つのノードに対して 2 つのライセンスだけで、複数の Hyper-V 仮想マシンを保護できます。 ### SAN や複雑なクラスタリングのスキルがなくても、{{ .Get "app" }} クラスターをセットアップすることは可能ですか? はい。この記事ではその方法について説明します [Hyper-V クラスターを迅速に実装する](/ja/quick-install/safekit-quick-installation-guide-with-hyper-v/) 特殊な SAN 管理や複雑な HA クラスタリングのスキルは必要ありません。 SafeKit を使用することで **自動フェイルオーバースクリプト** レプリケーションと再起動を処理するため **{{ .Get "app" }}** 仮想マシンを使用すると、従来のエンタープライズ仮想化スタックよりも導入と保守が大幅に簡単な堅牢な冗長ソリューションが得られます。 ### {{ .Get "app" }} 以外に、SafeKit はどのアプリケーションと環境を保護できますか? SafeKit は、標準の仮想マシン フェイルオーバーをはるかに超えて拡張する多用途の高可用性ソリューションです。それは可能にする **同期リアルタイムレプリケーション** また、次のような幅広い重要なワークロードに対する自動フェイルオーバーも可能です。 * **仮想環境と物理環境:** 完全な Hyper-V または KVM 仮想マシン。 * **コンテナオーケストレーション:** Docker、Podman、および K3s (Kubernetes) 環境。 * **データとサービス:** 個々のファイル ディレクトリ、サービス、およびさまざまなデータベース。 * **クラウドインフラストラクチャ:** クラウド アプリケーションの高可用性。 SafeKit は次の機能も提供します **ファームクラスター** ネイティブと **ネットワーク負荷分散とフェイルオーバー** ステートレス アプリケーションの場合 **ウェブサーバー**. 💡 [サポートされている HA ソリューションの完全なリストについては、こちらをご覧ください。](/ja/solutions/) ## SafeKit {{ .Get "app" }} クラスターはどのように機能しますか? {#safekit-hyperv-ha-how-it-works} 次の手順は、1 つのミラー モジュール内の 1 つの {{ .Get "app" }} 仮想マシンについて説明します。レプリケートされた各仮想マシンは、Hyper-V サーバー 1 または Hyper-V サーバー 2 のいずれかであるプライマリ サーバーを備えた独立したミラー モジュール (最大 32 の仮想マシン) で実行されます。 ### 1. {{ .Get "app" }} のリアルタイム レプリケーションはどのように機能しますか? サーバー 1 (PRIM) は、{{ .Get "app" }} VM (仮想マシン) を実行します。 SafeKit は、VM ファイル (仮想ハードディスク、VM 構成) をリアルタイムで複製します。ファイルに加えられた変更のみがネットワーク全体に複製されます。 ![ミラー {{ .Get "app" }} クラスター内のバイト レベルでのファイル レプリケーション](/wp-content/uploads/2023/02/safekit-prim-second-300.png "w:300") レプリケーションは [同期](/ja/best-practises/synchronous-replication-vs-asynchronous-replication/) 非同期レプリケーションとは異なり、障害時にデータが失われることはありません。 SafeKit で VM ディレクトリ名を設定するだけです。ディスク構成に関する前提条件はありません。ディレクトリはシステム ディスク内にある場合があります。 ### 2. {{ .Get "app" }} 自動フェイルオーバー中に何が起こりますか? サーバー 1 に障害が発生すると、サーバー 2 が引き継ぎます。 SafeKit は、サーバー 2 上の {{ .Get "app" }} VM を再起動します。Hyper-V は、サーバー 2 上で SafeKit によってレプリケートされた最新のファイルを見つけます。 VM は、サーバー 1 にレプリケートされなくなったファイルをローカルで変更することにより、サーバー 2 で引き続き実行されます。 ![ミラークラスターでの {{ .Get "app" }} のフェイルオーバー](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") フェイルオーバー時間は、障害検出時間 (デフォルトでは 30 秒に設定) に VM の再起動時間を加えたものと等しくなります。 ### 3. {{ .Get "app" }} 障害の後、データはどのように同期されますか? フェールバックには、サーバー 1 の障害の原因となった問題を修正した後でサーバー 1 を再起動することが含まれます。 SafeKit は VM ファイルを自動的に再同期します。 ![ミラー {{ .Get "app" }} クラスターでのフェイルバック](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") フェールバックは {{ .Get "app" }} VM に影響を与えることなく実行され、サーバー 2 で実行を継続できます。 ### 4. 通常の {{ .Get "app" }} 動作はどのように復元されますか? 再統合後、VM ファイルはステップ 1 と同様に再びミラー モードになります。システムは高可用性モードに戻り、{{ .Get "app" }} VM がサーバー 2 で実行され、SafeKit がファイル更新をサーバー 1 にレプリケートします。 ![ミラー {{ .Get "app" }} クラスターで通常の操作に戻る](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") 管理者が VM をサーバー 1 で実行することを希望する場合は、適切なタイミングで Web コンソールを使用して手動で実行することも、構成によって自動的に実行することもできます。 ### SafeKit {{ .Get "app" }} クラスターを構成するにはどうすればよいですか?
