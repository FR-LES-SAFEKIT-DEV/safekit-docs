**HA のための SAN 投資ゼロ：** 共有なしアーキテクチャを使用して完全な冗長性を実現します。標準的なローカルディスクで動作し、高可用性のために通常必要とされる高価な SAN ハードウェア、ファイバーチャネルスイッチ、および特殊なストレージメンテナンスの必要性を排除します。 * **ハードウェアに依存しない冗長性：** ベンダーロックインを回避します。あらゆるサーバーブランドや内部ストレージタイプを使用して高可用性クラスターを構築し、既存のハードウェアのライフサイクルを延長し、交換コストを削減します。 * **HA 運用の簡素化：** 稼働時間を維持するために、専門の「クラスタリングエキスパート」は必要ありません。SafeKit のプラグアンドプレイモジュールと統合 Web コンソールは SafeKit HA 展開と日常的な監視に必要な工数を削減します。 * **コスト予測可能なライセンス：** サブスクリプション中心のモデルとは異なり、SafeKit 1 回限りの永久ライセンスで高可用性を提供します。これにより、予算を予測しやすくなり、重要なインフラストラクチャに対する年間価格上昇のリスクを排除できます。 * **真の 2 ノード HA 効率：** ほとんどの High Availability ソリューションでは、スプリットブレインを防止するために 3 番目の「ウィットネス」ノードが必要です。SafeKit 堅牢な 2 ノードクラスターを提供し、初日からハードウェア、電力、ラックのスペースを 33% 節約します。 SafeKit は、**高可用性を**軽量なソフトウェア層に統合することで、従来の仮想化スイートのコストの何分の一かで、エンタープライズグレードの冗長性と事業継続性を提供します。 ![SafeKit 高可用性 {{ .Get "app" }} クラスターアーキテクチャ](/wp-content/uploads/2026/01/safekit-vm-repli-720-720.jpg "w:512") "app" }} に高可用性をもたらします。 この記事では、特別なスキルがなくても、SAN 上の共有ストレージなしで、{{ .Get "app" }} クラスターを迅速に実装する方法を説明します。 このソリューションの原理は、重要なアプリケーションを Hyper-V 下の仮想マシンに配置することです。SafeKit は、**仮想マシンのリアルタイムレプリケーションと自動フェイルオーバーを**実装します。 Hyper-V は、すべての Windows バージョン（Windows PC 版を含む）に付属する無料のハイパーバイザーであることに注意してください。 ### SAN なしで、高可用性 {{ .Get "app" }} クラスターで複数のアプリケーションを実行するにはどうすればよいですか？ {#how-can-i-run-multiple-applications-in-a-high-availability--get-app--cluster-without-a-san} 複数のアプリケーションを、**SafeKit によって複製および再起動される複数の仮想マシン**に配置できます。**SafeKit コンソールを使用して、両方のサーバー間で各仮想マシンを移行し、SafeKit -アクティブクラスター**で負荷を分散することができます。 ### アプリケーションレベルと仮想マシン（VM）レベルのどちらで高可用性を選択すべきですか？ {#should-i-choose-high-availability-at-the-application-level-or-the-virtual-machine-vm-level} SafeKit を使用すると、お客様のニーズに合った冗長化モデルを柔軟に選択できます。 **VM レベルの冗長性**（Hyper-V または KVM 用）は、仮想マシン全体を複製するため、内部アプリケーションに関する知識は不要で、最も簡単に実装できます。 あるいは、**アプリケーションレベルの冗長性**はよりきめ細かく、OS 全体ではなく、特定のデータフォルダのみを複製し、アプリケーションサービスを再起動します。 VM レベルの HA はセットアップが簡単ですが、アプリケーションレベルの HA はハイパーバイザーに依存せず、物理、仮想、またはクラウド環境で実行できます。 ### 競合製品と比較した場合 Hyper-V 向け高可用性ソリューションである SafeKit の際立った利点は何ですか？ {#what-are-the-distinctive-advantages-of-safekit-for-hyper-v-high-availability-compared-to-competitors} SafeKit は、**共有なしアーキテクチャ**と簡素化された管理によって、従来の Hyper-V クラスタリングソリューションと差別化されています。ほとんどの競合他社が VM フェイルオーバーを管理するために中央 SAN または vSAN を必要とするのに対し、SafeKit 以下を提供します * **統合リアルタイムレプリケーション：** データ同期はソリューションに直接組み込まれており、個別のストレージレイヤーを管理するオーバーヘッドなしに、{{ .Get "app" }} 仮想マシンが同期してミラーリングされることが保証されます。 * **簡素化された 2 ノードクラスタリング：** 3 ノードの「ウィットネス」クォーラムを推奨するエンタープライズスタックとは異なり、SafeKit 2 台の冗長サーバーのみで完全な高可用性を提供します。[ハートビートとクォーラムのメカニズムの詳細をご覧ください](/ja/best-practises/heartbeat-failover-quorum-windows-linux-cluster/)。 * **統合管理：** 管理者は、単一の SafeKit コンソールを介して VM のフェイルオーバー、レプリケーション、ロードバランシングを管理できるため、専門的なクラスタリングの専門知識を持たないチームでも利用できます。 * **カスタムチェッカー：** SafeKit ハードウェア監視にとどまらず、**カスタムチェッカー**を利用して VM のクラッシュを検出し、ローカルでの再起動または冗長ノードへのフェイルオーバーを自動的にトリガーします。また、このシステムは高い拡張性を備えており、お客様の特定の環境に合わせてカスタマイズされた新しいユーザー定義のカスタムチェッカーを容易に統合できます。 ### SafeKit は、VMware のようなソリューションと比較して、TCO（総所有コスト）をどのように削減しますか？ {#how-does-safekit-reduce-the-tco-total-cost-of-ownership-compared-to-vmware-type-solutions} 市場に出回っているほとんどの高可用性ソリューションとは異なり、SafeKit セキュリティや信頼性を損なうことなく、**最小限のハードウェアオーバーヘッド**で VMware するように設計されています。VMware や複雑なオープンソースの代替品と比較した主な節約効果は以下のとおりです * **真の 2 ノード効率：** ほとんどのエンタープライズスタックやオープンソースソリューションでは、スプリットブレインを防ぐために 3 ノードの「ウィットネス」クォーラムが必要ですが、SafeKit **冗長な 2 台のサーバー**だけで完全な高可用性を提供します。 * **ストレージコストゼロ：** SafeKit、ローカルディスクで動作する共有なしアーキテクチャを使用しており、高価な SAN または vSAN ハードウェアや特殊なストレージネットワークが不要です。 * **強制的なサブスクリプションはありません：** 最新のサブスクリプション専用モデルとは異なり、SafeKit **永久ライセンス**を提供します。お客様はソフトウェアを所有し、「サブスクリプショントラップ」や予測不可能な年間価格の引き上げを回避できます。 * **低い運用コスト（OPEX）：** プラグアンドプレイソリューションであるため、複雑なオープンソースクラスタリングツールとは異なり、メンテナンスに専門的なトレーニングや高価な外部コンサルタントは必要ありません。 * **CPU に依存しない価格設定：** ライセンスは CPU またはコアの数に依存しません。2 つのノードに 2 つのライセンスを適用するだけで、複数の Hyper-V 仮想マシンを保護できます。 ### SAN や複雑なクラスタリングスキルなしで、{{ .Get "app" }} クラスターを構築することは可能ですか？ 仮想マシンのレプリケーションと再起動を処理することで、従来のエンタープライズ仮想化スタックよりもはるかに簡単に展開および保守できる、堅牢な冗長性ソリューションが得られます。 ### SafeKit は、{{ .Get "app" }} 以外にどのようなアプリケーションや環境を保護できますか？ {#beyond--get-app--which-applications-and-environments-can-safekit-protect} SafeKit は、標準的な仮想マシンのフェイルオーバーをはるかに超える汎用性の高い高可用性ソリューションです。以下を含む、幅広い重要なワークロードに対して、**同期リアルタイムレプリケーション**と自動フェイルオーバーを可能にします * **仮想環境と物理環境：** 完全な Hyper-V または KVM 仮想マシン。 * **コンテナオーケストレーション：** Docker、Podman、K3s (Kubernetes) 環境。 * **データとサービス：** 個別のファイルディレクトリ、サービス、および各種データベース。 * **クラウドインフラストラクチャ：** クラウドアプリケーションの可用性を高めます。 SafeKit は、**Web サーバー**のようなステートレスアプリケーション向けに、ネイティブの**ネットワーク負荷分散とフェイルオーバー**を備えた **farm クラスター**も提供します。 💡 [サポートされている HA ソリューションの全リストはこちらでご確認ください。](/ja/solutions/) ## SafeKit {{ .Get "app" }} クラスターの仕組みは？ {#safekit-hyperv-ha-how-it-works} 次の手順は、1 つの mirror モジュール内の 1 つの {{ .Get "app" }} 仮想マシンについて説明しています。各レプリケートされた仮想マシンは、Hyper-V サーバー 1 または Hyper-V サーバー 2 のいずれかであるプライマリサーバーを持つ独立した mirror モジュール (最大 32 台の仮想マシン) で実行されます。 ### 1. {{ .Get "app" }} のリアルタイムレプリケーションはどのように機能しますか？ {#1-how-does-real-time-replication-work-for--get-app-} サーバー 1（PRIM）は、{{ .Get "app" }} VM（仮想マシン）を実行します。SafeKit は、VM ファイル（仮想ハードディスク、VM 構成）をリアルタイムで複製します。ファイルに加えられた変更のみがネットワーク経由で複製されます。 ![mirror {{ .Get "app" }} クラスターにおけるバイトレベルでのファイルレプリケーション](/wp-content/uploads/2023/02/safekit-prim-second-300.png "w:300") 非同期レプリケーションとは異なり、レプリケーションは[同期式](/ja/best-practises/synchronous-replication-vs-asynchronous-replication/)であり、障害が発生してもデータ損失はありません。 SafeKit で VM のディレクトリ名を構成するだけです。ディスクの構成に関する前提条件はありません。ディレクトリはシステムディスクに配置できます。 ### 2. {{ .Get "app" }} 自動フェイルオーバー中に何が起こりますか？ {#2-what-happens-during-an-automatic--get-app--failover} サーバー 1 に障害が発生すると、サーバー 2 が引き継ぎます。SafeKit サーバー 2 で {{ .Get "app" }} VM を再起動します。Hyper-V SafeKit によってサーバー 2 に最新の状態にレプリケートされたファイルを見つけます。 VM は、サーバー 1 にレプリケートされなくなったファイルをローカルで変更しながら、サーバー 2 上で引き続き実行されます。 ![mirror クラスター内の {{ .Get "app" }} のフェイルオーバー](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") フェイルオーバー時間は、障害検出時間（デフォルトでは 30 秒に設定）と VM の再起動時間を合計した時間になります。 ### 3. {{ .Get "app" }} 障害発生後、データはどのように同期されますか？ {#3-how-is-data-synchronized-after-a--get-app--failure} フェイルバックでは、障害の原因となった問題を解決した後、サーバー 1 を再起動します。SafeKit VM ファイルを自動的に再同期します。 ![mirror {{ .Get "app" }} クラスターでのフェイルバック](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") フェイルバックは、{{ .Get "app" }} VM を中断することなく実行され、App VM はサーバー 2 で引き続き稼働できます。 ### 4. 通常の {{ .Get "app" }} 動作はどのように復元されますか？ {#4-how-is-normal--get-app--operation-restored} 再統合後、VM ファイルはステップ 1 と同様に mirror モードに戻ります。システムは高可用性モードに戻り、{{ .Get "app" }} VM はサーバー 2 で実行され、SafeKit ファイル更新をサーバー 1 にレプリケートします。 ![mirror {{ .Get "app" }} クラスターで通常運用に復帰する](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") 管理者が VM をサーバー 1 で実行したい場合、適切なタイミングで Web コンソールから手動で実行するか、構成によって自動的に実行することができます。 ### SafeKit {{ .Get "app" }} クラスターを構成する方法 {#safekit-mirror-cluster-configure} ![SafeKit Web Console: VM レプリケーションと自動フェイルオーバーに対応した 2 ノード {{ .Get "app" }} "ハートビートとスプリットブレイン防止に関する技術的詳細")。 ### SafeKit {{ .Get "app" }} クラスターを監視する方法 {#safekit-mirror-cluster-monitoring} ![SafeKit Web Console: 2 ノード mirror {{ .Get "app" }} クラスターのリアルタイム監視。PRIM および SECOND 2 ノードの {{ .Get "app" }} クラスターの場合、コンソールには各サーバーの役割が明確に表示されます * **PRIM (プライマリ):** 現在 VM とアプリケーションを実行しているアクティブノード。VM ファイルをローカルストレージに書き込み、セカンダリノードにリアルタイムでレプリケートします。 * **SECOND：** 同期バイトレベルの更新を受信するスタンバイノード。プライマリに障害が発生した場合、即座に引き継ぐ準備ができています。 * **ALONE 状態：** クラスターが単一ノードで実行されている場合（メンテナンス中や障害発生後など）、冗長性が一時的に失われていることを視覚的に警告します。 * **再同期の進捗状況：** 障害が発生したノードが復旧すると、バックグラウンドでのデータ再統合中にそのステータスがオレンジ色に変わり、「通常状態に戻る」フェーズ中にダウンタイムが発生しないようにします。
