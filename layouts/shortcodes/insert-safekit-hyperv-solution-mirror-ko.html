SafeKit의 플러그 앤 플레이 모듈과 통합 웹 콘솔은 HA 배포 및 일일 모니터링에 필요한 작업 시간을 줄여줍니다. * **비용 예측 가능한 라이센스:** 구독이 많은 모델과 달리 SafeKit은 일회성 영구 라이센스를 통해 고가용성을 제공합니다. 이를 통해 예측 가능한 예산 책정이 보장되고 중요한 인프라에 대한 연간 가격 인상 위험이 제거됩니다. * **진정한 2노드 HA 효율성:** 대부분의 고가용성 솔루션에는 분할 브레인을 방지하기 위해 세 번째 "감시" 노드가 필요합니다. SafeKit은 모든 브랜드의 두 서버 사이에서 {{ .Get "app" }}에 고가용성을 제공합니다. 이 문서에서는 SAN의 공유 스토리지 없이 특정 기술 없이 {{ .Get "app" }} 클러스터를 빠르게 구현하는 방법을 설명합니다. 솔루션의 원칙은 중요한 애플리케이션을 Hyper-V의 가상 머신에 배치하는 것입니다. SafeKit 구현 **가상 머신의 실시간 복제 및 자동 장애 조치**. Hyper-V는 모든 Windows 버전(PC용 Windows 포함)에 포함된 무료 하이퍼바이저입니다. ### SAN 없이 고가용성 {{ .Get "app" }} 클러스터에서 여러 애플리케이션을 어떻게 실행할 수 있나요? 여러 응용 프로그램을 넣을 수 있습니다 **SafeKit에 의해 여러 가상 머신이 복제되고 다시 시작됨**. SafeKit 콘솔을 사용하여 두 서버 간에 각 가상 머신을 마이그레이션하여 로드 균형을 조정할 수 있습니다. **활성-활성 클러스터**. ### 애플리케이션 수준 또는 가상 머신(VM) 수준에서 고가용성을 선택해야 합니까? SafeKit을 사용하면 필요에 맞는 이중화 모델을 유연하게 선택할 수 있습니다. **VM 수준 중복성** (Hyper-V 또는 KVM의 경우)은 전체 가상 머신을 복제하므로 구현이 가장 간단하며 내부 애플리케이션에 대한 지식이 필요하지 않습니다. 대안적으로, **애플리케이션 수준 중복성** 더 세분화되어 있습니다. 특정 데이터 폴더만 복제하고 전체 OS가 아닌 애플리케이션 서비스를 다시 시작합니다. VM 수준 HA는 설정하기 쉽지만 애플리케이션 수준 HA는 하이퍼바이저에 구애받지 않으며 물리적, 가상 또는 클라우드 환경에서 실행할 수 있습니다. ### 경쟁사에 비해 Hyper-V 고가용성을 위한 SafeKit의 독특한 장점은 무엇입니까? SafeKit은 다음을 통해 기존 Hyper-V 클러스터링 솔루션과 차별화됩니다. **비공유 아키텍처** 관리가 단순화되었습니다. 대부분의 경쟁업체에서는 VM 페일오버를 관리하기 위해 중앙 SAN 또는 vSAN이 필요하지만 SafeKit은 다음을 제공합니다. * **통합 실시간 복제:** 데이터 동기화는 솔루션에 직접 구축되어 별도의 스토리지 계층을 관리하는 오버헤드 없이 {{ .Get "app" }} 가상 머신이 동기식으로 미러링되도록 보장합니다. * **단순화된 2노드 클러스터링:** 3노드 "감시" 쿼럼을 권장하는 엔터프라이즈 스택과 달리 SafeKit은 단 두 개의 중복 서버로 완전한 고가용성을 제공합니다. [하트비트 및 쿼럼 메커니즘에 대해 자세히 알아보세요.](/best-practises/heartbeat-failover-quorum-windows-linux-cluster/). * **통합 관리:** 관리자는 단일 SafeKit 콘솔을 통해 VM 장애 조치, 복제 및 로드 밸런싱을 관리할 수 있으므로 전문적인 클러스터링 전문 지식 없이도 팀이 액세스할 수 있습니다. * **사용자 정의 검사기:** SafeKit은 하드웨어 모니터링 그 이상입니다. 그것은 활용한다 **맞춤 체커** VM이 충돌했는지 감지하여 로컬 다시 시작 또는 중복 노드에 대한 장애 조치를 자동으로 트리거합니다. 또한 이 시스템은 확장성이 뛰어나 특정 환경에 맞는 새로운 사용자 정의 맞춤형 검사기를 쉽게 통합할 수 있습니다. ### SafeKit은 VMware 유형 솔루션에 비해 TCO(총 소유 비용)를 어떻게 절감합니까? 시중에 나와 있는 대부분의 고가용성 솔루션과 달리 SafeKit은 **절대 최소 하드웨어 오버헤드** , 보안이나 신뢰성을 손상시키지 않고. VMware 또는 복잡한 오픈 소스 대안에 비해 주요 절감 효과는 다음과 같습니다. * **진정한 2노드 효율성:** 대부분의 엔터프라이즈 스택 또는 오픈 소스 솔루션에는 분할 브레인을 방지하기 위해 3노드 "감시" 쿼럼이 필요하지만 SafeKit은 단지 **두 개의 중복 서버**. * **스토리지 비용 제로:** SafeKit은 로컬 디스크와 작동하는 비공유 아키텍처를 사용하므로 값비싼 SAN 또는 vSAN 하드웨어와 특수 스토리지 네트워킹이 필요하지 않습니다. * **강제 구독 없음:** 최신 구독 전용 모델과 달리 SafeKit은 **영구 라이센스**. "구독 함정"과 예측할 수 없는 연간 가격 인상을 피하면서 소프트웨어를 소유하게 됩니다. * **낮은 운영 비용(OPEX):** 플러그 앤 플레이 솔루션이므로 복잡한 오픈 소스 클러스터링 도구와 달리 유지 관리를 위한 전문 교육이나 값비싼 외부 컨설팅이 필요하지 않습니다. * **CPU 독립적 가격:** 라이센스는 CPU 또는 코어 수와 무관합니다. 2개의 노드에 대한 2개의 라이센스만으로 여러 Hyper-V 가상 머신을 보호할 수 있습니다. ### SAN이나 복잡한 클러스터링 기술 없이도 {{ .Get "app" }} 클러스터를 설정할 수 있습니까? 그렇습니다. 이 문서에서는 다음 방법을 설명합니다. [Hyper-V 클러스터를 신속하게 구현](/quick-install/safekit-quick-installation-guide-with-hyper-v/) 전문적인 SAN 관리나 복잡한 HA 클러스터링 기술이 필요하지 않습니다. SafeKit을 사용하여 **자동화된 장애 조치 스크립트** 복제 및 재시작을 처리하기 위해 **{{ .Get "app" }}** 가상 머신을 사용하면 기존 엔터프라이즈 가상화 스택보다 배포 및 유지 관리가 훨씬 더 간단한 강력한 이중화 솔루션을 얻을 수 있습니다. ### {{ .Get "app" }} 외에도 SafeKit은 어떤 애플리케이션과 환경을 보호할 수 있나요? SafeKit은 표준 가상 머신 장애 조치를 훨씬 뛰어 넘는 다양한 기능을 갖춘 고가용성 솔루션입니다. 그것은 가능하게 한다 **동기식 실시간 복제** 다음을 포함하여 광범위한 중요 워크로드에 대한 자동 장애 조치가 가능합니다. * **가상 및 물리적 환경:** Hyper-V 또는 KVM 가상 머신을 완성하세요. * **컨테이너 오케스트레이션:** Docker, Podman 및 K3s(Kubernetes) 환경. * **데이터 및 서비스:** 개별 파일 디렉터리, 서비스 및 다양한 데이터베이스. * **클라우드 인프라:** 클라우드 애플리케이션의 고가용성. SafeKit은 또한 다음을 제공합니다. **농장 클러스터** 네이티브와 함께 **네트워크 부하 분산 및 장애 조치** 다음과 같은 상태 비저장 애플리케이션의 경우 **웹 서버**. 💡 [여기에서 지원되는 HA 솔루션의 전체 목록을 살펴보세요.](/ko/solutions/) ## SafeKit {{ .Get "app" }} 클러스터는 어떻게 작동합니까? {#safekit-hyperv-ha-how-it-works} 다음 단계는 하나의 미러 모듈 내에 있는 하나의 {{ .Get "app" }} 가상 머신에 대해 설명됩니다. 복제된 각 가상 머신은 Hyper-V 서버 1 또는 Hyper-V 서버 2일 수 있는 기본 서버가 있는 독립 미러 모듈(최대 32개의 가상 머신 포함)에서 실행됩니다. ### 1. {{ .Get "app" }}에서는 실시간 복제가 어떻게 작동하나요? 서버 1(PRIM)은 {{ .Get "app" }} VM(가상 머신)을 실행합니다. SafeKit은 VM 파일(가상 하드 디스크, VM 구성)을 실시간으로 복제합니다. 파일의 변경 사항만 네트워크를 통해 복제됩니다. ![미러 {{ .Get "app" }} 클러스터의 바이트 수준에서 파일 복제](/wp-content/uploads/2023/02/safekit-prim-second-300.png "w:300") 복제는 [동기식](/best-practises/synchronous-replication-vs-asynchronous-replication/) 비동기식 복제와 달리 장애 시 데이터 손실이 없습니다. SafeKit에서 VM 디렉터리 이름을 구성하기만 하면 됩니다. 디스크 구성에는 전제 조건이 없습니다. 디렉터리는 시스템 디스크에 있을 수 있습니다. ### 2. 자동 {{ .Get "app" }} 장애 조치 중에는 어떤 일이 발생합니까? 서버 1이 실패하면 서버 2가 인계받습니다. SafeKit은 서버 2에서 {{ .Get "app" }} VM을 다시 시작합니다. Hyper-V는 서버 2에서 SafeKit uptodate에 의해 복제된 파일을 찾습니다. VM은 더 이상 서버 1에 복제되지 않는 파일을 로컬에서 수정하여 서버 2에서 계속 실행됩니다. ![미러 클러스터에서 {{ .Get "app" }} 장애 조치](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") 장애 조치 시간은 결함 감지 시간(기본적으로 30초로 설정됨)에 VM 재부팅 시간을 더한 시간과 같습니다. ### 3. {{ .Get "app" }} 오류 후 데이터는 어떻게 동기화됩니까? 장애 복구에는 서버 1의 실패 원인이 된 문제를 해결한 후 서버 1을 다시 시작하는 작업이 포함됩니다. SafeKit은 VM 파일을 자동으로 재동기화합니다. ![미러 {{ .Get "app" }} 클러스터의 장애 복구](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") 장애 복구는 서버 2에서 계속 실행될 수 있는 {{ .Get "app" }} VM을 방해하지 않고 수행됩니다. ### 4. 정상적인 {{ .Get "app" }} 작동은 어떻게 복원됩니까? 재통합 후 VM 파일은 1단계와 같이 다시 한 번 미러 모드가 됩니다. 시스템은 다시 고가용성 모드로 돌아가고 {{ .Get "app" }} VM은 서버 2에서 실행되고 SafeKit은 파일 업데이트를 서버 1에 복제합니다. ![미러 {{ .Get "app" }} 클러스터에서 정상 작동으로 복귀](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") 관리자가 서버 1에서 VM을 실행하려는 경우 적절한 시간에 웹 콘솔을 통해 수동으로 수행하거나 구성을 통해 자동으로 수행할 수 있습니다. ### SafeKit {{ .Get "app" }} 클러스터를 구성하는 방법은 무엇입니까? {#safekit-mirror-cluster-configure} ![SafeKit 웹 콘솔: VM 복제 및 자동 장애 조치를 위한 2노드 {{ .Get "app" }} 클러스터 대시보드.](/wp-content/uploads/2024/03/19-module-hyperv-edit-config-1.png "w:694") 는 **SafeKit 웹 콘솔** 중요한 애플리케이션의 고가용성을 구성할 수 있는 직관적인 인터페이스를 제공합니다. 몇 단계만 거치면 다음을 구성할 수 있습니다. **SafeKit {{ .Get "app" }} 클러스터** 비즈니스 연속성을 보장하기 위해: * 넣어 `VM_PATH`, {{ .Get "app" }} VM 파일이 있는 복제된 디렉터리(D:/Repli-Hyper-V)의 루트 경로입니다. * 입력하다 `VM_NAME`, {{ .Get "app" }} 가상 머신(VM1)의 이름입니다. 참고: 만약 `VM1` 입력되고, `D:/Repli-Hyper-V/VM1/` 복제되고 VM1은 Hyper-V 명령을 사용하여 자동으로 다시 시작됩니다. SafeKit 클러스터에는 전용 [네트워크 격리 문제를 해결하기 위한 분할 브레인 검사기]( "Technical details on heartbeat and split-brain prevention") 세 번째 감시 시스템이나 추가 하트비트 네트워크가 필요하지 않습니다. ### SafeKit {{ .Get "app" }} 클러스터를 모니터링하는 방법은 무엇입니까? {#safekit-mirror-cluster-monitoring} ![SafeKit 웹 콘솔: 활성 데이터 복제를 통해 PRIM 및 SECOND 상태를 보여주는 2노드 미러 {{ .Get "app" }} 클러스터의 실시간 모니터링.](/wp-content/uploads/2024/03/14-monitoring-prim-second.png "w:604") 는 **SafeKit 관리 콘솔** 고가용성 인프라에 대한 통합 보기를 제공합니다. 이를 통해 관리자는 **작동 상태** 클러스터의 데이터 동기화를 실시간으로 추적합니다. 2노드 {{ .Get "app" }} 클러스터의 경우 콘솔에 각 서버의 역할이 명확하게 표시됩니다. * **PRIM(기본):** 현재 VM과 애플리케이션을 실행 중인 활성 노드입니다. VM 파일을 로컬 스토리지에 쓰고 보조 노드에 실시간 복제를 수행합니다. * **두 번째(보조):** 동기 바이트 수준 업데이트를 수신하는 대기 노드입니다. 기본이 실패하면 즉시 인계받을 준비가 되어 있습니다. * **ALONE 상태:** 클러스터가 단일 노드에서 실행 중일 때(예: 유지 관리 중 또는 오류 발생 후) 시각적으로 경고하여 중복성이 일시적으로 손실되었음을 나타냅니다. * **재동기화 진행률:** 실패한 노드가 복구되면 백그라운드 데이터 재통합 중에 해당 상태가 주황색으로 바뀌므로 "정상으로 복귀" 단계에서 가동 중지 시간이 발생하지 않습니다. 단순한 상태 아이콘을 넘어 인터페이스는 다음과 같은 기능을 제공합니다. **원클릭 장애 조치 오케스트레이션** , 사용자 활동에 대한 지속적인 가용성을 보장하면서 계획된 유지 관리를 위한 기본 역할을 수동으로 재할당할 수 있습니다. 복제 및 장애 조치를 위해 여러 VM을 배포하는 경우 PRIM/SECOND 위젯이 여러 개 있게 됩니다. 이를 통해 각 VM에 대한 독립적인 장애 조치가 가능하고 서버 전체에 로드를 분산시키는 기능이 가능합니다. {{ $.Page.RenderString "{{% insert-safekit-usage-ko %}}" }} ## 비교: {{ .Get "app" }}용 SafeKit과 기본 Hyper-V 클러스터링 {#safekit-hyperv-ha-comparison} 특징 | {{ .Get "app" }}용 SafeKit | MS 장애 조치 클러스터링 | Hyper-V 복제본 ---|---|---|--- 건축 | SANless(비공유) | 공유 스토리지(SAN/S2D) | 공유 없음 장애 조치 논리 | 완전 자동 | 완전 자동 | 수동 개입(HA 솔루션 아님) 복제 유형 | 동기식(제로 RPO) | 동기식(SAN을 통해) | 비동기식(데이터 손실) 정족수 요구 사항 | 없음(내장 검사기) | 3번째 노드 / 클라우드 감시 | 없음 AD 종속성 | 독립 | 필수(Active Directory) | 독립 배포 복잡성 | 낮음(< 30분) | 높음(AD, 스토리지, 쿼럼) | 중간 **요약하면** , SAN의 필요성을 제거하고 설정을 단순화하여 다음과 같은 종속성을 제거합니다. **액티브 디렉토리** 그리고 전문화된 **정족수** 구성—SafeKit은 하드웨어에 구애받지 않는 간결한 대안을 제공합니다. 이를 통해 {{ .Get "app" }} 환경이 데이터 손실 없이 자동 복구된 탄력성을 유지하면서 TCO가 크게 절감됩니다. ## 비디오 가이드: {{ .Get "app" }}용 SafeKit HA 클러스터 구성 {#videoguide-safekit-hyperv-cluster} {{ $.Page.RenderString "{{% insert-safekit-hyperv-video-ko %}}" }}
