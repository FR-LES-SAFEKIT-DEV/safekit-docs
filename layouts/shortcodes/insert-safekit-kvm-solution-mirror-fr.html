Chaque machine virtuelle répliquée s'exécute dans un module miroir indépendant (avec un maximum de 32 machines virtuelles) et son serveur principal peut être soit le serveur {{ .Get "app" }} 1, soit le serveur {{ .Get "app" }} 2.. ### 1. Comment fonctionne la réplication en temps réel pour {{ .Get "app" }} ?? Le serveur 1 (PRIM) exécute les machines virtuelles {{ .Get "app" }} et VM. SafeKit réplique en temps réel les fichiers VM (disque dur virtuel, configuration VM). Seules les modifications apportées aux fichiers sont répliquées sur le réseau.. ![Réplication de fichiers au niveau octet dans un cluster miroir {{ .Get "app" }}](/wp-content/uploads/2023/02/safekit-prim-second-300.png "w:300") La réplication est [synchrone](/best-practises/synchronous-replication-vs-asynchronous-replication/) sans perte de données en cas de panne, contrairement à la réplication asynchrone. Il vous suffit de configurer le nom du répertoire VM dans SafeKit. Aucune organisation particulière du disque n'est requise. Le répertoire peut se trouver sur le disque système.. ### 2. Que se passe-t-il lors d'un basculement automatique {{ .Get "app" }} ?? En cas de défaillance du serveur 1, le serveur 2 prend le relais. SafeKit redémarre {{ .Get "app" }} et VM sur le serveur 2. {{ .Get "app" }} constate que les fichiers répliqués par SafeKit sont à jour sur le serveur 2.. Le VM continue de fonctionner sur le serveur 2 en modifiant localement ses fichiers qui ne sont plus répliqués sur le serveur 1.. ![Basculement de {{ .Get "app" }} dans un cluster miroir](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") Le temps de basculement est égal au temps de détection de panne (fixé à 30 secondes par défaut) plus le temps de redémarrage du VM. ### 3. Comment les données sont-elles synchronisées après une panne {{ .Get "app" }} ?? La restauration du serveur consiste à redémarrer le serveur 1 après avoir résolu le problème à l'origine de la panne. SafeKit resynchronise automatiquement les fichiers VM.. ![Failback dans un cluster {{ .Get "app" }} miroir](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") Le retour en arrière s'effectue sans perturber le serveur {{ .Get "app" }} VM, qui peut continuer à fonctionner sur le serveur 2.. ### 4. Comment le fonctionnement normal du {{ .Get "app" }} est-il rétabli ?? Après réintégration, les fichiers VM sont de nouveau en mode miroir, comme à l'étape 1. Le système est de nouveau en mode haute disponibilité, avec les serveurs {{ .Get "app" }} et VM fonctionnant sur le serveur 2 et le serveur SafeKit répliquant les mises à jour de fichiers sur le serveur 1.. ![Retour au fonctionnement normal dans un groupe de disques miroir {{ .Get "app" }}](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") Si l'administrateur souhaite que le VM s'exécute sur le serveur 1, il peut le faire manuellement via la console web au moment opportun, ou automatiquement via la configuration.. ### Comment configurer un cluster SafeKit {{ .Get "app" }}? {#safekit-mirror-cluster-configure} ![Console Web SafeKit : tableau de bord du cluster {{ .Get "app" }} à 2 nœuds pour la réplication VM et le basculement automatique.](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png "w:694") Le **Console Web SafeKit** offre une interface intuitive pour configurer la haute disponibilité de vos applications critiques. Pour un cluster {{ .Get "app" }} à 2 nœuds, la console affiche clairement les rôles de chaque serveur.: * **PRIM (Primaire):** Le nœud actif exécute actuellement l'application et gère le nœud virtuel IP. Au-delà des simples icônes d'état, l'interface offre **orchestration de basculement en un clic** , vous permettant de réaffecter manuellement le rôle principal pour la maintenance planifiée tout en assurant une disponibilité continue pour l'activité des utilisateurs.
