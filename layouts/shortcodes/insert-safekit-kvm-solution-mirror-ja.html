SafeKitでは、ニーズに合った冗長モデルを柔軟に選択できます。. **VMレベルの冗長性** （{{ .Get "app" }}またはHyper-Vの場合）は、仮想マシン全体を複製するため、実装が最も簡単で、内部アプリケーションに関する知識は必要ありません。. あるいは, **アプリケーションレベルの冗長性** よりきめ細かな制御が可能で、OS全体ではなく特定のデータフォルダのみを複製し、アプリケーションサービスを再起動します。. VMレベルのHAはセットアップが容易ですが、アプリケーションレベルのHAはハイパーバイザに依存せず、物理環境、仮想環境、クラウド環境のいずれでも実行できます。. ### SafeKitの{{ .Get "app" }}高可用性における競合他社製品との比較における際立った利点は何ですか？? SafeKitは、従来の{{ .Get "app" }}クラスタリングソリューションとは、 **共有なしアーキテクチャ** そして管理が簡素化されます。ほとんどの競合製品は複雑な分散ファイルシステム（例えばCeph）または中央SAN管理するVMフェイルオーバー、SafeKit提供する: * **統合リアルタイムレプリケーション:** データ同期機能はソリューションに直接組み込まれているため、{{ .Get "app" }} 仮想マシンは、別途ストレージ層を管理するオーバーヘッドなしに同期的にミラーリングされます。. * **簡略化された2ノードクラスタリング:** 3ノードの「ウィットネス」クォーラムを推奨するエンタープライズスタックとは異なり、SafeKitは2台の冗長サーバーだけで完全な高可用性を実現します。. VMは、サーバー1に複製されなくなったファイルをローカルで変更することにより、サーバー2上で引き続き動作します。. ![ミラークラスタにおける{{ .Get "app" }}のフェイルオーバー](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") フェイルオーバー時間は、障害検出時間（デフォルトでは30秒に設定）にVMの再起動時間を加えた時間です。. ### 3. {{ .Get "app" }}障害発生後、データはどのように同期されますか？? フェイルバックとは、サーバー1の障害の原因となった問題を修正した後、サーバー1を再起動することです。SafeKitはVMファイルを自動的に再同期します。. ![ミラーリングされた{{ .Get "app" }}クラスターでのフェイルバック](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") フェイルバックは、{{ .Get "app" }} VMこれはサーバー2で引き続き実行できます. ### 4. {{ .Get "app" }}の正常な動作はどのように復元されますか？? 再統合後、VMファイルはステップ1と同様にミラーモードに戻ります。システムは高可用性モードに戻り、{{ .Get "app" }}とVMはサーバー2で実行され、SafeKitはファイル更新をサーバー1に複製します。. ![ミラー{{ .Get "app" }}クラスターで通常動作に戻る](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") 管理者がVMをサーバー1で実行したい場合は、適切なタイミングでWebコンソールから手動で行うか、構成を通じて自動的に行うことができます。. ### SafeKit {{ .Get "app" }}クラスタの設定方法? {#safekit-mirror-cluster-configure} ![SafeKitウェブコンソール：2ノード{{ .Get "app" }}クラスターダッシュボードVMレプリケーションと自動フェイルオーバー。](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png "w:694") の **SafeKitウェブコンソール** 重要なアプリケーションの高可用性を構成するための直感的なインターフェースを提供します。わずか数ステップで、 **SafeKit {{ .Get "app" }}クラスター** 事業継続性を確保するため: * 入れる `VM_PATH`, {{ .Get "app" }} VM ファイルが格納されている複製ディレクトリ (/var/lib/libvirt/images) のルートパス. * 入場する `VM_NAME`, {{ .Get "app" }}仮想マシンの名前（VM1）.
