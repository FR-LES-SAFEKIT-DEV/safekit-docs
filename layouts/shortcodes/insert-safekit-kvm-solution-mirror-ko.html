SafeKit VM 파일을 자동으로 재동기화합니다. ![mirror {{ .Get "app" }} 클러스터의 장애 복구](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") 장애 복구는 {{ .Get "app" }} VM은 서버 2에서 계속 실행될 수 있습니다. ### 4. 일반 {{ .Get "app" }} 작동은 어떻게 복원되나요? {#4-how-is-normal--get-app--operation-restored} 재통합 후 VM 파일은 1단계에서와 같이 다시 mirror 모드가 됩니다. 시스템은 고가용성 모드로 돌아가며, {{ .Get "app" }} VM은 서버 2에서 실행되고 SafeKit 파일 업데이트를 서버 1로 복제합니다. ![mirror {{ .Get "app" }} 클러스터에서 정상 작동으로 복귀](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") 관리자가 VM을 서버 1에서 실행하도록 하려면 적절한 시기에 웹 콘솔을 통해 수동으로 실행하거나 구성을 통해 자동으로 실행할 수 있습니다. ### SafeKit {{ .Get "app" }} 클러스터를 구성하는 방법 {#safekit-mirror-cluster-configure} ![SafeKit 웹 콘솔: VM 복제 및 자동 장애 조치를 위한 2노드 {{ .Get "app" }} 클러스터 대시보드.](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png "w:694") **SafeKit 웹 콘솔**은 중요한 애플리케이션의 고가용성을 구성하기 위한 직관적인 인터페이스를 제공합니다. 몇 단계만으로 **SafeKit {{ .Get "app" }} 클러스터**를 구성하여 비즈니스 연속성을 보장할 수 있습니다 * `VM_PATH` 에 {{ .Get "app" }} VM 파일이 있는 복제된 디렉터리(/var/lib/libvirt/images)의 루트 경로를 입력합니다. * {{ .Get "app" }} 가상 머신(VM1)의 이름인 `VM_NAME` 입력합니다. SafeKit 클러스터에는 전용 [스플릿 브레인 검사기가 포함되어 있어, 세 번째 증인 머신이나 추가적인 하트비트 네트워크 없이도 네트워크 격리 문제를 해결할 수 있습니다]( "하트비트 및 스플릿 브레인 방지에 대한 기술적 세부 정보"). ### SafeKit {{ .Get "app" }} 클러스터를 모니터링하는 방법은 무엇입니까? {#safekit-mirror-cluster-monitoring} ![SafeKit 웹 콘솔: 2노드 mirror {{ .Get "app" }} 클러스터의 실시간 모니터링으로, 활성 데이터 복제와 함께 PRIM 및 보조 SECOND 상태를 표시합니다.](/wp-content/uploads/2024/03/14-monitoring-prim-second.png "w:604") **SafeKit 관리 콘솔**은 고가용성 인프라에 대한 통합된 보기를 제공합니다. 관리자는 이를 통해 클러스터의 **운영 상태**를 모니터링하고 데이터 동기화를 실시간으로 추적할 수 있습니다. 2개 노드 {{ .Get "app" }} 클러스터의 경우 콘솔에 각 서버의 역할이 명확하게 표시됩니다 * **PRIM (기본):** 현재 애플리케이션을 실행하고 가상 IP를 관리하는 활성 노드입니다. 로컬 스토리지에 쓰기를 수행하고 보조 노드에 실시간 복제를 수행합니다. * **SECOND (Secondary):** 동기식 바이트 수준 업데이트를 수신하는 대기 노드입니다. 주 노드에 장애가 발생하면 즉시 인계할 준비가 되어 있습니다. * **ALONE 상태:** 클러스터가 단일 노드에서 실행 중일 때(예: 유지보수 중 또는 장애 발생 후) 시각적으로 경고하여 이중화가 일시적으로 손실되었음을 나타냅니다. * **재동기화 진행 상황:** 장애가 발생한 노드가 복구되면 백그라운드 데이터 재통합 중에 상태가 주황색으로 바뀌어 "정상으로 돌아가기" 단계에서 다운타임이 발생하지 않도록 합니다. 단순한 상태 아이콘을 넘어, 이 인터페이스는 **원클릭 장애 조치 오케스트레이션**을 제공하여 계획된 유지보수 동안 주 역할을 수동으로 재할당하는 동시에 사용자 활동에 대한 지속적인 가용성을 보장합니다. 복제 및 장애 조치를 위해 여러 VM을 배포하는 경우 여러 PRIM/SECOND 위젯이 표시됩니다. 이를 통해 각 VM에 대한 독립적인 장애 조치와 서버 간 부하 분산이 가능합니다. {{ $.Page.RenderString "{{% insert-safekit-usage-ko %}}" }} ##
