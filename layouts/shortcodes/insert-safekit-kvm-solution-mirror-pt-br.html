SafeKit proporciona alta disponibilidade ao {{ .Get "app" }} entre dois servidores de qualquer marca.. Este artigo explica como implementar rapidamente um cluster {{ .Get "app" }} sem armazenamento compartilhado em um SAN e sem habilidades específicas.. O princípio da solução é colocar a aplicação crítica em uma máquina virtual sob {{ .Get "app" }}. SafeKit implementa **replicação em tempo real e failover automático da máquina virtual**. Note que {{ .Get "app" }} é o hipervisor gratuito incluído em todas as versões do Linux.. ### Como posso executar vários aplicativos em um cluster {{ .Get "app" }} de alta disponibilidade sem um SAN?? Diversas aplicações podem ser inseridas em **várias máquinas virtuais replicadas e reiniciadas por SafeKit**. Você tem a possibilidade de migrar cada máquina virtual entre os dois servidores com o console SafeKit e, assim, balancear a carga em um **cluster ativo-ativo**. ### Devo escolher alta disponibilidade no nível da aplicação ou no nível da máquina virtual (VM)?? Com o SafeKit, você tem a flexibilidade de escolher o modelo de redundância que melhor se adapta às suas necessidades.. **Redundância de nível VM** (para {{ .Get "app" }} ou Hyper-V) é o mais simples de implementar, pois replica toda a máquina virtual, não exigindo conhecimento do aplicativo interno.. Alternativamente, **redundância em nível de aplicação** É mais granular; replica apenas pastas de dados específicas e reinicia os serviços do aplicativo, em vez de todo o sistema operacional.. Embora o VM em nível de aplicação (HA) seja mais fácil de configurar, o HA em nível de aplicação é independente de hipervisor e pode ser executado em ambientes físicos, virtuais ou em nuvem.. ### Quais são as vantagens distintivas do SafeKit para a alta disponibilidade do {{ .Get "app" }} em comparação com os concorrentes?? O SafeKit se diferencia das soluções de clusterização {{ .Get "app" }} tradicionais por meio de sua **arquitetura sem compartilhamento** e gerenciamento simplificado. Além disso, o sistema é altamente extensível, permitindo a fácil integração de novos verificadores personalizados definidos pelo usuário e adaptados ao seu ambiente específico.. ### Como o SafeKit reduz o TCO (Custo Total de Propriedade) em comparação com as soluções do tipo VMware?? Cada máquina virtual replicada é executada em um módulo de espelhamento independente (com um máximo de 32 máquinas virtuais) com um servidor primário que pode ser o servidor {{ .Get "app" }} 1 ou o servidor {{ .Get "app" }} 2.. ### 1. Como funciona a replicação em tempo real para {{ .Get "app" }}?? O servidor 1 (PRIM) executa as máquinas virtuais {{ .Get "app" }} e VM. O servidor SafeKit replica em tempo real os arquivos do servidor VM (disco rígido virtual, configuração VM). Somente as alterações feitas nesses arquivos são replicadas pela rede.. ![Replicação de arquivos em nível de byte em um cluster espelho {{ .Get "app" }}](/wp-content/uploads/2023/02/safekit-prim-second-300.png "w:300") A replicação é [síncrono](/pt-br/best-practises/synchronous-replication-vs-asynchronous-replication/) sem perda de dados em caso de falha, ao contrário da replicação assíncrona.. Basta configurar o nome do diretório VM em SafeKit. Não há pré-requisitos quanto à organização do disco. O diretório pode estar localizado no disco do sistema.. ### 2. O que acontece durante uma falha automática de {{ .Get "app" }}?? Quando o Servidor 1 falha, o Servidor 2 assume o controle. SafeKit reinicia {{ .Get "app" }} e VM no Servidor 2. {{ .Get "app" }} verifica se os arquivos replicados por SafeKit estão atualizados no Servidor 2.. O sistema VM continua em execução no Servidor 2, modificando localmente seus arquivos, que não são mais replicados para o Servidor 1.. ![Failover de {{ .Get "app" }} em um cluster espelho](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") O tempo de failover é igual ao tempo de detecção de falhas (definido como 30 segundos por padrão) mais o tempo de reinicialização do VM.. ### 3. Como os dados são sincronizados após uma falha {{ .Get "app" }}?? O failback envolve reiniciar o Servidor 1 após corrigir o problema que causou a falha. SafeKit ressincroniza automaticamente os arquivos VM.. ![Failback em um cluster espelho {{ .Get "app" }}](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") O failback ocorre sem interromper o {{ .Get "app" }} VM, que pode continuar em execução no Servidor 2.. ### 4. Como é restaurado o funcionamento normal do {{ .Get "app" }}?? Após a reintegração, os arquivos VM voltam a estar em modo espelho, como no passo 1. O sistema retorna ao modo de alta disponibilidade, com os arquivos {{ .Get "app" }} e VM em execução no Servidor 2 e o arquivo SafeKit replicando as atualizações para o Servidor 1.. ![Retorno à operação normal em um cluster espelho {{ .Get "app" }}](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") Se o administrador desejar que o VM seja executado no Servidor 1, isso pode ser feito manualmente através do console da web em um momento apropriado ou automaticamente através da configuração.. ### Como configurar um cluster SafeKit {{ .Get "app" }}? {#safekit-mirror-cluster-configure} ![Console Web SafeKit: painel de controle do cluster {{ .Get "app" }} de 2 nós para replicação VM e failover automático.](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png "w:694") O **Console web SafeKit** Oferece uma interface intuitiva para configurar a alta disponibilidade de seus aplicativos críticos. Em apenas alguns passos, você pode configurar um **Cluster SafeKit {{ .Get "app" }}** para garantir a continuidade dos negócios: * Insira `VM_PATH`, o caminho raiz do diretório replicado (/var/lib/libvirt/images) onde residem os arquivos {{ .Get "app" }} e VM. * Insira `VM_NAME`, o nome da máquina virtual {{ .Get "app" }} (VM1). O cluster SafeKit inclui um dedicado [Verificador split-brain para resolver problemas de isolamento de rede]( "Technical details on heartbeat and split-brain prevention") sem a necessidade de uma terceira máquina testemunha ou de uma rede heartbeat adicional.. ### Como monitorar um cluster SafeKit {{ .Get "app" }}? {#safekit-mirror-cluster-monitoring} ![Console Web SafeKit: Monitoramento em tempo real de um cluster espelho {{ .Get "app" }} de 2 nós, mostrando os estados PRIM e SECOND com replicação de dados ativa.](/wp-content/uploads/2024/03/14-monitoring-prim-second.png "w:604") O **Console de gerenciamento SafeKit** Oferece uma visão unificada da sua infraestrutura de alta disponibilidade. Permite que os administradores monitorem a **estado operacional** do cluster e rastrear a sincronização de dados em tempo real. Para um cluster {{ .Get "app" }} de 2 nós, o console exibe claramente as funções de cada servidor.: * **PRIM (Primário):** O nó ativo está atualmente executando o aplicativo e gerenciando o nó virtual IP. Ele realiza gravações no armazenamento local e replicação em tempo real para o nó secundário.. * **SECOND (Secundário):** O nó de espera recebe atualizações síncronas em nível de byte. Ele está pronto para assumir o controle instantaneamente caso o nó primário falhe.. * **Estado ALONE:** Alerta visualmente quando o cluster está em execução em um único nó (por exemplo, durante a manutenção ou após uma falha), indicando que a redundância foi temporariamente perdida.. * **Progresso da ressincronização:** Quando um nó com falha se recupera, seu status fica laranja durante a reintegração de dados em segundo plano, garantindo que não haja tempo de inatividade durante a fase de "retorno ao normal".. Além de simples ícones de status, a interface fornece **orquestração de failover com um clique** , permitindo que você reatribua manualmente a função principal para manutenção planejada, garantindo ao mesmo tempo a disponibilidade contínua para a atividade do usuário.. Observe que, se você implantar várias VMs para replicação e failover, terá vários widgets PRIM/SECOND.
