{#what-is-the-safekit-ha-solution-for--get-app-} SafeKit 可为任何品牌的两台服务器之间的 {{ .Get "app" }} 提供高可用性。 本文介绍了如何在没有共享存储的 SAN 上快速实施 {{ .Get "app" }} 集群，而无需特定技能。 该解决方案的原理是将关键应用程序置于 {{ .Get "app" }} 下的虚拟机中。SafeKit 实现了**虚拟机的实时复制和自动故障转移** SafeKit 请注意，{{ .Get "app" }} 是所有 Linux 版本中包含的免费虚拟机管理程序。 ### 如何在没有 SAN 的情况下，在高可用性 {{ .Get "app" }} 集群中运行多个应用程序？ {#how-can-i-run-multiple-applications-in-a-high-availability--get-app--cluster-without-a-san} 多个应用程序可以放置在**多个虚拟机中，并由 SafeKit 进行复制和重启**。您可以使用 SafeKit 控制台在两台服务器之间迁移每个虚拟机，从而在**主动-主动集群**中平衡负载。 ### 我应该选择应用程序级别还是虚拟机 (VM) 级别的“高可用性”？ {#should-i-choose-high-availability-at-the-application-level-or-the-virtual-machine-vm-level} 使用 SafeKit，您可以灵活选择适合您需求的冗余模型。 **VM 级冗余**（适用于 {{ .Get "app" }} 或 Hyper-V）是最简单的实施方式，因为它会复制整个虚拟机，而无需了解内部应用程序。 或者，**应用程序级别的冗余**更细化；它只复制特定的数据文件夹并重新启动应用程序服务，而不是整个操作系统。 虽然虚拟机级别的 HA 更易于设置，但应用程序级别的 HA 与管理程序无关，可以在物理、虚拟或云环境中运行。 ### 与竞争对手相比，SafeKit 在 {{ .Get "app" }} 高可用性方面有哪些独特的优势？ {#what-are-the-distinctive-advantages-of-safekit-for--get-app--high-availability-compared-to-competitors} SafeKit 通过其**无共享架构**和简化的管理，使其有别于传统的 {{ .Get "app" }} 集群解决方案。虽然大多数竞争对手需要复杂的分布式文件系统（如 Ceph）或中央 SAN 来管理 VM 故障转移，SafeKit 提供： * **集成实时复制：** 数据同步直接内置于解决方案中，确保 {{ .Get "app" }} 虚拟机同步镜像，而无需管理单独的存储层。 * **简化的 2 节点集群：** 与推荐 3 节点“见证”仲裁的企业堆栈不同，SafeKit 仅需两台冗余服务器即可提供完全的高可用性。[了解更多关于我们的心跳和仲裁机制](/zh-hans/best-practises/heartbeat-failover-quorum-windows-linux-cluster/)。 * **统一管理：** 管理员可以通过单个 SafeKit 控制台管理虚拟机故障转移、复制和负载平衡，使没有专业集群专业知识的团队也能使用。 * **自定义检查器：** SafeKit 不仅限于硬件监控；它还利用**自定义检查器**来检测虚拟机是否崩溃，自动触发本地重启或故障转移到冗余节点。该系统还具有高度可扩展性，允许轻松集成新的、用户定义的自定义检查器，以适应您的特定环境。 ### 与 VMware 等解决方案相比，SafeKit 如何降低 TCO（总拥有成本）？ {#how-does-safekit-reduce-the-tco-total-cost-of-ownership-compared-to-vmware-type-solutions} 与市场上大多数高可用性解决方案不同，SafeKit 设计旨在以**绝对最低的硬件开销**运行，同时不影响安全性或可靠性。与 VMware 或复杂的开源替代方案相比，主要节省包括： * **真正的双节点效率：** 虽然大多数企业堆栈或开源解决方案需要三节点“见证”仲裁来防止分裂大脑，但 SafeKit 仅需**两台冗余服务器**即可提供完全的高可用性。 * **零存储成本：** SafeKit 采用无共享架构，可与本地磁盘配合使用，无需昂贵的 SAN 或 vSAN 硬件以及专用存储网络。 * **无强制订阅：** 与现代的仅限订阅模式不同，SafeKit 提供**永久许可证**。您拥有自己的软件，避免了“订阅陷阱”和不可预测的年度价格上涨。 * **运营费用低：** 作为即插即用解决方案，它不需要专门的培训或昂贵的外部咨询来维护，这与复杂的开源集群工具不同。 * **CPU 独立定价：** 许可与 CPU 或内核的数量无关。只需两个节点，即可保护多个 {{ .Get "app" }} 虚拟机。 ### 是否可以在没有 SAN ### 除了 {{ .Get "app" }}，SafeKit 还能保护哪些应用和环境？ {#beyond--get-app--which-applications-and-environments-can-safekit-protect} SafeKit 是一种多功能高可用性解决方案，其功能远超标准虚拟机故障转移。它支持对各种关键工作负载进行**同步实时复制**和自动故障转移，包括： * **虚拟和物理环境：** 完整的 Hyper-V 或 {{ .Get "app" }} 虚拟机。 * **容器编排：** Docker、Podman 和 K3s (Kubernetes) 环境。 * **数据与服务：** 单个文件目录、服务和各种数据库。 * **云基础设施：** 为云应用程序提供高可用性。 SafeKit 还为 **farm 集群**提供原生**网络负载均衡和故障转移**，以支持 **Web 服务器**等无状态应用程序。 💡 [在此处查看支持的 HA 解决方案的完整列表。](/zh-hans/solutions/) ## SafeKit {{ .Get "app" }} 集群如何工作？ {#safekit-kvm-ha-how-it-works} 以下步骤针对一个 mirror 模块中的一个 {{ .Get "app" }} 虚拟机进行描述。每个复制的虚拟机都在一个独立的 mirror 模块（最多 32 个虚拟机）中运行，其主服务器可以是 {{ .Get "app" }} 服务器 1 或 {{ .Get "app" }} 程序服务器 2。 ### 1. {{ .Get "app" }} 的实时复制功能如何运作？ {#1-how-does-real-time-replication-work-for--get-app-} 服务器 1（PRIM）运行 {{ .Get "app" }} 虚拟机（VM）。SafeKit 实时复制 VM 文件（SafeKit 硬盘、VM 配置）。只有对文件所做的更改才会通过网络复制。 ![在 mirror {{ .Get "app" }} 集群中进行字节级文件复制](/wp-content/uploads/2023/02/safekit-prim-second-300.png "w:300") 与异步复制不同，[同步](/zh-hans/best-practises/synchronous-replication-vs-asynchronous-replication/)复制在发生故障时不会丢失数据。 您只需在 SafeKit 中配置 VM 目录名称。对磁盘组织没有先决条件。该目录可以位于系统磁盘中。 ### 2. {{ .Get "app" }} 自动故障转移期间会发生什么？ {#2-what-happens-during-an-automatic--get-app--failover} 当服务器 1 出现故障时，SafeKit 2 接管。SafeKit 在服务器 2 上重新启动 {{ .Get "app" }} 虚拟机。{{ .Get "app" }} 在服务器 2 上找到 SafeKit 复制的最新文件。 虚拟机继续在服务器 2 上运行，并本地修改其文件，这些文件不再复制到服务器 1。 ![mirror 集群中 {{ .Get "app" }} 的故障转移](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") 故障转移时间等于故障检测时间（默认设置为 30 秒）加上虚拟机重启时间。 ### 3. {{ .Get "app" }} 故障后，数据如何同步？ {#3-how-is-data-synchronized-after-a--get-app--failure} 故障恢复包括在修复导致服务器 1 故障的问题后重新启动服务器 1。SafeKit 自动重新同步虚拟机文件。 ![mirror {{ .Get "app" }} 集群中的故障恢复](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") 故障恢复在不干扰 {{ .Get "app" }} 虚拟机的情况下进行，该虚拟机可以继续在服务器 2 上运行。 ### 4. 如何恢复 {{ .Get "app" }} 正常运行？ {#4-how-is-normal--get-app--operation-restored} 重新集成后，VM 文件再次处于 mirror 模式，如步骤 1 中所述。系统恢复高可用性模式，{{ .Get "app" }} VM 在服务器 2 上运行，SafeKit 将文件更新复制到服务器 1。 ![恢复 mirror {{ .Get "app" }} 集群的正常运行](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") 如果管理员希望虚拟机在服务器 1 上运行，可以在适当的时候通过 Web 控制台手动完成，也可以通过配置自动完成。 ### 如何配置 SafeKit {{ .Get "app" }} 集群？ {#safekit-mirror-cluster-configure} ![SafeKit Web 控制台：用于虚拟机复制和自动故障转移的 2 节点 {{ .Get "app" }} 集群仪表板。](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png "w:694") **SafeKit Web 控制台**提供了一个直观的界面，用于配置关键应用程序的高可用性。**只需几个步骤，您就可以配置 SafeKit {{ .Get "app" }} 集群**以确保业务连续性： * 在 `VM_PATH` 中，输入复制目录的根路径（/var/lib/libvirt/images），其中包含 {{ .Get "app" }} VM 文件。 * 输入 `VM_NAME`，即 {{ .Get "app" }} 虚拟机 (VM1) 的名称。 SafeKit 集群包含一个专用的[裂脑检查器，用于解决网络隔离问题，]( "关于心跳和防止裂脑的技术细节")而无需第三个见证机或额外的保活网络。 ### 如何监控 SafeKit {{ .Get "app" }} 集群？ {#safekit-mirror-cluster-monitoring} ![SafeKit Web 控制台：实时监控双节点 mirror {{ .Get "app" }} 集群，显示 PRIM 和 SECOND 运行状态以及数据实时复制情况。](/wp-content/uploads/2024/03/14-monitoring-prim-second.png "w:604") **SafeKit 管理控制台**提供高可用性基础设施的统一视图。**它允许管理员监控集群的运行状态**并实时跟踪数据同步。 对于一个 2 节点 {{ .Get "app" }} 集群，控制台会清晰地显示每个服务器的角色： * **PRIM（主）：** 当前运行应用程序并管理虚拟 IP 的活动节点。它将写入本地存储，并实时复制到辅助节点。 * **SECOND（辅助）：** 接收同步字节级更新的备用节点。如果主节点发生故障，它已准备好立即接管。 * **ALONE 状态：** 当集群在单个节点上运行时（例如，在维护期间或发生故障后），会向您发出视觉警报，表明冗余暂时丢失。 * **重新同步进度：** 当故障节点恢复时，其状态在后台数据重新集成期间变为橙色，确保在“恢复正常”阶段没有停机时间。 除了简单的状态图标，该界面还提供**一键式故障转移编排**，允许您在计划维护期间手动重新分配主角色，同时确保用户活动的持续可用性。
