SafeKit 为任意品牌的两台服务器之间的 {{ .Get "app" }} 提供高可用性. 本文解释了如何快速实施{{ .Get "app" }}集群上没有共享存储SAN而且缺乏特定技能. 该解决方案的原理是将关键应用程序放在 {{ .Get "app" }} 下的虚拟机中。SafeKit 实现了 **虚拟机的实时复制和自动故障转移**. 请注意，{{ .Get "app" }} 是所有 Linux 版本中包含的免费虚拟机管理程序。. ### 如何实现多个应用程序的高可用性？{{ .Get "app" }}没有集群SAN? 可以放置多个应用程序 **SafeKit 复制并重启了多台虚拟机**. 您可以使用 SafeKit 控制台在两台服务器之间迁移每个虚拟机，从而平衡负载。 **活跃-活跃簇**. ### 我应该选择应用层高可用性还是虚拟机（VM）层高可用性？? 使用 SafeKit，您可以灵活选择满足您需求的冗余模型。. **VM级冗余** （对于 {{ .Get "app" }} 或 Hyper-V）实现起来最简单，因为它复制了整个虚拟机，无需了解内部应用程序。. 或者, **应用层冗余** 它的控制更加精细；它只复制特定的数据文件夹并重启应用程序服务，而不是重启整个操作系统。. 虽然 VM 级别的 HA 设置起来更容易，但应用级别的 HA 与虚拟机管理程序无关，可以在物理、虚拟或云环境中运行。. ### 与竞争对手相比，SafeKit 在实现 {{ .Get "app" }} 高可用性方面有哪些独特优势？? VM 进程通过本地修改不再复制到服务器 1 的文件，继续在服务器 2 上运行。. ![镜像集群中 {{ .Get "app" }} 的故障转移](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") 故障切换时间等于故障检测时间（默认设置为 30 秒）加上 VM 重启时间. ### 3. {{ .Get "app" }}故障后如何同步数据? 故障恢复是指在修复导致服务器 1 故障的问题后重新启动服务器 1。SafeKit 会自动重新同步 VM 文件。. ![镜像 {{ .Get "app" }} 集群中的故障恢复](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") 故障恢复过程不会影响 {{ .Get "app" }} 和 VM，它们可以在服务器 2 上继续运行。. ### 4. 如何恢复正常的{{ .Get "app" }}操作? 重新集成后，VM 文件再次处于镜像模式，与步骤 1 相同。系统恢复到高可用性模式，{{ .Get "app" }} 和 VM 运行在服务器 2 上，而 SafeKit 将文件更新复制到服务器 1。. ![恢复镜像 {{ .Get "app" }} 集群的正常运行](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") 如果管理员希望 VM 在服务器 1 上运行，可以在适当的时候通过 Web 控制台手动完成，也可以通过配置自动完成。. ### 如何配置 SafeKit {{ .Get "app" }} 集群? {#safekit-mirror-cluster-configure} ![SafeKitWeb 控制台：2 节点{{ .Get "app" }}集群仪表板VM复制和自动故障转移。](/wp-content/uploads/2024/03/21-module-kvm-edit-config-1.png "w:694") 这 **SafeKit 网络控制台** 提供直观的界面，用于配置关键应用程序的高可用性。只需几个步骤，即可完成配置。 **SafeKit {{ .Get "app" }} 集群** 为确保业务连续性: * 普京 `VM_PATH`, 复制目录（/var/lib/libvirt/images）的根路径，其中包含 {{ .Get "app" }} 和 VM 文件. * 输入 `VM_NAME`, {{ .Get "app" }} 虚拟机的名称 (VM1). SafeKit 集群包含一个专用的 [split-brain 检测器用于解决网络隔离问题]( "Technical details on heartbeat and split-brain prevention") 无需第三台见证机或额外的 heartbeat 网络. ### 如何监控 SafeKit {{ .Get "app" }} 集群? {#safekit-mirror-cluster-monitoring} ![SafeKit Web 控制台：实时监控 2 节点镜像 {{ .Get "app" }} 集群，显示 PRIM 和 SECOND 状态以及活动数据复制。](/wp-content/uploads/2024/03/14-monitoring-prim-second.png "w:604") 这 **SafeKit 管理控制台** 它提供高可用性基础架构的统一视图。它允许管理员监控…… **运行状态** 集群和轨道数据实时同步. 对于一个包含 2 个节点的 {{ .Get "app" }} 集群，控制台会清晰地显示每个服务器的角色。: * **PRIM（主）:** 当前运行应用程序并管理虚拟 IP 的活动节点。它执行对本地存储的写入操作，并实时复制到辅助节点。. * **SECOND（二级）:** 备用节点接收同步字节级更新。如果主节点发生故障，它随时可以接管。. * **ALONE 州:** 当集群仅在一个节点上运行时（例如，在维护期间或故障后），会发出视觉警报，表明冗余暂时丢失。. * **重新同步进度:** 当故障节点恢复时，其状态会在后台数据重新集成期间变为橙色，从而确保在“恢复正常”阶段不会出现停机时间。. 除了简单的状态图标外，该界面还提供 **一键故障转移编排** , 允许您手动重新分配计划维护期间的主要角色，同时确保用户活动的持续可用性. 请注意，如果您部署多个虚拟机用于复制和故障转移，则会有多个 PRIM/SECOND 小部件。这允许每个 VM 独立进行故障转移，并能够将负载分配到各个服务器上。. {{ $.Page.RenderString "{{% insert-safekit-usage-zh-hans %}}" }} ##
