[Replicação de qualquer tipo de dados](/pt-br/architectures/file-replication-byte-level-with-failover-mirror-cluster/#step1) | A replicação funciona para bancos de dados e para quaisquer arquivos que precisem ser replicados. | A replicação ao nível da base de dados protege apenas a base de dados, não os ficheiros de configuração, os registos ou outros dados da aplicação. [Replicação de arquivos vs. disco compartilhado](/pt-br/best-practises/shared-nothing-architecture-vs-shared-disk-architecture/) | Os servidores podem ser implantados em dois locais remotos sem infraestrutura compartilhada. | As soluções de disco compartilhado exigem proximidade física e não podem abranger locais remotos. [Locais remotos e IP virtual](/pt-br/best-practises/how-a-virtual-ip-address-works/) | Todos os recursos de cluster funcionam para 2 servidores em locais remotos. [Cluster ativo/ativo](/pt-br/architectures/active-active-cluster-real-time-replication/) | O servidor secundário não é dedicado. [Solução uniforme de HA](/pt-br/architectures/clustering-software-load-balancing-mirroring/) | SafeKit implementa tanto cluster mirror (replicação + failover) quanto [cluster farm (balanceamento de carga + failover)](/pt-br/architectures/network-load-balancing-cluster/). Essa simplicidade o torna particularmente adequado para editores de software e organizações que precisam de alta disponibilidade confiável em servidores Windows e Linux padrão.
