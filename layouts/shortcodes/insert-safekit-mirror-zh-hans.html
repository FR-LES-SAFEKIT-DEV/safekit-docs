app */}} {{/* Source: content\_index.md */}} ## SafeKit mirror 集群如何与 {{ .Get "app" }} 配合使用？ {#safekit-mirror-cluster} ### 步骤 1. 实时复制 {#step1} 服务器 1（PRIM）运行 {{ .Get "app" }} 应用程序。客户端连接到[虚拟 IP 地址](/zh-hans/best-practises/how-a-virtual-ip-address-works/)。SafeKit 通过网络实时复制文件 SafeKit 所做的修改。 ![在 mirror {{ .Get "app" }} 集群中进行字节级文件复制](/wp-content/uploads/2023/02/safekit-prim-second-300.png "w:300") 与异步复制不同，[同步](/zh-hans/best-practises/synchronous-replication-vs-asynchronous-replication/)复制在发生故障时不会丢失数据。 您只需在 SafeKit 中配置要复制的目录名称。对磁盘组织没有先决条件。目录可以位于系统磁盘中。 ### 步骤 2. 自动故障转移 {#step2} 当服务器 1 出现故障时，服务器 2 将接管。SafeKit 切换虚拟 IP 地址，并在服务器 2 上自动重新启动 {{ .Get "app" }} 应用程序。 应用程序发现 SafeKit 在服务器 2 上复制的文件是最新的。应用程序继续在服务器 2 上运行，并本地修改其不再复制到服务器 1 的文件。 ![mirror 集群中 {{ .Get "app" }} 的故障转移](/wp-content/uploads/2023/02/safekit-stop-alone-300.png "w:300") 故障转移时间等于故障检测时间（默认为 30 秒）加上应用程序启动时间。 ### 步骤 3.自动回切 {#step3} 故障恢复是指在修复导致服务器 1 故障的问题后，重新启动服务器 1。 SafeKit 会自动重新同步文件，仅更新服务器 1 停止运行时服务器 2 上修改的文件。 ![mirror {{ .Get "app" }} 集群中的故障恢复](/wp-content/uploads/2023/02/safekit-resynchro-alone-300.png "w:300") 故障恢复在不中断 {{ .Get "app" }} 应用程序的情况下进行，该应用程序可以继续在服务器 2 上运行。 ### 步骤 4. 恢复正常 {#step-4-back-to-normal} 重新集成后，文件再次处于 mirror 模式，如步骤 1 中所示。系统恢复高可用性模式，{{ .Get "app" }} 应用程序在服务器 2 上运行，SafeKit 将文件更新复制到服务器 1。 ![恢复 mirror {{ .Get "app" }} 集群的正常运行](/wp-content/uploads/2023/02/safekit-second-prim-300.png "w:300") 如果管理员希望应用程序在服务器 1 上运行，可以在适当的时候通过 Web 控制台手动完成，也可以通过配置自动完成。 ### 如何为 {{ .Get "app" }} 配置 SafeKit mirror 集群？ {#safekit-mirror-cluster-configure} ![SafeKit Web 控制台： {{ .Get "app" }} 的高可用性配置仪表板，显示心跳网络、虚拟 IP 设置以及 mirror 集群的实时目录复制。](/wp-content/uploads/2026/01/safekit-mirror-cluster-config.png "w:763") **SafeKit Web 控制台**提供了一个直观的界面，用于为您的关键应用程序编排高可用性。**只需几个步骤，您就可以配置 SafeKit mirror 集群**以确保业务连续性： * **应用程序故障转移（宏选项卡）：** 定义在发生故障时要自动重新启动的特定应用程序服务。 * **心跳网络：** 集群节点用于持续监控彼此的运行状况和可用性以及同步故障转移决策的专用通信路径。 * **虚拟 IP 管理：** 设置虚拟 IP (VIP)，以便在故障转移后实现透明的客户端重新连接。 * **实时复制：** 选择用于基于主机、同步字节级复制的关键目录。 * **检查器：** 监控应用程序的运行状况，并在检测到进程故障时触发自动恢复。 SafeKit 集群包含一个专用的裂脑检查器，用于解决网络隔离问题，而无需第三个见证机或额外的保活网络。了解[有关集群中的保活、故障转移和仲裁的](/zh-hans/best-practises/heartbeat-failover-quorum-windows-linux-cluster/)更多信息。 ### 如何监控 SafeKit mirror 集群的 {{ .Get "app" }}？ {#safekit-mirror-cluster-monitoring} ![SafeKit Web Console：实时监控一个双节点 mirror 集群，该集群用于 {{ .Get "app" }}，显示 PRIM 和 SECOND 运行状态以及数据实时复制情况。](/wp-content/uploads/2026/05/mirror-monitoring-prim-second.png "w:604") **SafeKit 管理控制台**提供高可用性基础设施的统一视图。**它允许管理员监控集群的运行状态**并实时跟踪数据同步。 对于一个 2 节点 mirror 集群，控制台会清晰地显示每个服务器的角色： * **PRIM（主）：** 当前运行应用程序并管理虚拟 IP 的活动节点。它将写入本地存储，并实时复制到辅助节点。 * **SECOND（辅助）：** 接收同步字节级更新的备用节点。如果主节点发生故障，它已准备好立即接管。 * **ALONE 状态：** 当集群在单个节点上运行时（例如，在维护期间或发生故障后），会向您发出视觉警报，表明冗余暂时丢失。 * **重新同步进度：** 当故障节点恢复时，其状态在后台数据重新集成期间变为橙色，确保在“恢复正常”阶段没有停机时间。 除了简单的状态图标，该界面还提供**一键式故障转移编排**，允许您在计划维护期间手动重新分配主角色，同时确保用户活动的持续可用性。
