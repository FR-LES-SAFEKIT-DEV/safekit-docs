{#isolation} ### Una única red {#a-single-network} Cuando hay un aislamiento de red, el comportamiento predeterminado es: * a medida que se pierden heartbeats de cada nodo, cada nodo pasa a ALONE y ejecuta la aplicación con su dirección IP virtual (doble ejecución de la aplicación que modifica sus datos locales), * Cuando se repara el aislamiento, un nodo ALONE se ve obligado a detenerse y a resincronizar sus datos desde el otro nodo * Al final, el clúster es PRIM-SECOND (o SECOND-PRIM, según la detección de direcciones IP virtuales duplicadas realizada por Windows). ### Dos redes con una red de replicación dedicada {#two-networks-with-a-dedicated-replication-network} Cuando hay un aislamiento de red, el comportamiento con una red de replicación dedicada es el siguiente: * se implementa una red de replicación dedicada en una red privada, * se pierden heartbeats en la red de producción (red aislada), * Heartbeats en la red de replicación funcionan (no en una red aislada), * El clúster permanece en el estado PRIM/SECOND. ### Una única red y un checker split-brain {#a-single-network-and-a-splitbrain-checker} Cuando hay un aislamiento de red, el comportamiento con un checker split-brain es: * se ha configurado un checker split-brain con la dirección IP de un testigo (normalmente un enrutador), * el checker split-brain funciona cuando un servidor pasa de PRIM a ALONE o de SECOND a ALONE, * En caso de aislamiento de la red, antes de pasar a ALONE, ambos nodos prueban la dirección IP * el nodo que puede acceder a la dirección IP pasa a ALONE, el otro pasa a WAIT, * Cuando se repara el aislamiento, el nodo WAIT resincroniza sus datos y se convierte en SECOND. Nota: Si el testigo está inactivo o desconectado, ambos nodos pasan a WAIT y la aplicación deja de ejecutarse. Por eso debe elegir un testigo robusto como un enrutador.
