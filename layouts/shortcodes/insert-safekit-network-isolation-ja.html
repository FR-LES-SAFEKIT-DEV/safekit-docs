{{/* Shortcode: insert-safekit-network-isolation-ja — 3 instances in 3 files */}} {{/* Parameters: none */}} {{/* Source: content\best-practises\heartbeat-failover-quorum-windows-linux-cluster.md */}} ## クラスターでネットワーク分離が発生した場合、どのようなシナリオがありますか？ {#isolation} ### 単一のネットワーク {#a-single-network} ネットワーク分離が発生すると、既定では次のように動作します。 * 各ノードでハートビートが失われるため、それぞれのノードが ALONE になり、自身の仮想 IP アドレスでアプリケーションを実行します（アプリケーションが二重に実行され、それぞれのローカルデータを変更します）。 * 分離が解消されると、一方の ALONE ノードは強制的に停止し、もう一方のノードからデータを再同期します。 * 最終的にクラスターは PRIM-SECOND になります（Windows による仮想 IP アドレスの重複検出に応じて SECOND-PRIM になる場合もあります）。 ### 専用のレプリケーションネットワークを持つ 2 つのネットワーク {#two-networks-with-a-dedicated-replication-network} ネットワーク分離が発生した場合、専用のレプリケーションネットワークがあると次のように動作します。 * 専用のレプリケーションネットワークをプライベートネットワーク上に構築します。 * 本番ネットワークのハートビートは失われます（分離されたネットワーク）。 * レプリケーションネットワークのハートビートは機能します（分離されていないネットワーク）。 * クラスターは PRIM/SECOND 状態のままです。 ### 単一のネットワークとスプリットブレインチェッカー {#a-single-network-and-a-splitbrain-checker} ネットワーク分離が発生した場合、スプリットブレインチェッカーがあると次のように動作します。 * スプリットブレインチェッカーに監視役（通常はルーター）の IP アドレスを設定しておきます。 * サーバーが PRIM から ALONE、または SECOND から ALONE に移行するときに、スプリットブレインチェッカーが動作します。 * ネットワーク分離時には、両方のノードが ALONE になる前に IP アドレスをテストします。 * IP アドレスにアクセスできるノードは ALONE に、もう一方は WAIT に移行します。 * 分離が解消されると、WAIT ノードがデータを再同期して SECOND になります。 注：監視役が停止または切断されていると、両方のノードが WAIT になり、アプリケーションは実行されなくなります。そのため、ルーターのような信頼性の高い監視役を選ぶ必要があります。
