{{/* Shortcode: insert-safekit-network-isolation-pt-br — 3 instances in 3 files */}} {{/* Parameters: none */}} {{/* Source: content\best-practises\heartbeat-failover-quorum-windows-linux-cluster.md */}} ## Quais são os diferentes cenários em caso de isolamento de rede em um cluster? {#isolation} ### Uma única rede {#a-single-network} Quando ocorre um isolamento de rede, o comportamento padrão é: * como os heartbeats de cada nó são perdidos, cada nó passa para ALONE e executa a aplicação com seu endereço IP virtual (execução dupla da aplicação, modificando seus dados locais), * quando o isolamento é resolvido, um nó ALONE é forçado a parar e a ressincronizar seus dados a partir do outro nó, * ao final, o cluster fica em PRIM-SECOND (ou SECOND-PRIM, conforme a detecção de endereço IP virtual duplicado realizada pelo Windows). ### Duas redes com uma rede de replicação dedicada {#two-networks-with-a-dedicated-replication-network} Quando ocorre um isolamento de rede, o comportamento com uma rede de replicação dedicada é: * uma rede de replicação dedicada é implementada em uma rede privada, * os heartbeats na rede de produção são perdidos (rede isolada), * os heartbeats na rede de replicação funcionam (rede não isolada), * o cluster permanece no estado PRIM/SECOND. ### Uma única rede e um verificador de split-brain {#a-single-network-and-a-splitbrain-checker} Quando ocorre um isolamento de rede, o comportamento com um verificador de split-brain é: * um verificador de split-brain foi configurado com o endereço IP de uma testemunha (geralmente um roteador), * o verificador de split-brain atua quando um servidor passa de PRIM para ALONE ou de SECOND para ALONE, * em caso de isolamento de rede, antes de passar para ALONE, os dois nós testam o endereço IP, * o nó que consegue acessar o endereço IP passa para ALONE, e o outro passa para WAIT, * quando o isolamento é resolvido, o nó WAIT ressincroniza seus dados e passa a SECOND. Nota: Se a testemunha estiver fora de serviço ou desconectada, os dois nós passam para WAIT e a aplicação deixa de ser executada. Por isso, você deve escolher uma testemunha robusta, como um roteador.
