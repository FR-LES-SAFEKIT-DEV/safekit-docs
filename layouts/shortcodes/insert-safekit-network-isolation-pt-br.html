{#isolation} ### Uma única rede {#a-single-network} Quando há um isolamento de rede, o comportamento padrão é: * à medida que heartbeats são perdidas para cada nó, cada nó vai para ALONE e executa o aplicativo com seu endereço IP virtual (execução dupla do aplicativo modificando seus dados locais), * quando o isolamento é reparado, um nó ALONE é forçado a parar e a ressincronizar seus dados com o outro nó, * no final, o cluster é PRIM-SECOND (ou SECOND-PRIM, de acordo com a detecção de endereço IP virtual duplicado feita pelo Windows). ### Duas redes com uma rede de replicação dedicada {#two-networks-with-a-dedicated-replication-network} Quando há um isolamento de rede, o comportamento com uma rede de replicação dedicada é: * uma rede de replicação dedicada é implementada em uma rede privada, * Heartbeats na rede de produção são perdidos (rede isolada), * Heartbeats na rede de replicação estão funcionando (não na rede isolada), * o cluster permanece no estado PRIM/SECOND. ### Uma única rede e um checker split-brain {#a-single-network-and-a-splitbrain-checker} Quando há um isolamento de rede, o comportamento com um checker split-brain é: * um checker split-brain foi configurado com o endereço IP de uma testemunha (normalmente um roteador), * o checker split-brain opera quando um servidor passa de PRIM para ALONE ou de SECOND para ALONE, * Em caso de isolamento de rede, antes de ir para ALONE, ambos os nós testam o endereço IP * o nó que pode acessar o endereço IP vai para ALONE, o outro vai para WAIT, * Quando o isolamento é reparado, o nó WAIT resincroniza seus dados e se torna SECOND. Observação: se a testemunha estiver inativa ou desconectada, ambos os nós entram em WAIT e o aplicativo não está mais em execução. É por isso que você deve escolher uma testemunha robusta, como um roteador.
