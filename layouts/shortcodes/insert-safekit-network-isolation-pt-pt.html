{#isolation} ### Uma única rede {#a-single-network} Quando existe um isolamento de rede, o comportamento predefinido é: * à medida que heartbeats são perdidos para cada nó, cada nó vai para ALONE e executa a aplicação com o seu endereço IP virtual (execução dupla da aplicação que modifica os seus dados locais), * quando o isolamento é reparado, um nó ALONE é forçado a parar e a resincronizar os seus dados a partir do outro nó, * no final, o cluster é PRIM-SECOND (ou SECOND-PRIM, de acordo com a deteção de endereço IP virtual duplicado feita pelo Windows). ### Duas redes com uma rede de replicação dedicada {#two-networks-with-a-dedicated-replication-network} Quando existe isolamento de rede, o comportamento com uma rede de replicação dedicada é: * uma rede de replicação dedicada é implementada numa rede privada, * Heartbeats na rede de produção são perdidas (rede isolada), * Heartbeats na rede de replicação estão a funcionar (não é uma rede isolada), * o cluster permanece no estado PRIM/SECOND. ### Uma única rede e um checker split-brain {#a-single-network-and-a-splitbrain-checker} Quando existe um isolamento de rede, o comportamento com um checker split-brain é: * um checker split-brain foi configurado com o endereço IP de um testemunha (normalmente um router), * o checker split-brain funciona quando um servidor passa de PRIM para ALONE ou de SECOND para ALONE, * em caso de isolamento de rede, antes de ir para ALONE, ambos os nós testam o endereço IP, * o nó que consegue aceder ao endereço IP vai para ALONE, o outro vai para WAIT, * Quando o isolamento é reparado, o nó WAIT resincroniza os seus dados e torna-se SECOND. Nota: Se a testemunha estiver inativa ou desconectada, ambos os nós entram em WAIT e a aplicação deixa de funcionar. É por isso que deve escolher uma testemunha robusta, como um router.
