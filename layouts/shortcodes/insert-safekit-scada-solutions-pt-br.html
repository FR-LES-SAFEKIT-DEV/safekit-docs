{{/* translation: translate_md 2026-11-08.15 | glossaire 2026-11-09.10 | Translation LLM | 30 expressions */}} {{/* Shortcode: insert-safekit-scada-solutions-en — 1 instance in 1 file */}} {{/* Parameters: app */}} {{/* Source: content\use-cases\scada-software-redundancy-high-availability.md */}} ## SafeKit oferece duas soluções para redundância e alta disponibilidade de um software {{ .Get "app" }} {#safekit-brings-two-solutions-for-redundancy-and-high-availability-of-a-scada-software} ### Redundância e alta disponibilidade no nível do aplicativo {#redundancy-and-high-availability-at-the-application-level} Nesse tipo de solução, apenas os dados do aplicativo são replicados. E apenas o aplicativo é reiniciado em caso de falha. ![Redundância no nível do aplicativo para um software {{ .Get "app" }}](/wp-content/uploads/2023/02/application-ha-4.png "w:168") Com esta solução, os scripts de reinicialização devem ser escritos para reiniciar o aplicativo. Esta solução é independente da plataforma e funciona com aplicativos em máquinas físicas, máquinas virtuais e na nuvem. Qualquer hipervisor é suportado (VMware, Hyper-V ...). * Solução para uma nova aplicação (reiniciar scripts para escrever): 💡 [Windows](/pt-br/solutions/windows-high-availability-software-synchronous-replication-failover/), 💡 [Linux](/pt-br/solutions/linux-high-availability-software-synchronous-replication-failover/) ### Redundância e alta disponibilidade no nível da máquina virtual {#redundancy-and-high-availability-at-the-virtual-machine-level} Nesse tipo de solução, o software {{ .Get "app" }} é colocado dentro de uma máquina virtual. A máquina virtual (VM) completa é replicada e reiniciada (aplicativo + SO). ![Redundância no nível da máquina virtual para um software {{ .Get "app" }}](/wp-content/uploads/2023/02/vm-ha-4.png "w:186") A vantagem dessa solução é que não há scripts de reinicialização para escrever por aplicativo. Essa solução é genérica para qualquer software {{ .Get "app" }}. Ela funciona com Windows/Hyper-V e Linux/KVM, mas não com VMware. Essa é uma solução ativa/ativa com várias máquinas virtuais replicadas e reiniciadas entre dois nós. * Solução para uma nova aplicação (sem script de reinicialização para escrever): 💡 [Windows/Hyper-V](/pt-br/solutions/hyper-v-replication-automatic-failover-load-balancing/), 💡 [Linux/KVM](/pt-br/solutions/linux-kvm-high-availability-replication-automatic-failover-load-balancing/)
