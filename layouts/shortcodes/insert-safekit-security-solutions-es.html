Y solo se reinicia la aplicación en caso de error. ![Redundancia a nivel de aplicación para un software {{ .Get "app" }}](/wp-content/uploads/2023/02/application-ha-4.png "w:168") Esta solución requiere un conocimiento técnico de la aplicación. Es necesario definir qué servicios reiniciar, especificar las carpetas de la aplicación que se van a replicar y configurar una dirección IP virtual para la conmutación por error. Pero esta solución es independiente de la plataforma y funciona con aplicaciones dentro de máquinas físicas, máquinas virtuales y en la nube. Se admite cualquier hipervisor (VMware, Hyper-V ...). ### Ejemplos {#examples} * Gestión de vídeo: 💡 [Milestone (gestión, SQL, registro, eventos)/SafeKit](/es/solutions/milestone-xprotect-corporate-high-availability-synchronous-replication-failover/) * Gestión de vídeo: 💡 [Genetec (SQL)/SafeKit](/es/solutions/genetec-sql-server-the-simplest-high-availability-cluster-with-synchronous-replication-and-failover-between-two-redundant-servers/) * Control de acceso: 💡 [Nedap (AEOS, SQL)/SafeKit](/es/solutions/nedap-high-availability-synchronous-replication-failover/) * Nueva aplicación (definir los servicios que se reiniciarán, las carpetas de la aplicación que se replicarán, una dirección IP virtual para la conmutación por error): 💡 [Windows](/es/solutions/windows-high-availability-software-synchronous-replication-failover/), 💡 [Linux](/es/solutions/linux-high-availability-software-synchronous-replication-failover/) ### Redundancia y alta disponibilidad a nivel de máquina virtual {#redundancy-and-high-availability-at-the-virtual-machine-level} En este tipo de solución, el software {{ .Get "app" }} se coloca dentro de una máquina virtual. La máquina virtual completa (VM) se replica y se reinicia (aplicación + sistema operativo). ![Redundancia a nivel de máquina virtual para un software {{ .Get "app" }}](/wp-content/uploads/2023/02/vm-ha-4.png "w:184") La ventaja de esta solución es que no requiere un conocimiento técnico de la aplicación; solo es necesario definir la ubicación de los archivos de la máquina virtual donde está instalada la aplicación. Esta solución es genérica para cualquier software {{ .Get "app" }}. Sin embargo, solo funciona con Windows/Hyper-V y Linux/KVM, pero no con VMware. Se trata de una solución activa/activa con varias máquinas virtuales replicadas y reiniciadas entre dos nodos. ### Ejemplos {#examples-1} * Gestión de edificios: 💡 [Siemens Desigo CC/SafeKit](/es/solutions/siemens-desigo-cc-redundancy-high-availability-cluster-active-active/) * Gestión de vídeo y control de acceso: 💡 [Suite Siemens Siveillance/SafeKit](/es/solutions/siemens-siveillance-redundancy-high-availability-cluster-active-active/) * Nueva aplicación (defina la ubicación de la carpeta de archivos de la máquina virtual donde está instalada la aplicación): 💡 [Windows/Hyper-V](/es/solutions/hyper-v-replication-automatic-failover-load-balancing/), 💡 [Linux/KVM](/es/solutions/linux-kvm-high-availability-replication-automatic-failover-load-balancing/) Más comparaciones entre [HA de VM y la HA de aplicación](/es/best-practises/vm-ha-vs-application-ha/)
