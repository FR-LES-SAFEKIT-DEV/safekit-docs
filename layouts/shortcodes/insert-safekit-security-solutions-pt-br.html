E apenas o aplicativo é reiniciado em caso de falha. ![Redundância no nível do aplicativo para um software {{ .Get "app" }}](/wp-content/uploads/2023/02/application-ha-4.png "w:168") Essa solução requer um conhecimento técnico da aplicação. Você precisa definir quais serviços reiniciar, especificar as pastas da aplicação a serem replicadas e configurar um endereço IP virtual para o failover. Mas essa solução é independente de plataforma e funciona com aplicações em máquinas físicas, máquinas virtuais e na nuvem. Qualquer hipervisor é suportado (VMware, Hyper-V ...). ### Exemplos {#examples} * Gestão de vídeo: 💡 [Milestone (Gestão, SQL, Log, Evento)/SafeKit](/pt-br/solutions/milestone-xprotect-corporate-high-availability-synchronous-replication-failover/) * Gestão de vídeo: 💡 [Genetec (SQL)/SafeKit](/pt-br/solutions/genetec-sql-server-the-simplest-high-availability-cluster-with-synchronous-replication-and-failover-between-two-redundant-servers/) * Controle de acesso: 💡 [Nedap (AEOS, SQL)/SafeKit](/pt-br/solutions/nedap-high-availability-synchronous-replication-failover/) * Novo aplicativo (defina os serviços para reiniciar, as pastas do aplicativo para replicar, um endereço IP virtual para failover): 💡 [Windows](/pt-br/solutions/windows-high-availability-software-synchronous-replication-failover/), 💡 [Linux](/pt-br/solutions/linux-high-availability-software-synchronous-replication-failover/) ### Redundância e alta disponibilidade no nível da máquina virtual {#redundancy-and-high-availability-at-the-virtual-machine-level} Nesse tipo de solução, o software {{ .Get "app" }} é colocado dentro de uma máquina virtual. A máquina virtual (VM) completa é replicada e reiniciada (aplicativo + SO). ![Redundância no nível da máquina virtual para um software {{ .Get "app" }}](/wp-content/uploads/2023/02/vm-ha-4.png "w:184") A vantagem dessa solução é que ela não requer um conhecimento técnico do aplicativo; você só precisa definir a localização dos arquivos da VM onde o aplicativo está instalado. Essa solução é genérica para qualquer software {{ .Get "app" }}. No entanto, ela funciona apenas com Windows/Hyper-V e Linux/KVM, mas não com VMware. Essa é uma solução ativa/ativa com várias máquinas virtuais replicadas e reiniciadas entre dois nós. ### Exemplos {#examples-1} * Gestão de edifícios: 💡 [Siemens Desigo CC/SafeKit](/pt-br/solutions/siemens-desigo-cc-redundancy-high-availability-cluster-active-active/) * Gestão de vídeo e controlo de acesso: 💡 [Suite Siemens Siveillance/SafeKit](/pt-br/solutions/siemens-siveillance-redundancy-high-availability-cluster-active-active/) * Nova aplicação (defina o local da pasta de arquivos da VM onde a aplicação está instalada): 💡 [Windows/Hyper-V](/pt-br/solutions/hyper-v-replication-automatic-failover-load-balancing/), 💡 [Linux/KVM](/pt-br/solutions/linux-kvm-high-availability-replication-automatic-failover-load-balancing/) Mais comparações entre [HA de VM e HA de aplicação](/pt-br/best-practises/vm-ha-vs-application-ha/)
