### ロードバランサーのルールを構成する方法： {{ .Get "app" }} はステートフルですか、それともステートレスですか？ {#stateful-stateless} ロードバランサーの構成は、アプリケーションがステートフルかステートレスかによって異なります #### ステートフル構成（セッションアフィニティ） {#stateful-configuration-session-affinity} **ステートフル**{{ .Get "app" }} の場合、セッションアフィニティ（永続性）が必要です。これにより、特定のクライアントが複数の TCP セッションにわたって同じノードに接続されたままで、アプリケーションコンテキストを維持できます。このシナリオでは、ロードバランサーは**クライアントの IP アドレス**に基づくルールで構成されています。その結果、個々のクライアントが特定のノードにロックされている間、異なるクライアントからのトラフィックは farm 内のさまざまなノードに分散されます。 #### ステートレス構成（アフィニティなし） {#stateless-configuration-no-affinity} 逆に、**ステートレス**{{ .Get "app" }} の場合、セッションアフィニティは必要ありません。セッション間でローカルコンテキストがノードに保存されないため、単一のクライアントは、新しい TCP セッションごとに異なるノード間で負荷分散できます。この場合、ロードバランサーのルールは**TCP セッション ID** に基づいて構成されます。この構成は、farm 全体で最も効率的なトラフィック分散を提供しますが、セッションの依存関係なしに設計されたサービスにのみ適用できます。 ### {{ .Get "app" }} で SafeKit farm クラスターを構成する方法 {#safekit-farm-cluster-configuration} ![SafeKit Web Console:ネットワーク負荷分散と仮想 IP 管理のための farm **チェッカー：** アプリケーションの正常性を監視し、プロセスの障害が検出された場合は自動再起動をトリガーします。 ### {{ .Get "app" }} で SafeKit farm クラスターを監視する方法 {#safekit-farm-cluster-monitoring} ![SafeKit Console: 2 ノード farm クラスターを監視。両方のノードが UP
