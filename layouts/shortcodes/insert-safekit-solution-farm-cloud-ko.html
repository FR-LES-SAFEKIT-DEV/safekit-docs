SafeKit은 두 개 이상의 노드에서 {{ .Get "app" }} 네트워크 부하 분산과 고가용성을 제공합니다. 이 문서에서는 전문적인 고가용성(HA) 지식 없이 {{ .Get "app" }} 클러스터를 빠르게 구현하는 방법을 설명합니다. 이 솔루션은 SafeKit의 **애플리케이션 상태 확인**을 {{ .Get "app" }} 로드 밸런서 수준에서 정의된 가상 IP와 통합합니다. 특정 애플리케이션 서비스 이름과 애플리케이션 검사기를 구성하면 로드 밸런서가 정상 작동하는 애플리케이션으로만 트래픽을 전달하도록 SafeKit이 보장합니다. SafeKit은 **네트워크 부하 분산 및 자동 페일오버**를 제공하여 업무상 중요한 애플리케이션의 원활한 확장성과 지속적인 서비스 가용성을 보장합니다. ### SafeKit 애플리케이션 모니터링은 표준 NLB 상태 확인과 어떻게 다른가요? 간단한 **ping** 및 포트 확인에 의존하는 표준 NLB 하드웨어와 달리 SafeKit에는 **애플리케이션 수준 검사기**가 통합되어 있습니다. 기존 로드 밸런서는 서버가 "살아 있는지"만 확인하지만, SafeKit은 특정 {{ .Get "app" }} 애플리케이션의 실제 상태를 모니터링합니다. 이 심층 모니터링을 통해 서버는 작동 중이지만 소프트웨어가 중단된 "좀비" 상태를 감지하고, 표준 NLB 솔루션에서는 불가능한 **서비스 자동 재시작** 또는 트래픽 전환을 수행합니다. ### SafeKit은 일관된 배포와 클라우드 가상 IP를 어떻게 처리하나요? SafeKit은 클라우드에 종속되지 않으며 온프레미스 서버와 주요 클라우드 공급자 모두에서 배포 절차와 아키텍처의 일관성을 유지합니다. 주요 아키텍처 차이는 네트워크에 **[가상 IP(VIP)](/ko/best-practises/how-a-virtual-ip-address-works/)**를 제공하는 방식입니다. * **온프레미스:** SafeKit은 효율적인 **커널 수준 필터링**을 사용해 애플리케이션 서버에서 VIP 부하 분산을 직접 관리합니다. 페일오버 시 로컬 스위치에 **GARP(Gratuitous ARP)** 패킷을 보내 IP를 활성 노드에 즉시 재할당합니다. * **클라우드:** 클라우드 네트워크는 GARP를 지원하지 않으므로 가상 IP는 **클라우드 로드 밸런서**에 호스팅됩니다. 이 구성에서 노드 상태를 확인하는 데 필요한 지능형 상태 확인을 **SafeKit이 제공합니다**. 로드 밸런서는 활성 노드를 실시간으로 감지하고 트래픽을 자동으로 전달하여 가용 영역 간 원활한 페일오버를 지원합니다. ### 분리된 도구 대신 통합형 올인원 HA 솔루션을 선택해야 하는 이유는 무엇인가요? 클러스터링을 위해 별도의 제품을 조합하는 추가형 솔루션과 달리, **SafeKit**은 **가상 IP, 네트워크 부하 분산, 자동 페일오버, 자동 페일백, 동기식 실시간 파일 복제**를 단일 엔진에 통합합니다. 따라서 업데이트가 서로 다른 도구 간의 취약한 연결을 깨뜨리는 "모래성" 위험을 없애고 HA 스택 전체의 책임을 단일화합니다. 또한 {{ .Get "app" }} 애플리케이션 **고가용성**을 단일 인터페이스에서 제공하여 인적 오류를 줄입니다. ### 클러스터링 기술이 없어도 {{ .Get "app" }} `farm` 클러스터를 설정할 수 있나요? 예. 이 문서에서는 전문적이고 복잡한 클러스터링 기술 없이 {{ .Get "app" }} `farm` 클러스터를 [빠르게 구현하는 방법]({{ .Get "guide" }})을 설명합니다. SafeKit 상태 확인으로 가상 IP 부하 분산, 애플리케이션 모니터링 및 재시작을 처리하므로 기존 NLB 클러스터 솔루션보다 배포와 유지 관리가 훨씬 쉬운 견고하고 확장 가능한 솔루션을 제공합니다. ### {{ .Get "app" }} 외에 SafeKit은 어떤 애플리케이션과 환경을 보호할 수 있나요? SafeKit은 **Windows와 Linux 모두**를 지원하는 유연한 고가용성 솔루션으로 {{ .Get "app" }} `farm` 클러스터에 국한되지 않습니다. **동기식 실시간 복제**와 자동 페일오버를 제공하는 Mirror 클러스터를 통해 다음과 같은 다양한 중요 워크로드를 보호합니다. * **가상 및 물리 환경:** 전체 Hyper-V 또는 KVM 가상 머신. * **컨테이너 오케스트레이션:** Docker, Podman 및 K3s(Kubernetes) 환경. * **데이터 및 서비스:** 개별 파일 디렉터리, 서비스 및 다양한 데이터베이스. * **클라우드 인프라:** 클라우드 애플리케이션의 고가용성. 💡 [지원되는 HA 솔루션 전체 목록을 확인하세요.](/ko/solutions/) ## SafeKit NLB 및 HA 아키텍처** ### 로드 밸런서 규칙을 구성하는 방법: {{ .Get "app" }} 애플리케이션은 상태 저장인가요, 상태 비저장인가요? {#stateful-stateless} 로드 밸런서 구성은 애플리케이션이 상태 저장인지 상태 비저장인지에 따라 달라집니다. #### 상태 저장 구성(세션 고정) **상태 저장** {{ .Get "app" }} 애플리케이션에는 세션 고정(지속성)이 필요합니다. 이를 통해 특정 클라이언트가 여러 TCP 세션 동안 같은 노드에 연결되어 애플리케이션 컨텍스트를 유지합니다. 이때 로드 밸런서 규칙은 **클라이언트 IP 주소**를 기준으로 합니다. 개별 클라이언트는 특정 노드에 고정되고, 서로 다른 클라이언트의 트래픽은 `farm`의 여러 노드에 분산됩니다. #### 상태 비저장 구성(고정 없음) 반대로 **상태 비저장** {{ .Get "app" }} 애플리케이션에는 세션 고정이 필요하지 않습니다. 세션 사이에 노드에 로컬 컨텍스트를 저장하지 않으므로 새 TCP 세션마다 하나의 클라이언트를 서로 다른 노드로 분산할 수 있습니다. 이 경우 규칙은 **TCP 세션 ID**를 기준으로 합니다. `farm` 전체에 트래픽을 가장 효율적으로 분산하지만 세션 종속성이 없는 서비스에만 적용됩니다. ### {{ .Get "app" }}에서 SafeKit `farm` 클러스터를 구성하는 방법 {#safekit-farm-cluster-configuration} ![SafeKit 웹 콘솔: 네트워크 부하 분산 및 가상 IP 관리를 위한 `Farm` 클러스터 구성.](/wp-content/uploads/2026/01/safekit-farm-cluster-config.png "w:966") SafeKit **`farm` 클러스터**는 서비스의 고가용성과 확장성을 위해 설계되었습니다. 구성은 두 노드에 들어오는 트래픽을 동시에 분산하는 데 중점을 둡니다. * **부하 분산 서비스(Macros 탭):** 모든 사용하는 클라우드 로드 밸런서에 가상 IP를 구성합니다. * **부하 분산 규칙:** 온프레미스에서는 SafeKit 웹 콘솔에서 원본 IP 주소 또는 포트 기준으로 트래픽 분산 정책을 구성합니다. 클라우드에서는 클라우드 로드 밸런서에서 정책을 구성합니다. * **검사기:** 애플리케이션 상태를 모니터링하고 프로세스 장애가 감지되면 자동 재시작을 실행합니다. 모니터링.](/wp-content/uploads/2026/01/safekit-farm-cluster-monitor.png "w:473") `farm` 클러스터 모니터링을 통해 모든 노드가 애플리케이션 성능에 기여하는 **액티브-액티브** 인프라를 확인할 수 있습니다(이 예에서는 2개 노드를 표시). * **UP 상태(2개 노드에서 50%):** 정상적인 `farm`에서는 두 노드 모두 "UP"(50%) 상태이며 공유 가상 IP를 통해 클라이언트 요청을 활발하게 수신하고 처리합니다. * **자동 재분배:** 한 노드에 장애가 발생하면 남은 노드가 트래픽의 100%를 처리하는 모습이 콘솔에 표시됩니다. 페일오버 지연은 클라우드 로드 밸런서의 상태 확인 폴링 간격에 따라 달라집니다. * **노드 추가:** 복구된 노드를 다시 시작하면 "STOP"에서 "UP"으로 전환되고 관리자의 개입 없이 트래픽 일부를 자동으로 받기 시작합니다. * **데이터 동기화 없음:** `farm` 클러스터에는 "Orange" 재동기화 상태가 없습니다. 노드는 상태 비저장이거나 백엔드 데이터베이스를 공유하는 것으로 간주하며, 해당 데이터베이스는 Mirror 클러스터에서 별도로 보호할 수 있습니다. 단순 상태 아이콘 외에도 인터페이스에서 원클릭 노드 관리를 제공합니다. 계획된 유지 관리를 위해 노드를 수동으로 중지하거나 시작해도 공유 가상 IP가 사용자 활동을 중단하지 않고 트래픽을 자동으로 재분배합니다. ## 비교: 온프레미스 SafeKit `Farm` 클러스터와 클라우드 SafeKit `Farm` 클러스터 전달하지 않습니다. 인프라 요구 사항 | 표준 Layer 2 네트워크(VIP용 동일 서브넷). | 최대 복원력을 위한 Multi-AZ(가용 영역). **요약하면**, 온프레미스와 클라우드 어디서나 SafeKit은 단일 통합 인터페이스를 통해 중요 애플리케이션의 복원력과 확장성을 보장하고 관리를 간소화합니다. 소프트웨어 공급업체에게 **소프트웨어만으로
