SafeKit 软件如何轻松实现 {{ .Get "app" }} 网络负载均衡（NLB）集群？ {#safekit-farm-ha-cluster} ### 什么是适用于 {{ .Get "app" }} 的 SafeKit Farm NLB 解决方案？ SafeKit 可在两个或更多节点之间为 {{ .Get "app" }} 提供网络负载均衡和高可用性。 本文介绍如何在不具备专业高可用性（HA）知识的情况下快速实现 {{ .Get "app" }} 集群。 该解决方案将 SafeKit 的**应用程序运行状况检查**与在 {{ .Get "app" }} 负载均衡器级别定义的虚拟 IP 集成。通过配置特定的应用程序服务名称和应用程序检查器，SafeKit 可确保负载均衡器仅将流量发送到健康且正常运行的应用程序。 SafeKit 可实现**网络负载均衡和自动故障转移**，为关键任务应用程序带来无缝扩展能力和持续服务可用性。 ### SafeKit 应用程序监控与标准 NLB 运行状况检查有何不同？ 标准 NLB 硬件依赖简单的 **ping** 和端口检查，而 SafeKit 则具有**集成的应用程序级检查器**。传统负载均衡器只能确认服务器是否“存活”，SafeKit 则监控特定 {{ .Get "app" }} 应用程序的实际运行状况。 这种深度监控可检测服务器仍在运行但软件已崩溃的“僵尸”状态，并触发**服务自动重启**或流量重定向，而标准 NLB 解决方案无法实现这些操作。 ### SafeKit 如何处理统一部署和云虚拟 IP？ SafeKit 不依赖特定云平台，确保在本地服务器和所有主流云服务商上采用一致的部署流程和架构。主要的架构差异在于向网络提供**[虚拟 IP (VIP)](/zh-hans/best-practises/how-a-virtual-ip-address-works/)**的方式： * **本地部署：** SafeKit 使用高效的**内核级过滤**，直接在应用程序服务器上管理 VIP 负载均衡。故障转移通过向本地交换机发送 **GARP (Gratuitous ARP)** 数据包完成，交换机随即将 IP 重新分配给活动节点。 * **云端：** 云网络不支持 GARP，因此虚拟 IP 由**云负载均衡器**承载。在此配置中，**SafeKit 提供智能运行状况检查**以判断节点状态。负载均衡器可实时检测活动节点并自动路由流量，从而在可用区之间实现无缝故障转移。 ### 为什么选择统一的一体化 HA 解决方案，而不是零散工具？ 与组合多个集群产品的附加式解决方案不同，**SafeKit** 将**虚拟 IP、网络负载均衡、自动故障转移、自动故障恢复和同步实时文件复制**集成到一个引擎中。 这消除了“纸牌屋”风险，避免更新破坏不同工具之间脆弱的连接；它还为整个 HA 技术栈提供单一责任方，并通过一个界面管理 **{{ .Get "app" }} 应用程序高可用性**，减少人为错误。 ### 没有集群技能，也可以设置 {{ .Get "app" }} farm 集群吗？ 可以。本文介绍如何在无需专业且复杂的集群技能的情况下[快速实现 {{ .Get "app" }} farm 集群]({{ .Get "guide" }})。SafeKit 的运行状况检查负责虚拟 IP 负载均衡、应用程序监控和重启，因此相比传统 NLB 集群解决方案，该方案更可靠、更易于部署和维护，并且具有良好的扩展性。 ### 除了 {{ .Get "app" }}，SafeKit 还能保护哪些应用程序和环境？ SafeKit 是适用于 **Windows 和 Linux** 的多用途高可用解决方案，远不止于 {{ .Get "app" }} farm 集群。它支持采用**同步实时复制**和自动故障转移的 Mirror 集群，可保护多种关键工作负载，包括： * **虚拟和物理环境：** 完整的 Hyper-V 或 KVM 虚拟机。 * **容器编排：** Docker、Podman 和 K3s (Kubernetes) 环境。 * **数据和服务：** 单个文件目录、服务和各种数据库。 * **云基础设施：** 云应用程序的高可用性。 💡 [在此查看支持的 HA 解决方案完整列表。](/zh-hans/solutions/) ## SafeKit farm 集群如何与 {{ .Get "app" }} 配合工作？ {#safekit-farm-cluster} ### {{ .Get "app" }} 的网络负载均衡 (NLB) 如何工作？ * **Multi-AZ 部署：** 将节点分布在多个可用区，以确保数据中心中断时的最大韧性。 * **主动-主动冗余：** 关键 {{ .Get "app" }} 应用程序同时在 farm 的所有节点上运行。 * **智能流量路由：** 用户通过由 {{ .Get "app" }} 负载均衡器管理的[虚拟 IP 地址](/zh-hans/best-practises/how-a-virtual-ip-address-works/)进行连接。 * **实时运行状况监控：** 负载均衡器使用 SafeKit 运行状况检查 URL。节点健康时 SafeKit 返回 **HTTP 200 OK**，发生故障时返回 **HTTP 404**（或超时），使负载均衡器能够自动仅向正常运行的节点路由流量。 ### {{ .Get "app" }} 的高可用性 (HA) 如何工作？ * **高级应用程序检查：** SafeKit 使用内置进程检查器和可自定义脚本持续监控 {{ .Get "app" }} 应用程序。 * **自我修复能力：** 发生软件故障时，SafeKit 会使用预配置的重启脚本尝试在本地自动重启应用程序。 * **无缝故障转移：** 如果本地重启失败，SafeKit 将停止响应运行状况检查，触发负载均衡器立即故障转移到其余健康节点。 * **简化维护：** 每个节点都包含 SafeKit Web 控制台连接器，提供“一键式”界面，可在硬件或软件维护期间手动将节点从集群中排除。 ![SafeKit {{ .Get "app" }} farm 集群示意图，采用 Multi-AZ 冗余；负载均衡器使用 HTTP 运行状况检查在活动节点间路由流量并处理自动故障转移。](/wp-content/uploads/2023/03/cloud-farm-cluster-load-balancing-cluster.png "w:256") **{{ .Get "app" }} SafeKit NLB 和 HA 架构** ### 如何配置负载均衡器规则：{{ .Get "app" }} 应用程序是有状态还是无状态？ {#stateful-stateless} 负载均衡器的配置取决于应用程序是有状态还是无状态： #### 有状态配置（会话亲和性） 对于**有状态**的 {{ .Get "app" }} 应用程序，需要会话亲和性（持久性）。这可确保特定客户端在多个 TCP 会话期间始终连接到同一节点，从而保留其应用程序上下文。在此情况下，负载均衡器规则基于**客户端 IP 地址**。因此，单个客户端固定到特定节点，而不同客户端的流量分布到 farm 的各个节点。 #### 无状态配置（无亲和性） 相反，**无状态**的 {{ .Get "app" }} 应用程序不需要会话亲和性。由于节点不会在会话之间存储本地上下文，同一客户端可在每个新 TCP 会话中分配到不同节点。在这种情况下，负载均衡器规则基于 **TCP 会话标识**。此配置可在 farm 中最高效地分配流量，但仅适用于不依赖会话的服务。 ### 如何在 {{ .Get "app" }} 中配置 SafeKit farm 集群？ {#safekit-farm-cluster-configuration} ![SafeKit Web 控制台：用于网络负载均衡和虚拟 IP 管理的 Farm 集群配置。](/wp-content/uploads/2026/01/safekit-farm-cluster-config.png "w:966") SafeKit **farm 集群**旨在实现服务的高可用性和可扩展性。其配置侧重于同时在两个节点之间分配传入流量： * **负载均衡服务（Macros 选项卡）：** 定义要在所有节点上保持活动的应用程序服务（例如 Apache、IIS、Nginx）。 * **Heartbeat 网络：** 用于检测节点是否已离开 farm 的通信路径。 * **虚拟 IP (Farm VIP)：** 本地部署时，直接在 SafeKit Web 控制台中配置 VIP。云端部署时，使用 SafeKit 运行状况检查在云负载均衡器中配置虚拟 IP。 * **负载均衡规则：** 本地部署时，在 SafeKit Web 控制台中根据源 IP 地址或端口配置流量分配策略。云端部署时，在云负载均衡器中配置策略。 * **检查器：** 监控应用程序运行状况，并在检测到进程故障时触发自动重启。 ### 如何监控 {{ .Get "app" }} 中的 SafeKit farm 集群？ {#safekit-farm-cluster-monitoring} ![SafeKit 控制台：监控 2 节点 Farm 集群，两个节点均处于 UP 状态且负载均衡已启用。](/wp-content/uploads/2026/01/safekit-farm-cluster-monitor.png "w:473") 监控 farm 集群可清楚了解基础设施的**主动-主动**特性，即所有节点都为应用程序性能作出贡献（本例显示 2 个节点）： * **UP 状态（2 个节点各 50%）：** 健康的 farm 中两个节点都处于“UP”（50%）状态，通过共享虚拟 IP 主动接收并处理客户端请求。 * **自动重新均衡：** 一个节点发生故障时，控制台会显示剩余节点接管 100% 流量。故障转移延迟取决于云负载均衡器的运行状况检查轮询间隔。 * **插入节点：** 修复后的节点重新启动时会从“STOP”变为“UP”，无需管理员干预即可自动开始接收其对应的负载。 * **无数据同步：** farm 集群没有“Orange”重新同步状态，因为节点应为无状态或共享后端数据库（该数据库可由 Mirror 集群单独保护）。 除了简单的状态图标外，界面还提供一键节点管理功能，可手动停止或启动节点以进行计划维护，同时共享虚拟 IP 会自动重新分配流量，不会中断用户活动。 ## 比较：本地 SafeKit Farm 集群和云端 SafeKit Farm 集群
