是一种针对云环境优化的软件定义高可用性解决方案。通过在应用程序节点上直接提供**深度监控和自我修复**功能，它确保在软件故障影响可用性之前，在本地检测并解决这些故障。**它与 {{ .Get "app" }} 负载均衡器**无缝集成，使用智能运行状况检查仅将流量路由到完全运行的节点。 ### SafeKit farm 集群为 {{ .Get "app" }} 程序带来了哪些优势？ **深度监控和自我修复：** 检测“僵尸”状态，即云实例“正在运行”，但应用程序已崩溃 SafeKit 在通知云负载均衡器进行故障转移之前，会在本地触发自动服务重启。 * **混合 Farm 和 Mirror 功能：** 独特地允许 farm 集群（通过云 LB 扩展前端）与 mirror 集群（用于后端数据的同步复制）混合，从而解决 {{ .Get "app" }} 中的持久性存储挑战。 * {#safekit-farm-ha-cluster} ### SafeKit Farm NLB {{ .Get "app" }} 解决方案是什么？ {#what-is-the-safekit-farm-nlb-solution-for--get-app-} SafeKit 为跨两个或多个节点的 {{ .Get "app" }} 提供网络负载均衡和高可用性。 本文介绍如何在无需专业高可用性 (HA) 知识的情况下，快速实施 {{ .Get "app" }} 集群。 该解决方案通过将 SafeKit 的**应用程序运行状况检查**与在 {{ .Get "app" }} 负载均衡器级别定义的虚拟 IP 集成在一起，从而实现其功能。通过配置特定的应用程序服务名称和应用程序检查器，SafeKit 确保负载均衡器仅将流量引导至运行状况良好且可操作的应用程序。 SafeKit 支持**网络负载均衡和自动故障转移**，为您的关键任务应用程序提供无缝的可扩展性和持续的服务可用性。 ### SafeKit 应用程序监控与标准 NLB 健康检查有何不同？ {#how-does-safekit-application-monitoring-differ-from-standard-nlb-health-checks} 与依赖简单 **ping** 和端口检查的标准 NLB 硬件不同，SafeKit 具有**集成的应用程序级检查器**。传统负载均衡器仅确认服务器是否“存活”，而 SafeKit 监控特定 {{ .Get "app" }} 程序的实际运行状况。 这种深度监控使系统能够检测到“僵尸”状态（即服务器正常运行但软件崩溃），从而触发**自动服务重启**或流量重定向，而标准 NLB 解决方案无法执行这些操作。 ### SafeKit 如何处理统一部署和云虚拟 IP？ {#how-does-safekit-handle-uniform-deployment-and-the-cloud-virtual-ip} SafeKit 是一种与云无关的解决方案，可确保部署过程和架构在本地服务器和所有主要云提供商之间保持一致。主要架构差异在于 **[虚拟 IP (VIP)](/zh-hans/best-practises/how-a-virtual-ip-address-works/)** 如何呈现给网络： * **本地部署：** SafeKit 使用高效的**内核级过滤**直接在应用程序服务器上管理 VIP 负载均衡。**故障转移通过向本地交换机发送 GARP（免费 ARP）** 数据包来处理，该数据包会立即将 IP 重新分配给活动节点。 * **在云中：** 由于云网络不支持 GARP，虚拟 IP 由**云负载均衡器**托管。**在此配置中， SafeKit 提供确定节点状态所需的智能运行状况检查**。这使负载均衡器能够实时检测活动节点并自动路由流量，从而确保可用区之间的无缝故障转移。 ### 为什么选择统一的一体化高可用性解决方案，而不是零散的工具？ {#why-choose-a-unified-all-in-one-ha-solution-over-fragmented-tools} 与将独立产品组合在一起进行集群的“附加”解决方案不同，**SafeKit** 将**虚拟 IP、网络负载均衡、自动故障转移、自动回切和同步实时文件复制集成**到单个引擎中。 这消除了更新破坏不同工具之间脆弱链接的“纸牌屋”风险，为整个 HA 堆栈提供了一个单一的责任点，并通过为 **{{ .Get "app" }}应用级 HA** 提供一个单一的界面来减少人为错误。 ### 是否可以在没有集群技能的情况下建立 {{ .Get "app" }} farm 集群？ {#is-it-possible-to-set-up-a--get-app--farm-cluster-without-clustering-skills} 是的。本文介绍了如何在不需要专业和复杂的集群技能的情况下[快速实现 {{ .Get "app" }} farm 集群]({{ .Get "guide" }})。通过使用 SafeKit 的健康检查来处理虚拟 IP 网络负载均衡，以及 SafeKit 的应用程序监控和重启，您可以获得一个强大的可扩展解决方案，其部署和维护比传统的 NLB 集群解决方案简单得多。 ### 除了 {{ .Get "app" }}，SafeKit 还能保护哪些应用和环境？ {#beyond--get-app--which-applications-and-environments-can-safekit-protect} SafeKit 是一款**适用于 Windows 和 Linux** 多功能高可用性解决方案，其功能远超 {{ .Get "app" }} farm 集群。**它支持 mirror 集群，具有同步实时复制**和自动故障转移功能，适用于各种关键工作负载，包括： * **虚拟和物理环境：** 完整的 Hyper-V 或 KVM 虚拟机。 * **容器编排：** Docker、Podman 和 K3s (Kubernetes) 环境。 * **数据与服务：** 单个文件目录、服务和各种数据库。 * **云基础设施：** 为云应用程序提供高可用性。 💡 [在此处查看支持的 HA 解决方案的完整列表。](/zh-hans/solutions/) ## SafeKit farm 集群如何与 {{ .Get "app" }} 配合使用？ {#safekit-farm-cluster} ### 网络负载均衡(NLB) 如何为 {{ .Get "app" }} 工作 {#how-network-load-balancing-nlb-works-for--get-app-} * **多可用区部署：** 节点分布在多个可用区（Multi-AZ）中，以确保在数据中心中断时具有最大的弹性。 * **主动-主动冗余：** 关键 {{ .Get "app" }} 程序在 farm 中的所有节点上同时运行。 * **智能流量路由：** 用户通过由 {{ .Get "app" }} 负载均衡器管理的[虚拟 IP 地址](/zh-hans/best-practises/how-a-virtual-ip-address-works/)进行连接。 * **实时健康监控：** 负载均衡器利用 SafeKit 的健康检查 URL。**当节点健康时，SafeKit 返回 HTTP 200 OK**；当节点出现故障时，返回 **HTTP 404**（或超时），从而允许负载均衡器自动将流量仅路由到运行中的节点。 ### {{ .Get "app" }} 的高可用性 (HA) 工作原理 {#how-high-availability-ha-works-for--get-app-} * **高级应用程序检查：** SafeKit 使用内置进程检查器和可自定义的脚本持续监控 {{ .Get "app" }} 程序。 * **自我修复功能：** 如果出现软件故障，SafeKit 会自动尝试使用预配置的重启脚本在本地重新启动应用程序。 * **无缝故障转移：** 如果本地重启失败，SafeKit 将停止响应健康检查，从而触发负载均衡器立即故障转移到其余健康的节点。 * **简化维护：** 每个节点都包含一个 SafeKit Web 控制台连接器，提供“一键式”界面，用于在进行硬件或软件维护时手动将节点从集群中排除。 ![显示具有多可用区冗余的 {{ .Get "app" }} 的 SafeKit farm 集群图表，其中负载均衡器使用 HTTP 健康检查在活动节点之间路由流量并处理自动故障转移。](/wp-content/uploads/2023/03/cloud-farm-cluster-load-balancing-cluster.png "w:256") **SafeKit NLB 和 HA 架构适用于 {{ .Get "app" }}** ### 如何配置负载均衡器规则： {{ .Get "app" }} 程序是有状态还是无状态？ {#stateful-stateless} 负载均衡器的配置取决于您的应用程序是有状态还是无状态： #### 有状态配置（会话亲和性） {#stateful-configuration-session-affinity} 对于**有状态**{{ .Get "app" }} 程序，需要会话亲和性（持久性）。这可确保特定客户端在多个 TCP 会话中保持连接到同一节点，以维护其应用程序上下文。在此场景中，负载均衡器根据**客户端 IP 地址**配置规则。因此，虽然单个客户端锁定到特定节点，但来自不同客户端的流量会分布到 farm 中的各个节点。 #### 无状态配置（无亲和性） {#stateless-configuration-no-affinity} 相反，对于**无状态**{{ .Get "app" }} 程序，不需要会话亲和性。由于会话之间没有在节点上存储本地上下文，因此单个客户端可以在每个新的 TCP 会话中跨不同节点进行平衡。在这种情况下，负载均衡器规则是根据**TCP 会话标识**配置的。此配置可为整个 farm 提供最有效的流量分配，但它仅适用于设计时没有会话依赖性的服务。 ### 如何在 {{ .Get "app" }} 中配置 SafeKit farm 集群？ {#safekit-farm-cluster-configuration} ![SafeKit Web Console：用于网络负载均衡和虚拟 IP 管理的 farm 集群配置。](/wp-content/uploads/2026/01/safekit-farm-cluster-config.png "w:966") **SafeKit farm 集群**旨在实现服务的高可用性和可扩展性。其配置侧重于同时在两个节点上分配传入流量： * **负载均衡服务（宏选项卡）：** 定义要在所有节点上保持激活的特定应用程序服务（例如，Apache、IIS、Nginx）。 * **心跳网络：** 用于检测节点是否已离开 farm 的通信路径。 * **虚拟 IP（Farm VIP）：** 对于本地部署，请直接在 SafeKit Web 控制台中配置 VIP。对于云部署，请使用 SafeKit 的健康检查在云负载均衡器中配置虚拟 IP。 * **负载均衡规则：** 对于本地部署，请在 SafeKit Web 控制台中根据源 IP 地址或端口配置流量分配策略。对于云部署，请在云负载均衡器中配置策略。 * **检查器：** 监控应用程序的运行状况，并在检测到进程故障时触发自动重启。 ### 如何在 {{ .Get "app" }} 中监控 SafeKit farm 集群？ {#safekit-farm-cluster-monitoring} ![SafeKit 控制台：监控一个双节点 farm 集群显示两个节点均处于 UP 状态，并处于主动负载均衡模式。](/wp-content/uploads/2026/01/safekit-farm-cluster-monitor.png "w:473") 监控一个 farm 集群可以了解基础设施的**主动-主动**性质，其中所有节点都为应用程序的性能做出贡献（此示例中显示 2 个节点）： * **UP 状态（2 个节点均为 50%）：** 在健康的 farm 中，两个节点都处于“ UP ”（50%）状态，这意味着它们都通过共享虚拟 IP 积极接收和处理客户端请求。 * **自动重新平衡：** 如果一个节点发生故障，控制台会直观地显示剩余节点承担 100% 的流量。故障转移延迟取决于云负载均衡器的健康检查轮询间隔。 * **节点插入：** 修复后的节点重新启动时，会从“ STOP ”状态转变为“ UP ”状态，并自动开始接收其负载部分，无需管理员干预。 * **无数据同步：** 请注意，在 farm 集群中，没有“橙色”重新同步状态，因为节点预计是无状态或共享后端数据库（可以在 mirror 集群中单独保护）。
