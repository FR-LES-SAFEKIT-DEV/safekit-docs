{#safekit-mirror-ha-solution} SafeKit 可为任何品牌的两台服务器之间的 {{ .Get "app" }} 提供高可用性。 本文介绍了如何在没有共享存储的 SAN 上快速实施 {{ .Get "app" }} 集群，而无需特定技能。 该解决方案的原理是定义 **{{ .Get "app" }} 程序**数据、其服务、虚拟 IP 和检查器所在的文件夹。 SafeKit 随后实施**实时复制**和**自动故障转移**，以确保服务的持续可用性。 ### 为什么选择统一的一体化高可用性解决方案，而不是零散的工具？ {#why-choose-a-unified-all-in-one-ha-solution-over-fragmented-tools} 与将复制和集群的独立产品组合在一起的“附加”解决方案不同，**SafeKit** 将**虚拟 IP、自动故障转移、自动回切和实时文件复制集成**到单个引擎中。 这消除了操作系统更新破坏不同工具之间脆弱链接的“纸牌屋”风险，为整个 HA 堆栈提供了一个单一的责任点，并通过为 {{ .Get "app" }} HA 提供一个单一的界面来减少人为错误。 ### 我应该选择应用程序级别还是虚拟机 (VM) 级别的“高可用性”？ {#application-vs-vm-high-availability} 使用 SafeKit，您可以灵活选择适合您需求的冗余模型。 **VM 级冗余**（适用于 Hyper-V 或 KVM）最易于实施，因为它会复制整个虚拟机，而无需了解内部应用程序。 或者，**应用程序级别的冗余**更细化；它只复制特定的数据文件夹并重新启动应用程序服务，而不是整个操作系统。 虽然虚拟机级别的 HA 更易于设置，但应用程序级别的 HA 与管理程序无关，可以在物理、虚拟或云环境中运行。 ### 与竞争对手相比，SafeKit {{ .Get "app" }} 高可用性有哪些独特的优势？ {#safekit-mirror-ha-advantages} SafeKit 通过其**无共享架构**和简化的部署，使其有别于传统的 {{ .Get "app" }} 集群。虽然大多数企业解决方案需要复杂的复制部署或昂贵的 SAN 存储，但 SafeKit 提供： * **零数据丢失的同步复制：** SafeKit 实现 100% 同步复制，确保事务应用程序的数据完整性。**发生故障时， 数据零丢失 (RPO=0)**。此外，SafeKit 不仅可以复制 {{ .Get "app" }} 数据库，还可以复制**任何其他数据文件夹**（日志、配置文件等），确保整个环境被镜像。 * **简化的双节点集群：** 与通常需要“见证”（第三个节点、磁盘、文件共享）来维持仲裁的标准集群不同，SafeKit 仅需两个冗余服务器即可提供完全的高可用性，从而降低了基础设施成本和复杂性。 [了解更多关于我们的心跳和仲裁机制](/zh-hans/best-practises/heartbeat-failover-quorum-windows-linux-cluster/)。 * **统一管理：** 管理员可以通过单个 SafeKit 控制台管理 {{ .Get "app" }} 故障转移、数据复制和监控。这使得没有专业“集群管理员”专业知识的团队也能实现高可用性。 * **自定义检查器：** SafeKit 不仅限于基本的服务监控，还**提供检查器**来监控 {{ .Get "app" }} 程序进程的运行状况。该系统具有高度可扩展性，允许添加适合您环境的自定义检查器。 ### 与标准集群相比，SafeKit 如何降低 {{ .Get "app" }} 的总拥有成本 (TCO)？ {#safekit-mirror-ha-tco} 与传统的高可用性解决方案不同，SafeKit 的设计旨在以**绝对最低的基础设施开销**运行，同时不影响可靠性。与传统故障转移集群相比，主要节省包括： * **零存储成本：** SafeKit 采用无共享架构，可与本地磁盘配合使用。这样就无需昂贵的 SAN 硬件、iSCSI 网络或复杂的 vSAN 配置。 * **无需企业版：** 虽然原生复制机制可能需要昂贵的企业版许可证，但 SafeKit 提供**永久许可证**。您拥有自己的软件，避免了现代云端或基于订阅的模式中常见的“订阅陷阱”和不可预测的年度价格上涨。 * **运营费用低：** 作为即插即用解决方案，它不需要专门的培训或昂贵的外部咨询来维护，这与复杂的开源集群工具不同。 * **CPU 独立定价：** 许可独立于 CPU 或内核的数量。只需两个节点即可获得两个许可证，从而保护 {{ .Get "app" }} 免受故障影响。
