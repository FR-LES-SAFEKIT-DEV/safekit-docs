**クラウドプロバイダー**はネイティブの冗長性を提供していますが、データレプリケーションと真の高可用性との間には大きな隔たりが残ることがあります。現在、クラウド利用者は、手動フェイルオーバーが必要でデータ損失の恐れがあるネイティブの**非同期レプリケーション**か、シームレスな業務継続に必要な自動フェイルオーバー機能を備えていない**クラウド共有ディスク**のいずれかを選ばなければなりません。 ### SafeKit：複雑な {{ .Get "app" }} クラスターに代わる軽量なオールインワンソリューション {#safekit-cloud-mirror} * **2ノードのオールインワン {{ .Get "app" }} クラスター：** SafeKit は、ネイティブの Multi-AZ（Availability Zone）機能、仮想 IP、自動フェイルオーバーとフェイルバック、リアルタイムの同期ファイルレプリケーションを、統合ソフトウェアパッケージで提供します。 * **データ損失ゼロ（RPO=0）：** DR（災害復旧）向けのクラウド VM ネイティブレプリケーションとは異なり、SafeKit は**ファイルレベルの同期レプリケーション**を使用してトランザクションアプリケーションのデータ整合性を保ち、障害時のデータ損失を防ぎます。 * **共有ストレージ不要のアーキテクチャ：** SafeKit はクラウド共有ディスクと、それに伴う「ディスクロック」の問題をなくします。**ローカルディスクを使うため、最高速度と最低コストを実現します。** 従来のクラスターでは障害ノードのストレージロックがクラウドプロバイダーによって解除されるまで待つことがありますが、SafeKit は各ノードのローカルディスク上に独立した同期フォルダーを使用し、即時のフェイルオーバーを可能にします。 * **アプリケーションの再構成不要：** SafeKit はファイルレベルで透過的にレプリケーションを行います。専用のクラウド共有ディスクへデータを移行せず、システムディスクを含む現在の場所にあるアプリケーションとデータを保護できます。 * **Kubernetes の代替：** SafeKit は Kubernetes 向けに設計されていない従来型およびコンテナー化アプリケーションにも高可用性を提供し、Kubernetes オーケストレーションの運用負荷や複雑さを避けられます。 * **統一された導入（オンプレミスまたはクラウド）：** [クラウドロードバランサー内の仮想 IP](/ja/best-practises/how-a-virtual-ip-address-works/)の設定を除き、SafeKit の導入手順はオンプレミス環境とクラウド環境で同じです。 **高可用性**を軽量なソフトウェア層に集約することで、SafeKit は従来型クラスタリングスイートのわずかなコストで、エンタープライズレベルの冗長性とクラウドでの業務継続を実現します。 ![仮想 IP、自動フェイルオーバー、自動フェイルバック、リアルタイム同期ファイルレプリケーションを備えた {{ .Get "app" }} 向け SafeKit 高可用性クラスターのアーキテクチャ]({{ ソフトウェアは共有ストレージを使わない {{ .Get "app" }} 高可用性クラスターをどのように簡単に実装しますか？ {#safekit-mirror-ha-cluster} ### {{ .Get "app" }} 向け SafeKit Mirror HA ソリューションとは？ SafeKit は、2つの Availability Zone（AZ）にある2台の仮想マシン間で {{ .Get "app" }} の高可用性を実現します。 この記事では、クラウド共有ディスクや特別なスキルを必要とせず、{{ .Get "app" }} クラスターを迅速に導入する方法を説明します。 基本的な仕組みは、{{ .Get "app" }} アプリケーションデータのフォルダー、サービス、仮想 IP、チェッカーを定義することです。 SafeKit は**リアルタイムレプリケーション**と**自動フェイルオーバー**を実装し、サービスの継続的な可用性を確保します。 ### 分断されたツールではなく、統合されたオールインワン HA ソリューションを選ぶ理由 レプリケーションとクラスター化に別々の製品を組み合わせる後付けソリューションと異なり、**SafeKit** は**仮想 IP、自動フェイルオーバー、自動フェイルバック、リアルタイム同期ファイルレプリケーション**を単一エンジンに統合します。 これにより、更新によって異なるツール間の脆弱な連携が壊れる「砂上の楼閣」のリスクをなくし、HA スタック全体の責任窓口を一本化し、**{{ .Get "app" }} アプリケーションの HA**を単一のインターフェイスで管理して人的ミスを減らします。 ### SafeKit は統一導入とクラウド仮想 IP にどのように対応しますか？ SafeKit はクラウドに依存しないソリューションです。オンプレミスサーバーでも主要クラウドプロバイダーでも、導入手順とアーキテクチャは同じです。唯一のアーキテクチャ上の違いは、ネットワークへの**[仮想 IP](/ja/best-practises/how-a-virtual-ip-address-works/)**の提示方法です。 * **オンプレミス：** SafeKit はローカルスイッチに **GARP（Gratuitous ARP）**パケットを送信して VIP を直接管理し、ノード間で IP を即時に移動します。 * **クラウド：** クラウドネットワークは GARP をサポートしないため、**クラウドロードバランサー**が仮想 IP をホストします。**SafeKit はヘルスプローブを提供**してプライマリノードを特定します。ロードバランサーはアクティブノードをリアルタイムに検出して自動的にトラフィックを転送し、Availability Zone 間でシームレスにフェイルオーバーします。 ### 競合製品と比べた {{ .Get "app" }} 高可用性における SafeKit の特長は？ SafeKit は**共有ストレージ不要のアーキテクチャ**と導入の簡単さによって、従来の {{ .Get "app" }} クラスターと差別化されています。多くのエンタープライズソリューションではクラウド共有ディスクの複雑な管理が必要ですが、SafeKit は次の機能を提供します。 * **データ損失のない同期レプリケーション：** SafeKit は100%同期レプリケーションを実行し、トランザクションアプリケーションのデータ整合性を確保します。障害時の**データ損失はゼロ（RPO=0）**です。{{ .Get "app" }} データベースだけでなく、**その他すべてのデータフォルダー**（ログ、構成ファイルなど）もレプリケーションし、環境全体をミラー化します。 * **2ノードクラスターの簡素化：** 標準的なクラスターではクォーラム維持のために「Witness」（第3ノード、ディスク、ファイル共有）が必要になることがあります。SafeKit は2台の冗長サーバーだけで完全な高可用性を実現し、コストと複雑さを抑えます。 [ハートビートとクォーラムの仕組みについて](/ja/best-practises/heartbeat-failover-quorum-windows-linux-cluster/)。 * **統合管理：** 管理者は単一の SafeKit コンソールで、{{ .Get "app" }} アプリケーションのフェイルオーバー、データレプリケーション、監視を管理できます。クラスター管理の専門知識がなくても高可用性を利用できます。 * **カスタムチェッカー：** SafeKit は基本的なサービス監視にとどまらず、{{ .Get "app" }} アプリケーションプロセスの状態を監視する**チェッカーを提供**します。環境に合わせたチェッカーを追加できる拡張性も備えています。 ### 標準的なクラスターと比べて、SafeKit は {{ .Get "app" }} の総所有コスト（TCO）をどのように削減しますか？ SafeKit は信頼性を損なうことなく、**インフラのオーバーヘッドを最小限**に抑えて動作するよう設計されています。従来型フェイルオーバークラスターと比べた主なコスト削減効果： * **クラウド共有ディスクの費用ゼロ：** SafeKit はローカルディスクを使う共有ストレージ不要のアーキテクチャです。 * **Enterprise エディション不要：** ネイティブのデータベースレプリケーションでは高価な Enterprise ライセンスが必要な場合があります。SafeKit は**Enterprise エディションを必要とせず**、標準エディションや**無料エディション**でも動作し、低コストで高可用性を実現します。 * **2ノードで真の効率性：** クォーラム用の「Witness」（第3ノード、ディスク、ファイル共有）を必要とする一般的なクラスターとは異なり、SafeKit は**2台の冗長サーバー**だけで完全な高可用性を実現します。 * **強制サブスクリプションなし：** SafeKit は**永久ライセンス**を提供します。ソフトウェアを所有でき、サブスクリプション依存や予測不能な年次値上げを避けられます。 * **運用経費（OPEX）の低減：** すぐに使えるソリューションのため、複雑なオープンソースのクラスタリングツールのような専門トレーニングや高額な外部保守コンサルティングが不要です。 * **CPU に依存しない価格設定：** ライセンスは CPU やコアの数に依存しません。2ノード分のライセンスで {{ .Get "app" }} アプリケーションを障害から保護できます。 ### クラスター化のスキルがなくても {{ .Get "app" }} Mirror クラスターを構成できますか？ はい。この記事では、複雑な HA クラスター化のスキルがなくても、{{ .Get "app" }} Mirror クラスターを[すばやく導入する方法]({{ .Get "guide" }})を説明します。SafeKit の**自動フェイルオーバースクリプト**がレプリケーションと**{{ .Get "app" }} アプリケーション**の再起動を処理するため、従来型クラスターより簡単に導入・保守できる堅牢な冗長化を実現できます。 ### {{ .Get "app" }} 以外に、SafeKit DR 向けのネイティブクラウド VM レプリケーションの代わりになりますか？ {#ha-vs-backup-ransomware} **いいえ。** 高可用性とバックアップは相互補完であり、置き換えられるものではありません。**SafeKit** はハードウェア障害時もアプリケーションを稼働させて**業務継続性**を確保しますが、論理エラー、誤削除、ランサムウェア攻撃からは保護しません。リアルタイムレプリケーションは変更を即座に反映するため、プライマリノードへのランサムウェア攻撃はセカンダリノードにもすぐ複製されます。このような脅威や誤削除から復旧するには、堅牢な保持ポリシーを備えた専用の**バックアップソリューション**が必要です。破損前の正常な状態に環境を戻せます。
