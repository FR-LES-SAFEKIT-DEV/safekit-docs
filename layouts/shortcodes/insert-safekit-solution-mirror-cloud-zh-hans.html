{#cloud-ha-limitation} 虽然主要的**云提供商**提供原生冗余，但它们通常在数据复制和真正的可用性之间留下一个显著的差距。**目前，云用户必须在两个不理想的路径之间进行选择：原生异步复制**，这需要手动故障转移并存在数据丢失的风险；或者**云共享磁盘**，这缺乏无缝业务连续性所需的自动故障转移机制。 ### SafeKit：复杂 {{ .Get "app" }} 集群的轻量级一体化替代方案 {#safekit-cloud-mirror} * **一体化双节点 {{ .Get "app" }} 集群：** SafeKit 是一款完整的解决方案，在一个集成的软件包中提供**原生多可用区 (AZ)** 功能，包括虚拟 IP、自动故障转移、自动回切和同步实时文件复制。 * **零数据丢失 (RPO = 0)：** 与用于灾难恢复 (DR) 的原生云虚拟机复制不同，SafeKit 使用**同步文件级复制**来确保事务性应用程序的数据完整性，保证在发生故障时不会丢失数据。 * **无共享架构：** SafeKit 消除了对云共享磁盘的需求，并解决了其相关的“磁盘锁定”问题。**它使用本地磁盘以实现最快的速度和最低的成本**。传统集群通常会挂起，等待云提供商从失败的节点释放存储锁，而 SafeKit 使用每个节点本地磁盘中的独立同步文件夹来确保即时故障转移。 * **零应用重配置：** SafeKit 执行透明的文件级复制，允许您保护应用程序和数据在其安装位置（包括系统磁盘），而无需将数据迁移到专用的云共享磁盘。 * **Kubernetes 替代方案：** SafeKit 为传统和容器化应用程序（非为 Kubernetes 设计）提供高可用性，而无需 Kubernetes 编排的操作开销和复杂性。 * **统一部署（本地或云）：** 除了[在云负载均衡器中配置虚拟 IP 外](/zh-hans/best-practises/how-a-virtual-ip-address-works/)，SafeKit 部署过程在本地和云环境中保持一致。 通过将**高可用性**整合到轻量级软件层中，SafeKit 以传统集群套件一小部分的成本，在云中提供企业级冗余和业务连续性。 "app" }}高可用性集群？ {#safekit-mirror-ha-cluster} ### 什么是适用于 {{ .Get "app" }} SafeKit Mirror HA 解决方案？ {#what-is-the-safekit-mirror-ha-solution-for--get-app-} SafeKit 可为两个可用区 (AZ) 中两台虚拟机之间的 {{ .Get "app" }} 提供高可用性。 本文介绍了如何在没有云共享磁盘和特定技能的情况下快速实施 {{ .Get "app" }} 集群。 该解决方案的原理是定义 {{ .Get "app" }} 程序数据、其服务、虚拟 IP 和检查器所在的文件夹。 SafeKit 随后实施**实时复制**和**自动故障转移**，以确保服务的持续可用性。 ### 为什么选择统一的一体化高可用性解决方案，而不是零散的工具？ {#why-choose-a-unified-all-in-one-ha-solution-over-fragmented-tools} 与将用于复制和集群的独立产品组合在一起的“附加”解决方案不同，**SafeKit** 将**虚拟 IP、自动故障转移、自动回切和同步实时文件复制集成**到一个引擎中。 这消除了更新破坏不同工具之间脆弱链接的“纸牌屋”风险，为整个 HA 堆栈提供了一个单一的责任点，并通过为 **{{ .Get "app" }}应用级 HA** 提供一个单一的界面来减少人为错误。 ### SafeKit 如何处理统一部署和云虚拟 IP？ {#how-does-safekit-handle-uniform-deployment-and-the-cloud-virtual-ip} SafeKit 是一种与云无关的解决方案，这意味着部署过程和架构在本地服务器和所有主要云提供商之间保持不变。唯一的架构差异在于 **[虚拟 IP](/zh-hans/best-practises/how-a-virtual-ip-address-works/)** 如何呈现给网络： * **本地部署：** SafeKit 通过向本地交换机发送 **GARP（免费 ARP）** 数据包直接管理 VIP，从而在节点之间即时移动 IP。 * **在云中：** 由于云网络不支持 GARP，虚拟 IP 由**云负载均衡器**托管。**SafeKit 提供健康探测**来确定哪个节点是主节点。这允许负载均衡器实时检测活动节点并自动将其流量路由到该节点，从而确保可用区之间的无缝故障转移。 ### 与竞争对手相比，SafeKit 在 {{ .Get "app" }} 高可用性方面有哪些独特的优势？ {#what-are-the-distinctive-advantages-of-safekit-for--get-app--high-availability-compared-to-competitors} SafeKit 通过其**无共享架构**和简化的部署，使其有别于传统的 {{ .Get "app" }} 集群。虽然大多数企业解决方案需要对云共享磁盘进行复杂管理，但 SafeKit 提供： * **零数据丢失的同步复制：** SafeKit 实现 100% 同步复制，确保事务应用程序的完全数据完整性。**如果发生故障，则不会丢失任何数据（RPO = 0）**。此外，SafeKit 不仅可以复制 {{ .Get "app" }} 程序数据库，还可以复制**任何其他数据文件夹**（日志、配置文件等），从而确保整个环境都得到镜像。 * **简化的双节点集群：** 与通常需要“见证”（第三个节点、磁盘、文件共享）来维持仲裁的标准集群不同，SafeKit 仅需两个冗余服务器即可提供完全的高可用性，从而降低了基础设施成本和复杂性。 [了解更多关于我们的心跳和仲裁机制](/zh-hans/best-practises/heartbeat-failover-quorum-windows-linux-cluster/)。 * **统一管理：** 管理员可以通过单个 SafeKit 控制台管理 {{ .Get "app" }} 程序故障转移、数据复制和监控。这使得没有专业“集群管理员”专业知识的团队也能实现高可用性。 * **自定义检查器：** SafeKit 不仅限于基本的服务监控，还**提供检查器**来监控 {{ .Get "app" }} 程序进程的运行状况。该系统具有高度可扩展性，允许添加适合您环境的自定义检查器。 ### 与标准集群相比，SafeKit 如何降低 {{ .Get "app" }} 的总拥有成本 (TCO)？ {#how-does-safekit-reduce-the-tco-total-cost-of-ownership-for--get-app--compared-to-standard-clustering} 与传统的高可用性解决方案不同，SafeKit 设计旨在以**绝对最低的基础设施开销**运行，同时不影响可靠性。与传统故障转移集群相比，主要节省包括： * **零云共享磁盘成本：** SafeKit 采用共享无架构，可与本地磁盘配合使用。 * **无需企业版：** 虽然原生数据库复制机制可能需要昂贵的企业版许可证，但 SafeKit **不需要企业版**。它与标准版甚至**免费版**无缝配合，以极低的成本提供高端可用性。 * 作为即插即用解决方案，它不需要专门的培训或昂贵的外部咨询来维护，这与复杂的开源集群工具不同。 * **CPU 独立定价：** 许可独立于 CPU 或内核的数量。只需两个节点即可获得两个许可证，从而保护您的 {{ .Get "app" }} 程序免受故障影响。 ### 是否可以在没有集群技能的情况下设置 {{ .Get "app" }} mirror 集群？
