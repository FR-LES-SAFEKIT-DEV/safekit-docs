尽管主要**云服务提供商**提供原生冗余能力，数据复制与真正的高可用性之间往往仍存在明显差距。如今，云用户只能在两种不理想的方案中选择：原生**异步复制**需要手动故障转移并有数据丢失风险；而**云共享磁盘**又缺少保障业务连续性所需的自动故障转移机制。 ### SafeKit：复杂 {{ .Get "app" }} 集群的轻量级一体化替代方案 {#safekit-cloud-mirror} * **一体化双节点 {{ .Get "app" }} 集群：** SafeKit 是一套完整解决方案，在单一集成软件包中提供原生 Multi-AZ（可用区）能力、虚拟 IP、自动故障转移和自动切回，以及实时同步文件复制。 * **零数据丢失（RPO=0）：** 与用于灾难恢复（DR）的原生云虚拟机复制不同，SafeKit 使用**文件级同步复制**确保事务型应用的数据完整性，避免故障时丢失数据。 * **无共享架构：** SafeKit 不需要云共享磁盘，也消除了相关的“磁盘锁定”问题。**使用本地磁盘可实现最高速度和最低成本。** 传统集群可能需要等待云服务商释放故障节点的存储锁；SafeKit 则在每个节点的本地磁盘上使用独立且同步的文件夹，从而实现即时故障转移。 * **无需重新配置应用：** SafeKit 以透明的文件级方式复制数据，可保护应用及其当前安装位置的数据（包括系统磁盘），无需迁移到专用云共享磁盘。 * **Kubernetes 替代方案：** SafeKit 为传统应用和容器化应用（并非为 Kubernetes 而设计）提供高可用性，无需承担 Kubernetes 编排的运维负担和复杂性。 * **统一部署（本地或云端）：** 除了配置[云负载均衡器中的虚拟 IP](/zh-hans/best-practises/how-a-virtual-ip-address-works/)之外，SafeKit 在本地和云环境中的部署流程完全相同。 SafeKit 将**高可用性**整合到轻量级软件层中，以远低于传统集群套件的成本，在云端提供企业级冗余和业务连续性。 ![SafeKit {{ .Get "app" }} 高可用性集群架构，提供虚拟 {#safekit-mirror-ha-cluster} ### 什么是 {{ .Get "app" }} 版 SafeKit Mirror HA 解决方案？ SafeKit 可在两个可用区（AZ）的两台虚拟机之间为 {{ .Get "app" }} 提供高可用性。 本文介绍如何快速部署 {{ .Get "app" }} 集群，无需云共享磁盘或专门技能。 其原理是指定 {{ .Get "app" }} 应用数据所在的文件夹、相关服务、虚拟 IP 和检查器。 随后，SafeKit 通过**实时复制**和**自动故障转移**确保服务持续可用。 ### 为什么选择统一的一体化 HA 解决方案，而不是零散工具？ 与组合不同复制和集群产品的临时拼凑方案不同，**SafeKit** 将**虚拟 IP、自动故障转移、自动切回和实时同步文件复制**集成到一个引擎中。 这可避免更新破坏不同工具间脆弱连接所造成的“纸牌屋”风险，为整个 HA 技术栈提供统一的责任方，并通过一个界面管理**{{ .Get "app" }} 应用高可用性**，减少人为错误。 ### SafeKit 如何实现统一部署和云虚拟 IP？ SafeKit 与云平台无关：在本地服务器和各大云服务商上，部署流程和架构都保持一致。唯一的架构差异是如何向网络提供**[虚拟 IP](/zh-hans/best-practises/how-a-virtual-ip-address-works/)**： * **本地环境：** SafeKit 直接管理 VIP，向本地交换机发送 **GARP（Gratuitous ARP）**数据包，并立即在节点间迁移 IP。 * **云端：** 云网络不支持 GARP，因此由**云负载均衡器**托管虚拟 IP。**SafeKit 提供健康探测**以确定主节点。负载均衡器可实时检测活动节点并自动转发流量，实现可用区之间的无缝故障转移。 ### 与竞争方案相比，SafeKit 为 {{ .Get "app" }} 高可用性带来哪些独特优势？ SafeKit 凭借**无共享架构**和简化的部署方式区别于传统 {{ .Get "app" }} 集群。多数企业方案需要复杂地管理云共享磁盘，而 SafeKit 提供： * **同步复制，零数据丢失：** SafeKit 实现 100% 同步复制，确保事务型应用的数据完整性。发生故障时，**数据丢失为零（RPO=0）**。除了 {{ .Get "app" }} 数据库，SafeKit 还可复制**任何其他数据文件夹**（日志、配置文件等），镜像整个环境。 * **简化双节点集群：** 标准集群通常需要“见证节点”（第三个节点、磁盘或文件共享）来维持仲裁。SafeKit 只需两台冗余服务器即可实现完整高可用性，降低基础设施成本和复杂性。 [了解心跳和集群仲裁机制](/zh-hans/best-practises/heartbeat-failover-quorum-windows-linux-cluster/)。 * **统一管理：** 管理员可通过单个 SafeKit 控制台管理 {{ .Get "app" }} 应用故障转移、数据复制和监控。团队无需具备专门的集群管理技能即可使用高可用性。 * **自定义检查器：** SafeKit 不仅提供基本服务监控，还**提供检查器**来监控 {{ .Get "app" }} 应用进程的健康状况。系统可扩展，支持添加适合您环境的自定义检查器。 ### 与标准集群相比，SafeKit 如何降低 {{ .Get "app" }} 的总拥有成本（TCO）？ SafeKit 的设计目标是在不影响可靠性的前提下，**将基础设施开销降至最低**。与传统故障转移集群相比，主要节省包括： * **无需支付云共享磁盘费用：** SafeKit 使用本地磁盘和无共享架构。 * **无需 Enterprise 版本：** 原生数据库复制机制可能需要昂贵的 Enterprise 许可。SafeKit **无需 Enterprise 版本**，可运行于 Standard 版本甚至**免费版本**，以低得多的成本提供高可用性。 * **双节点真正高效：** 标准集群通常需要“见证节点”（第三个节点、磁盘或文件共享）来维持仲裁，而 SafeKit 只需**两台冗余服务器**即可实现完整高可用性。 * **无强制订阅：** SafeKit 提供**永久许可证**。软件归您所有，可避免订阅绑定和不可预测的年度涨价。 * **低运营支出（OPEX）：** 该即用型方案不需要专业培训或昂贵的外部维护咨询，而复杂的开源集群工具通常需要这些投入。 * **定价与 CPU 无关：** 许可费用不取决于 CPU 或核心数量。两个节点使用两份许可证即可保护 {{ .Get "app" }} 应用免受故障影响。 ### 没有集群技能，也能设置 {{ .Get "app" }} Mirror 集群吗？ 可以。本文介绍如何[快速部署 {{ .Get "app" }} Mirror 集群]({{ .Get "guide" }})，无需复杂的 HA 集群技能。SafeKit 的**自动故障转移脚本**负责复制和重启**{{ .Get "app" }} 应用**，提供可靠的冗余方案，部署和维护都比传统集群简单得多。 ### 除了 {{ .Get "app" }}，SafeKit 还能保护哪些应用和环境？ SafeKit 是适用于 **Windows 和 Linux** 的多功能高可用性方案，支持范围远超 {{ .Get "app" }} Mirror 集群。它可为多种关键工作负载提供**实时同步复制**和自动故障转移： * **虚拟和物理环境：** 完整的 Hyper-V 或 KVM 虚拟机。 * **容器编排：** Docker、Podman 和 K3s（Kubernetes）环境。 * **数据和服务：** 单个文件目录、服务及各种数据库。 * **云基础设施：** 云应用高可用性。 SafeKit 还提供 Farm 集群，为**Web 服务器**等无状态应用提供原生**网络负载均衡和故障转移**。 💡 [在此查看支持的 HA 解决方案完整列表。](/zh-hans/solutions/) {{ $.Page.RenderString (printf "{{%% insert-safekit-mirror-zh-hans app=%q **不能。** 高可用性和备份互为补充，不能相互替代。**SafeKit** 通过在硬件故障期间保持应用运行来保障**业务连续性**，但不能防范逻辑错误、意外删除或勒索软件攻击。实时复制会立即镜像每一项更改，因此主节点遭受勒索软件攻击时，攻击也会立刻复制到辅助节点。要从这类威胁或意外删除中恢复，需要采用具有可靠保留策略的专用**备份解决方案**，以便将环境恢复到损坏发生前的正常状态。 ### 结论
