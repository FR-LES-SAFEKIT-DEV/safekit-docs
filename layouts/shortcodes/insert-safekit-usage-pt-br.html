• Rede de 10 Gb/s ≈ 1 hora / TB (dependendo do desempenho de gravação do disco) | • Usar [armazenamento compartilhado externo](/best-practises/san-vs-nas-shared-storage-for-a-failover-cluster/)(mais caro, mais complexo). Quantidade de arquivos: < 1.000.000 de arquivos | • Desempenho do tempo de ressincronização após uma falha ([passo 3](/architectures/file-replication-byte-level-with-failover-mirror-cluster/#safekit-mirror-cluster)).
• Tempo necessário para verificar cada arquivo entre ambos os nós. | • Colocar os múltiplos arquivos a serem replicados dentro de um disco rígido virtual / máquina virtual.
• Neste caso, apenas os arquivos que representam o disco rígido virtual / máquina virtual serão replicados e ressincronizados. Capacidade de failover: ≤ 32 VMs | • Cada VM roda em um módulo espelho (mirror module) independente.
• Máximo de 32 módulos espelho rodando no mesmo cluster. | • Usar armazenamento compartilhado externo e outra solução de cluster de VM (mais caro, mais complexo). Arquitetura de rede: Rede LAN/VLAN entre sites remotos | • Failover automático do [endereço IP virtual](/best-practises/how-a-virtual-ip-address-works/)com 2 nós na mesma sub-rede.
• Boa largura de banda para ressincronização ([passo 3](/architectures/file-replication-byte-level-with-failover-mirror-cluster/#safekit-mirror-cluster)) e baixa latência para [replicação síncrona](/best-practises/synchronous-replication-vs-asynchronous-replication/)(tipicamente um tempo de ida e volta inferior a 2ms). | • Usar um [balanceador de carga para o endereço IP virtual](/best-practises/how-a-virtual-ip-address-works/)se os 2 nós estiverem em 2 sub-redes diferentes (suportado pelo SafeKit, especialmente em nuvem).
• Usar soluções de backup com replicação assíncrona para redes com alta latência.
