• Rede de 1 Gb/s ≈ 3 horas / TB
• Rede de 10 Gb/s ≈ 1 hora / TB (dependendo do desempenho de escrita em disco) | • Utilizar [armazenamento partilhado externo](/best-practises/san-vs-nas-shared-storage-for-a-failover-cluster/) (mais caro, mais complexo). Contagem de ficheiros: < 1.000.000 ficheiros | • Desempenho do tempo de ressincronização após uma falha ([etapa 3](/architectures/file-replication-byte-level-with-failover-mirror-cluster/#safekit-mirror-cluster)).
• Tempo necessário para verificar cada ficheiro entre ambos os nós. | • Colocar os vários ficheiros a replicar num disco rígido virtual / máquina virtual.
• Nesse caso, apenas os ficheiros que representam o disco rígido virtual / a máquina virtual serão replicados e ressincronizados. Capacidade de failover: ≤ 32 VMs | • Cada VM é executada num módulo de espelho independente.
• Máximo de 32 módulos de espelho em execução no mesmo cluster. | • Utilizar um armazenamento partilhado externo e outra solução de clustering de VMs (mais caro, mais complexo). Arquitetura de rede: Rede LAN/VLAN entre locais remotos | • Failover automático do [endereço IP virtual](/best-practises/how-a-virtual-ip-address-works/) com 2 nós na mesma sub-rede.
• Boa largura de banda para a ressincronização ([etapa 3](/architectures/file-replication-byte-level-with-failover-mirror-cluster/#safekit-mirror-cluster)).
• Baixa latência para [replicação síncrona](/best-practises/synchronous-replication-vs-asynchronous-replication/): tipicamente < 5 ms de RTT; valores superiores devem ser validados em função da taxa de escrita da aplicação. | • Utilizar um [balanceador de carga para o endereço IP virtual](/best-practises/how-a-virtual-ip-address-works/) se os 2 nós se encontrarem em 2 sub-redes (suportado pelo SafeKit, especialmente na cloud).
• Utilizar soluções de cópia de segurança com replicação assíncrona para redes de alta latência.
